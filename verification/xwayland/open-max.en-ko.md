# Graphics descriptor limit / 그래픽 파일 디스크립터 상한

CHG-340 · REQ-015/024 · DES-009/013 · VER-015/024. The selected Xtrans server calls `sysconf(_SC_OPEN_MAX)` to check the numeric descriptor assigned by `socket()`. Its caller is `_XSERVTransSocketOpenCOTSServer` in `Xtranssock.c`. [Native server interfaces #471](https://github.com/Romanof123/JNOX/issues/471)

The graphics Picolibc adapter recognizes the target header's `_SC_OPEN_MAX` and returns 104. POSIX defines this limit as one above the highest assignable descriptor number. The JNOX broker assigns 64–67 to sockets, and the kernel's shared-file table assigns 96–103. Each process has four socket slots and eight shared-file slots. Object pools and package permissions can constrain allocation further. A successful query leaves `errno` unchanged. An unrecognized selector returns −1 and sets Picolibc's `EINVAL`. This profile implements the single query used by Xtrans. [POSIX limits.h, OPEN_MAX](https://man7.org/linux/man-pages/man0/limits.h.0p.html) · [SDK descriptor range](../../sdk/native-aarch64/include/jnox/shared_fd_abi.h) · [Kernel allocator](../../kernel/src/native_shared_fd.rs)

To exercise the contract, compile `open_max_caller.c` against Picolibc's actual `unistd.h`, the installed native graphics include overlay and the SDK's quoted JNOX headers. Link the installed graphics OS archive before the target runtime libraries. In an AArch64 virt package, run the caller in slot 0 and the Rust socket service in slot 1 with argument `1`, route `0:1` and shared FD support. The caller checks socket descriptors 64–67 and a fifth socket's `EMFILE`, duplicates a real shared FD to 103, checks the shared size, and verifies that a minimum of 104 is rejected with `EINVAL`. Its expected exit is 76. [Guest caller](../../sdk/native-aarch64/graphics/os/open_max_caller.c)

이 그래픽 프로필의 `sysconf(_SC_OPEN_MAX)`는 할당 가능한 마지막 번호 103에 1을 더한 104를 반환한다. 프로세스별 동시 할당량은 소켓 4개와 공유 파일 디스크립터 8개로 각각 제한된다. 게스트 호출자는 소켓 테이블 포화, 공유 파일의 마지막 번호 할당과 상한 초과 거부, 정상·오류 시 `errno`를 검사한다. 성공 종료값은 76이다.
