# Exact shared descriptor replacement / 공유 파일 디스크립터 교체

CHG-340 · REQ-015/024 · DES-009/013 · VER-015/024. The AArch64 Picolibc graphics profile supports `dup2(oldfd, newfd)` between shared descriptor slots 96–103. SVC 208 takes the old and new descriptor numbers and requires a zero third argument. EL1 first checks the caller's shared-file route and source ownership. In one masked operation it replaces the exact destination entry, retains the source's access rights and open-file position, and clears the destination's close-on-exec flag. A live equal-number call returns the same descriptor with its existing flags. Source validation and range checks precede replacement. Aliases of the displaced file keep their references. [Native OS interface issue #471](https://github.com/Romanof123/JNOX/issues/471) · [Kernel implementation](../../kernel/src/native_shared_fd.rs)

For Xwayland 24.1.6, the final link references `dup2` from `OsInit` in `os/osinit.c`. It first probes `write(2, fname, 0)`. On failure it tries to open the administration log or `/dev/null`; a successful `fopen` with another file number leads to `dup2(fileno(err), 2)`. The package's authorized native console accepts zero-byte writes to descriptor 2. In `os/utils.c`, the separate popen child path redirects a pipe to stdout or stdin before a shell exec. Cross-class replacement, including a shared file installed at 2, currently returns `ENOTSUP`. The selected runtime's tinystdio standard streams have their own callbacks. The log fallback and popen path still need end-to-end support.

The [guest caller](../../sdk/native-aarch64/graphics/os/dup2_caller.c) expects a shared-FD-enabled slot 0 with `--console-write 0`, Rust socket service in slot 1 with argument `1`, and route `0:1`. Build with the installed graphics overlay and Picolibc headers. A status of 76 covers an occupied destination, the highest descriptor (103), shared cursor, read-only attenuation, stale source preservation, close-on-exec, distinct descriptor classes and cleanup. The last check executes the same zero-length stderr write used by `OsInit`.

게스트 그래픽 런타임의 공유 파일 96–103에서는 지정한 번호를 한 번에 교체한다. 같은 번호는 상태를 보존하고, 닫힌 원본이나 범위 밖 번호는 대상 파일에 영향을 주지 않는다. 읽기 전용 권한과 파일 위치는 원본을 따른다. Xwayland 초기화의 표준 오류 로그 대체, 파이프를 표준 입출력에 연결하는 기능은 별도 수용 항목이다.

The graphics adapter routes named RAM descriptors 32–39 to their owning service for read, write, close, seek, flags and exact duplication. A failed cross-class duplicate first validates the source and leaves the destination unchanged. Seeking an open stream socket, an installed pipe, or an authorized console output returns `ESPIPE`. A closed socket, an unassigned descriptor number or an absent low descriptor returns `EBADF`. In the selected console-output package descriptor 0 has no input endpoint. The console availability check uses a zero-byte write to query the actual output grant. [Named file acceptance](tmpfs/guest.c)

이름 있는 RAM 파일은 32–39번을 담당하는 서비스에서 읽기·쓰기·닫기·탐색과 정확한 번호 복제를 처리한다. 열린 소켓·파이프·허용된 콘솔 출력에 대한 탐색은 `ESPIPE`, 닫힌 소켓이나 미할당 번호에 대한 탐색은 `EBADF`다. 게스트 호출자는 80번 번호, 열린 소켓과 닫은 소켓, 출력만 허용한 패키지의 표준 입출력을 각각 검사한다.
