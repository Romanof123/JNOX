# Native node identity execution / 네이티브 노드 이름 실행 결과

EVD-345 supplies partial VER-020 evidence for IMP-345. Each boot started the same standalone native C ELF in two process slots. Each process read the package identity through SVC 198 and checked the result through the Xtrans hostname caller. The receipt records the three kernel hashes, six exit statuses, native entry PCs and trace digests. [Measured receipt](receipt.json) · [Selected UART](uart.txt)

The same native ELF executed twice per boot for two distinct configured names and an absent configuration. All six processes exited 0. The guest checked uname fields, gethostname, both exact-fit and short output, and the SHA-pinned Xtrans GetHostname function compiled with the checked-error patch. QEMU confirmed function entry PCs for uname, gethostname and the upstream Xtrans function. Each packaged kernel came from a clean Git checkout at the guest revision recorded in receipt.json. Four invalid labels were rejected before image creation. The original first runner failed to supply a leading hyphen as an argument value; the corrected runner uses a single option=value argument.

The whole libX11 1.8.10 xim_trans.c translation unit advanced past sys/utsname.h. Initial compilation then failed inside Xos_r.h at netdb.h. The upstream Unix-only configure succeeded with TCPCONN undefined and UNIXCONN defined. A private copy of Xtrans 1.4.0 now matches explicit local hosts against the package node name, with no DNS lookup on this path. The first Unix-only attempt selected the old staged include through Automake's search order. After correcting precedence, the real next failure was Xtranssock.c line 110, missing sys/ioctl.h. Its SocketBytesReadable needs FIONREAD for socket byte counts. No complete libX11 archive or Xwayland executable was generated by this gate.

세 번의 실제 부팅에서 프로세스 여섯 개가 모두 0으로 종료했다. 서로 다른 두 노드 이름과 미설정 오류, 짧은 버퍼, Xtrans 원본 함수의 동작을 확인했다. UNIX 전용 libX11 컴파일은 기존 utsname 및 DNS 헤더 요구를 지나 소켓 대기 바이트 수를 조회하는 ioctl 단계에서 중단됐다. 커널 이미지와 원본 추적 파일은 로컬 증거 묶음에 보존했다.
