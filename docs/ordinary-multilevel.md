# POL-009 계획된 인수 기준 (#21, #89)

[English](ordinary-multilevel.en.md) · [EVD-040](evidence/evd-040.md)

CHG-042 / IMP-040 / 예정 EVD-040. virt CPU0에서 JNOX_PROFILE=multilevel과 JNOX_APP=mlq 또는 mlfq를 선택한다. JNOX_MULTILEVEL_TRACE=1은 별도의 고정 크기 RAM 기록을 켠다. 신뢰된 Rust 태스크는 최대 네 개이며 각자 16 KiB 스택을 사용하고 선언 순서로 시작한다. MLQ는 큰 클래스부터 선택하고 동률이면 FIFO로 순환한다. MLFQ는 세 단계의 양수 할당량을 사용하고 양보와 차단 전후의 남은 양을 유지한다. 소진하면 강등하고 누적 서비스 주기마다 대기 순서를 보존하며 전체 우선순위를 복원한다.

전환 시 CNTPCT 차이와 IRQ 지연분을 이전 소유자에게만 부과한다. 예외 진입과 복원 지연을 포함하고 선택 처리 시간은 제외한다. 남은 할당량과 다음 부스트까지의 시간 중 짧은 값에 타이머를 설정한다. 늦은 경계에서는 실제 사용량을 정산한 뒤 지나간 부스트를 한 번 적용한다. 프레임, 큐, 클래스, 잔량, 타이머, 서비스 기록으로 독립 재생한다. 상위 두 태스크가 준비된 동안 하위 태스크의 기아, CPU 작업, 조기 양보, 차단과 깨우기, 경쟁자가 있는 부스트 직후 배정을 확인한다.

태스크 함수 반환은 종료다. 빈 구성과 전체 종료는 타이머를 끄고 대기한다. 전부 차단된 경우 정체를 보고한다. 잘못된 깨우기는 false를 반환한다. 잘못된 구성, 계수기 래핑, 산술 오버플로, 잘못된 벡터, 진단 버퍼 소진은 실패 종료한다. 실제 제품 태스크, 클래스, 실행 수요, 지연 목표, 하드웨어 증거는 추가로 필요하다.

## 재현

영문판의 순차 Linux 명령을 mlq와 mlfq에 각각 실행한다. 각 앱의 일반 ELF와 진단 ELF는 별도 디렉터리에 생성한다. 진단은 최대 256개 이벤트에 원본 프레임 104워드, 다음 프레임과 PC, ESR 또는 PPI/제어값, 시작·만료·중지 시각, 태스크별 누적 서비스와 등급·잔량을 기록한다. 선택 직전 큐는 태스크 번호에 1을 더한 니블을 오래된 순서로 이어 붙인다. 수집기는 인터럽트 로그, UART와 종료 대기 PC를 보존한다. 단위는 CNTFRQ의 1/100이고 MLQ 양자 1, MLFQ 할당량 4/6/8, 부스트 주기 16이다. 늦은 인터럽트의 초과분은 하위 단계와 최하위 반복 양자까지 반영한다. 여러 주기를 넘으면 다음 선택 전에 한 번 복원한다. 선택, 기록 복사와 유휴 시간은 서비스에서 제외한다.

## IMP-046 경계 작업

각 행을 QEMU virt에서 새로 부팅한다. 공통 환경은 `JNOX_BOARD=virt JNOX_PROFILE=multilevel`이다. 일반 빌드는 `JNOX_MULTILEVEL_TRACE`를 해제하고 진단 빌드는 `JNOX_MULTILEVEL_TRACE=1`을 추가한다.

| 일반 JNOX_APP | 진단 JNOX_APP | 작업 |
| --- | --- | --- |
| mlq-blocked | mlq-blocked | 동급 태스크 둘이 차단되어 STALL |
| mlq-exited | mlq-exited | 동급 태스크 둘이 복귀하여 DONE |
| mlq-saturated | mlq-saturated | 상위 둘의 공통 종료 시각은 첫 시작 + 24U, 하위는 U 동안 작업 |
| mlfq-delayed | mlfq-delayed | 셋의 공통 종료 시각은 첫 시작 + 96U, 첫 비교값은 시작 + 3P + P/4 |

위 빌드 명령에서 앱을 선택한다. 일반·진단 각각 해당 ELF와 새 캡처 디렉터리로 위 캡처 래퍼를 실행한다. 기본 UART 시한은 호스트 단조 시계로 5초이며, 마지막 줄 수신 뒤 1초 동안 추가 출력을 감시한다. 일반 이미지의 audit.bin에는 타이머 비활성화 후 CNTP_CTL_EL0 실측값 8바이트가 들어간다. 진단에서는 같은 값을 multilevel_terminal_ctl.bin에, 전체 저널을 audit.bin에 저장한다. 양쪽 모두 예외 순서와 최종 idle PC를 남긴다.

신규 진단 저널은 기존 EVD-040의 256행 전체 뒤에 행당 리틀엔디언 u64 11개씩 256행을 덧붙인다. 두 배열의 같은 인덱스가 같은 경계이다.

| 단어 | 관측값 |
| --- | --- |
| 0–2 | 서비스 차감 직후·리셋 전 큐, 직전 소유자의 순위와 잔량. 초기 행은 0 |
| 3 | 정책 리셋을 실행한 누적 호출 횟수 |
| 4–5 | 생존·수면 비트맵. i번째 비트가 슬롯 i이며 미사용 슬롯은 수면 |
| 6–7 | 직전 소유자 타이머 설정 직후 읽은 비교값과 제어값. 초기 행은 0 |
| 8 | 최종 타이머 비활성화 후 제어값. 그 외에는 UINT64_MAX |
| 9 | 작업 공통 절대 종료 카운트. 차단·종료 작업은 0 |
| 10 | 이번 서비스 차감 전 누적 서비스 |

각 최초 캡처를 보존한다. 독립 관측자는 의도적 지연 다음 타이머를 포함하여 비교값과 실제 경계를 명목 기한과 대조한다. 포화 구간과 소유자별 서비스, 리셋 직전 잔량·FIFO 순서·후속 주기 통과의 판정 기준은 [동결 계획](multilevel-limits-plan.md)에 있다. 기존 두 작업은 원래 형식과 재생기를 사용한다.
