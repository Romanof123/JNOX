# CHG-067 · Ordinary Rust tasks sharing a protected batch / 일반 Rust 작업의 배치 공유

[#49](https://github.com/Romanof123/JNOX/issues/49) · [#21](https://github.com/Romanof123/JNOX/issues/21) · POL-014 · [CHG-020 contract](m1-mutex.en.md) · [한국어 기준](m1-mutex.md)

## English

**Gap.** EVD-018 independently checked all 34 assembly-fixture transitions (8 direct, 14 chained/timeout, 12 nested ceiling), saved acquire returns and timer expiry. The kernel mutex policy is Rust. The existing dispatcher is reached through the mutex bench and its assembly clients. The ordinary scheduling profiles inspected at this revision do not supply a POL-014 client workload with a checked data product. Keep the earlier chain/timeout, tie and validation evidence. The remaining virtual question is whether ordinary Rust workers can preempt, block, hand off and resume useful protected work without observing a partial commit. [EVD-018](evidence/evd-018.en.md) · [Mutex policy](../kernel/src/mutex_policy.rs) · [Release matrix](scheduling-release-cases.en.md)

**Frozen reference load.** One Cortex-A72 QEMU virt/GICv2/TCG CPU, 128 MiB, default clock, physical timer PPI30. Two separate opt-in application configurations, PI and ceiling, with linked Rust LOW=2, MEDIUM=5 and HIGH=9 on private EL1 stacks, plus idle. Reuse the admitted users, owner-only unlock, exact waiter ranking, priority restoration, nesting bound two and LIFO rules in CHG-020. No workload calls the oracle. Each cold run begins with record version 0 and zeroed batch, result and audit. LOW computes one 65,536-sample batch x[i]=1+(i mod 16), in 256 chunks of 256; publish a count and sum as a single logical commit under the appropriate lock, then version 1. Independent expected count=65,536 and sum=557,056. Keep scratch and chunk progress private; expose real checkpoint progress without logging each sample. MEDIUM independently consumes the 256 integers 1…256, expected sum 32,896. HIGH reads the permitted committed record once, saves version/count/sum to its private result and exits. LOW, MEDIUM and HIGH must all terminate exactly once. Disallow a precomputed answer; retain linked loop and volatile/observable input progression.

| Configuration | Required normal execution and visible outcome |
| --- | --- |
| PI · single X, users LOW/HIGH | LOW takes X and computes its batch with IRQs enabled. A one-shot timer releases HIGH and MEDIUM together while LOW holds X. HIGH’s actual acquire blocks; ready MEDIUM loses to LOW at effective 9. LOW resumes its interrupted loop, commits version 1 and unlocks. Ownership transfers to HIGH and LOW returns to 2 before the next choice. HIGH resumes its original acquire call successfully and reads the complete committed result. MEDIUM then completes its independent sum; LOW eventually exits. No other worker writes the batch. |
| Immediate ceilings · X=5 (LOW/MEDIUM), Y=9 (LOW/HIGH) | LOW takes X and then Y before processing the batch. It reaches 5 and then 9 without donation. On release IRQ HIGH becomes an equal-priority peer. Use the existing ready-queue ordering/one explicit yield at the predetermined midpoint (128 chunks) if needed; record which scheduling point lets HIGH attempt Y. HIGH blocks on Y. LOW commits the protected snapshot under Y, releases Y to HIGH and retains 5 while still holding X. Before releasing X, LOW completes its audit of the committed batch, writing version 1 and chunk count 256 under X. MEDIUM must acquire X to read the audit, then completes its sum. HIGH reads the snapshot under Y. Check all declared data and the final restoration to 2, no assumption that equal-priority peers execute in a particular incidental order. |

**Real contention, no artificial stall.** At the first return from LOW's successful acquisition of its final required lock, arm the physical one-shot for that actual scheduling point +100 µs (F must exactly represent the offset). Capture arm/start/compare, architectural counter, IRQ entry, interrupted LOW PC, mask, actual chunk index, released readiness, selected frame and ERET. Freeze target, work count and yield point before the run. LOW continues computing without waiting for the timer. Require the release while actual protected work is in progress and before the midpoint yield in the ceiling case. If the timer arrives outside the intended work, retain the run as unqualified. Do not insert a busy wait, rearm or change the deadline during the run. This offset defines a stimulus, never a claimed interrupt bound. The 256-chunk ledger and data outputs still need validation even when the scheduler’s owner sequence looks correct.

**Independent assessment.** Keep one first cold plain and one first cold externally traced launch per configuration (four positions, fresh native Linux capture directories, 15 s host observation allowance each). Plain/traced use the same per-configuration ELF. Record source revision, compiler/options, ELF/hash, QEMU argv, F, all attempted launches and termination cause. Use a fixed RAM journal with explicit completeness/overflow and deferred UART. For every acquisition, block, handoff, release, yield, exit and timer release, record actual caller and successor, base/effective priorities, lock owner/waiters, ready mask, frame/range, saved PC, acquire result and ordered counter samples. Retain private chunk, accumulator, data commit and read markers. Compare raw journal to independent lock/priority and arithmetic replay; map external IRQ/SVC/ERET to the linked ELF and each worker stack, matching resumed PC/register and versioned results. Report IRQ-to-actual HIGH acquire, HIGH blocked→ownership transfer, transfer→actual acquire return and critical-section residency separately with sampling uncertainty; do not equate a selected frame with a completed user operation. Refuse a passing verdict on missing markers, foreign ownership, partial snapshot, invalid restoration or lost returns. Keep historical EVD-018 and both application results separate. Product lock sets, deployed callers, WCET, physical maximum blocking and M3 board interference remain open. REQ-002/005/023 → DES-003/012 → VER-002/005/023. Source implementation and evidence are pending.

## 한국어

EVD-018은 어셈블리 작업의 직접 상속 8회·연쇄/시간초과 14회·중첩 천장 12회 결정과 프레임 복귀를 독립 검증했다. 커널 뮤텍스 정책은 Rust다. 이번 개정은 기존 연쇄·동률·거부 검사를 반복하는 대신, 일반 Rust 작업이 경쟁할 때 실제 보호 데이터가 완전하게 전달되는지 확인한다. [기존 증거](evidence/evd-018.md) · [출시 기준](scheduling-release-cases.md)

- 단일 Cortex-A72 QEMU virt/GICv2/TCG, 128 MiB, 기본 시계에서 별도 PI·천장 구성으로 실행한다. 전용 EL1 스택의 LOW=2, MEDIUM=5, HIGH=9와 유휴 문맥을 둔다. 허가 사용자·소유자 해제·대기자 우선순위·중첩 2·역순 해제는 기존 계약을 따른다. 초기 버전과 결과는 0이다. LOW는 1~16을 반복하는 실제 65,536개 입력을 256개씩 256묶음으로 계산해 개수 65,536, 합 557,056, 버전 1을 잠금 아래 게시한다. HIGH는 잠금 획득 후 완성 스냅샷을 한 번 읽는다. MEDIUM은 1~256을 합산해 32,896을 만든다. 세 작업은 각각 한 번만 종료한다.
- **PI.** LOW/HIGH가 X를 사용한다. LOW가 X를 갖고 계산하는 동안 실제 타이머로 HIGH·MEDIUM을 깨운다. HIGH가 X에서 차단되면 LOW가 9로 상승해 준비된 MEDIUM보다 먼저 중단된 루프를 재개한다. LOW가 게시·해제하면 X는 HIGH로 전달되고 LOW는 다음 선택 전에 2로 복원된다. HIGH는 저장된 acquire 호출로 돌아와 허용된 결과를 읽는다. MEDIUM의 독립 결과도 확인한다.
- **즉시 천장.** X=5는 LOW/MEDIUM, Y=9는 LOW/HIGH가 사용한다. LOW는 X→Y 획득으로 대기자 없이 5→9가 된다. HIGH의 실제 Y 시도는 릴리스 IRQ의 스케줄링 또는 128묶음 지점의 명시적 한 번 양보로 발생하며 실제 선택 시점을 기록한다. Y에서 HIGH가 막힌 뒤 LOW는 버전 1 스냅샷을 게시하고 Y를 넘긴다. X를 보유한 동안 우선순위 5를 유지하며 검산 기록에 버전 1·256묶음을 쓴다. MEDIUM은 X 획득 후에만 이를 읽고 HIGH는 Y에서 배치를 읽는다. LOW의 최종 2 복원과 모든 결과를 확인한다.
- 마지막 필요 잠금을 획득해 LOW로 복귀하는 스케줄링 지점에서 실제 시각+100 µs에 PPI30을 한 번 설정한다. F로 정확히 표현 가능한 경우만 사용한다. IRQ를 허용하고 작업을 계속한다. 마스킹 상태·중단 PC·묶음 인덱스·준비 전이·복귀를 기록하며, 실제 계산 중이고 천장 구성의 중간 양보 전이어야 한다. 놓친 경우 원본을 미적격으로 보존한다. 타이머 대기를 위한 반복·재설정·실행 중 목표 변경은 없다. 100 µs는 자극 위치일 뿐 측정된 지연 상한이 아니다.
- 각 구성별 동일 ELF로 일반/외부 추적 콜드 첫 실행을 한 번씩, 총 네 자리를 사전 선언한다. Linux 기본 파일시스템의 새 경로, 호스트 관측 한도 15초, 최초 실패·누락 포함이다. 고정 RAM 기록과 종료 후 UART로 해시·구성·주파수·호출자/후속 작업·소유자/대기자·우선순위·프레임·반환값·순서·진행·게시·읽기를 보존한다. 독립 정책/산술 재현 및 실제 IRQ/SVC/ERET와 링크된 PC·스택을 대조한다. IRQ→실제 HIGH acquire, 차단→소유권 이전, 이전→실제 복귀와 임계구간 체류를 계측 오차와 함께 분리한다. 누락·부분 게시·잘못된 소유·복원은 불합격이다. 제품 잠금 집합·WCET·실보드 최대 블로킹과 간섭은 별도 근거가 필요하다. REQ-002/005/023 → DES-003/012 → VER-002/005/023.
