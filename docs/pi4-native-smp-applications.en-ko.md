# Native partitioned processes on two Pi 4 cores / Pi 4 두 코어의 네이티브 분할 실행

[#355](https://github.com/Romanof123/JNOX/issues/355) · CHG-146 / IMP-146 / EVD-146 prospective design on `3373dcc6ce8230cc65240fe78f6500fb2798f6b6`. The existing Pi fixed profile runs two ELFs on CPU0; the existing Pi SMP workloads release CPU1 to linked kernel entries. This profile combines real per-CPU selection with independently packaged user processes on the stock raspi4b Cortex-A72/GICv2 model. [Pi native ABI and layout](pi4-native-fixed-applications.en-ko.md) · [Pi secondary bootstrap](boards/pi4-smp.en.md) · [POL-013](scheduling-release-cases.en.md)

기존 Pi 네이티브 FIFO/RR에서는 CPU0가 두 ELF를 구동한다. 별도 SMP 근거의 페이로드는 커널에 링크되어 있다. 새 선택기는 일반 ELF의 전용 주소 공간과 실제 코어별 선점을 결합한다.

## Operator package / 운영자 패키지

~~~sh
python3 tools/build_native_el0.py --board pi4 --policy smp-partitioned --out pi4-two \
  --elf low.elf --peer-elf high.elf --cpu-mask 1 --peer-cpu-mask 2 \
  --priority 2 --peer-priority 2
~~~

Accept exactly 2–3 ordinary native-v1 ELF slots; preserve existing per-slot argv, order, language and permissions. CPU0/1 online, CPU2/3 parked. One singleton CPU mask per slot (decimal 1 or 2); require both online cores represented. There is no silent conversion of a multi-CPU mask into an assignment. Each slot supplies fixed priority 1–255, higher wins, equal priority FIFO by ready insertion/slot order for simultaneous arrivals, retaining the eligible incumbent until block/yield/exit or a strictly higher priority. `--release-cell K` and repeated `--peer-release-cell K` default to zero; if peer offsets supplied require one per peer in order. One finite release per ELF; 0≤K≤255. Yield places caller behind equal-priority peers. Real absolute sleep, wake, ordinary clock read and signed exit use the existing syscall ABI. Unsupported calls return the existing errno. Preserve original FIFO/RR selector and Pi single-CPU startup. Reject wrong board, count, mask, cardinality, priority, conflicting knobs, arithmetic overflow or invalid ELF before first EL0 entry. CLI and raw build must share the normalized table; bind selected BSP, CPU set, descriptors, ordered ELF hashes/argv, executable layout and toolchain to the manifest. Package data decides eligibility; no program-specific return PC, result address or app callback selects the owner.

2~3개 사용자 ELF에 CPU0 또는 CPU1 단일 마스크와 우선순위, 유한 최초 릴리스 셀을 지정한다. 두 CPU 모두 사용해야 한다. 동순위는 준비 순서, 동시 도착은 슬롯 순서다. 실행 중인 작업은 상위 우선순위 준비 또는 실제 차단·양보·종료 시 교체한다. 기존 인자·슬립·종료·권한과 단일 코어 선택기를 보존한다. 직접 빌드도 동일한 형식 및 범위 오류를 EL0 이전에 거부한다.

## Boot, ownership and stop / 부팅·소유권·정지

1. Start at the #322 raw physical load address 0x80000. CPU0 alone checks exception level, establishes bootstrap stack, relocates initialized image into the protected linked region, zeroes BSS exactly once and loads user images/stacks. Keep secondary trampoline and release word physically reachable across the transition. Use the verified stock raspi4b spin slot for CPU1 at 0xe0, publish the physical trampoline only after table/data/instruction-cache maintenance, clean to PoC as required, DSB SY then SEV. Other secondary slots remain untouched. On CPU1 validate full MPIDR and entry EL before taking its private stack. Set up EL1h, VBAR, translation/cache attributes and timer access; both CPUs rendezvous with release/acquire synchronization before admitting app work. Do not transplant the linked workload's small identity window over the native 4–8 MiB user VA or stack. Record the target, stub, kernel map and physical addresses; direct-model boot does not validate real firmware/SD startup.
2. Dedicated guarded EL1 exception/IRQ stack and idle stack per CPU, disjoint from every user stack. CPU-local current slot/generation, owner lease, TTBR, per-core PPI/SGI state, timer bookkeeping and journal. Select CPU-local state by validated architectural core identity; reserve kernel CPU-local storage independently of EL0 TLS. Configure shared GIC distributor once, each banked PPI30/CPU interface locally. Device and coherent normal-memory mappings keep their correct attributes. Mask local IRQ during context transitions and protect genuinely shared state with bounded synchronization. Never retain a mutable Rust borrow across an unmasked IRQ or lock while running EL0, waiting, writing UART or waiting for another CPU.
3. Fixed affinity prohibits migration in this increment. Each transition has exactly one owner and charge: inactive → ready-on-assigned-core → claimed → executing → interrupted/saved → ready, blocked or terminal. Publish the complete saved frame before a new claimant can restore it. Preserve GPRs, ELR/SPSR, SP_EL0, SIMD, FPCR/FPSR and user TLS registers. The process retains its own VA layout, private backing and unique ASID for the entire boot. Use the same privileged-only kernel mappings and inner-shareable page attributes in every root; CPU-local translation and instruction synchronization must complete before first ERET. Publish immutable page tables before CPU1 enables them. No live ASID reuse, private-page remapping or shared writable user pages in this profile. Any future rebind must invalidate stale translations on every affected CPU with appropriate shareable TLBI, DSB/ISB and completion acknowledgment before reuse.
4. After both CPUs report ready, establish a checked future common epoch E and Q=floor(F/50)>0 (20 ms nominal), measured physical F on **both** CPUs. CPU0 owns release calendar; at E+kQ publish each newly eligible descriptor once. For remote availability order normal stores before precisely targeted SGI1 to CPU1. Acknowledge raw IAR including sender/target and EOI the same IAR. CPU1 rechecks ready priority; another local IRQ cannot opportunistically dispatch the remote job before its designated causal handoff in the named SGI case. If local state changes naturally and a different event wins, report its actual cause and withhold that SGI witness; do not defer lawful dispatch to arrange evidence. Each CPU arms its own anchored PPI30 checkpoint while work remains, or its earliest required sleep/wake deadline if sooner. Keep absolute releases despite late handling, log skips, and never charge another CPU's interrupted context or elapsed idle time.
5. A process exit terminates only its slot. Idle cores park with IRQs enabled when future releases/wakes exist. Terminal iff all finite releases consumed, no process runnable/blocked/executing, and no live handoff. CPU0 requests stop via a separately identified coordinated rendezvous; each CPU disables its own comparator, completes pending acknowledgment, saves final owner/counters and release-publishes its parked acknowledgment. CPU0 emits one consolidated terminal report only after CPU1 acknowledges; no postterminal user return. Bound capture timeout, trace loss and per-CPU journal capacity, publishing total/stored/dropped individually.

CPU0만 재배치·BSS 초기화·페이지 테이블 구성을 수행한다. CPU1은 0xe0 물리 spin slot과 정해진 장벽으로 기동하고 전용 예외 및 idle 스택을 사용한다. CPU2/3은 주차한다. CPU별 GIC·PPI·현재 소유자와 로그, 태스크별 전체 프레임·TLS·고유 ASID를 분리한다. 릴리스 정보를 먼저 게시한 후 원격 SGI를 보낸다. 실제 선점 원인을 변경하지 않는다. 마지막 종료는 양 코어의 로컬 타이머 정지와 CPU1 승인 후 CPU0가 한 번만 기록한다.

**1단계.** 각 부팅의 원본 RAM·ELF·프레임·예외 로그를 인증한다. 저장 PC 직전 실제 데이터 흐름에서만 후보 값을 읽는다. C는 나눗셈 루프에서 W8을 사용하고 Rust W11은 0x40007c에서 결과 카운트로 덮인다. 원본 저장/복원 프레임, CPU·ASID, 다음 행의 실제 복귀 카운터(8), 이번 예외 진입(4), IAR·비교값과 외부 ERET를 연결한다. 두 작업의 후보 증가, 중간 인터럽트·복귀 공백과 상대 코어의 내부 관측 시점에서의 소유권을 대조한다. SGI 프레임은 추가 증거이며 필수 PPI를 대신하지 않는다. 공통 카운터 오프셋의 가능한 전체 범위에서 엄격한 순서를 판정한다. 송신 측 게시 후(15), SGIR 전(16), 전송 함수 후(36), 수신 IAR·메일과 C의 첫 시계 SVC를 구분한다. 수신이 36번 표본보다 빠를 수 있다. 시험 중인 동일 인계를 시계 보정에도 사용하지 않는다. 원래 셀 2의 엄격한 기한을 적용한다.

**2단계.** 미확인으로 남을 때만 원본 실행 파일 해시·빌드 설정과 일치하는 QEMU 공개 플러그인 기능을 먼저 확인한다. 기존 Pi 관측기는 다른 해시이므로 동일 버전만으로 승인하지 않는다. 기능 부족 시 새 부팅 없이 기록한다. 가능할 때만 원래 추적 쌍의 커널·두 앱·마스크·타이머·호스트 설정 그대로 식별된 추가 1회를 고정한다. 두 실제 저장 명령과 바로 다음 PC, 루트별 물리 페이지를 확인하고 검증된 저장 256건마다 기록한다(C 최대 307, Rust 최대 276). 저장 전 콜백·메모리 이벤트·같은 vCPU의 실제 다음 PC 도착을 묶고, 사이에 예외·abort·idle·문맥 교체·누락이 있으면 폐기한다. 반환 후 같은 PC에 도달했더라도 중단된 표본을 재사용하지 않는다. 두 코어의 실제 EL0 시작과 다음 예외까지 모두 확인한다.

해상도·순서 불확실성을 넓혀도 겹치지 않는 호스트 단조 시각 구간 4개가 A0,B0,A1,B1 또는 역순이고, 그 전체가 두 작업의 실제 연속 EL0 실행 안에 있어야 한다. 게스트 구간은 별도로 복귀·진입 카운터와 코어 간 오프셋으로 감싼다. 호스트 나노초를 게스트 틱으로 환산하지 않는다. 모호한 값·순서·소유권·누락은 미관측이다. 추가 실행의 모델상 진전만 판정하며 원본 일반 실행, 실제 보드, 호스트 병렬성 및 원격 추적 기한 판정을 승계하거나 변경하지 않는다.
