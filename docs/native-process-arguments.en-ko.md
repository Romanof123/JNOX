## Package contract / 패키지 규약

~~~sh
python3 tools/build_native_el0.py --out sensor-pair --elf sensor.elf \
  --arg sum --arg 16 --arg 32 --arg 'west rack' \
  --peer-elf sensor.elf --peer-arg minmax --peer-arg 64 --peer-arg 96 --peer-arg ''
~~~

Repeat --arg for slot 0, --peer-arg for slot 1 (first --peer-elf), --peer2-arg for slot 2 (second --peer-elf). Each occurrence contributes one string in encounter order for its own slot, independent of interleaving across slots. The fixed argv[0] is /bin/app. No occurrences means argc=1 for that slot; one empty argument means argc=2. An empty string, embedded spaces, commas, quotes, newlines and UTF-8 bytes are data. Use --arg=-west for a value beginning with a dash (similarly for peers). The invoking shell processes its own quoting once. Never split, normalize Unicode, evaluate shell syntax, perform variable expansion, or recreate a command line from the received values. Reject embedded NUL and invalid UTF-8. Ordinary --source accepts primary arguments just as --elf does. Reject arguments for a missing peer or the no-input startup probe. Preserve all policy selectors.

Per slot allow at most 15 extra strings (argc ≤16), with at most 1,024 bytes across the **extra strings including their terminating NULs**. Count UTF-8 bytes. Report the slot and failed limit before launching any program. A single extra payload of 1,023 bytes fits; a 1,024-byte payload alone exceeds the budget. Empty extras each consume one byte. Store each effective vector as an ordered JSON string array alongside its slot's ELF filename and SHA-256 in the manifest. Repeated ELF digests can have distinct vectors; use the slot index as identity.

For raw Cargo, use JNOX_NATIVE_ARGV0_HEX, JNOX_NATIVE_ARGV1_HEX and JNOX_NATIVE_ARGV2_HEX for slots 0, 1 and 2 respectively. The digits in these names are slot IDs. Each is the ASCII hex encoding of one binary vector of extras: unsigned one-byte count, followed by a little-endian u16 payload length and exactly that many UTF-8 bytes per argument. Exclude terminating NULs from this wire encoding and append them when forming the native stack. Absence or 00 denotes zero extras; 010000 denotes one empty extra. An empty environment value, odd hex length, nonhex byte, length overrun, trailing byte, prohibited NUL, invalid UTF-8 or exceeded limits is a raw-build refusal. Reject even 00 for an absent slot or probe. Bound encoded size before allocation. Track each variable for Cargo rebuilds, remove inherited selectors from the package build environment, and embed the validated slot vectors in the kernel artifact. Identical ELF inputs with changed arguments must rebuild the launch configuration. Use byte-valued generated data or safely escaped constants. Shell interpolation is unnecessary.

슬롯 0·1·2에 각각 --arg, --peer-arg, --peer2-arg를 반복한다. 입력 한 번이 인수 하나이며 빈 문자열과 공백·UTF-8도 그대로 전달한다. 첫 문자열 /bin/app 다음에 최대 15개, 각 NUL을 포함한 추가 문자열 합계 1,024바이트까지 허용한다. 패키지 명세는 ELF 해시와 슬롯별 문자열 배열을 함께 저장한다. Cargo에는 개수·길이·UTF-8 바이트를 16진수로 전달하고 잘못된 길이·문자·누락 슬롯·초과분을 거부한다.

## Native stack and dispatch / 초기 스택과 디스패치

Validate all slot inputs and compute all tails before installing mappings or entering EL0. For a customized slot use the LP64 little-endian layout at SP: argc, argc pointer words, argv[argc]=NULL, and a second NULL for empty envp. Follow with /bin/app and each extra in order, all NUL-terminated; trailing alignment padding is zero. Header size is 8×(argc+3), initial string bytes are 9 for /bin/app including its NUL, and tail length is align_up_16(header+9+extra_bytes). Check every size, alignment, offset addition, stack subtraction and final pointer range. At the maximum, the tail is 1,200 bytes, within the existing 64 KiB private stack. Encode absolute **user** addresses. Each argv[i] must refer to its complete string inside this slot's initialized tail. Initialize SP_i=STACK_TOP−tail_len_i in the saved frame for every process; pass SP_first of the actual selected slot to the initial native_el0_enter. Every later restore uses the selected slot's saved SP, including its current in-function stack after a yield. Retain per-slot ELF entry, startup argc, SP and tail length for independent inspection. Preserve existing primary journal fields and output contracts for legacy cases.

For any ordinary slot without extras, including one in a mixed customized/default package, retain the exact legacy 80-byte tail: SP=0x01010fb0, strings at SP+48, argc=1, empty argv/envp sentinels and identical padding. Preserve the probe tail byte-for-byte at the same SP with argc=3 and strings /bin/native_startup_probe, 8 and 13 in their existing positions. Continue to use the established probe path. Only customized slots use the compact layout. For a concrete customized vector [/bin/app, sum, 16, 32, west rack], argc=5, header=64, extra_bytes=20 and tail=96. When the returned virtual addresses coincide across slots, private mappings still select distinct physical backing. [Startup probe](../examples/portability/native_startup_probe.c)

모든 슬롯의 크기·정렬·포인터와 문자열 범위를 부팅 전에 검사한다. argc, 포인터 배열, argv와 빈 envp의 종료 NULL 두 개 뒤에 문자열을 놓고 16바이트 정렬을 적용한다. 최댓값은 1,200바이트다. 실제 첫 실행 슬롯의 SP를 EL0 진입에 사용하고 이후에는 해당 슬롯의 저장된 SP로 복귀한다. 인수 없는 슬롯과 기존 프로브는 80바이트 스택, 원래 포인터·패딩까지 그대로 보존한다.

## First observations / 최초 관측

1. Freeze source, binaries, disassemblies, manifests, argument bytes, selected policy, QEMU virt/GICv2 one Cortex-A72, 128 MiB, boot command and plain/externally traced positions before launch. Host controls cover exact-limit acceptance and one-byte/count overflow, multibyte UTF-8 split at a limit, malformed raw encodings, missing peers, probe refusal, duplicate ELFs, and all combinations of default/custom slots. Compare default/probe tail bytes against the accepted main layout, including all pointer words and zeros. Rebuild with the same ELFs after changing only slot 1's text and inspect its embedded data and manifest.
2. Build one C sensor ELF taking operation, low, high and label. For i in [low,high) consume a volatile private ramp sample i mod 256, publish count and either sum or min/max, plus argc, argument lengths and exact label bytes. Yield through the ordinary SDK after every four samples, then reread the label through the original argv pointer and verify a private stack local. Run the command above cooperatively. Slot 0 must publish count 16, sum 376 and label bytes for west rack, exit 17. Slot 1 must publish count 32, extremes 64 and 95, zero-length label, exit 29. Require actual handoff, return, distinct initialized data and complete products. Exit codes alone cannot establish argument delivery.
3. Add an independently linked no_std Rust ELF using the existing native main C ABI (argc, argv). Validate count and NULL terminators, consume C strings as bounded byte slices, and compute the same sum over [240,256): count 16, sum 3,960, exit 43. Run as slot 2 with the exact UTF-8 label -동쪽 센서 using --peer2-arg='-동쪽 센서'. Use FIFO priorities 1,2,7 so slot 2 enters first; repeat the two-slot C package with priorities 1,7 so slot 1 enters first. Keep the Rust UTF-8 label exactly as shown; its tail is 112 bytes. For the two-slot priority control only, replace slot 1's empty label with exactly 32 ASCII x bytes; its tail is 128 bytes. Slot 0 retains its 96-byte tail in both runs. Inspect each actual _start SP, argc, all user pointers and bytes in the active mapping, post-yield restoration and products. A highest-priority process may reselect itself on yield; the cooperative run supplies the inter-process handoff.
4. Run unchanged native startup probe and a default single ordinary app; also run a mixed pair with only the peer customized and the primary's argc=1 default path. Preserve original outputs and compare recorded initial frames against actual addresses. Record failures, unobserved switches or missing private data explicitly. These observations cover argument transport and native startup on the named virtual machine. Shell execution, environment configuration and physical-board qualification are outside the deployed interface.

최초 실행 전에 ELF·인수 바이트·정책·명령을 고정한다. 같은 C 바이너리를 두 번 배치해 양보 후에도 서로 다른 구간과 라벨을 유지하는지 확인한다. Rust 슬롯을 세 번째 고우선순위로, C 동료를 두 번째 고우선순위로 각각 시작시켜 실제 첫 SP와 _start에서 읽은 포인터·바이트를 대조한다. 기본 단일 앱, 기존 프로브, 동료만 사용자 인수를 받는 혼합 패키지도 확인한다. 계산 결과, 스택 복귀, 실패 원본을 각각 보존한다.
