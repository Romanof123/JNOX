# Native periodic processes with RM and DM / 네이티브 주기 프로세스의 RM·DM 스케줄링

Prospective [#300](https://github.com/Romanof123/JNOX/issues/300) / #12 / #21 POL-004 design on accepted EDF main `33ee8c35a62ede54987f9af4ae51d3f2fcea3d35`. CHG-118 / IMP-118 / EVD-118 reserved. A packaged C or Rust program processes successive batches without restarting. An operator can select rate-monotonic (RM) or deadline-monotonic (DM) dispatch for the same ELF images. Shorter periods rank first under RM; shorter relative deadlines rank first under DM. This delivers a recurring operating-system service, with no application-specific kernel workload.

같은 C·Rust ELF들을 패키지에 넣고 운영자가 RM 또는 DM을 고른다. 앱은 첫 공개 시점에 시작해 배치 하나를 완료하고 다음 세대를 기다린다. 프로세스·사설 데이터·스택은 계속 유지된다. RM은 주기가 짧은 순서, DM은 상대 마감이 짧은 순서로 선택한다.

## Existing paths and integration / 기존 경로와 통합

The existing native absolute-sleep example sets its own deadlines. The #299 EDF tuple describes one finite release per process. The ordinary linked periodic selector builds control-rm/control-dm scenarios. The original periodic and overrun kernels already rank jobs using DispatchPolicy and ReadyQueue. Enable those same RM/DM keys for the normal private EL0 slots, reusing the native release IRQ, full frame, address-space switch, idle and exit plumbing. Keep the linked periodic controls and EDF admission model intact. [Periodic benchmark](../kernel/src/periodic.rs) · [Overlapping jobs](../kernel/src/periodic_overrun.rs) · [Shared ranking](../kernel/src/dispatch_policy.rs) · [Native EDF](native-edf-applications.en-ko.md)

기존 네이티브 절대 대기 예제는 앱이 시각을 계산하고, EDF는 슬롯당 한 번 공개한다. 기존 주기 벤치와 연결형 제어 작업의 정책 비교 함수를 재사용한다. 일반 EL0 경로에 필요한 추가 상태는 세대별 공개·마감·완료와 다음 세대를 기다리는 호출이다.

## Operator and SDK contract / 패키지와 SDK 계약

Proposed command (durations in integer nanoseconds):

~~~sh
python3 tools/build_native_el0.py --out rm-batches --policy rm \
  --elf crc.elf --periodic 0,100000000,90000000 \
  --peer-elf histogram.elf --peer-periodic 0,120000000,40000000
~~~

Use `--policy dm` with identical files and tuples for DM. Each primary or peer supplies exactly one `phase_ns,period_ns,relative_deadline_ns` tuple in package order. Support one to three independent slots and the existing primary C source option. Require period > 0, 0 < relative deadline ≤ period, phase ≥ 0. Reject malformed/duplicate/orphan descriptors, mixed policies or scheduling fields and invalid arithmetic at the CLI/build or, for frequency-dependent checks, before user entry. Choose and report a common future counter epoch S after verifying every ELF. Require exact positive physical tick conversion for each positive parameter on the selected clock, using wide intermediates and checked u64 results. Record tuples, units, raw counter frequency, mode, slot order and ELF hashes. Every live slot continues until ordinary exit; neither EDF's reference horizon nor a generation limit is part of this interface.

Add native-v1 service number 9 (previous public services end at 8), no arguments: C `int jnox_periodic_wait_next(void)` in `<jnox/periodic.h>` returns 0 after the following generation is eligible for that process, or −1 with errno. Safe Rust `wait_next_period() -> Result<(), i32>` uses the same service. Outside these profiles return ENOTSUP without changing scheduler state. On first release enter the standard main once, with ordinary startup arguments. A successful wait commits the current generation at the sampled call entry and blocks or rolls forward to the next released one. Restore that exact post-SVC frame when selected. Calling the service twice completes two successive activations; startup is already generation zero. SDK exit commits the current generation with its status, cancels further work for that process and reports any previously released unserved generations as cancelled. A prior completed wait never counts again. Arithmetic exhaustion must be detected and reported explicitly before wrapping timestamps or identities.

튜플 단위는 ns이며 순서는 초기 위상·주기·상대 마감이다. 주기와 마감은 양수이고 마감은 주기 이하다. 주파수에 정확히 대응하는 카운터 틱과 공통 시점 S를 기록한다. 호출 9는 현재 세대를 한 번 완료하고 다음 세대가 실행될 때 자기 호출 뒤로 복귀한다. 일반 종료는 현재 세대를 완료하고 이후 작업을 취소한다. 기존 정책에서 이 호출은 상태를 바꾸지 않고 ENOTSUP를 반환한다.

## Generation calendar / 세대 달력

For slot i and generation g=0,1,… derive nominal release Rᵢ,g=S+phaseᵢ+gTᵢ and absolute deadline Dᵢ,g=Rᵢ,g+dᵢ. Compute from the anchored calendar. Charge measured time only to the actually running slot. At a syscall/IRQ sample, account through the sample, record a submitted completion, resolve due deadlines and admit releases, then select. Order different nominal instants chronologically. For the same nominal instant a completion observed at that exact counter passes, unfinished older jobs are checked for deadline miss, then new releases join in slot order. Preserve already elapsed deadlines when a late completion enters before a delayed IRQ: a completion sample > D is a miss even if its timer has not run; a live job at D may be finalized as missed upon observing time > D. Count at most one miss per slot/generation and disclose the observation instant. Retain nominal and actual timestamps separately.

When separate scheduler entries sample the same physical counter value, retain their observed order, owners and frames. For an incumbent that remains running across a poll, fold its wait-next or exit completion at that value before evaluating its coincident deadline and releases. The poll can therefore show a provisional overlap, cancellation candidate or waiting-queue insertion. Use the settled timestamp group to count overlaps, cancellations and misses and to determine which equal-time enqueue survives. Preserve strictly earlier enqueues in their original order. Preserve every actual dispatch or yield and its resulting ownership, including one at the same counter value. Folding calendar bookkeeping never undoes a handoff or assigns an event to a process that did not run. [#300](https://github.com/Romanof123/JNOX/issues/300)

서로 다른 스케줄러 진입이 같은 물리 카운터 값을 읽으면 원본 순서·실행자·프레임을 보존한다. 폴링 전후에 같은 작업이 계속 실행되고 그 값에서 다음 세대 대기 또는 종료를 제출했다면, 해당 작업의 완료를 같은 시각의 마감·공개보다 먼저 반영한다. 폴링 행의 겹침·취소 후보·대기열 삽입은 잠정 상태일 수 있다. 동시 사건을 모두 반영한 결과로 겹침·취소·마감 실패와 최종 대기 순서를 판정한다. 더 이른 시각의 대기열 순서와 실제 디스패치·양보에 따른 실행권 이전은 같은 카운터 값에서도 보존한다.

When the next release arrives while an older generation remains unfinished, record an overlap and keep the new generation pending. Run the oldest unfinished generation of each slot only. Per-slot monotonically growing first-unfinished and next-release indices represent the consecutive backlog, with deadline and miss cursors derived from the calendar. No additional user frame is created on overlap. Batch arithmetic for late/coincident events must agree with chronological replay; do not replay phantom dispatches or spin once per elapsed nanosecond. Interrupt a lower-ranked active slot when higher-ranked work becomes ready. Preserve an equal-rank incumbent except on yield; waiting ties retain enqueue order. Idle and arm the earliest live release, deadline observation or sleeper wake; avoid continually rearming an already serviced compare. Once all exit, cancel their compares and finish.

Ordinary yield offers the CPU to equal-ranked waiting peers and retains the current generation. Absolute nanosleep temporarily suspends that generation, and return from sleep preserves its original deadline; releases may accrue meanwhile. Both remain distinct from wait-next. A single runnable slot can yield and continue. Log rejected calls, truncation and any overflow explicitly without imposing a trace-capacity lifetime on ordinary programs.

각 세대의 공개와 마감은 최초 S에서 계산해 지연이 다음 세대로 누적되지 않는다. 물리 시각이 마감과 같을 때 완료하면 통과하고 초과 완료는 늦은 IRQ보다 먼저 도착해도 실패다. 다음 공개가 먼저 오면 겹침으로 기록하고 슬롯별 오래된 미완료부터 순차 실행한다. 대기열은 연속 세대 범위를 인덱스로 표현해 사용자 스택을 복제하지 않는다. 높은 정책 순위가 준비되면 선점하고 동률은 현재 실행자와 준비 순서를 유지한다. 일반 양보·절대 수면은 현재 세대를 완료하지 않는다.

## Ordinary acceptance cases / 일반 앱 검증

Use QEMU virt/GICv2, one Cortex-A72 and its ordinary physical timer. In the reference pair let q=10 ms, A=(T=10q,d=9q), B=(T=12q,d=4q); both start at S. The C task computes standard reflected CRC-32/ISO-HDLC over (64+g) complete 256-byte ramps with byte j=(index+g) mod 256. The Rust task counts the high-nibble histogram over (32+g) complete ramps using byte j=(17·index+g) mod 256, so all sixteen bins equal 16(32+g). Both keep per-generation products, completed byte counts and a sequence of report writes in private memory; after three generations exit 17 and 29. Recompute each CRC independently with zlib, each bin and all counts from the input formula. Make the products observable in the packaged binaries. These ordinary programs do no external I/O or physical control.

1. **RM and DM.** Package identical binaries twice. Observe A then B for the initial RM pair and B then A for DM; later releases at ticks 10/12 and 20/24, idle between short jobs, three real report writes per slot, two wait-next returns and one exit each. Every release phase is anchored to S. Compare each physical completion with its own absolute deadline. Release a lone task at positive phase in a separate run.
2. **Preemption and overlap.** Use a separately frozen A workload that produces extra private checksum blocks in generation 1 until the observed clock passes its generation-1 start plus 110 ms (finite fail bound and independently recomputed block count/CRC). In the reference calendar A1 starts near tick 10, so it should span A1's deadline at 19 and A2's release at 20. Require evidence that this actually happened. Under DM B1 preempts A1 at tick 12, computes its report by tick 16 and A1 resumes the saved PC. Under RM B1 remains waiting while A1 executes and B1 misses its tick-16 deadline. Show A2 retained until A1 completes, both actual products, individual completion observations and the complete set of misses in each capture. Compare observed dispatch/dwell and lateness; a nominal timeline cannot establish these conditions. Retain the original overrun control's distinct historical timing.
3. **ABI and calendar edges.** Cover one slot waiting repeatedly with a persistent local across releases, two equal keys and explicit yield, sleep later than a release, a delayed initial release, early exit with released backlog, all slots idle then wake, and three slots with independently built inputs. Check outside-profile ENOTSUP, malformed metadata and arithmetic exhaustion. Check completion at D and D+1, coincident releases, duplicate timer delivery and delayed sampling with deterministic host inputs; distinguish exact equality observed in a real guest from equality shown only by the model.
4. **Conditional timing.** Freeze a host RTA run (the reference pair with C_A=C_B=q, zero additional costs yields RM response q,2q and DM 2q,q in A,B order). Supply and record any actual release jitter, blocking, IRQ and dispatch bounds separately for the analyzed configuration. The existing host tool rejects equal keys without an interference model; native tie behavior remains functionally testable. Self-suspending and deliberately overrun jobs are separate functional cases. No measured product WCET or board guarantee follows from the declared costs. [Host RTA](fp-response.en.md) · [Overrun contract](m1-periodic-overrun.en.md)

Freeze binaries, private symbol/ELF identities, each expected result, epoch and timer command, input sizes and first default plain and externally traced positions before guest use. Store counter/nominal release and deadline, generation, overlap/backlog and miss/commit identity, ready/running/suspended sets, cause and armed compare, saved/restored PC and SP, dispatch/service timestamps, private outputs and exit statuses. Independently replay policy ranks, calendar and products. A missing transition or incomplete observation leaves that position unqualified.

최초 일반·외부 추적 부팅 전에 입력과 ELF·순서·판정식을 고정한다. CRC와 16구간 히스토그램이 세 세대를 모두 완료하는지 각자 검산한다. 동일한 앱에서 RM은 A, DM은 B가 먼저여야 하며 매 마감은 물리 완료 시각으로 판정한다. 별도 과부하에서 DM의 B 선점·A 원래 PC 복귀, RM의 B 지연, 겹친 A2 보존을 기록한다. 경계·대기·동률·세 슬롯은 별도 대조한다. 실제 서비스와 작업·보드별 상한을 구분한다.
