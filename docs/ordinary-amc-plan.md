# 일반 Rust 작업의 혼합 임계도 실행

[English](ordinary-amc-plan.en.md) · [#21](https://github.com/Romanof123/JNOX/issues/21) · CHG-076 · POL-015 · 구현·독립 실행 전 설계

#51의 어셈블리 작업으로 작업 슬롯 네 개가 점유된 상태에서 IRQ에 의한 모드 전환, LO 작업 제거, 두 번째 HI 작업의 생존을 이미 확인했다. 그 한 부팅에서 프로그래밍한 만기부터 재개된 HI 작업까지 172,759 카운터 틱(2.764144 ms)이 걸렸다. 이번 설계는 일반 Rust 작업의 소요량을 LO 허용량과 정확히 같게, HI 허용량과 정확히 같게, HI 허용량보다 한 단위 많게 설정한다. 기존 어셈블리 실행과 실측값은 별도 기준으로 보존한다. [#51 검증 계약](m3-mixed-criticality.md) · [EVD-020](evidence/evd-020.md)

## 작업 구성과 예산

일반 AArch64 `virt` 이미지 구성을 사례별로 지정한다. Cortex-A72 한 코어, GICv2/CNTP, TCG, RAM 128 MiB를 쓴다. 링크된 Rust 작업 진입점은 각자의 EL1 스택에서 실행하고, 준비·실행 허가·슬롯 종료·모드 복귀에는 기존 `AmcRuntime<4>`를 사용한다. 입력 명세에는 예산, 우선순위, 기한, 준비 시점과 수요를 넣는다. 아래 예상 순서는 검증자가 사용한다. IRQ가 현재 허가분의 실행을 마감하면 정책이 다음 소유자를 고른다. [AMC 정책](../kernel/src/amc_policy.rs)

#51과 같은 작업 ID 0~3을 쓴다. LO 0과 2는 예산 2, 우선순위 각각 1과 2, 상대 기한 3이다. HI 1은 LO/HI 예산 1/3, 우선순위 4, 상대 기한 4다. HI 3은 예산 1/1, 우선순위 3, 상대 기한 5다. 시간 단위는 모델의 서비스 슬롯이다. 아키텍처 카운터의 기점 E와 Q = floor(CNTFRQ/20)에 대해 경계 k는 E+kQ다. 처음에 LO 0을 한 슬롯 동안 실행한다. 경계 1에서 이전 인스턴스를 종료한 뒤 아래 작업을 준비시킨다. 표의 수요 0은 새 작업이 없다는 뜻이다.

| 사례 | 경계 1에서 ID 0~3의 수요 | 슬롯 0부터의 예상 실행 순서 | 판정 항목 |
| --- | --- | --- | --- |
| LO 허용량과 일치 | (1,1,0,0) | 0,1,0 | 작업 1이 첫 허가분을 쓰고 경계 2에서 완료한다. 모드는 LO이고 대기하던 LO 세대가 실행을 완료한다. |
| HI 허용량과 일치 | (2,3,2,1) | 0,1,1,1,3,0 | 경계 2의 잔여 수요는 (2,2,2,1)이다. 작업 1이 두 번째 허가에서 HI에 진입하고 세 번째 실행이 끝나는 경계 4에서 정상 완료해 절대 기한 5를 지킨다. |
| HI 허용량보다 한 단위 초과 | (2,4,2,1) | 0,1,1,1,3,0 | 경계 2의 잔여 수요는 (2,3,2,1)이다. 작업 1이 세 번째 허가분을 쓰고도 한 단위가 남는다. 경계 4에서 네 번째 허가를 거부하고 예산 소진을 기록한 뒤 시간을 전진시키지 않고 작업을 종료한다. 같은 경계에서 작업 3을 선택한다. |

전환이 일어나는 두 사례는 각 ID의 활성 세대 한 개씩으로 선언된 네 슬롯을 채운다. 한 단위 초과 사례의 잔여 요청 여덟 단위는 이 입력 명세의 최대값이며 거부할 한 단위를 포함한다. 경계 2에서 LO 허용량을 넘기는 양의 허가가 발생하면 다음 실행 전에 LO 0과 2를 제거한다(마스크 5). 새 LO 작업의 준비 요청과 HI 작업이 남은 상태의 승인 복귀를 거부한다. 두 사례 모두 생존한 작업 3이 절대 기한 6에 앞선 경계 5에 완료한다. 모든 작업이 멈추면 미승인 복귀를 거부하고 승인 복귀를 수락한다. 새 LO 0을 한 슬롯 실행해 경계 6까지 그 결과를 확인한다. 제거한 세대에는 추가 서비스를 주지 않는다.

## Rust 작업과 독립 판정

고정된 가상 계측 입력 `[2,5,1,6,3,7,4,8]`을 순환해 읽는다. 각 세대는 IRQ가 활성화된 Rust 작업 문맥에서 측정값을 누적하고 완료한 표본 수와 합을 일관된 쌍으로 공개한다. 작업별 세대 번호는 수락한 준비 요청마다 0부터 매기며, 수락 후 제거된 세대도 포함한다. 작업 i의 세대 g는 합 0, 시작 인덱스 (i+g) mod 8로 시작한다. 표본 수 n의 예상 합은 36 × floor(n/8)에 시작 위치에서부터 n mod 8개 값의 합을 더한 값이다. 덧셈은 u64 범위에서 순환한다. i·g·n을 보존하고 검증자가 입력과 관측한 수만으로 합을 재계산한다. 새 세대의 초기값, 실행한 모든 슬롯의 진척, HI 작업의 두 차례 재개에 걸친 완료 표본 수 증가, 중간 상태 보존, 생존 HI와 새 LO의 최종 결과를 확인한다. 제거한 세대의 마지막 공개 표본 수는 유지돼야 한다. 허가 횟수로 모델의 CPU 배분을, 체크섬으로 해당 작업이 처리한 입력을 판정한다.

각 사례의 최초 독립 콜드부트 판정, 입력 명세, ELF와 해시, UART, 같은 프로세스의 예외·복귀 추적, 판정에 사용한 크기 제한 기록을 보존한다. 링크된 Rust 진입점·전용 스택과 비교해 작업 세대, 네 슬롯의 점유, 허가별 사용량, 모드, 제거·예산 소진 판정, 절대 만기 및 실제 중단·복귀 PC를 재구성한다. 전환 시 같은 카운터에서 만기 b₂, IRQ 관측 i, 모드 반영 c, 복귀 후 작업 자체의 첫 관측 x가 b₂ ≤ i ≤ c ≤ x < b₃인지 본다. 관측 주파수에 따라 x−b₂를 원시 틱과 시간으로 기록하고 세 단위를 받아 정상 완료한 HI 작업의 실제 완료 관측이 b₅보다 이른지, 생존 작업의 실제 완료 관측이 b₆보다 이른지 확인한다. 네 번째 서비스 부여, 제거된 프레임 재개, 새 세대에 이전 체크섬 사용, 기한 위반이 발생하면 해당 사례는 실패다. 근거가 빠지거나 판별할 수 없으면 판정 보류로 기록한다.
