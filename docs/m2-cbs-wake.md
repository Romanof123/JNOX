# M2 하드 CBS 대기 및 깨움

[English](m2-cbs-wake.en.md) · CHG-031 · IMP-029 · 예정 EVD-029 · #65

POL-008은 단일 CPU에서 슬롯 전체를 과금하며 EDF로 선택하고 동률이면 작은 서버 ID가 우선한다. 활성 서버에는 남은 작업이 있다. 수면 작업은 버스트 종료 후 SVC로 대기한다. 활성 서버의 예산이 0이면 기한까지 기다리고 기한에 (Q,d+P)를 받는다. 예산이 양수인 활성 서버는 실행 가능하다. 시각 t에 깨울 때 t≥d 또는 qP>Q(d−t)이면 (Q,t+P)로 갱신한다. 그 밖에는 등호와 잔여 예산 0을 포함하여 (q,d)를 유지한다. SVC 이후 남은 슬롯은 유휴 작업이 사용한다.

A=(2,8)는 0,4,5,13,22에 한 슬롯씩, 23에는 100슬롯을 요청한다. 이웃 B=(1,4)는 1에 100슬롯을 요청한다. 관측 구간은 [0,34)이다. 4에서는 밀도가 같아 (1,8)을 유지하고, 5에서는 소진 상태가 8까지 계속된다. 13에서는 밀도 초과로 (2,21)을 받고 경쟁에서 B가 앞선다. 22에서는 기한 만료로 새 기한이 30이 된다. 23에서는 밀도가 낮아 예산과 기한이 유지된다. 초과 수요 중에도 B는 1부터 시작하는 매 완전한 4슬롯 구간마다 한 슬롯을 받아야 한다. A의 SVC 다섯 번 각각에 대해 실제 복귀를 확인한다.

REQ-002/005/023 → DES-003/012 → IMP-029 → VER-002/005/023. 독립 산술 EDF 재생으로 모든 실행·유휴 슬롯을 검증한다. 첫 콜드 부팅 ELF 식별자, 비교 레지스터와 카운터, 프레임과 IRQ/SVC/복귀 주소를 기록하고 기존 EVD-006 프로필도 별도 부팅한다. 실기기 타이밍 및 제품 간섭에는 별도 측정이 필요하다.

## 캡처 및 재생

cbs-wake-bench 기능으로 빌드한다. POSIX 셸에서 보관한 ELF와 새 출력 경로를 지정한다.

```sh
chmod +x tools/cbs_wake_capture.py
CBS_WAKE_CAPTURE_DIR="$capture" python3 tools/qemu_boot.py --profile cbs-wake --timeout 15 --qemu ./tools/cbs_wake_capture.py --kernel "$elf"
```

기본 부팅 및 준비 출력 뒤 CBS WAKE TIMER STOP과 CBS WAKE PASS 두 줄을 확인한다. cbs_wake_witness는 리틀엔디언 u64 24열 × 34행이다. 열 0–1은 틱과 깨움 비트, 2–5는 깨운 직후의 A(q,d), B(q,d), 6은 선택 ID(A=0,B=1,유휴=2), 7–10은 과금 직후의 같은 할당이다. 11–15는 기준 카운터, 슬롯 길이, 비교값, 디스패치 PC와 프레임 주소이다. 16–19는 IRQ 카운터, 중단 ID, PC, x20이다. 20–22는 SVC 카운터, 복귀 PC, x20이며 SVC가 없으면 0이다. 열 23은 IRQ 프레임 주소이다. 첫 진입 프레임은 같은 작업의 이후 저장 프레임보다 16바이트 높다. 선택되지 않은 서버의 원시 상태를 읽을 때 지연 보충을 고려한다.

계측 실행기의 호스트 시간 한도는 시작·수집·UART를 포함해 15초다. 게스트 안에서는 물리 타이머로 연속된 50 ms 슬롯 34개를 집행한다. 각 IRQ에는 기존 한 슬롯 이내의 지연 상한을 그대로 적용하고 전체 행과 종료 표식 둘을 모두 확인한다. 최초 5초 관측은 25개 행에서 끝났고 부분 실행 기록으로 보존한다.
