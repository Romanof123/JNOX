## Inputs and service

Use AArch64 virt, one Cortex-A72 vCPU, GICv2 physical timer PPI 30, TCG and 128 MiB. Select `JNOX_PROFILE=eevdf` and `JNOX_APP=telemetry` on virt with no benchmark feature. Three runnable EL1 task entries have separate 16 KiB stacks. In ID order, weights are [2,1,1] and physical service request sizes are [2Q,Q,Q/2], where Q is exactly CNTFRQ/100 counts and Q/2 is integral. The initial configuration uses the existing EEVDF ready reference, clamp of stale sleeper credit, earliest eligible virtual deadline and lower-ID tie rule. At the first dispatch E, the consumer's Q/2 request makes it the first owner.

- Batch IDs 0 and 1 each keep independent input count n, sum and weighted sum. Read from the 16-word ring [11,7,23,5,19,3,29,13,2,31,17,37,41,43,47,53] at (3n+5×ID) mod 16. Accumulate the reading and reading×(1+n mod 7) for complete 64-reading blocks. Continue until the eighth response has finished. Count must be a positive multiple of 64 strictly below 2³⁸. Use the 112-reading cycle to check large results.
- ID 2 requests sequence k=1…8 from its own stack by SVC #1. It must be waiting before its absolute due time E+8kQ. Only a physical timer IRQ can wake that sequence. On return it samples CNTPCT in task code immediately after the SVC, reads ring[(j+k) mod 16] for j=0…15 and computes Rₖ=Σ(j+1)×reading. After eight cycles its SVC #2 carries (ID,count,ΣRₖ,ΣkRₖ)=(2,128,27028,115128); that accepted completion starts batch drain. Each batch submits its own results with SVC #2. No host submission or wake is required.
- For each dispatch, program the earlier of start+min(Q,remaining request) and the next outstanding absolute due time. Only the timer vector wakes the sleeper. Charge the full positive CNTPCT difference from the dispatch sample just before timer setup and frame restore to the outgoing IRQ/SVC vector sample after saving x9. This includes timer setup, return and exception entry overhead between samples. The gap between leases belongs to the scheduler. Counts measure delivered intervals; worker checksums measure useful work.
- If an IRQ is late, advance the selected owner's virtual request by the full measured service with checked whole-request renewals and a partial remainder. At sleep preserve the remainder; wake places stale runtime at or above the existing ready reference and shifts its deadline by the same amount. If no task is ready, dispatch has no owner. Existing strict, quota-limited policy calls keep their original semantics. A/B remain ready through the measurement horizon; all three terminal results retire ownership.

At C's fifth accepted wait, its first four payloads have been reported. Charge its elapsed lease, put C to sleep, then reconfigure ready B from (weight 1, request Q) to (weight 2, request 2Q) before the next dispatch. Use the existing reconfiguration rule with the A+B reference immediately before the change. It replaces B's request at a rounded runtime preserving its signed service lag to within one tick. Require success exactly once. The fifth wait's saved x0, the next row's B tuple, new reference and all subsequent choices establish the transition. Use each row's opening weights in windows crossing the change. All eight absolute releases keep their original due times.

## Acceptance and evidence

1. Reconstruct each decision and timestamp from the linked image, raw journal and same-process exception/return trace. Check ready membership, exact rational reference, earliest eligible deadline, charges, frame extents on their own stacks, saved-to-restored ELRs, compare and PPI identity. Verify actual timer interruption and later return into both batch workloads, the eight block/IRQ-wake/task-response sequences, three exact output tuples (counts plus recomputed sums) and no owner left.
2. Fix five overlapping wall-counter windows of width 32Q, starting E+[0,8,16,24,32]Q. Split each observed interval at window edges. For its overlap d, give the selected owner d actual counts and each ready task ideal service d×weight/sum(ready weights). Count gaps in neither quantity. Require ≥28Q delivered per window (at most one eighth unavailable), and |actual−ideal|≤4Q for every task in every window. The error allowance budgets one largest 2Q request at each endpoint. This is a predeclared engineering target for the admitted mix. Report all 15 signed errors, exact fractions and denominators; do not round a failing result into range.
3. Record due, accepted wake and first task timestamp for all eight events. Require due≤wake≤first and first−due≤4Q, reserving half of the eight-quantum cycle for subsequent work. Report raw delays, nearest-rank p50/p95/max for both due-to-first and wake-to-first, actual frequency, row count and scheduler gaps. A missed wait, overlapping release, row overflow, loss of trace, ambiguous interval or bound miss cannot qualify. Archive the first cold independent run, full UART, raw journal, ELF/symbols and hashes, disassembly, actual emulator argv/version and interrupt trace, including failures. The terminal marker alone reports control-flow completion.
