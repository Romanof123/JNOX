# 단일 가상 CPU의 계층형 CPU 예산

[English](m4-hierarchy.en.md) · [변경 #57](https://github.com/Romanof123/JNOX/issues/57)

CHG-026 · POL-016 · IMP-024 · 예정 증거 EVD-024. 이 프로파일은 QEMU virt의 Cortex-A72 가상 CPU 한 개에서 GICv2와 EL1 물리 타이머를 사용한다.

## 여섯 슬롯씩 두 구간

리프 네 개가 각자 전용 스택에서 실행된 후 SVC #2로 대기한다. 첫 타이머 IRQ가 유휴 루프를 선점할 때 리프 1·2·3이 동시에 준비된다. 리프 0은 우선순위가 높은 자신의 경로에 예산이 있어도 계속 대기한다. 준비 마스크는 12슬롯 내내 0xE이다. 슬롯 0에서 첫 구간의 예산이 전액 주어지고 슬롯 6에서 처음 정한 주기에 맞춰 모든 한도가 복원된다. 경계 12의 마지막 IRQ에서 타이머를 끈다.

부모 예산은 [3, 6]이다. 부모 0의 자식 그룹 0·1·2는 각각 6·1·4슬롯을, 부모 1의 자식 그룹 3은 6슬롯을 갖는다. 각 자식에는 번호가 같은 리프 하나가 속하며 모든 리프의 예산은 6이다. 6슬롯 요청이 들어오면 준비 상태와 잔액 조건을 충족하는 (부모, 자식, 리프) 중 사전순으로 가장 앞선 경로를 선택한다. 요청량, 구간 끝까지 남은 시간, 표현 가능한 시간, 세 단계의 잔액이 모두 할당 길이의 상한이다. 선택한 경로에서 전체 길이를 한 번씩 차감한다.

| 첫 구간 / 둘째 구간의 슬롯 | 부모 → 자식 → 리프 | 할당 길이 | 예약 직후 잔액 (부모 / 자식 / 리프) |
|---|---|---:|---|
| 0 / 6 | 0 → 1 → 1 | 1 | 2 / 0 / 5 |
| 1–2 / 7–8 | 0 → 2 → 2 | 2 | 0 / 2 / 4 |
| 3–5 / 9–11 | 1 → 3 → 3 | 3 | 3 / 3 / 3 |

부모 0의 3슬롯을 모두 예약한 뒤에도 그 아래 활성 리프 두 개는 계속 준비 상태이다. 특히 리프 2는 자기 예산과 자식 그룹 예산이 모두 남아 있다. 부모 1이 나머지 슬롯을 쓰고, 다음 구간이 열리면 리프 1의 경로가 다시 선택된다. 깨어난 리프는 카운터 증가와 분기만 있는 짧은 루프를 끝없이 반복한다. 따라서 할당이 끝나도 자발적으로 CPU를 반환하지 않으며, 다른 경로로 전환하려면 실제 타이머 IRQ가 루프를 선점해야 한다. 여러 슬롯을 예약한 리프는 할당 중간의 IRQ에서 자신의 저장 프레임으로 돌아간다.

빈 계층, 잘못된 상위 노드 번호, 1부터 주기까지의 범위를 벗어난 예산은 구성 단계에서 거부한다. 앞선 예약의 종료 전 요청, 길이 0, 더 전진할 수 없는 시간, 적격 경로 부재 시 추가 할당 없이 잔액을 유지한다. 실행 중에는 IRQ 30, 스택 주소, 저장 PC, 레지스터와 TLS 식별값, 작업 카운터 증가를 검사한다. 한 슬롯 이상 늦은 IRQ나 다음 경계에 이른 디스패치는 실패 처리한다. 논리 슬롯은 정수 단위로 예약한 서비스량이며, 물리 카운터 간격에는 디스패치와 인터럽트 처리 시점의 영향이 들어간다. 실보드 지연 상한, 멀티코어 간섭, 제품 부하에서의 타이밍 보장은 별도의 검증 대상이다.

## 최초 실행 캡처와 재검증

kernel 디렉터리에서 `cargo build --release --locked --features hierarchy-bench -j1`로 빌드한다. Linux에서 `exec python3 -B /absolute/path/to/tools/hierarchy_capture.py "$@"`로 인수를 전달하는 실행 래퍼를 만든다. 저장소 루트에서 실제 래퍼 경로와 존재하지 않는 새 캡처 경로를 지정한다.

~~~sh
HIERARCHY_CAPTURE_DIR="$PWD/hierarchy-first" python3 tools/qemu_boot.py \
  --profile hierarchy --qemu /absolute/path/to/wrapper \
  --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel
~~~

첫 실행 전에 소스 리비전과 미커밋 변경분, ELF SHA-256, 빌드 명령, 도구 버전을 기록한다. 캡처가 미완료된 경우에도 첫 시도의 관찰기 출력과 종료 상태를 launch.json, uart.bin, int.trace, qmp.json, audit.bin, exit.json과 함께 보존한다. 예상 UART는 부트 두 줄 뒤에 HIERARCHY WAIT, HIERARCHY THROTTLE, HIERARCHY REFILL, HIERARCHY PASS가 한 줄씩 이어진다.

QMP로 실행 ELF의 hierarchy_witness 심벌이 가리키는 물리 메모리 1,584바이트를 읽는다. 모든 필드는 리틀엔디언 u64이다. 헤더 여섯 단어는 완료 슬롯 수(12), 슬롯당 카운터 수(CNTFRQ / 20), 최초 절대 비교값, 초기 대기 마스크(15), IRQ 수(13), 통과 플래그(1) 순이다. 이어지는 12개 행은 각각 16단어이다.

| 행 안의 단어 오프셋 | 필드 순서 |
|---|---|
| 0–4 | 슬롯, 부모, 자식, 실행 리프, 준비 마스크 |
| 5–9 | 할당 시작 슬롯, 길이, 부모 잔액, 자식 잔액, 리프 잔액 |
| 10–12 | 진입 시 선택 PC, 종료 시 선점된 PC, 저장 프레임 주소 |
| 13–15 | 디스패치 카운터, IRQ 관측 카운터, 저장한 X20 작업 카운터 |

표에 따라 각 예약을 재계산한다. 같은 예약 안의 행에는 예약 직후 잔액이 반복된다. IRQ 카운터가 각 슬롯의 절대 종료 경계 이상이고 그다음 경계 미만인지 확인한다. 원시 PC는 실제로 실행한 ELF의 심벌로 해석한다. 첫 선택 PC는 SVC 직후의 h_leafN_wake이며 이후에는 [h_leafN_work, h_leafN_end) 안에서 마지막으로 선점된 PC로 돌아간다. int.trace에서 대기 SVC 네 번, 유휴 루프의 최초 IRQ, 리프 IRQ 열두 번, 예외 복귀를 대조한다. EVD-024에는 실제 카운터 간격과 프레임 주소를 원시 덤프와 함께 기록한다.

독립 가상 게스트 결과와 시험 이미지 식별자는 다음 기록에서 확인할 수 있다. [EVD-024](evidence/evd-024.md)
