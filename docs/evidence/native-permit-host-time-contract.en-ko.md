# #389 — What the default guest counter measures / 기본 게스트 카운터의 시간 기준

**Yes. During an ordinarily running QEMU VM, a runnable vCPU thread can be descheduled while guest CNTPCT time continues to accrue.** In this Linux TCG configuration a later counter read derives its value from elapsed host monotonic time plus a VM offset. If the WSL monotonic clock advances by 1 ms while the thread gets no CPU and the VM stays running, the next physical-counter sample advances by 62,500 ticks for that interval. No timer callback or guest instruction needs to execute during the gap for the next read to reflect it. This is a property of the counter. The four-arm A0 captures have no host scheduling trace for those intervals.

**그렇다. QEMU VM이 실행 상태인 동안 vCPU 스레드가 실행 가능 상태로 CPU 배정을 기다린 시간도 게스트 CNTPCT에 반영된다.** 이 구성은 WSL 리눅스의 단조 시계와 VM 오프셋에서 카운터 값을 계산한다. VM이 계속 실행 상태이고 호스트 단조 시계가 1 ms 전진했다면, 그동안 게스트가 실행되지 않아도 다음 읽기에는 그 구간의 62,500틱이 반영된다. 이 성질만으로 네 빌드의 A0 지연 원인을 호스트 선점으로 판정할 수 없다.

## Host supply and admission / 호스트 실행 보장과 기한 승인

The live WSL2 Linux probe ran under `SCHED_OTHER`, priority/nice 0, affinity 0–11 and an RT priority limit of 0. The visible root cgroup CPU quota was unlimited with weight 100; child CPU controls were unavailable. The current Linux clocksource was TSC. Windows 11 Pro 26200.9974 reported a running WSL utility VM under Hyper-V. Its VmmemWSL accounting process reported Normal priority. The Hyper-V processor-settings WMI namespace was unavailable. These observations establish current context. Historical QEMU thread scheduling, outer virtual-processor reservations, maximum dispatch latency and per-phase off-CPU time were unrecorded. [Microsoft WSL2 VM architecture](https://learn.microsoft.com/en-us/windows/wsl/compare-versions) · [Linux scheduling reservations](https://docs.kernel.org/scheduler/sched-deadline.html)

Universal 1 ms target-to-park admission would require a specified workload and upper bounds for outer Hyper-V and Linux service interruptions, QEMU timer/event-loop and vCPU dispatch, cold translation and other emulator work, and guest interrupt masking, scheduling, service and final park. A composed bound must cover nested or overlapping delays without double-counting. Here an allowed delay in host service can consume the entire 1 ms while the guest clock advances. The 32 observed healthy empty A0 deadline misses already refute the claim for the captured configuration. Traces establish measured elapsed intervals and definite deadline failures. They supply neither a universal worst-case bound nor a breakdown of host causes.

현재 WSL2 관측 프로세스는 일반 스케줄링 정책, 우선순위·nice 0, CPU 0–11 허용 상태였다. Windows에서는 Hyper-V 위의 WSL VM이 실행 중이었고 VM 프로세서 예약 메타데이터는 확인할 수 없었다. 과거 QEMU 스레드의 실제 오프 CPU 시간이나 최장 배정 지연은 기록되지 않았다. 1 ms의 보편적 상한을 주장하려면 외부 가상 CPU와 리눅스의 공급 중단, QEMU 타이머·스레드 디스패치와 최초 번역, 게스트 마스킹·스케줄링·서비스·최종 대기 전환을 포함하는 합성 상한이 필요하다. 정상 A0 32건의 실제 초과는 해당 구성의 기한 실패를 확정하지만 원인별 시간이나 최악 상한을 주지 않는다.

The prior clock comparison established sensitivity to icount. A separate instrumented campaign measured 371–856 µs of vCPU-thread CPU time and zero recorded switches in the first CHECK. Those earlier measurements apply to their observed services and builds. They do not identify the source of a particular four-arm A0 gap. [Clock comparison](https://github.com/Romanof123/JNOX/blob/f30db111e7b020ec712f268e3e7b0814ab01a926/docs/evidence/native-permit-clock-comparison.en-ko.md) · [Host service probes](https://github.com/Romanof123/JNOX/blob/f30db111e7b020ec712f268e3e7b0814ab01a926/docs/evidence/native-permit-host-services.en-ko.md) · [Four-arm measurements](https://github.com/Romanof123/JNOX/blob/a7aa0a659f239950fa29b3326813cf4b35d846f9/docs/evidence/native-permit-receiver-copy.en-ko.md)

게스트가 유휴 상태여도 VM이 실행 중이면 기본 시계는 전진한다. QMP 정지 구간은 재개 시 오프셋 조정으로 제외된다. 물리 타이머의 비교값 도달과 게스트 IRQ 첫 표본 사이에는 실행 지연이 들어갈 수 있다. 고정 시프트 icount는 명령과 유휴 보정에 기반하며 RTC 설정은 별개다. 기존 별도 계측의 첫 CHECK는 스레드 CPU 시간 자체가 371–856 µs였고 기록된 문맥 전환은 없었다. 그 결과를 이번 A0에 그대로 적용할 수 없다.
