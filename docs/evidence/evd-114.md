# EVD-114 · 협력형 네이티브 프로세스

CHG-114 / IMP-114 / POL-001 / [#291](../native-cooperative-processes.en-ko.md) / [#292](https://github.com/Romanof123/JNOX/pull/292)

소스 `94bef763dbbcc7419e2d2902361052c6acec1f86`에서 주 C 앱(PID 0)과 Rust 동료 앱(PID 1)은 0 → 1 → 0 순으로 양보했다. PID 0이 대기하는 동안 PID 1은 전용 보고 계산을 마치고 29로 종료했다. PID 0은 깨어난 뒤 17로 종료했다. 앞서 보조 호스트 명령은 `-nodefaults` 누락으로 게스트 부팅 전에 중단됐다. 표준 실행 명령으로 두 앱을 시작했다.

별도 종료 후 검사에서 두 전용 누계의 가상 주소는 모두 `0x402000`이었다. 초기값 10과 20에서 시작해 주 앱의 물리 페이지 `0x4022d000`에는 17, 동료의 물리 페이지 `0x40642000`에는 29가 남았다.

별도 순차 실행에서 동료가 실행 중인 경우에서는 동료가 EL0에서 실행 중일 때 타이머 IRQ가 발생했고 저장 PC와 ERET PC가 `0x4016d0`로 일치했다. 동료는 작업을 계속하다가 자발적으로 양보했고 그 뒤 깨어난 앱이 실행됐다. 두 프로세스가 모두 대기하는 순차 실행에서는 두 앱이 모두 대기했고 EL1 유휴 PC `0x402013f4`에서 IRQ가 두 번 발생했다. 100 ms 기한의 C 앱이 17로 먼저 종료한 뒤 300 ms 기한의 Rust 앱이 29로 종료했다.

Windows에 보존한 순차 워크로드 6개만 채점했다. 별도 일곱 번째 부팅으로 종료 후 메모리를 확인했다. 최초 WSL 임시 바이너리와 로그는 아카이브 전에 사라졌고 원인은 확인되지 않았다. 당시 실행 중인 동료의 PC 0x40018c는 관측 기록만 남았다. 동시에 실행된 복구 부팅들은 별도로 보관했으며 채점에서 제외했다. 당시 관측에 따르면 임시 보조 실행 2회는 외부 Rust 예제가 실제로 `0x403000`에 링크된 심볼의 주소를 잘못 가정해 112로 종료했다. 수정 실행에서는 외부 앱만 바꿨다. 기존 시작 대조는 37, 단일 앱 시계 및 주기 대기 대조는 각각 0으로 종료했다. 실기기 타이밍은 측정하지 않았다.
