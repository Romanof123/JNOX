# EVD-034 · EEVDF에서 16회 반복 기상한 작업의 서비스와 응답

[English](evd-034.en.md) · [사전 계약](../m4-eevdf-wake-design.md) · [원본 파일 11개와 해시](evd-034.json)

독립 검증자는 한 번의 QEMU virt 콜드 부팅에서 타이머 IRQ 128회, C의 차단 SVC #1 16회와 소유자 변경 127회를 재구성했다. Cortex-A72 가상 CPU 하나에서 A와 B는 계속 준비 상태였다. 가중치 A/B/C는 2/2/1, 요청 슬라이스는 모두 1로 고정했다. C는 처음 16회 할당 후 직접 차단했고 다른 작업의 완료 할당 1·2·3·4회가 순환할 때마다 다시 준비됐다.

| 관찰값 | 결과 |
|---|---|
| A/B/C 실행 할당 | 55 / 54 / 19 |
| 모든 접두 구간에서 태스크별 최대 절대 서비스 오차 | 1.1 / 1.6 / 2.2퀀텀. 사전 한계는 각각 20퀀텀 |
| 준비부터 실제 작업 재개까지 중간 할당 수 | 3·2·5·4가 네 번 반복. 최근접 순위 p50/p95/p99/최대는 3/5/5/5. 한계 6 |
| 준비부터 실제 작업 재개까지 카운트 | p50 2,235,564, p95/p99/최대 3,718,362. 62.5 MHz에서 최대 59.493792 ms, 즉 5.9493792퀀텀. 한계 8퀀텀(퀀텀당 625,000카운트) |

독립 계산은 매 할당의 준비 가중치 비율을 누적해 실제 서비스와 대조했다. 16회 모두 SVC 프레임과 복귀 PC, 작업 코드가 읽은 최초 카운트를 연결했다. 이 분포는 위 고정 설정의 한 실행에 적용된다. 가중치와 슬라이스 변경은 기존 [EVD-023](evd-023.md)에서 실행했다. 변경과 반복 기상을 함께 적용한 작업, 실보드 지연과 제품 한계 승인은 남아 있다.

## 오프라인 재현

저장소 루트에서 아래 Python 3 코드로 원본을 복원한 뒤 `python evd-034-replay/verify.py`를 실행한다. 출력 JSON은 보존된 `summary.json`과 비교할 수 있다. `raw/`에 관찰 메모리, 예외 추적, UART, QMP·실행·종료 기록이 있다. 최상위에는 검증기, 요약, ELF 심벌, C 작업 디스어셈블리, 부팅 로그가 있다.

```python
import base64, hashlib, io, json, zipfile
from pathlib import Path

record = json.loads(Path("docs/evidence/evd-034.json").read_text())
blob = base64.b64decode(record["zip_base64"], validate=True)
assert hashlib.sha256(blob).hexdigest() == record["zip_sha256"]
dest = Path("evd-034-replay")
dest.mkdir(exist_ok=False)
with zipfile.ZipFile(io.BytesIO(blob)) as archive:
    assert set(archive.namelist()) == set(record["files"])
    for name, spec in record["files"].items():
        data = archive.read(name)
        assert len(data) == spec["size"]
        assert hashlib.sha256(data).hexdigest() == spec["sha256"]
        path = dest / name
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_bytes(data)
```
