# EVD-030 · 단일 코어 고정 우선순위 런타임

[English](evd-030.en.md) · [런타임 명세](../fixed-runtime.md) · [#69](https://github.com/Romanof123/JNOX/issues/69)

최초 FIFO 게스트에서는 B가 잠든 동안 HIGH가 종료하자 선점된 A가 재개됐다. 이 부팅에서는 준비 상태인 동순위 작업과의 순서를 판정할 수 없었다. 최초 RR 게스트는 교대 실행과 작업별 스택을 보였지만, 공통 루프 PC와 경계 카운터 부재로 정확한 잔여량과 저장 프레임의 소유자는 확인되지 않았다. [최초 FIFO 게스트](evd-030-first-fifo.json) · [최초 RR 게스트](evd-030-first-rr.json)

## 일반 게스트

독립 검증자는 QEMU에서 구성별 콜드 부팅을 한 번씩 관측했다. 인터페이스는 단일 CPU에서 정적으로 링크된 신뢰된 Rust 작업을 0~4개까지 받는다. 각 작업은 고정 우선순위와 별도의 16 KiB 스택을 가지며 유휴 실행에는 다섯 번째 스택을 사용한다. 이번 시험은 동순위 작업의 FIFO 및 RR 정책을 다룬다.

| 구성 | 관측 결과 |
|---|---|
| FIFO | B가 0틱 수면으로 A에 양보하고 준비 상태를 유지했다. HIGH 종료 직후 선점된 A가 B보다 먼저 PC `0x4020127c`에서 재개됐다. 이후 B는 25,000,000틱 수면을 요청했고, 유휴 상태 뒤 재개됐다. 오버플로 수면 요청이 거부된 뒤에도 계속 실행해 명시적으로 종료했다. |
| RR | 설정 퀀텀은 12,500,000틱이었다. 검증자는 작업 표, UART, 스택 관측 및 예외 순서로 A/HIGH/A/B/A/B/idle을 재구성했다. 일반 캡처는 공통 루프 PC를 사용하고 사건별 카운터를 기록하지 않아 정확한 잔여량과 저장 프레임의 소유자를 판정하기 어렵다. |
| 빈 표 | 즉시 유휴 상태에 진입했고 관측 워드 8개는 모두 0이었다. |
| 지연 시작 | 유일한 작업의 초기 지연은 6,250,000틱이었다. 유휴 상태로 부팅한 후 IRQ로 슬롯 0이 실행됐고, 명시적 종료로 유휴 상태에 복귀했다. |

네 캡처 모두 제한된 무출력 관측 구간에서 최종 PC는 `0x4020125c`, 유휴 SP는 `0x40218120`이었다. 검증 범위는 이 가상 실행들이다. 실물 타이밍, 무기한 유휴 동작과 제품 안전에는 별도 근거가 필요하다. [일반 게스트 검증 결과와 원시 기록](evd-030-ordinary.json) · [검증 소스](https://github.com/Romanof123/JNOX/commit/653691e27523d54dcca0263719a3438b7f2ccea4)

## 진단 게스트

독립 검증자는 FIFO 10행, RR 7행, 빈 구성 1행, 지연 시작 구성 3행을 재현했다. 각 행은 19워드다. 62.5 MHz 카운터에서 A는 HIGH에 선점되기 전 RR 퀀텀 12,500,000틱 중 6,377,034틱을 사용했다. A가 카운터 9,695,826에서 재개됐을 때 남은 시간은 6,122,966틱이었고 타이머 비교 레지스터는 15,818,792로 설정됐다. 새 퀀텀을 부여했다면 비교값은 22,195,826이 된다.

검증자는 타이머 IRQ가 PPI30임을 대조하고 선점된 작업에 실행 시간을 귀속했다. 예외 순서, 작업 진행량 및 스택 범위로 중단·복귀 ELR과 스택 포인터를 대조했다. 네 구성 모두 최종 유휴 기록의 타이머 제어값은 0이었다. IRQ 전달과 후속 동작은 인터럽트 처리 완료의 간접 근거이며 개별 GIC EOI 쓰기는 캡처하지 않았다. 단독 실행 뒤 동순위 작업 도착, 릴리스와 만료의 동시 발생, 여러 작업의 늦은 기상, 여러 퀀텀에 걸친 지연의 근거는 호스트 시험에 한정된다. [진단 재현, 19워드 기록, 독립 검증기와 원시 캡처](evd-030.json)

최종 소스에서 Rust 테스트 126개, Python 테스트 32개, 잘못된 구성 거부 8건과 추가 순차 회귀 부팅 5회가 통과했다. 일반 FIFO ELF의 파일 크기는 94,192바이트이고 적재 범위는 113,608바이트다. 일반 RR은 각각 94,048바이트와 113,400바이트다. 두 이미지 모두 BSS에 고정 작업·유휴 스택을 둔다. 실제 최대 스택 사용량과 실보드 응답시간 상한은 미결이다. 지연 IRQ와 동시 릴리스의 실제 실행은 [#72](https://github.com/Romanof123/JNOX/issues/72)에서 추적한다.
