# EVD-130 · C·Rust 앱의 반복 CPU 창

CHG-130 / IMP-130 / POL-006 / [#323](../native-cyclic-applications.en-ko.md) / [#324](https://github.com/Romanof123/JNOX/pull/324)

`c3c89fd04d37992bfd00912814e8171e255749c8` · [SDK / QEMU](../../examples/native-cyclic/README.md)

원본 네 건(P·Q 일반·추적)의 50/50 경계가 1 ms 이내였다(최대 46,087틱). 오프라인 판독기의 문법 오류를 고쳐 원본을 재생했다. 원본은 시스템 호출 진입 시각으로 창을 선택해 처리 도중 경계를 넘는 경우가 미검증으로 남았다.

수정 소스 213a8efa1d3dfa72eadc3ecb85fa4924b60ca3b8은 처리 후 시각으로 선택한다. 단일 Cortex-A72 virt 기본 시계에서 새 P·Q 일반·추적 부팅 네 건의 50/50 경계가 1 ms 이내였다. 실행 앱의 실제 첫 EL0 표본까지 최대 47,016틱, EL1 유휴 루프 읽기까지 최대 24,344틱이었다(62.5 MHz, 한도 62,500틱). Q의 연속 B 창 모두 새 표본과 작업 진척이 있었다. 별도 P 수면 부팅에서 차단된 B의 남은 창은 유휴였고 B가 준비돼도 A는 자기 창에서 계속 실행했다.

두 후보 모두 수면 대조군을 포함한 다섯 부팅에서 각 앱의 페이지 테이블로 사설 결과를 확인했다. 각 앱의 완료 블록 수 N에 대해 C 에너지는 N × 5,559,680, Rust 히스토그램은 N × [1,8,28,56,70,56,28,8,1]이었다. 종료값은 41/42였고 건너뛴 경계, 저널 손실, 앱 표본 초과는 없었다. 수정 후보의 별도 1 ms 교대 창 실험에서 440번의 clock_gettime 중 한 번이 A 호출 중 경계를 넘어 B로 복귀했다. 두 앱 모두 220개 배치, 체크섬 229,833,914, 종료값 23을 기록했다. 이 실험은 정상 창의 시간 판정과 별도다.
