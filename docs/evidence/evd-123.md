# EVD-123 · 네이티브 프로세스별 시작 인수

CHG-123 / IMP-123 / [#310](../native-process-arguments.en-ko.md) / [#311](https://github.com/Romanof123/JNOX/pull/311) / [#12](https://github.com/Romanof123/JNOX/issues/12)

`1c45bee0cb37e13f1a53f8dab902bd0e7e9fec94`

단일 Cortex-A72 QEMU virt에서 패키지 6개를 각각 일반 부팅, 별도 기본 캡처·리플레이, 별도 외부 중단점 부팅으로 확인했다. 기본 리플레이 6개 모두 통과했다. 외부 관측기는 실제 _start 진입 시 활성 전용 벡터 11개의 포인터·문자열·종료값·패딩을 비교했다. 같은 C ELF의 협력형 두 인스턴스는 같은 가상 SP에서 서로 다른 물리 스택 페이지를 사용했다. 양보와 복귀를 거쳐 주 앱은 표본 16개 합 376을 계산하고 17로, 동료는 표본 32개에서 최소 64·최대 95를 구하고 29로 종료했다.

FIFO 두 슬롯 구성은 128바이트 스택 꼬리를 가진 C 슬롯 1을 먼저 선택했다. 세 슬롯 구성에서는 112바이트 꼬리를 가진 Rust 슬롯 2가 먼저 실행됐다. Rust는 14바이트 UTF-8 라벨 `-동쪽 센서`를 유지하며 표본 16개 합 3,960을 구하고 43으로 종료했다. 주 앱의 꼬리는 96바이트였다. 기본 앱과 시작 프로브는 구현 전 실제 부팅과 80바이트 전체가 일치했다. 각각 argc 1·3, 종료값 0·37이었다.

최초 독립 호스트 단위 검사 도구는 E0308로 컴파일에 실패했다. 수정본 `fffbb31d46c88670dd82485be4fdea1171b3a78b`에서 테스트 전용 코드에 슬라이스 타입을 명시한 후 검사 3개가 모두 통과했다. 게스트 실행 근거는 최초 소스의 결과다. 이 기록의 적용 범위는 지정 가상 머신에서 네이티브 앱의 시작 인수 전달과 진입이다.
