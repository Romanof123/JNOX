# EVD-138 · 유휴 재충전 지연의 부팅 단위 상태

CHG-138 / IMP-138 / POL-016 / [#339](../native-hierarchy-refill-health.en-ko.md) / [#340](https://github.com/Romanof123/JNOX/pull/340)

`a1a6a2f7440342125e257825775d4f2caacf0cd6`

단일 Cortex-A72 virt의 10개 후보 최초 위치 중 wake-trace에서 실제 유휴 재충전 초과가 1회 기록됐다. 결정 60→61에서 고정 비교값 250,487,263, PPI30 최초 진입 260,476,531로 9,989,268틱(159.828288 ms)이 걸렸다. 한도 1,953,125틱보다 8,036,143틱 늦었다. 이 IRQ는 재충전 전용이었고 유휴 차감은 0이었다. 이 부팅의 29회 재충전 중 유일한 위반으로, 최초 위반 및 최대 지연이 UART와 RAM에서 일치했다. 보고 앱·히스토그램·에너지의 계산과 종료 7/70/179가 일치했다.

다른 9개 후보 최초 위치와 별도 수동 관측 2건은 재충전 한도 이내였다. 비교군 일반 부팅 2건과 기본 CRC 대조군은 별도다. 실패한 부팅에는 외부 예외 기록이 있지만 수동 GIC 추적은 없다. 인터럽트 발생·WFI·호스트 스케줄의 개별 기여를 확인할 수 없다. #334의 최초 초과 두 건과 이번 시간 실패를 #339에서 추적하며 POL-016은 미승인이다.

원본 CLI는 상충하는 입력 두 건을 받아들였다. 첫 수정 dfc6eb3은 두 건을 거부하고 기존 실행의 실제 초과를 보존했지만 서로 모순되는 증거 조합 9건을 받아들였다.

두 번째 리더 e780079는 원본 두 반례와 증거 중첩 아홉 건을 거부했으나 요약 간 모순 여섯 건을 받아들였다. 세 번째 a242 수정은 여섯 건을 해결했지만 생략된 타이머 설정의 시각 순서 반례가 남았다. 이 과정은 동일 UART의 오프라인 재판독이다. 호스트 시계 설계는 사전 계획이며 아직 실제 시계 관측은 없다. [Host-clock plan / 호스트 시계 계획](https://github.com/Romanof123/JNOX/blob/5c58e7fb/docs/native-idle-delivery-time.en-ko.md)

세 번째 오프라인 패킷은 실제 UART 접두 1,506개에서 최초 위반과 최대 지연을 올바르게 유지했다. 그러나 생략된 타이머 설정의 시각 순서를 위배한 세 반례를 거부하지 못했다. 네 번째 리더 15a25a5는 시각 순서 반례 세 건을 거부했으나 유휴 레지스터가 모순된 두 입력을 받아들였다. 오프라인 판독 결과는 원래 게스트의 시간 판정을 변경하지 않는다.

독립 Release는 024161c3의 선택형 공학 계측과 운영자 판독기 병합을 승인했다. 다섯 번째 리더는 명명된 100개 사례, 실제 UART 접두부 1,506개, 단위 검사 7개 그룹과 실제 상태 기록 12개를 오프라인에서 통과했다. 다섯 차례 판독에 같은 관측 자료를 사용했다. POL-016의 1,953,125틱 시간 판정은 실패이며 세 초과의 원인은 [#339](https://github.com/Romanof123/JNOX/issues/339)에 남는다. 수동 추적에서 관측한 것은 사건 순서다. 실환경·실보드 시간, 호스트 스케줄러의 인과관계, IRQ 선 상승 시각과 최악 지연 상한은 미검증이다. 동일 부하의 후속 호스트 대조는 [#343](https://github.com/Romanof123/JNOX/issues/343) / [#344](https://github.com/Romanof123/JNOX/pull/344)에 계획했다.
