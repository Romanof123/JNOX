# EVD-101 · 유한 MLFQ 작업의 깨움부터 패킷 결과 게시까지의 조건부 지연

`CHG-101` · `IMP-101` · `POL-009` · [#264](https://github.com/Romanof123/JNOX/issues/264) · [#265](https://github.com/Romanof123/JNOX/pull/265) · [English](evd-101.en.md)

수용된 일반·추적 구성의 최초 부팅에서 패킷 작업은 실제 타이머 인터럽트로 강등됐다. 동료가 잠든 작업을 깨웠고, 이 작업은 준비 큐에서 부스트를 거친 뒤 앞선 동료가 서비스를 받은 다음 저장된 프레임으로 복귀해 패킷 계산 결과를 게시했다. 성공한 깨움 SVC의 정지 시각부터 게시 직후 작업이 읽은 카운터까지 일반 구성은 2,459,842카운트, 추적 구성은 2,486,422카운트였다. 두 값 모두 조건부 상한 14,375,000카운트 이내였다. 검증자는 동료의 큐 순서, 태스크별 서비스 시간과 패킷 연산 결과를 독립적으로 재구성했다. [설계](../mlfq-wake-design.en-ko.md) · [Rust 작업](../../kernel/src/mlfq_wake.rs)

같은 부하에서 한도만 14,374,999카운트로 낮추자 두 구성 모두 첫 디스패치 전에 거부했다. 최초 네 실행이 각각의 예상 판정을 충족했다. 기존 게스트 구성 16개에서 종료 UART 출력·종료 PC·실행 섹션이 기준과 일치했다. 지연 결과는 AArch64 QEMU CPU 한 개에서 실행한 명시된 네 작업에 적용된다. 제품 부하, 안전 승인과 실기 타이밍은 #1·#10·#34에서 계속 추적한다.
