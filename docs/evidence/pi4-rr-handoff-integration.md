# 통합 AArch64 소스에서의 Pi 4 RR 전달

통합 소스 f1e2a730614f9313e711b89dcc5a1a9f0b96e760에서 QEMU raspi4b를 순서대로 네 번 콜드 부팅했다. 일반 RR은 O1과 O2에서 완료됐다. 공학용 E1과 E2에서 HIGH의 복귀와 두 동료 작업의 연산을 기록했다. A는 세대 5에서 값을 공개했고 B의 획득 측정 구간은 세대 4–6에 걸쳤다. 두 공학용 부팅은 모두 종료값 2였다. 단일 세대 전달과 후속 루프 진행은 미확인이다.

| 순서 | 종료값 | 공개·획득값 | 공개 / 획득 틱 |
|---|---:|---:|---:|
| O1 | 0 | — | — |
| E1 | 2 | 1,958,498 | 631 / 19,896 |
| E2 | 2 | 1,744,682 | 1,121 / 30,303 |
| O2 | 0 | — | — |

기본 ELF 및 Pi 4 directed-wake ELF가 독립 빌드한 main 17cf31bd02903ea874c8e23b09f342bcebc7ec8b과 각각 일치했다. SMP ELF는 보존된 #156 ELF와 바이트 단위로도 일치했다(SHA-256 17922086bf52386a5868b1c8eaa6efd96b644d527146edff6f51025b955493f6). 네 게스트는 모두 RR을 실행했다. 일반 RR의 실행 코드는 main과 일치했고 이미지의 2바이트 차이는 Rust 소스 행 번호였다. v1 공학용 이미지 대비 실행 코드는 452바이트, 읽기 전용 데이터는 1바이트, BSS는 176바이트 늘었다. 원본 #146 FIFO/RR 재생은 0/0, 통합 v1은 0/2였다. 변형 캡처 6건과 잘못된 빌드 선택 7건을 거부했다. 첫 준비 단계에서 소스 묶음 누락으로 컴파일이 중단됐다. 네 실행 모두 완전한 고정 소스에서 빌드했다.
