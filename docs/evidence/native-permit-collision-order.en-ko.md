# Same-tick permit publication and CHECK on single-vCPU icount

**The exact live collision gate remains open.** For the four linked kernel images inspected here, a successful PID 0 ring-tail publication and a separate PID 1 CHECK operand cannot share a 62.5 MHz tick on the archived single-vCPU, shift-0 QEMU configuration. This is a machine-code and clock-model result. The two collision captures observed publication first and a later expiry CHECK. Neither capture began the expiry interval with ENABLE high. The original requirement calls for a live, valid next frame in the same open generation, exact publication and expiry at the same deadline, rejection, latch and output fall. [Original gate](https://github.com/Romanof123/JNOX/blob/1197c7daf7ede7929de8a09f0ee408ee6111abc7/docs/native-safety-boundary-bench.en-ko.md)

## Which clock and which operations

All four capture receipts identify Cortex-A72, stock virt/GICv2, one vCPU, single-thread TCG and `-icount shift=0,align=off,sleep=off`. The guest recorded 62,500,000 Hz. The executable SHA-256 was `0a63468782d096485932acf6aa0a69d358b3e3a6f68f655e960e9f5e3fc578d8` from Ubuntu `1:6.2+dfsg-2ubuntu6.31`. The source verifier checked the official orig archive, all 209 quilt-series entries and the 12 cited source or documentation files against upstream release commit `44f28df24767cf9dca1ddc9b23157737c4cbb645`. [Ubuntu source descriptor](https://security.ubuntu.com/ubuntu/pool/main/q/qemu/qemu_6.2+dfsg-2ubuntu6.31.dsc) · [Distributed executable provenance](https://github.com/Romanof123/JNOX/blob/1197c7daf7ede7929de8a09f0ee408ee6111abc7/docs/evidence/native-permit-host-time-contract.en-ko.md)

QEMU charges each translation block's instruction count at block entry. The translator counts one for each guest instruction, including a pair store. An exhausted budget can shorten a block. Exception restoration returns unused counts. Ordinary RAM stores carry no architectural clock sample. For A64 `MRS CNTPCT_EL0`, the register is marked `ARM_CP_IO`. In icount mode the translator enables I/O before issuing the register helper and ends the block at that instruction. The helper obtains the virtual clock, including the current vCPU's charged count, then divides its nanoseconds by 16. The fixed shift is zero, giving one virtual ns per counted instruction. With sleep off an idle warp can advance to a timer deadline. The argument below uses only a lower bound during successfully executed guest instructions. [Translation loop](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/accel/tcg/translator.c#L77-L137) · [TB charging](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/include/exec/gen-icount.h#L19-L93) · [Exception restoration](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/accel/tcg/translate-all.c#L339-L371) · [A64 I/O termination](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/target/arm/translate-a64.c#L1954-L1988) · [Register declaration](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/target/arm/helper.c#L3007-L3011) · [Counter read](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/target/arm/helper.c#L2434-L2439) · [Counter period](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/target/arm/cpu.c#L1190-L1211) · [Clock update and conversion](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/softmmu/icount.c#L72-L163) · [Idle warp](https://github.com/qemu/qemu/blob/44f28df24767cf9dca1ddc9b23157737c4cbb645/softmmu/icount.c#L341-L368)

Let B and A be the real counter reads before and after the successful PID 0 SVC 34 publication, P the ring tail's release store inside that interval, and C the input to `check_at` for ordinary PID 1 SVC 60 command 1. The sender's wire issue, the journal timestamp, command 2's validation and command 3's COMPLETE each have different meanings. On the collision FIFO binary, the sender reads B at `0x40204ab0`, stores the handle, release-stores the incremented tail at `0x402069fc`, then reads A at `0x40204ad8`. The controller's role-checked counter read at `0x40205f9c` goes directly into `check_at`. The distinct earlier service-entry read is at `0x40205f50`. ## Why both orders separate

The kernel enters each lower-A64 SVC on a private EL1 frame with IRQs masked. Its dispatcher calls the loan or safety service with CURRENT, then polls the fixed scheduler. A process change saves the old frame, switches address space, installs the selected frame and changes CURRENT. The normal return restores 16 SIMD pairs and 15 integer pairs before ERET. The second ordinary SVC must independently enter through the lower-A64 vector, even if a scheduler or idle IRQ intervened. In all four ELFs `0x40200c00` branches to `0x4020124c` (`msr daifset,#15`). There is no branch before the call to `native_el0_sync` at `0x40201318`. In that compulsory entry, `0x402012c0…0x402012fc` are **16 distinct guest instructions**, `stp q0,q1` through `stp q30,q31`. The lower bound counts only these stores in the second SVC. Its derivation needs no assumed scheduler cost, host duration or unobserved store timestamp. [Vector, save and return](https://github.com/Romanof123/JNOX/blob/1dfa7fa19593fb1cfcdbe6cbc6e2a5964d6616c8/kernel/src/native_el0_vectors.S#L291-L363) · [Context handoff](https://github.com/Romanof123/JNOX/blob/1dfa7fa19593fb1cfcdbe6cbc6e2a5964d6616c8/kernel/src/native_el0.rs#L337-L346) · [Protected service dispatch](https://github.com/Romanof123/JNOX/blob/1dfa7fa19593fb1cfcdbe6cbc6e2a5964d6616c8/kernel/src/native_el0.rs#L749-L782)

| Execution order | Two precise MRS endpoints | Consequence |
|---|---|---|
| Publisher first | A precedes the controller's entry saves, which precede C. | At least 16 virtual ns separate A and C. C is at least one counter tick after A, and P is no later than A. |
| Controller first | C precedes the publisher's entry saves, which precede B. | B is at least one counter tick after C, and P is no earlier than B. |

For any nanosecond phase, `floor((t+16)/16) = floor(t/16)+1`. Both anchor reads end their own translation block, so a translation block cannot charge the second SVC's stores to the earlier read. Any assignment of P consistent with the before/after observations leaves the two events in different counter ticks. This conclusion applies to these authenticated binaries, successful separate SVCs and this clock model. The ordinary host-time clock, different binaries or another CPU configuration require their own analysis.

D is the third accepted wire issue plus 1,250,000 ticks. In both first collision captures sequence 4's wire issue equalled D. ## 한국어

**실제 동일 틱 충돌 기준은 미충족이다.** 검사한 네 커널에서 PID 0의 대여 링 꼬리 게시와 독립된 PID 1의 CHECK는 단일 CPU 고정 icount의 같은 62.5 MHz 틱에 들어갈 수 없다. QEMU는 번역 블록 시작에서 명령 수를 미리 차감한다. 일반 RAM 저장 시각은 직접 기록되지 않는다. 반면 CNTPCT 읽기는 A64 I/O 시스템 레지스터 접근이어서 그 명령에서 블록이 끝나고 현재 vCPU의 누적 명령 수가 시계에 반영된다.

게시가 먼저이면 게시 뒤의 카운터 읽기 A와 제어기의 CHECK 피연산자 C 사이에 제어기 SVC의 프레임 저장이 있다. CHECK가 먼저이면 C와 게시 직전 읽기 B 사이에 송신자 SVC의 같은 프레임 저장이 있다. 두 번째 진입은 분기 없이 16개의 SIMD 레지스터 쌍 저장 명령을 각각 실행한다. shift 0에서는 이 명령들만으로 최소 16 가상 ns, 즉 카운터 한 틱이 지난다. 실제 꼬리 저장은 B와 A 사이에 있으므로 두 순서 모두에서 동시 틱은 배제된다. 실제 하드웨어나 기본 호스트 시계에는 이 계산을 적용할 수 없다.

첫 collision 캡처에서 매체의 4번 발행 값은 D였지만 실제 게시 구간은 FIFO에서 D+517…650, RR에서 D+531…664였다. 열린 게이트에서 3번의 만료를 판정한 실제 CHECK는 각각 D+1,045 및 D+1,082였다. 4번의 CRC·핸들·수신·반환을 대조했고 제어기는 커밋을 건너뛰었다. 안전 기록의 손실은 0이었다. 두 실행 모두 ENABLE 상승 이력이 없고 감독자 종료값은 95였다.

다음 기능 시험은 기존 커널 서비스와 가상 시계를 유지하면서 먼저 출력 상승을 확인하고, 같은 세대의 정상 4번을 D 전에 대기열에 넣은 뒤 D에서 처음 만료되는 CHECK를 관측한다. 핸들 수신·반환, 이전 3번 유지, 거부, 래치 및 실제 출력 하강까지 연결한다. 이 결과는 이미 대기 중인 프레임과 만료의 우선순위를 검증한다. D에서 게시까지 동시에 일어나는 원래 기준은 별도로 열린 상태다.

## Offline replay

Use x86-64 Linux, Python 3.10+, GNU tar with xz and GNU AArch64 objdump/nm. `PHASE` and `REARM` are the original archives, with SHA-256 `b87f47d99067701deb1f99abc10099f96070aa0c1a24879e93909146567b4017` and `d83937a537964d345f3b90b4fd54744855f42b88d4c3abfabe84291f6fb7215d` respectively. Put the two named official Ubuntu source files in `QEMU_SOURCE`. The script authenticates the packets, reconstructs the compact captures, disassembles the four original kernels and checks both decision joins using UART and private RAM.
