# EVD-115 · 네이티브 앱의 고정 우선순위

CHG-115 / IMP-115 / POL-002 / [#293](../native-fixed-processes.en-ko.md) / [#294](https://github.com/Romanof123/JNOX/pull/294)

소스 c7f88eadf582aba0d350bb444a553426ef01be37의 최초 작은 작업으로 동순위 FIFO 및 두 슬롯 배치에서 FIFO·RR의 상위 우선순위 깨우기를 확인했다. 12,500,000틱으로 고정한 동순위 RR 두 앱은 타이머 전환 없이 끝났다. 세 앱 실행에서는 낮은 우선순위 앱이 12,208,969틱을 남기고 재개했지만 설정된 비교값에 도달하기 앞서 종료했다. 최초 잔여 퀀텀 만료 사례는 부분 관측이다.

1,250,000틱에서는 같은 작은 동순위 RR 앱이 타이머 만료로 8회 전환됐다. 세 앱 실행에서 A는 958,657틱을 남기고 6,275,651에 재개했다. 설정된 비교값은 7,234,308이었다. 7,238,753에 타이머가 B를 선택해 새 퀀텀으로 재시작했을 때의 만료 시각 7,525,651보다 빨랐다. A와 B의 전용 최종값은 78,498·70,435, 종료값은 12·77이었고 HIGH의 종료값은 32였다.

긴 계산 작업 8개 사례는 모두 최초 설정인 12,500,000틱에서 실행했다. 동순위 RR은 타이머로 8회 전환됐다. 세 앱 실행에서 A가 5,983,507에 시작하고 HIGH가 6,276,616에 깨어났다. A는 12,206,891틱을 남기고 6,282,863에 재개했다. 비교값은 18,489,754였다. B가 18,494,787에 선택돼 새 퀀텀 만료 시각 18,782,863보다 빨랐으며 이후 A도 다시 실행됐다. C와 Rust에서 서로 다른 진행값이 각각 43개·72개 관측됐다. HIGH·A·B의 전용 최종값은 32·348,513·316,066, 종료값은 32·25·90이었다. 일반 부팅에서 깨우기와 퀀텀 만료가 정확히 일치한 사례는 관측되지 않았다. 이 경계는 별도의 결정적 대조에서 다뤘다. 관측 대상은 에뮬레이터의 CPU 하나다.

네이티브 부팅 20회 중 고정 정책 실행 18회에서 선택 124건을 기록했다. 별도의 연결형 대조 2회에서는 동시 및 지연 타이머 사건을 검증했다. 잘못된 패키지 구성 14개가 거부됐고 수정된 호스트 시험이 통과했다.
