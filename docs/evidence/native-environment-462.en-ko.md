# Per-process startup environments / 프로세스별 시작 환경

CHG-344 changes native startup. IMP-344 supplies per-process environments. EVD-344 records the VER-020 observations for REQ-020 and DES-005. / CHG-344의 프로세스별 환경 구현은 IMP-344이며, REQ-020 및 DES-005에 대한 VER-020의 검증 결과는 EVD-344에 수록했다.

Eight serial AArch64 QEMU virt boots exercised two native processes per boot on tested source `6e3690354b62e69d3e974225aeb3beb70ea2fc48`. The kernel and application ELF hashes in the receipt identify the binaries from the tested revision. [Issue #462](https://github.com/Romanof123/JNOX/issues/462) · [Application UART, exit statuses and ELF identities](native-environment-462.json)

각 부팅에서 동일한 ELF를 두 슬롯으로 실행했다. 일반 SDK와 Picolibc에서 각각 환경이 다른 두 슬롯, 양쪽 모두 빈 환경, 한쪽만 빈 환경을 시험했다. 생성자 단계(C)와 main 단계(M)의 UART에는 각 프로세스가 직접 읽은 환경 항목 수와 바이트 체크섬이 남았다. 통합 소스에 수록한 자료의 실행 기준은 위의 검증 커밋이다.

| Case / 시험 | PID 0 | PID 1 | Observed result / 관측값 |
| --- | ---: | ---: | --- |
| Populated / 서로 다른 환경 | 73 | 74 | Four ordered entries per slot, including an empty value and an embedded equals sign |
| Legacy empty / 환경 생략 | 83 | 84 | An empty list with the terminating NULL in each process |
| Mixed / 한 슬롯만 설정 | 83 | 74 | PID 0 remained empty while PID 1 retained all four entries |
| Equal-priority yield / 동일 우선순위 양보 | 91 | 92 | Both SDKs printed A-before, B-before, A-after, B-after |

The extra yield guest checks `WAYLAND_DISPLAY=/wayland-0` versus `/wayland-1` and the role-specific `A_ONLY` or `B_ONLY` before and after the scheduler yield. It verifies the complete ordered vector and its final NULL. Picolibc also checks `environ`, `getenv`, the absent peer variable and absent host canary. Two controls independently change the recorded A-after marker and PID 1's exit identity. Both reader checks rejected the changed data in each runtime.

추가 시험은 실제 양보 전후의 환경과 프로세스 전환 순서를 확인했다. A의 양보 후 표식 또는 PID 1 종료값을 바꾼 두 대조군을 런타임별로 모두 거부했다. 원본 게스트 메모리와 실행 추적은 공개 자료에 포함하지 않았다.

Three host packager tests and six native-stack tests passed. The original source `54fdf5a069fcf38ad3e3e792474a159e152e1b46` first passed all three parser tests, then Rust rejected a repeated empty array reference in the stack unit test at `native_stack.rs:178` (E0308). That attempt stopped before a guest boot. The correction changed the fixture argument to `b"".as_slice()`. The source package's malformed/duplicate/oversize cases, legacy stack-byte checks and the guest receipts cover the stated startup subset. [REQ-020](../requirements.en.md) · [DES-005](../architecture.en.md) · [VER-020](../verification-plan.en.md)

## Reproduction / 재현

Use Linux, the native AArch64 toolchain, QEMU and the selected Picolibc graphics runtime generated by the repository's graphics SDK. Set `PICO_RUNTIME` to that runtime directory. From the repository root, the following commands create fresh outputs and execute each case serially. [Picolibc build instructions](../../sdk/native-aarch64/graphics/README.md)

```sh
set -eu
root=$(git rev-parse --show-toplevel)
work=$(mktemp -d)
export PYTHONDONTWRITEBYTECODE=1 CARGO_BUILD_JOBS=1
export WAYLAND_DISPLAY=HOST_SHOULD_NOT_LEAK JNOX_ENV_HOST_CANARY=HOST_SHOULD_NOT_LEAK
python3 tools/test_native_environment.py -v
rustc --edition=2021 --test kernel/src/native_stack.rs -o "$work/stack-tests"
"$work/stack-tests"
python3 verification/native-env/run.py "$work/core" --runtime "$PICO_RUNTIME" --empty
python3 verification/native-env/yield/yield.py "$root" "$work/yield" "$PICO_RUNTIME"
```

The additional fixture SHA-256 values are `e240cff75a25cd385763a3d1b68af4c5835f2dcfcd7c0cc686732bfc5af8bdba` for the Python runner and `e0fa3926f7b527e142f0e86db56cc26db1ec2ea2805734fa36d7fe23900f1d9b` for the C probe.
