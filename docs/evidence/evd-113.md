# EVD-113 · 네이티브 앱의 단조 시계 절대 대기

CHG-113 / IMP-113 / [#289 설계](../native-absolute-sleep.en-ko.md) / [#290](https://github.com/Romanof123/JNOX/pull/290)

소스 `446b5d57d27f86d29b748a8962bb2f9dcfc4d9bc`에서 C와 Rust 주기 보고 앱은 각각 단일 코어 AArch64 QEMU virt 최초 실행에서 종료값 0을 전달했다. 두 실행에서 인터럽트 컨트롤러가 각각 PPI 30을 세 번 수락했다.

각 앱은 직전 절대 기한에 40 ms를 더해 세 번 대기했다. 미래 기한 호출 6회 모두 태스크가 차단되고 EL1이 유휴 스택에서 WFI를 실행했으며 카운터가 기한에 도달한 뒤 물리 타이머 인터럽트를 처리했다. 커널은 저장된 프레임과 주소 공간을 복원해 같은 EL0 앱의 SVC 다음 명령으로 복귀했다. 이후 앱이 읽은 시각은 매번 기한 이상이었다. 두 앱 모두 첫 기한을 다시 요청했을 때 유휴 전환이나 추가 타이머 인터럽트 없이 즉시 0을 반환받았다. 종료 시 각 앱의 스택에서 보고 누계 6을 읽었다.

C에서 잘못된 timespec을 전달하면 양의 EINVAL(22)을 반환했고 errno(4)와 잔여 시간 (17, 23)이 보존됐다. 안전한 Rust 래퍼는 범위 초과 오류 75를 반환했다. 기존 C 시계 예제는 0, 지정된 레거시 시작 프로필은 37로 종료했다. 별도 보조 실행에서는 일반 인자 프로필로 시작 예제를 실행해 argc 검사에서 90으로 종료했다. 시각 값은 에뮬레이터에서 관측했으며 실기기 복귀 지연은 측정하지 않았다.
