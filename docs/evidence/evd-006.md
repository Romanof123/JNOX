# EVD-006 · CPU 예산 소진과 보충

한국어 · [English](evd-006.en.md)

**두 작업 모두 실행할 일이 남았어도 예산이 바닥나자 CPU가 유휴 태스크로 전환됐다.** 2026-11-24에 독립 검증자가 Cortex-A72 단일 코어 게스트의 첫 부팅에서 UART 9줄, 112바이트를 확인했다. 이어 같은 실행의 예외 주소를 링크된 ELF와 대조했다. [검증 계약](../m1-cbs.md) · [소스 후보](https://github.com/Romanof123/JNOX/commit/6ee2ebb48e78b60e3c46fd0f04f453c97d2eae71)

| 물리 타이머 경계 | 중단된 태스크와 PC | 다음 실행 |
| --- | --- | --- |
| 1 | A · `0x40201278` | B 첫 진입 |
| 2 | B · `0x402012fc` | 유휴 태스크 첫 진입 |
| 3 | 유휴 · `0x40201380` | A 재개 · `0x40201278` |
| 4 | A · `0x402012c8` | B 재개 · `0x402012fc` |
| 5 | B · `0x4020134c` | 타이머 비활성화 후 대기 |

A는 3슬롯마다 1슬롯, B는 4슬롯마다 1슬롯의 예산을 받았다. 예산과 서버 기한으로 실행할 문맥을 선택했고, 자발적 양보 없이 다섯 번의 IRQ를 처리했다. 비교 시각은 게스트 카운터의 같은 기준점에 고정했다. 슬롯당 공칭 50 ms이며 실보드 지연 상한은 별도 검증 대상이다. 관측기 종료 코드는 0이었다. 호스트의 변형 출력 3건은 모두 거부됐다. [원본 UART·예외 추적·판정](evd-006.json)

호스트 테스트 28개가 통과했다. 별도 시험은 주기 1~5와 유효 예산으로 만든 세 서버의 순서 있는 조합 3,375개에 대해 60틱 동안 요청한 총 슬롯 수를 직접 계산했다. CPU 용량 안의 81개는 모두 수용하고 나머지 3,294개를 거부했다. 수용된 각 조합을 120틱 동안 포화 상태로 실행해 매 주기 할당량과 실제 실행량을 대조했다. 정확히 용량에 맞는 입력, 한도를 미세하게 초과한 입력, 산술 표현 한계도 검사했다. 수용 판정의 가정은 단일 코어, 주기와 같은 기한, 독립 서버, 간섭·오버헤드 0이다. [호스트 시험 결과](evd-006-host.txt) · [시험 입력](../../tools/scheduling_tests.rs)

공통 예외 문맥 코드 변경 후 기본 부팅, 고정 우선순위 선점, FIFO, 라운드로빈과 EDF 이미지를 각각 다시 빌드하고 한 번씩 순차 부팅했다. 다섯 관측기가 모두 통과했고 전체 기능 조합의 컴파일 검사도 통과했다. [구성별 해시와 실제 출력](evd-006-regressions.json)

ELF SHA-256은 `5e7c0098151706243d66fc0c41080888fdc2b074706450fee452bd49087b0e6c`이다. 독립 검증자는 실행한 이미지와 같은 해시의 ELF로 명령 주소를 대조했다. 레지스터·카운터 수치는 따로 덤프하지 않았으므로 복원과 시간 창 검사는 실행된 검사 코드와 추적을 근거로 한다.
