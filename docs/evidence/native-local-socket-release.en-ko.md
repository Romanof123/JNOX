# Native AF_UNIX release verification / 로컬 AF_UNIX 릴리스 검증

**The corrected candidate passed the exercised local AF_UNIX profile on AArch64 QEMU virt under FIFO and RR.** This verdict covers the ordinary C and Rust APIs, three socket types, peer close and death, bounded queues, grants and terminal cleanup. The original #24 IPC cases and independent IPv4 TCP/UDP peer group retain their separate acceptance requirements. [Release captures and replay](native-local-socket-release-supplement.tar.gz) · [SHA-256](native-local-socket-release-supplement.tar.gz.sha256)

The release verifier checked out commit `70f2ab812d1d0a444da04c0f8ecdf1f568d533d7`, tree `b704fbf0af36762d30205ddd3e0a09511325017b`, into a new Linux Git directory from shared objects. The supplied Windows worktree pointed to the earlier commit when inspected. Source identity comes from the explicit checkout and each kernel's build manifest. Tracked input matched the requested commit before and after the builds. Cargo generated two untracked lockfiles and Python generated a cache. The verification contract came from documentation commit `559c91ee76cd7ff133ee1a3cf7ec3942afdd5197` and the supplied #376 issue snapshot.

The verifier rebuilt the C server, Rust client and isolated Rust broker. On one emulated Cortex-A72 vCPU with QEMU 6.2.0 TCG, 24 ordinary boots and eight additional register-traced boots completed. RR used a 625000-tick quantum. Each capture records the kernel, three process hashes, package arguments, raw UART, process exits and guest RAM. The independent first and corrected archives also passed an offline recheck of their member digests and original result decoders. **API and evidence boundaries.** C exposes the documented socket subset with positive errno on failure. Rust links the same encoder and returns negative errno in Result. The v1 accept shape supports C `accept(fd, NULL, NULL)` and Rust `accept(fd)`. C accept with address storage returned ENOTSUP before consuming a connection. The C read/write/close wrappers handled socket descriptors. The empty-record tests distinguish a successful zero-byte receive from EOF through the sender and following record. The scheduler's 128-row UART buffer dropped up to 256 event rows. The second boots recorded the indicated broker receive and reply registers directly.

The target C header `sdk/native-aarch64/include/errno.h` omits the ENFILE macro even though the guest observed positive errno 23 at the eight-object limit. The header also omits ENOENT, EPROTOTYPE and EDESTADDRREQ, whose values the service returns for missing names, mismatched types and datagram sends without destinations. Portable C source comparing these symbolic error names requires an SDK header correction. Rust exposes the numeric errors through Result.

Blocking accept, send and receive were observed. The guest backlog test used nonblocking connect and an explicit retry. The code also retains a blocking connect at a full backlog, but this release packet has no guest witness for that wait. Each SDK call uses an infinite transport deadline. The raw finite-deadline case only proves timeout followed by timely ABORT. Source review found that a pending retry can modify socket state before discovering its reply token has expired. General cancellation without that follow-up remains unverified. Board execution, physical timing, DMA and network peer traffic are outside these captures.

**Offline replay.** Extract the release archive on Linux with Python 3 and GNU AArch64 binutils. Run `sha256sum -c SHA256SUMS` and `python3 recipes/audit.py .` to rederive the 24 results and eight traced outcomes. With QEMU available, `python3 recipes/replay.py . /path/to/new-directory --case qwriteclose-rr` reboots one frozen image and traces its close. Omit the case to replay all. Tool versions, command lines, fixture sources, process images, type-layout witnesses and the decoded results are in the archive. [Release packet](native-local-socket-release-supplement.tar.gz)

## 한국어

**수정본의 로컬 AF_UNIX 검증 범위는 AArch64 QEMU virt의 FIFO·RR에서 통과했다.** 명시한 커밋과 트리를 새 Linux 체크아웃에서 확인하고 C 서버, Rust 클라이언트, 격리된 Rust 브로커를 다시 빌드했다. 기본·경계 시험 24회와 동일 커널의 레지스터 추적 8회에서 종료값·해시·슬롯별 RAM을 확인했다. 첫 실패 및 수정 독립 보관물도 해시를 검사한 뒤 원시 데이터에서 결과를 다시 계산했다. [첫 실패](native-local-socket-first.en-ko.md) · [수정 독립 실행](native-local-socket-corrected.en-ko.md) · [릴리스 보관물](native-local-socket-release-supplement.tar.gz)

스트림은 쓰기 경계를 넘는 읽기와 64바이트를 모두 읽은 뒤의 EOF를 확인했다. 데이터그램과 순차 패킷에서 C·Rust 양쪽 모두 길이 0의 레코드를 발신자 이름과 함께 받았다. 4바이트 레코드는 수신 버퍼가 0바이트일 때 MSG_TRUNC로 4를 반환했다. 같은 조건에서 플래그 없이 받은 1바이트 레코드는 0을 반환하고 소비되었다. 32바이트 레코드는 성공했고 33바이트는 EMSGSIZE였다. 큐에 네 건을 채운 뒤에는 0바이트 전송도 EAGAIN이었다.

명시적 close는 스트림 읽기에 EOF, 포화된 순차 패킷 쓰기에 EPIPE, 연결된 데이터그램 읽기에 ECONNREFUSED를 각각 한 번 반환했다. 추적상 상대 close가 대기 요청 뒤에 들어왔고 응답 시점에는 상대 프로세스가 살아 있었다. 데이터그램 경로를 같은 이름으로 다시 바인딩해도 기존 연결의 쓰기는 EPIPE였으며 재연결 뒤에만 새 소켓이 데이터를 받았다. 슬롯 1에만 권한을 준 경우 슬롯 0은 EACCES였고 브로커에서 관측한 종료 사건은 슬롯 1 한 건이었다. 종료 RAM에는 점유 객체·기술자·연결·데이터 큐·대기 토큰·커널 종료 사건이 남지 않았다.

v1 C accept는 주소 저장 공간을 넘기면 ENOTSUP를 반환했고 직후 주소 없는 accept가 성공했다. 아홉 번째 객체의 errno는 23이지만 대상 C 헤더에 ENFILE 상수가 빠졌다. 서비스가 돌려주는 ENOENT·EPROTOTYPE·EDESTADDRREQ도 정의되어 있지 않아 일반 C 코드에서 이 이름을 쓰려면 SDK 헤더 보완이 필요하다. 포화된 연결 대기열에서는 비차단 connect와 재시도를 게스트에서 확인했다. 차단 connect 토큰을 보관하는 경로는 소스에서 확인했다. C·Rust SDK는 무기한 기한을 사용한다. 원시 RPC의 유한 기한은 만료 직후 ABORT한 경우만 확인했다. 재시도 과정에서 소켓 상태가 먼저 변경된 다음 토큰 만료를 알 수 있어 ABORT 이전의 일반적인 취소 의미는 인수 범위에 넣지 않았다. 전체 IPC-006에는 #24의 기존 사례와 독립 IPv4 상대 트래픽 증거가 더 필요하다.

The C SDK subsequently named the six observed broker error codes. An independent AArch64 C11 header consumer compiled with all six static assertions.
