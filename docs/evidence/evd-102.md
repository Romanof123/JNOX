# EVD-102 · CPU0 깨움·배정·응용 패킷 결과 게시

CHG-102 · IMP-102 · POL-009 · CAP-013 · [English](evd-102.en.md) · [이슈 #268](https://github.com/Romanof123/JNOX/issues/268) · [추적 설계](../scheduling-app-trace-v1.en-ko.md)

최초 결합 검증은 QEMU virt에서 서로 다른 구성 35개를 콜드 부팅했다. 깨움 추적 구성 8건 모두 예상 UART와 봉인 파일을 남겼다. 수집기가 정지 요청 뒤 실제 상태를 저장하지 않아 공개 디코더는 8건 모두 거부했다. 이 최초 거부 기록도 보존했다. [결합 최초 보고서](sched-app-trace-joint-first.en-ko.md)

수집기를 수정한 뒤 컴파일 제외·런타임 비활성·활성·포화와 기존 저널 켬·끔을 조합해 8건을 새로 수집했다. 모두 VM 정지 상태를 관측했고 공개 디코딩에 성공했다. 활성 스트림 두 개는 각각 이벤트 27개를 게시했다. 포화 스트림은 각각 4개를 보존하고 커널 22개와 응용 1개의 손실을 집계했다. 전체 구간 복원에는 활성 스트림이 필요하다. 추적을 포함한 이미지의 기록 객체는 8,320바이트다. 동적 스택 최대 사용량과 최장 IRQ 차단 시간은 미측정이다. [수정 후 최초 보고서](sched-app-trace-halt-corrected.en-ko.md)

W는 성공한 깨움 SVC의 정지 표본, Q는 준비 큐 삽입 직후의 새 표본, S는 대상 작업의 첫 재배정, E는 대상이 실제 계산한 패킷 결과를 게시한 직후의 표본이다. S−Q는 관측된 준비~배정 지연이고 E−S는 복원과 대상 작업의 계산을 포함한다. 네 작업의 계산값을 재구성하고 E−W를 해당 부하의 조건부 23U 한도와 대조한다. 타이머 쌍은 Rust 처리 구간을 측정하며 스케줄러의 소유 시간과 겹칠 수 있다. [스케줄링 한도와 패킷 계산](../mlfq-wake-design.en-ko.md)

이 근거는 신뢰된 링크 방식 EL1 이미지의 시간·메모리·관측·스케줄링 동작 일부에 적용된다. 생성자·내보내기 범위는 REQ-011에 영향을 준다. 도메인 간 접근 통제, 실기 시간 특성 및 제품 승인은 미결이다.

최종 형식 검사 소스 `10413a1ae6a34b85caf414444e26b23758b39879`의 첫 8회 부팅에서 정수 CPU0, 중지 명령의 실제 응답, 이후 일시 정지 응답이 기록됐다. 독립 재계산한 작업 결과 32개가 일치했다. 활성 두 실행은 각각 27개 이벤트를 보존했다. 포화 두 실행에서는 각각 커널 22개와 앱 1개가 누락됐고, 빠진 지연 구간은 미확정으로 표시했다. 현재 판독기로 유효한 구형 8개는 통과했고, 최초 정지 기록이 빠졌던 8개는 같은 이유로 다시 거부됐다. [최종 원본 및 독립 검산](sched-app-trace-typed-first.en-ko.md).
