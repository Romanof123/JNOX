# EVD-017 · One running thread moves from CPU0 to CPU1

[한국어](evd-017.md) · [Acceptance contract](../m3-smp.en.md) · [Change #47](https://github.com/Romanof123/JNOX/issues/47)

Two independent verifiers each cold-booted the same Rust kernel on QEMU 6.2.0 virt with two Cortex-A72 CPUs. In both runs the timer interrupted M at `0x40201304` on CPU0. CPU1 restored that PC, the private stack, TLS, SIMD and the loop counter. CPU0 ran its pinned replacement. The partitioned and singleton-cluster epochs retained the declared task homes. Both verifiers reconciled all 11 ownership intervals and task service totals, including refusal to claim M while already owned and refusal to cross the cluster boundary.

| Final configuration, first boot | Host threads for two guest CPUs | IRQ entry to destination task callback | Result |
| --- | --- | ---: | --- |
| Multithreaded TCG | 495, 496 | 1,033.888 µs | Passed. [UART, QMP, journal and exception trace](evd-017-multi.json) |
| Single-threaded TCG | 497, 497 | 1,029.792 µs | Passed. [UART, QMP, journal and exception trace](evd-017-single.json) |

Each run had one PSCI call, one IRQ and ten SVCs. The individual counter samples include dispatcher and instrumentation time at 62.5 MHz. QMP identifies the host threads. The guest journal supplies CPU attribution and the exception trace corroborates saved and resumed PCs. These figures describe one virtual boot per mode. Physical migration latency, shared-cache interference, product timing limits and safety approval remain open.

The first candidate passed the multithreaded case. Single-thread TCG timed out at five seconds, and a diagnostic trial with a twelve-second deadline also timed out. Explicit AArch64 YIELD in peer-wait loops let the serialized emulator advance both CPUs within the original five-second deadline. The first results and the diagnostic trace are retained. [Initial candidate](evd-017-initial.json) · [QEMU YIELD implementation](https://github.com/qemu/qemu/blob/v6.2.0/target/arm/op_helper.c#L327-L336)

The final integration run passed 63 Rust host tests, eight response-analysis tests and eleven sequential guest regressions. A harness path error also presented a minimal boot ELF to the SMP observer, which rejected its truncated transcript. The corrected five-profile build/boot matrix used the ELF from each build’s actual target directory. [Regression and failed harness run](evd-017-regressions.json)
