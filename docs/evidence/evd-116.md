# EVD-116 · 네이티브 앱의 가중 CPU 서비스

CHG-116 / IMP-116 / POL-011 / [#296](../native-weighted-applications.en-ko.md) / [#297](https://github.com/Romanof123/JNOX/pull/297)

최초 기본 시계 실행에서 CRC·히스토그램 쌍은 필요한 완전한 실행량 36개 중 25개, 가중치를 맞바꾼 쌍은 13/36개, 모두 준비된 세 앱은 49/60개를 기록했다. 기본 시계의 1:2 서비스 합계는 5,043,073 및 10,679,176틱이었다. 앱 최종값은 일치했으나 최초 실행량 관측 구간은 짧았다. 주기 보고 앱은 기한과 복귀 검사 세 번을 통과했다. 동료 계산이 둘째 대기 중 끝나 세 대기 구간의 동료 서비스는 2,474,346·1,711,854·0틱이었다. 별도 icount 실행에서는 세 대기 모두 동료 서비스를 관측했다. icount shift 3에서 최초 완전한 정산 36건의 서비스는 7,500,120틱과 15,000,240틱이었다. 종료 출력 중 캡처 제한 시간에 도달해 1,149행이 보존됐고 마지막 저널과 종료 기록은 불완전했다.

작업량을 늘린 기본 시계 실행 4건은 모두 통과했다. 완전한 실행량 첫 36개에서 1:2 쌍의 물리 서비스는 7,563,657틱과 15,081,733틱이었다. 가중치를 맞바꾸자 15,111,026틱과 7,542,390틱이었다. 세 앱 1:2:3 실행의 첫 60개에서는 각각 6,317,305·12,579,009·18,882,070틱을 받았다. 각 앱의 C 또는 Rust 실제 계산 루프 안에서 중단된 PC를 각각 10·20·30회 확인했다. 세 번의 40 ms 대기 동안 동료 서비스는 2,466,269·2,500,316·2,501,756틱이었다. 독립 검증에서 정해 둔 범위와 앱이 계산한 결과, 복귀 프레임을 확인했다.

별도 보조 icount 실행에서는 최초와 같은 이미지로 RAM 저널 1,616행(누락 0), 종료값 52·197, 첫 정산 36건의 정확한 1:2 결과를 확인했다. 최초 캡처의 종료 출력이 불완전했던 기록은 별도로 유지한다. 과거 #177·#184 판정과 실물 보드 검증은 별개다.

위 결과는 소스 `100d32e1b6e49277c9801723b8cc5b0dd3ad801f`에서 얻었다. 릴리스 검토에서 native_el0.rs의 일반 가중치 모드 대기에 부호 있는 거리 범위 검사가 빠진 점을 확인했다. 표현 범위를 넘는 기한은 정책 상태를 바꾸기 전에 EOVERFLOW로 반환해야 한다. 위의 실행량 및 깨우기 관측은 이 오류 경로를 다루지 않았다. 최초 보고서에서 네 분할 파일과 복원 절차를 확인할 수 있다.
