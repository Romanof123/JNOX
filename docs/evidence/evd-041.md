# EVD-041 · 고정 런타임 핸들러 비용과 관측된 스택 사용량

[English](evd-041.en.md) · [측정 설계](../fixed-cost.md) · [#90](https://github.com/Romanof123/JNOX/issues/90)

최초 래퍼 호출 24건은 캡처 디렉터리가 이미 존재해 QEMU 실행 전에 실패했다. 각 호출의 로그와 상태를 보존했다. 수정 후 FIFO/RR 구성 8종에서 실제 콜드 부팅을 각각 3회 실행했고 24회 모두 UART 판정과 유휴 함수 내 정지 PC 확인을 통과했다. 게스트 실패는 없었다. 측정 환경은 QEMU 6.2.0과 단일 가상 Cortex-A72였다.

외부 구간은 타이머 처리와 선택적 추적 출력을 포함해 표본으로 측정한 Rust 핸들러 구간이다. 내부 구간은 정책 이벤트 전체다. 아래 값은 카운터 틱 최솟값–최댓값이며 각 그룹은 부팅 3회에 걸친다. 추적 꺼짐과 켜짐은 별도 이미지에서 측정했다.

계측 부팅 12회에서 카운터 주파수는 모두 62.5 MHz(틱당 16 ns)였다. 부팅마다 순서가 보장된 연속 읽기 한 쌍으로 보정 구간을 기록했고 측정값에서 차감하지 않았다. 벡터 진입, 어셈블리 저장·복원, ERET, 핸들러 진입·종료 코드는 계측 구간 밖이다. 끝점 이후 저널 쓰기는 후속 결정에 영향을 줄 수 있다. 비용 계측을 끈 구성은 동작과 정적 크기만 제공하므로 시간 오버헤드나 구성 간 속도 순위를 산출할 수 없다.

계측 구성마다 세 번의 깊이가 동일했다. 이 값은 최초 832바이트 프레임을 포함하며 실제 최대 스택 사용량의 관측 하한이다. 원래 바이트가 복원되거나 페인트 패턴과 우연히 같거나 SP 조정 뒤 쓰지 않으면 더 깊은 사용이 가려질 수 있다. 미사용 슬롯 3은 모든 최종 스냅샷에서 0을 유지했다. 모든 이미지가 16 KiB 스택 5개에 81,920바이트를 예약했고 계측은 별도 저널 7,208바이트를 추가했다. 부트 스택 16 KiB는 페인트 측정 범위 밖이다. 관측 범위는 WCET, 제품 타이밍·스택 기준 충족, 실물 보드 성능이나 안전 적격성을 입증하지 않는다.
