# EVD-003 · 동일 우선순위 FIFO 실행 검증

한국어 · [English](evd-003.en.md)

**판정은 AArch64 단일 코어 FIFO 시험 합격이다.** 2026-11-24에 독립 검증팀이 소스 `76b88ee7fe4c8ece0eb206bd3ed2126d1b761ff1`에서 빌드한 ELF `b5f87bf6086cf8a33eadb54a7c0b91622bfcaf6a16b29b81ddcdf5c65ab8806d`(SHA-256)를 대상으로 UART 판정을 먼저 기록한 뒤 같은 실행의 예외 주소를 심볼·명령과 대조했다. 커널 빌드는 한 번 수행했다. [시험 계약](../m1-fifo.md) · [소스 커밋](https://github.com/Romanof123/JNOX/commit/76b88ee7fe4c8ece0eb206bd3ed2126d1b761ff1)

| 단계 | 관측 결과 |
| --- | --- |
| 최초 실행 | 호스트 관측기가 `ENODATA` 오류로 QEMU를 일찍 종료했다. UART 83바이트는 B의 첫 실행까지만 보여준다. 이 시도는 판정 불가다. |
| 순차 재시도 | 같은 ELF와 같은 기계 구성에서 관측기의 임시 파일을 WSL 기본 경로에 두고 새 게스트 하나를 실행했다. 10줄·142바이트의 UART와 관찰 구간을 모두 확인했다. |
| 타이머 선점 | LOW의 비양보 루프에서 IRQ가 발생했다. 하드웨어 에뮬레이터가 기록한 LOW 복귀 주소는 `0x402012bc`다. |
| FIFO 및 양보 | A와 B의 ID는 2와 1이고 우선순위는 같다. A가 먼저 준비됐다. 실행 순서는 A 진입 → B 진입 → A 복귀 → B 복귀였고, 두 양보와 두 종료에서 관측한 SVC 번호는 각각 2, 2, 1, 1이다. |
| LOW 재개 | 마지막 예외 복귀가 처음 저장한 LOW 주소 `0x402012bc`로 향했다. 스택·레지스터 표식은 게스트 코드에서 확인했고, 세 스택의 분리와 준비 대기열 연산은 링크된 이미지와 소스에서 검토했다. |

별도 호스트 단위 시험 세 가지가 역순 ID 삽입·양보, 선점된 동순위 스레드의 차례 보존, 잘못된 ID·중복·용량 초과 거부를 통과했다. 독립 검증자는 기록된 UART를 호스트에서 재생해 판정기의 실패 검출도 확인했다.

호스트 시험은 저장소 루트에서 `rustc +1.95.0 --edition 2024 --test kernel/src/ready_queue.rs -o queue-tests`로 빌드하고 실행 파일에 `--test-threads=1`을 전달한다. 기본 기능과 기존 `sched-bench` 프로파일은 `cargo check`로 각각 확인했다. 이번에 실제 부팅한 프로파일은 `fifo-bench`다.

`CHG-003` · `REQ-002`, `REQ-005` → `DES-003` → `IMP-003` → `VER-002`, `VER-005`. 이 증거는 하나의 에뮬레이터 코어에서 실행한 세 스레드에 해당한다. 시간 할당량에 의한 라운드로빈, SMP, 최악 응답시간과 실보드 기능안전 판정은 별도로 검증한다. [원본 관측과 재현 정보](evd-003.json) · [추적 관계](../../trace/links.csv)
