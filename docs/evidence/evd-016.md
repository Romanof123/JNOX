# EVD-016 · 비주기 요청의 예산·보충·실제 CPU 서비스

[English](evd-016.en.md)

같은 6단위의 요청을 틱 1, 3, 4, 7에 제출했다. 각 서버에 예산 2와 주기 4를 적용했다. 첫 구간이 비었기 때문에 폴링은 틱 4까지 대기했고 DS와 SS는 틱 1에 첫 요청을 실행했다. SS 보충 큐를 한 칸으로 줄이면 틱 3에서 예정 크레딧 두 개가 틱 7의 2단위로 합쳐져 틱 5의 실행을 미뤘다.

| 서버 | 실행 슬롯 | 10틱에서 완료 / 대기 (작업 단위) |
| --- | --- | --- |
| PS | 4, 5, 8, 9 | 4 / 2 |
| DS | 1, 3, 4, 5, 8, 9 | 6 / 0 |
| SS | 1, 3, 5, 7, 9 | 5 / 1 |
| SS1 | 1, 3, 7, 8 | 4 / 2 |

독립 검증팀의 첫 게스트는 UART 1,659바이트와 종료 코드 0을 기록했다. 같은 실행의 타이머 IRQ 40회가 대조표의 작업 또는 유휴 루프를 실제로 중단했고, 생산 태스크 SVC 32회에서 제출·응답 확인·대기 경로를 확인했다. 슬롯의 요청 ID, 남은 예산, 모든 보충 만기와 양을 비교했다. 완료 표식·레지스터·스택·진척 값은 게스트 안에서 확인했고 예외 복귀 주소는 외부 추적에서 확인했다. [UART / IRQ / SVC](evd-016.json)

독립 호스트 모델이 CPU 가용성과 도착을 바꿔 6,144개 조합을 비교했다. 호스트 시험 55개, 변형 UART 대조군 3개와 별도 회귀 부팅 구성 4개가 기대 결과와 일치했다. 실보드 간섭·지연과 제품 서비스 시간 보장은 미검증이다. [QEMU](evd-016-regressions.json)
