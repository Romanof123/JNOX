# EVD-044 v2 · 보통 Rust 작업의 P/Q 콜드 재생

v2의 새 정상 콜드 실행은 P 10/10, Q 13/13 경계에서 1 ms를 충족했다. v1은 P 9/10, Q 11/12 경계가 초과했고 Q가 준비된 B 구간을 건너뛰었다. 실제 지연 주입과 IRQ 마스킹은 미검증이다.

[CHG-046 / IMP-044](../ordinary-partition-capture.md) · [JSON](evd-044-v2.json) · [#104](https://github.com/Romanof123/JNOX/pull/104) · [155083f](https://github.com/Romanof123/JNOX/tree/155083fdc539ae3ed8b8e5b0bfa6a3530b21b949)

62.5 MHz 가상 카운터의 틱이다. 각 표는 실제 콜드 실행 하나씩을 나타낸다.

| 관측 | P | Q |
|---|---:|---:|
| 최대 경계→작업 관측 지연 | 48035 | 44051 |
| 첫 A 경계 c−d / i−c / x−i | 0 / 34674 / 13361 | 0 / 16903 / 9209 |
| B 준비 / 선택 / 작업 관측 | 9460296 / 18853112 / 18861981 | 3195232 / 12587900 / 12596344 |
| 실행 A / B / 유휴 | 24976586 / 6223660 / 12444538 | 18732987 / 18695152 / 12431548 |
| 커널 / 경계 불확실 | 67165 / 56044 | 68895 / 80287 |
| 누산기 반복 검증 | 11970848 | 14088949 |

P/Q ELF는 v1의 해당 이미지와 바이트 단위로 일치했다. 향상된 판정기가 원본 게스트 예외·복귀 PC, ELF 최초 PC·SP, 작업 스택, 누산기 및 반복을 대조했다. 새 P/Q 최대 지연은 각각 0.768560 ms와 0.704816 ms였다. v1 원본은 재생 시 두 건 모두 상태 2를 반환했다. 새 측정에서 나타난 지연 차이의 원인은 밝혀지지 않았다.

값, 최초 PC, 세대, 다음 경계, 저장 PC를 각각 바꾼 5건은 상태 1로 거절됐다. 과거 합성 정상·근접·장기 지연 입력 6개도 이전 누산기와 최초 프레임 형식 때문에 거절됐다. 현재 생성기의 P/Q 각 세 사례는 모두 예상한 판정을 냈다. 근접 사례는 한계를 넘고 장기 지연은 슬롯을 건너뛴다. 호스트 검사 8개가 기록되었다. 와이어 형식에는 실행 ID가 없다. 실제 부트와의 대응은 표·세대·ELF 해시·독립 IRQ/복귀열로 확인한다. 별도 레거시 어셈블리 진단은 [#112](https://github.com/Romanof123/JNOX/pull/112)의 범위다.

JSON의 복원 절차를 적용한 뒤 AArch64 nm가 설치된 POSIX 환경에서 실행한다.

```sh
for t in P Q; do
  lower=$(printf '%s' "$t" | tr 'PQ' 'pq')
  run="partition-restored/partition-select-fresh/104-ordinary-partition-$lower"
  digest=$(python3 -c 'import json,sys;print(json.load(open(sys.argv[1]))["elf_sha256"])' "$run/execution.json")
  python3 partition-restored/frozen-source/tools/ordinary_partition_account.py "$run/uart" --origin guest --case healthy --table "$t" --elf "$run/kernel.elf" --elf-sha256 "$digest" --exceptions "$run/exceptions.log" || exit 1
done
```
