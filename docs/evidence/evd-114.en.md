# EVD-114 · Cooperative native processes

CHG-114 / IMP-114 / POL-001 / [#291](../native-cooperative-processes.en-ko.md) / [#292](https://github.com/Romanof123/JNOX/pull/292)

On `94bef763dbbcc7419e2d2902361052c6acec1f86`, the shipped C primary (PID 0) and Rust peer (PID 1) yielded in sequence 0 → 1 → 0. PID 0 then slept. PID 1 completed its private report and exited 29, and PID 0 woke and exited 17. An earlier auxiliary host command omitted `-nodefaults` and stopped before guest boot. The standard invocation started both applications.

A separate post-exit inspection located both private accumulators at virtual address `0x402000`. The primary’s backing page at `0x4022d000` held 17 and the peer’s page at `0x40642000` held 29, from initial values 10 and 20.

In the separate serial running-peer capture, the timer interrupted the running EL0 peer. The saved PC and ERET PC matched at `0x4016d0`. The peer continued useful work until it yielded voluntarily, then the awakened sleeper ran. In serial two-sleeper both processes slept. Two IRQs reached EL1 at idle PC `0x402013f4`. The C process with a 100 ms deadline exited 17 before the Rust process with a 300 ms deadline exited 29.

Only the six serial Windows-sealed workloads were scored. A seventh boot supplied the independent post-exit memory inspection. The original WSL temporary binaries and logs disappeared before archiving. The cause remains unknown. The temporary running-peer PC 0x40018c survives only as a witness observation. The overlapping recovery boots are archived separately and unscored. Two temporary supplemental runs were reported to have exited 112 because their external Rust fixture assumed a fixed address for a symbol linked at `0x403000`. The corrected runs changed only the external programs. The legacy startup control exited 37 and the single-app clock and periodic controls exited 0. Physical timing remains unmeasured.
