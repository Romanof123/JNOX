# EVD-039 · EEVDF service and wake latency across live configuration changes

[한국어](evd-039.md) · [Acceptance design](../m4-eevdf-dynamic-design.md) · [#85](https://github.com/Romanof123/JNOX/issues/85) · [#88](https://github.com/Romanof123/JNOX/issues/88)

The first and only guest boot passed on QEMU 6.2.0, single-core Cortex-A72 TCG. Across 256 consecutive grants, A/B/C received 122/94/40. Each grant was 625,000 ticks of the 62.5 MHz counter. The independent replay matched all selections and all 20 wakes. The exception trace recorded 256 IRQs, 20 blocking SVC #1 calls and four configuration SVC #2 calls.

C targeted A immediately before sleeps 5, 9, 13 and 17. Requests (weight, slice) were (2,3) accepted, (0,3) rejected, (3,3) accepted and (3,0) rejected, respectively. Both rejections preserved the reference and every recorded task tuple. The linked worker disassembly corroborates the target and request sequence.

All four ranks met each declared fixture limit. The longest wake-to-worker interval was 73.599824 ms. The handler recorded arguments, frame pointers and guest timestamps. QEMU independently recorded exception types, syndromes, ELRs, vectors and return PCs. There are no per-trap raw register dumps or saved-frame contents. These distributions describe this one virtual run. Board timing and product safety need separate evidence.
