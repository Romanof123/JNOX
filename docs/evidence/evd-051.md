**독립 검증자의 정정.** 동결된 판독기와 독립 검증기 모두 (t, a)를 구간, b를 위상으로 읽는다. 02번 부팅의 RAM n=9는 (kind=8, t=273778, a=275568, b=0)이고 UART 행은 (21, 275568, 0, 273778)이다. 두 판독 결과 모두 위상 0, 1,790틱이다. 검증자는 실제 저널 4개의 위상·비용이 잘못됐다는 주장을 철회했다. 순서를 뒤집은 두 끝점이 UART에도 그대로 반영된 가상 손상 입력은 원래 구간 검사를 통과할 가능성이 있다. 이는 소스 검사에서 확인한 검증 공백이다. 독립 검증은 실제 위상 624개의 끝점 순서 및 네 RAM 저널과의 대응을 확인했다. ZIP에 최초 보고서와 후속 정정문 원문을 함께 보존했다. [동결 판독기](https://github.com/Romanof123/JNOX/blob/188faa91e5e0655f56cf6aca97001a4e61fa75c4/tools/control_service_markers.py#L98-L103)

네이티브 Linux ext4에서 순서를 교차한 RM·DM 12쌍을 직렬 실행했다. 콜드 부팅 24회 모두 최초 시도에서 완료됐고 정상 시퀀스는 0회였다. 기준 ELF의 PT_LOAD는 EVD-050 v2의 해당 이미지와 달랐다. 시간 단위는 62.5 MHz 카운터 틱이다.

기술자 사용 시 첫 목표부터 릴리스 행까지 +1574, +137, +1144, +8657틱이었고 최장 마스크 구간은 −639, −148, +855, +501틱 변했다. 릴리스 행에는 IRQ 지연과 다른 작업이 포함된다. 모든 구간이 짧아졌다고 판단할 수 없다. 기술자 사용 시 text는 정책별 76바이트 줄었고, opt3에서는 RM 16,992·DM 16,996바이트에서 각각 20,360바이트로 늘었다. 마커군의 첫 서비스 변화는 −3357, +9883, +12443, −10625틱이었다.

첫 서비스는 22/24에서 15,625틱을 초과했다. 기술자 DM 14·15번만 15,295틱과 14,838틱으로 통과했다. 이후 600개 위상은 모두 서비스 한계 이내, IRQ 624건은 모두 31,250틱 이내였다. 최대 판정 간격 165,877틱과 최대 작업 완료 172,840틱은 312,500틱 이내였다. 1·2·3·6·8번 부팅은 위상 0 완료가 62,500틱을 넘었다. 최초 허가 전에 차단한 22회 중 서비스 예산이 최초 사유인 경우는 17회, 위상 시간은 5회였다. 이들은 허가 7건을 모두 거절했고 최종 출력은 OFF였다. 결함에서 억제 동작 시작까지 968–2,206틱, 래치까지 1,291–2,422틱이었다. 기술자 DM 두 부팅은 결함·래치 없이 허가 7건 모두 수락했으나 첫 발행 간격은 589,967·582,002틱(요구 625,000), 명령 오프셋은 937,501·937,507틱(요구 937,500)이었다. 재무장·상승 에지 없이 OFF였다.

마커 RAM 저널 4개에서 각각 중단 PC 59개와 복귀 PC 59개가 외부 IRQ/SVC·ERET 순서와 일치했고 저널 경계 후 추가 복귀가 있었다. 독립 판독은 종류 8의 필드를 t=시작, a=끝, b=위상으로 읽어 행 6·8·21을 대조했다. 첫 판정 본체 1,133–3,326틱, 기록 제외 선택 387–408틱, 복귀 본체 83–118틱, 복귀 꼬리부터 작업 표본까지 594–2,825틱, 과금 내 쓰기 49–67틱, 잔여 과금 21,241–26,368틱이었다. 마스크 노출 하한은 12,701–16,921틱, 상위 괄호는 14,546–18,617틱이며 비용 항목과 겹친다. 잔여분에서 작업·진입·콜드 변환 비용을 개별 산정할 수 없다. 출력 ON 이후의 상실, 동시 경계, 전기적 차단 또는 제품 최악시간을 입증한 실행은 없다.
