| Observation | Behavior in the same guest boot |
| --- | --- |
| LOW preempted | An IRQ interrupted the lower-priority thread's non-yielding loop. QEMU recorded the return address as `0x402012bc`. The kernel requires timer interrupt ID 30 from the GIC and an asserted timer before proceeding. |
| HIGH dispatched | Both threads were runnable when the fixed-priority dispatcher selected HIGH. Exception return targeted HIGH's entry point at `0x4020134c`. HIGH ran on its separate stack and signaled completion with `SVC #1`. |
| LOW resumed | The final exception returned to `0x402012bc`, the address originally interrupted in LOW. LOW checked stack data, general registers, SIMD and processor state before emitting `SCHED PASS`. The entire UART stream contained seven lines and 101 bytes. |

QEMU independently recorded exception classes and return addresses. The kernel checked stack and register values and the interrupt ID. The verifier inspected the corresponding instructions in the ELF. Host replays rejected seven negative cases including boot-only output, a missing resumption line and an incorrect sequence. This round ran one scheduler guest. The default boot matcher was checked against its existing captured UART.

`CHG-002` → `REQ-002`, `REQ-005` → `DES-003` → `IMP-002` → `VER-002`, `VER-005`. This record establishes one preemption and resumption between two threads on one emulated core.
