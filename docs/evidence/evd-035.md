# EVD-035 · 비례 배분 스케줄러의 최초 실패 기록

[English](evd-035.en.md) · [#79](https://github.com/Romanof123/JNOX/issues/79) · [승인 설계](../m4-proportional.md)

처음 셸 호출은 QEMU 실행 전에 실패했다. 이어 가상 Cortex-A72 한 개에서 세 구성을 각 한 번 실행했다. 일반 및 진단 게스트는 각각 UART 116바이트, 적용 행 81개, IRQ 75회, SVC 6회로 통과했다. 두 실행 모두 복권 시드별 A/B/C 서비스는 10/8/14와 5/11/16이었다. 스트라이드 서비스는 C가 기준값 720,720에서 합류한 뒤 4/8/0에서 2/4/8로 바뀌었다. 지연된 실행권은 3틱을 차감하고 패스를 2,162,160 증가시켰다. 일반 ELF에는 실패 심볼이 없었다. 진단 기록은 `[0,3,0,0,0]`이었고 첫 워드 0은 확정된 실패가 없다는 뜻이다. 오프라인 검증자는 선언된 형식에 따라 모든 워드가 0이어야 한다는 최초 가정을 수정했다. 게스트 재실행은 없었다.

강제 실패 게스트는 PROPORTIONAL FAIL까지 UART 45바이트를 출력했다. 출력 검증기의 종료 코드는 1, 캡처 후 QEMU 종료 코드는 0이었다. 유일한 적용 행은 구간 0의 슬롯 0이었다. 추첨값 2는 총 7장 중 B의 구간 [1,3)에 속했다. 시작·비교·종료 카운터는 각각 72,495, 1,322,495, 1,454,468이었다. 경과량 1,381,973카운트를 틱당 625,000카운트로 환산하면 2틱이다. B는 `0x40201268`에서 진입했고 PPI30은 PC `0x4020127c`에서 B를 중단했다. 진행값은 75,504,959였다. 다섯 워드 `[468,0,0,2,1]`은 소스 행, 구간, 슬롯, 실제 2틱과 예상 1틱을 가리킨다. 이후 행은 비어 있었다.

과거 #79 ELF에서는 B/A/B/A 순으로 PC `0x4020127c`, `0x40201260`, `0x4020127c`, `0x40201260`에서 IRQ가 발생했다. 앞의 핸들러 세 개가 복귀한 뒤 구간 0의 슬롯 3에서 네 번째 중단이 기록됐다. 당시 카운터와 판정 피연산자 기록이 없어 최초 원인은 미해결이다. 이번 측정 범위는 해당 QEMU 시험 구성이며 실물 타이밍과 제품 간섭에는 별도 근거가 필요하다.

[원시 캡처, 검증기와 오프라인 재현](evd-035.json) · [검증한 판정식 468행](https://github.com/Romanof123/JNOX/blob/532f94cb72a494fa725565e3cff70923ae2a731d/kernel/src/proportional.rs#L468)

통합 실행에서 호스트 검사 160건과 QEMU 부팅 8회가 통과했다. 출력 관찰기는 의도적으로 유발한 비례 배분 실패를 예상대로 거부했고, 유효하지 않은 빌드 조합 6건도 거부됐다. 적재용 원시 이미지 5개 모두 독립 검증 이미지와 바이트 단위로 일치했다. [통합 회귀 검사 기록](evd-036-regressions.json)
