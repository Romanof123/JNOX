# EVD-046 · MLQ 포화 및 MLFQ 지연 부스트

[English](evd-046.en.md) · [시험 계획](../multilevel-limits-plan.md) · [#102](https://github.com/Romanof123/JNOX/issues/102) · [#107](https://github.com/Romanof123/JNOX/pull/107)

**유한 작업 6종 통과.** 각 선택자를 QEMU 기본 가상 시간에서 일반·진단 이미지로 각각 한 번 콜드 부팅했고 최초 게스트 12개가 모두 통과했다. 실행 전 WSL Git 작업 트리 확인은 실패했으나 Windows Git으로 소스와 깨끗한 트리를 확인했다. 일반 이미지의 근거는 작업 출력, 예외 순서와 유휴 관측이다. 아래 소유자별 수치는 독립 진단 재현 결과다.

| 선택자 | 결정 수 | 예외 수 | 서비스 카운트, 소유자 0 / 1 / 2 |
|---|---:|---:|---|
| mlq | 16 | 15 | 244,396 / 3,898,218 / 4,576,257 |
| mlfq | 42 | 41 | 2,722,245 / 20,420,398 / 15,121,957 |
| mlq-blocked | 3 | 2 | 168,543 / 129,569 / 0 |
| mlq-exited | 3 | 2 | 176,222 / 125,314 / 0 |
| mlq-saturated | 25 | 24 | 865,755 / 7,677,069 / 7,542,977 |
| mlfq-delayed | 15 | 14 | 40,262,226 / 10,133,885 / 9,966,062 |

**전체 차단과 종료.** 각 진단 실행에서 서로 다른 두 작업이 SVC를 호출했다. 마지막 생존/수면 마스크는 차단 뒤 3/15, 종료 뒤 0/15였다. 미사용 슬롯도 수면으로 집계한다. 두 사례 모두 일반·진단 이미지가 링크된 유휴 함수에 도달했고 타이머 활성 비트는 0이었다. 진단 프레임 포인터와 저장 복귀 PC를 각 작업의 16 KiB 전용 스택 및 QEMU 예외 복귀와 대조했다. 작업 코드를 공유하는 소유자는 프레임 주소와 큐 이력으로 구분했다.

**유한 포화.** 최초 타이머 사건 8회에서 최상위 동순위 작업 1·2가 교대했고 각 종료 구간에 양의 서비스가 청구됐다. 하위 작업 0은 준비 상태로 대기하다 마지막 상위 작업이 종료한 직후 선택돼 865,755카운트를 실행했다.

**지연 부스트.** 소유자 0은 70,876에서 시작했다. 명목 마감은 2,570,876이었고 실제 설정 후 읽은 비교값은 32,570,876이었다. 타이머 PPI가 32,744,052에서 구간을 종료해 경과량 32,673,176카운트 전체를 소유자 0에 청구했다. 재설정 직전 최하위 순위 0에 잔여량 3,576,824였다. 세 부스트 주기를 한 번의 재설정으로 합쳤고 준비 순서 [1,2,0]를 유지했다. 세 작업 모두 최상위 순위 2와 잔여량 2,500,000을 받았고 소유자 1이 재개됐다. 다음 비교값은 일반 명목 마감 35,263,215와 일치했으며 35,392,778에 종료해 2,629,563카운트를 청구했다. 이후 주기 경계도 재현했다.

이 유한 실행으로 무기한 상위 클래스 포화 시 하위 클래스의 최소 지분을 보장할 수 없다. 실제 배포 클래스·부스트 설정, 작업 부하의 지연 한계, 실물 타이밍과 제품 적격성은 별도 검증 대상이다.
