# EVD-133 · M4 telemetry alarm publication deadline

CHG-133 / IMP-133 / POL-009 / [#329](../multilevel-telemetry-deployment.en-ko.md) / [#330](https://github.com/Romanof123/JNOX/pull/330)

On one default-clock Cortex-A72 QEMU virt/GICv2 CPU, the first plain and traced boots of MLQ and MLFQ each published three complete alarm results. From requested release to the first monotonic sample after publication, the 12 upper bounds ranged from 120,944 to 387,760 ns. All 12 met 40 ms, with a minimum margin of 39,612,240 ns. Counts were 256 each round and 256/512/768 cumulative. The CRC worker advanced during every sleep and its CRC-32 matched recomputation from the actual block count. The two apps exited 53/17.

Both traced boots matched actual due IRQ and EL0 return PCs and the subsequent reporter clock calls. Each feedback boot crossed six charged-service boosts. Each ready list contained only PID 1 and selected it. Separate EVD-040 replay checks multipeer boost order. EVD-122 retains its original 512-row prefix and missing suffix.

The no-argument control kept the original unscored output and exit 53. Zero milliseconds returned 106 before any publication. The reader decoded all six actual snapshots, each with zero lost journal rows. Exact equality and a one-nanosecond overrun were host arithmetic controls. Timing observations use the named guest clock.

Independent Release issued a conditional pass after reviewing the source, hashes, six captures and EVD-040/122. PM approved POL-009 for the four first plain and traced M4 reporter/CRC boots on single-vCPU Cortex-A72 QEMU virt/GICv2 at the default clock. Strict MLQ uses classes 7/1 and a 10 ms quantum. MLFQ uses 10/20/40 ms service allotments and a boost after 100 ms of charged service. The publication bound is 40 ms from requested release.

Other workloads, configurations, physical-board timing and safety approval remain outside this decision. Observed CRC progress establishes no universal minimum service for a low class.
