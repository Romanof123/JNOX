# EVD-005 · EDF의 타이머 선점과 복귀

한국어 · [English](evd-005.en.md)

**에뮬레이트한 Cortex-A72 한 코어에서 통과했다.** LOW가 먼저 도착했고 고정 우선순위도 더 높았다. 물리 타이머가 절대 기한이 더 이른 URGENT를 깨우자 인터럽트 복귀를 통해 URGENT가 자신의 스택에서 실행됐다. URGENT가 종료된 뒤 LOW는 타이머가 중단시켰던 바로 그 명령에서 재개했다. [공개 검증 기준](../m1-edf.md) · [시험한 소스 커밋](https://github.com/Romanof123/JNOX/commit/2d5b5ffbda9b411c2c600f08808aae5f23b3646c)

| 관찰 항목 | 결과 |
| --- | --- |
| 첫 실행, 2026-11-24 | 처음 참여한 검증자가 예외 로그·커널 소스·링크된 명령을 보기 전에 UART 7줄 101바이트를 합격으로 기록했다. 관측기는 0.1초의 무출력 구간을 확인한 뒤 종료 코드 0을 반환했다. |
| 타이머와 문맥 | 물리 타이머 IRQ가 LOW의 `0x402012bc`에서 발생했고 예외 복귀가 URGENT의 `0x4020134c`로 진입했다. URGENT가 `0x40201388`에서 `SVC #1`을 실행하자 `0x402012bc`로 곧바로 복귀했다. |
| 정책을 구별한 입력 | 고정 우선순위는 LOW 3, URGENT 2로 LOW가 높고, LOW를 먼저 큐에 넣었다. 둘 다 실행 가능했다. 커널은 게스트 카운터에서 읽은 각 해제 시각에 LOW는 60초, URGENT는 1초를 더해 절대 기한을 만들고 URGENT 기한이 더 이른지 검사했다. EDF 선택기는 실제 준비 큐에 이 순서를 적용했다. |
| 관측기 대조 시험 | 호스트에서 변형한 출력 5개를 각각 거부했고 같은 내용의 CRLF 출력은 수락했다. 대조 시험은 기존 관측기를 재사용했다. |

동결한 `edf-bench` 릴리스 ELF의 SHA-256은 `1363c7fe8b0e354be13ce40a52eb2b07f2b7adc9e7da0efcbf664e1c619ac4f5`이다. QEMU 6.2.0, GICv2, TCG, 1코어, 128 MiB에서 한 번 실행했다. 원본 기록에는 명령, 관측기 종료 상태, UART, 예외 추적과 명령 주소가 있다. 개별 소스 파일 해시는 검증자가 사용한 Windows 체크아웃의 CRLF 바이트 기준이며, Git 원본은 커밋과 트리로 식별한다. [원본 검증 기록](evd-005.json)

게스트 종료 뒤 호스트 스케줄링 테스트 26개가 통과했다. 기본·스케줄러·FIFO·RR 구성, EDF와 FIFO 또는 RR을 조합한 구성도 차례대로 릴리스 모드 `cargo check --locked -j 1`을 통과했다. 단일 정책 빌드에서는 선택형 정책 경로의 미사용 코드 경고가 발생했다. 이번 회차에서 부팅한 구성은 단독 EDF다.

`CHG-006` · `POL-005` · `REQ-023`, `REQ-002`, `REQ-005` → `DES-012`, `DES-003` → `IMP-005` → `VER-023`, `VER-002`, `VER-005`. 게스트에서 기한의 순서와 상태 복원을 검사했다. 절대 기한과 레지스터 값의 수치 샘플은 출력하지 않았다. 과부하, 태스크 집합 수용 판정, SMP, 실보드 시간 측정과 제품 기능안전 승인은 후속 범위다.
