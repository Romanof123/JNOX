# EVD-106 · CPU별 디스패치 리스와 활성화별 TLS

CHG-106 / IMP-106 / POL-013 / [#278](../boards/pi4-migration-local-state.en-ko.md) / [#279](https://github.com/Romanof123/JNOX/pull/279) / [#47](https://github.com/Romanof123/JNOX/issues/47) / [#21](https://github.com/Romanof123/JNOX/issues/21)

고정한 #279 소스 ce8aebc에서 공개 MG3 판독기는 짧은 작업 첫 부팅 3/6회와 스트림 첫 부팅 6/6회를 인정했다. 짧은 작업의 전역 2번은 CPU1에서, 분할 1번과 클러스터 2번은 CPU0에서 재개했다.

#278 계획은 판정 부팅 전에 CPU별 디스패치 리스, 활성화별 TLS 객체 네 개와 MG3의 저장·복귀 상태 검사를 고정했다. 독립 검증에서는 12개 위치 모두에서 저장된 TLS와 복귀 후 실제 TLS, CPU 식별자가 붙은 IRQ·ERET 복귀 주소의 일치, 체크포인트까지 다시 계산한 값의 일치를 확인했다. 이 중 9개 위치가 엄격한 작업 기준을 충족했다. 나머지 짧은 작업 세 위치(전역 1번, 분할 2번, 클러스터 1번)도 실행을 재개했으나 루프 기준을 충족하지 못했다. 인터럽트 전에 종료한 위치는 없었다. 과거 자료를 별도로 재판독한 결과는 짧은 MG1 1/6회, 짧은 MG2 0/6회, CRC 스트림 6/6회였다. 일반 virt 대조 부팅은 SMP PASS를 출력했고 Pi SW1은 종료 기록에 도달했다.

짧은 작업의 미충족 세 위치 모두 목적지에서 M의 실제 체크포인트가 관측됐고 복귀 시 TLS와 PC가 저장값과 일치했다. 전역 1번의 복귀 주소 `0x801e4`는 `[0x82304,0x82328)` 밖이었고, 분할 2번의 `0x82368`은 `[0x82308,0x8232c)` 밖이었으며, 클러스터 1번의 `0x82088`은 `[0x823b4,0x823d8)` 밖이었다. 일반 virt 대조에서는 CPU0→CPU1 이주 후에도 작업 쿠키가 유지됐다. 공개 Pi SW1 판독기는 기존의 30초 상한과 1초 무출력 기준으로 CPU별 PC의 일치를 확인하고 종료 코드 0을 반환했다. 최초 고정 시간 SW1 기동 기록은 별도로 보존했다.
