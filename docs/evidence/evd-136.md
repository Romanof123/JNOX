# EVD-136 · 네이티브 스레드 우선순위와 뮤텍스 인계

CHG-136 / IMP-136 / POL-014 / [#335](../native-thread-priority-protocols.en-ko.md) / [#336](https://github.com/Romanof123/JNOX/pull/336)

`383f1d40b10798af89d5f3ddf44c456accb96b0b`

단일 Cortex-A72 QEMU virt에서 같은 C·Rust ELF의 우선순위 사례 12건과 기존 호환 대조군 3건이 최초 부팅에서 모두 0으로 종료됐다. 우선순위 사례는 행 손실 없이 최종 단계 3에 도달했다. RAM에서 작업별 블록 수·합·제곱합 및 조인 반환 주소를 확인했다. 외부 추적 9건의 EL0 복귀 PC 순서가 전부 일치했다. 역할은 저장된 SP·TLS·세대와 스케줄러 상태로 식별했다.

체인에서는 X를 기다리는 HIGH가 LOW와 BASE를 순위 4로 올려 준비된 MEDIUM보다 BASE가 먼저 계산 루프(0x400044)에 복귀했다. Y는 LOW에게, X는 HIGH에게 직접 인계됐다. 시간 만료 사례에서 BASE는 잠든 상태였고 HIGH가 ETIMEDOUT(110)을 받은 뒤에도 Y의 LOW 기부가 남아 두 상위 순위가 2가 됐다. 즉시 천장은 1→2→4→2→1을 보였다. 높은 순위 인계, 동순위 FIFO 양방향, 순환 거부(EDEADLK 35)를 확인했다.

RR에서 HIGH가 LOW를 선점한 뒤 LOW는 625,000틱 중 남은 380,969틱으로 재개했다. FIFO에서는 LOW가 종료한 뒤 동순위 MEDIUM이 실행됐다. 두 스레드 협력·RR 및 단일 스레드 대조군도 기존 결과를 유지했다. 잘못된 입력 9개를 패키저와 직접 빌드가 각각 거부했다(18건). 기부 변화만으로 RR 잔여 시간이 유지되는 경우, 실제 같은 틱의 경합, 세대 래핑, 예외 경로 전체는 이 게스트 부팅에서 관측되지 않았다. 제품별 천장 및 실물 M3 최대 차단 시간은 미결이다.

첫 호스트 패킷은 정책 4건과 준비 큐 3건을 통과했고 후속 전이 뒤 한 번만 읽히는 완료를 확인했다. 별도 9aef21d5 호스트 패킷에서는 9건을 통과했다. D=150에서 잠금 해제·디스패치 전에 ETIMEDOUT(110)이 한 번 전달됐다. D−1=149에서는 해제 직후 디스패치 전에 소유권과 성공 0이 인계됐다. 비소모 대조군은 D−1/D/D+1의 0/110/110을 후속 전이까지 보존했다. RR 소유자의 100틱에서 30틱 사용 후 기부 시 70틱, 다시 20틱 사용 후 철회 시 50틱이 남았다. 고정 호스트 카운터의 정책 관측이며 게스트의 동일 하드웨어 틱 경합이나 기부만으로 변하는 RR 잔여 시간을 추가 관측한 것은 아니다.
