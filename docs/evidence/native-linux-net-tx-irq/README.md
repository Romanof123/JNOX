# EVD-342 · Original Linux TX callback on native JNOX / 원본 드라이버 송신 완료

An independent reader verified the two IRQ boots and the polling control. For each IRQ boot it joined 80 accepted used entries to 80 executed entries in the original skb_xmit_done at 0x40b160, 80 calls to the subqueue-wake operation and 80 later releases of the corresponding cookies. All 80 replies (5,912 bytes per boot) matched the host and PCAP. The two boots had 127 and 137 complete SPI 79 transactions. In 34 and 24 TX receipt observations respectively the RX side was pending too. The ordinary control had 80 polling retirements and 81 shared IRQ transactions. Its trace filter excluded the callback PC, so this observation is based on its selected mode, polling path and cookie progression. Eleven deliberately altered inputs were rejected. 독립 검증팀은 두 부팅에서 각각 원본 송신 완료 함수 진입 80회, 송신 하위 큐 깨우기 80회, 해당 쿠키의 지연 회수 80회를 대조했다. 수신과 송신을 함께 알린 IRQ도 따로 집계했다. 실물 NIC 동작과 인터럽트 지연 상한은 별도 인수 대상이다.

Extract the raw ZIP and [independent reader companion](jnox456-independent-companion.zip) into the same new directory. The companion includes the separately written reader, original verdicts and eleven mutation cases. Its SHA-256 is `ead83a66ac540f2b4b678f7320c41a95a4e2702c36b6ab210a3953df997212e2`.

The opt-in AArch64 QEMU profile runs the registered original Linux virtio_net.c in a native JNOX service. Each of two cold boots used a different NIC configuration and exchanged 80 application replies with the external host. The capture-time reader traced 80 entries into the upstream skb_xmit_done per boot and matched TX used descriptors, the shared device interrupt, the owner’s receipt, subqueue wake and deferred cookie release. RX and TX share the interrupt line. The original polling profile also returned 80 replies. It used a different set of trace addresses. [Driver contract](../../native-linux-net-tx-completion.en-ko.md) · [Acceptance #456](https://github.com/Romanof123/JNOX/issues/456)

The [raw ZIP](jnox456-raw.zip) (2,563,893 bytes, SHA-256 `a66d911d10bc0b7c561b1a26e564917e94872c1d92520cd2f051cd3b907188c4`) retains PCAP, QEMU execution and device traces, captured memory ranges, the source object and linked native service/peer. It also preserves the initial invalid priority invocation and the first reader's failed large physical read. The corrected reader processes the same protected region in bounded extents. Its two opt-in replays each rejected six changes to the evidence. The ordinary replay rejected four. QEMU executable version and hash were collected after capture. The raw package contains the capture team's reader. [Offline instructions](REPLAY.md)
