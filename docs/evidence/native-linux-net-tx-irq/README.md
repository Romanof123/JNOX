# EVD-342 · Original Linux TX callback on native JNOX / 원본 드라이버 송신 완료

The opt-in AArch64 QEMU profile runs the registered original Linux virtio_net.c in a native JNOX service. Each of two cold boots used a different NIC configuration and exchanged 80 application replies with the external host. The capture-time reader traced 80 entries into the upstream skb_xmit_done per boot and matched TX used descriptors, the shared device interrupt, the owner’s receipt, subqueue wake and deferred cookie release. RX and TX share the interrupt line. The original polling profile also returned 80 replies. It used a different set of trace addresses. [Driver contract](../../native-linux-net-tx-completion.en-ko.md) · [Acceptance #456](https://github.com/Romanof123/JNOX/issues/456)

The [raw ZIP](jnox456-raw.zip) (2,563,893 bytes, SHA-256 `a66d911d10bc0b7c561b1a26e564917e94872c1d92520cd2f051cd3b907188c4`) retains PCAP, QEMU execution and device traces, captured memory ranges, the source object and linked native service/peer. It also preserves the initial invalid priority invocation and the first reader's failed large physical read. The corrected reader processes the same protected region in bounded extents. Its two opt-in replays each rejected six changes to the evidence. The ordinary replay rejected four. QEMU executable version and hash were collected after capture. The raw package contains the capture team's reader. Independent acceptance is tracked separately. [Offline instructions](REPLAY.md)

두 게스트는 서로 다른 네트워크 설정으로 부팅했다. 각 80회의 실제 외부 응답과 원본 C 송신 완료 함수 진입을 기록했다. 원본 콜백에서 하위 송신 큐를 깨우고 사용자 서비스가 나중에 반환된 버퍼를 회수한다. 하나의 공유 IRQ가 수신과 송신을 함께 알릴 수 있다. 원본 ELF, 네트워크 패킷, 인터럽트 및 선택 메모리의 측정 범위는 가상 보드에 한정된다.
