# EVD-112 · 네이티브 응용 프로그램의 단조 시계

CHG-112 / IMP-112 / [#286](https://github.com/Romanof123/JNOX/issues/286) / [#288](https://github.com/Romanof123/JNOX/pull/288)

최초 소스 `46a87fb7177e748963726f44f262525a51d865fd`의 C·Rust 예제는 모두 단조 시계를 두 번 읽고 체크섬을 검증한 뒤 종료값 0을 전달했다. 링크된 코드에서는 두 번째 읽기 뒤에 체크섬의 마지막 연산을 수행했으므로 최초 측정 구간은 계산의 일부만 포함한다. 별도 Rust Cargo 앱은 자체 시계 표본을 보존했고, 시계를 16회 읽은 별도 앱도 정상 종료했다. 기존 C 프로브의 종료값은 37, 쓰기 반환값은 −38(ENOSYS)이었다.

수정 소스 `7af3ca22b88c9ea9d81f4495b37613f241b67adc`는 두 예제에서 두 번째 시계 읽기 전에 완성된 체크섬을 저장한다. 두 버전은 같은 커널과 SDK를 사용한다.

수정 소스에서는 두 앱 모두 단일 코어 Cortex-A72 QEMU virt 최초 부팅에서 종료값 0을 전달했다. EL0 시계 호출 두 번 사이에 체크섬 계산과 저장을 마쳤다. C에서는 두 시각 (0초, 1,715,056나노초)과 (0초, 2,014,704나노초)가 RAM에 보존됐고 Adler-32 `0x11e60398`을 확인했다. Rust는 결과 버퍼를 재사용했다. 첫 나노초 값 1,716,736은 스택에 저장된 x20에서 읽었다. 첫 초 값 0은 SDK 범위 검사, 앱의 순서 검사 통과, 마지막 초 값 0으로부터 추론했다. 마지막 시각 (0초, 1,989,488나노초)과 FNV-1a 체크섬 `0x4f9f2cab`은 정지 RAM에서 직접 읽었다. 별도 16회 읽기 대조에서는 진단 저널이 8개 기록 한도에 도달한 뒤에도 정규화된 증가 시각 16개가 모두 보존됐다. 이 결과는 에뮬레이터에서 한 부팅 구간의 단조 시계를 읽는 일반 호출을 검증한다.
