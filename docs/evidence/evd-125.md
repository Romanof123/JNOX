# EVD-125 · 네이티브 작업 스레드 생성 및 조인

CHG-125 / IMP-125 / [#313](../native-joinable-threads.en-ko.md) / [#314](https://github.com/Romanof123/JNOX/pull/314)

`304667baa498d12f0c99774891f32a28ca287b0c`

최초 소스 304667b에서는 앱 ELF 두 개가 생성되고 호스트 검사 169개가 통과했다. C와 Rust의 커널 패키징은 타입 오류 E0308 세 건으로 실패해 해당 소스의 게스트 부팅은 0회였다.

수정 소스 `3d53da8b72a3f58e44e02d256af815fa3159adb9`에서는 호스트 검사 169개가 통과했다. 단일 Cortex-A72 QEMU virt CPU의 콜드 부팅 13회는 각 앱의 일반·외부 추적 실행 및 수명·오류·호환성 대조 9회로 구성됐다. C는 두 실행 모두 17로 종료했다. 두 공유 보정 배열의 256개 원소가 모두 일치했고 작업자 합은 32,896·33,152, 메인 합은 32,640이었다. 첫 조인은 메인을 차단했다. 작업자가 잠든 동안 유휴 CPU가 PPI 30을 수락했고 작업자는 기한 이후 깨어났다. 다음 작업자는 명시적으로 먼저 종료해 메인의 조인이 즉시 반환됐다. 세대별 핸들은 3·5였고 회수된 이전 핸들은 ESRCH로 거부됐다. Rust는 두 실행 모두 29로 종료하고 제곱값 256개 전체(합 5,559,680) 및 조인으로 받은 공유 결과 주소 0x402004를 확인했다.

프로세스 물리 메모리와 페이지 테이블에서 동일 TTBR 아래의 공유 배열, 서로 다른 가드 스택(초기 SP 0x1010fb0·0x1009000), TPIDRRO_EL0의 별도 errno 셀(0x1001000·0x1001004, 값 22·38)을 확인했다. 두 작업자 세대 모두 초기 errno는 0이었다. 외부 추적에서 C 28회·Rust 8회의 SVC 진입 및 대응하는 EL0 복귀가 일치했다. 추가 대조는 사용 중·미회수 슬롯, 자기 조인, 잘못된 래퍼 입력, 결과를 버리는 조인, 메인 스레드 종료, 전체 프로세스 종료 및 단일 스레드 호환성을 다뤘다.

검증 범위는 CPU0의 단일 협력형 프로세스다. EL0 실행 중 타이머, 전체 FP/SIMD/TLS 레지스터 표식, 첫 명령 시점의 스택 초기화, SMP, 실물 보드 타이밍 및 더 넓은 POSIX API는 이번 실행에서 검증하지 않았다.
