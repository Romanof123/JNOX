# EVD-045 v2 · 일반 Rust 비주기 서버 통합 재현

[English](evd-045-v2.en.md) · [EVD-045](evd-045.md) · [#101](https://github.com/Romanof123/JNOX/issues/101)

**통합 기본 클록 실행은 일반 스케줄 8개를 모두 완료했다.** 의도적으로 지연시킨 대조군 2개는 각각 1단위를 청구하고 완료 처리 없이 정지했다. 이전 단독 기본 클록 실행에서는 10개 이미지 모두 첫 IRQ에서 중재 전에 정지했다. 통합 재현에서 두 계열의 사례별 ELF와 QEMU 해시가 일치했다. 타이밍 차이의 원인은 미해결이다.

| 자료 | 클록 및 기록 위치 | 결과 |
|---|---|---|
| 단독 v1 | 기본 클록, WSL DrvFS에 UART·예외 기록 | 정상 완료 0/8. 지연 이미지 두 개도 청구 전 시작 단계에서 정지했다. |
| 통합 v2 | 기본 클록, Linux /tmp에 UART·예외 기록 | 정상 완료 8/8, 의도한 지연 차단 2/2. |
| 통합 v2 | 결정론적 명령 계수 | 정상 완료 8/8, 의도한 지연 차단 2/2. |

통합 정상 실행은 각각 IRQ 17회와 슬롯 2/6/10/14의 우선순위 높은 주기 작업 완료를 기록했다. 아래 서버 실행 순서는 통합 클록 두 모드에서 일치했다. A는 4단위, B는 6단위를 완료했다. 단위마다 256단계 작업과 완료 SVC를 확인하고 크레딧, 프레임 복귀와 실제 FIFO 요청을 재현했다.

| 서버 | A 슬롯 | B 슬롯 |
|---|---|---|
| 폴링 | 4,5,8,9 | 0,1,4,5,8,9 |
| 지연 가능 | 1,3,4,5 | 0,1,4,5,8,9 |
| 산발적, 크레딧 항목 2개 | 1,3,5,7 | 0,1,4,5,8,9 |
| 산발적, 크레딧 항목 1개 | 1,3,7,8 | 0,1,5,7,11,12 |

62.5 MHz에서 통합 기본 클록 정상 8건의 IRQ 지연 최댓값은 27,922틱(0.446752 ms), 상한은 62,500틱이었다. 복귀 표본까지 준비 구간 최댓값은 86,006틱(1.376096 ms), 상한은 312,500틱이었다. 두 모드 모두 지연 A/SS2에서 1단위, B/DS에서 4단위가 미완료 상태로 남았고 청구한 단위는 완료 처리되지 않았다.

통합 게이트는 이전 단독 기본 클록 10건을 포함해 원시 스트림 30개를 재현했다. 기존 검증기는 기본 클록 스트림이 모두 첫 IRQ에서 실패한다고 가정해 통합 기본 클록 10건을 거부했다. 새 재현은 실제 IRQ·중재·게스트 종료값으로 분기했으며 최초 판정 오류도 보존했다. 기록 저장 위치의 차이는 확인했으나 타이밍 변화의 원인은 확인하지 못했다.

#107/#108 결합 커널 트리는 `a097b300e0ffb2803b88e0fe02e5d88f0a2dec2b`다. AP 10개와 ML 12개의 PT_LOAD 구간·바이트와 .text는 각각 대응하는 단독 빌드와 일치했다. 유한 가상 실행만으로 향후 기본 클록 시간 보장, 제품 수용, 보드 WCET나 실제 M3 간섭을 입증할 수 없다. 45 ms 서비스 허용량은 여전히 근거가 필요한 예산이다.
