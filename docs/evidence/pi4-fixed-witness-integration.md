# Pi 4 통합 FIFO·RR 이미지 네 종의 첫 모델 부팅

[English](pi4-fixed-witness-integration.en.md) · [이미지별 해시와 수신 시간](pi4-fixed-witness-integration.json) · [전체 증거 ZIP](pi4-fixed-witness-integration.zip) · [시험 소스](https://github.com/Romanof123/JNOX/tree/aa691462c52bcad40a2b17077bd48e9ddfb9bd09)

이미지마다 raspi4b 모델을 한 번씩 콜드 부팅했다. 네 번 모두 호스트 수집 시작 후 30초 안에 예상 작업 마커를 수신했고 마지막 LF 뒤 1초 이상 추가 바이트가 없었다. 계측 FIFO는 **종료 코드 0(완전)**, 계측 RR은 **종료 코드 2(유효하나 동순위 작업 재개 증거 일부 미관측)**였다. 같은 통합 디코더로 과거 계측 FIFO·RR UART를 재생한 결과는 각각 0이었다. [기존 첫 수집](pi4-fixed-witness-first.md) · [기존 재생](pi4-fixed-witness-replay.md)

| 이미지 | UART 바이트 | 마지막 LF / 무수신 초 | 코어 0 IRQ / SVC / 선택된 EL1 ERET | 이후 실행 증거 |
|---|---:|---|---|---|
| 일반 FIFO | 175 | 0.666 / 1.011 | 2 / 7 / 10 | HIGH 종료 후 0x8127c로 복귀했고 producer 블록 0x814c8 실행 |
| 일반 RR | 124 | 0.600 / 1.010 | 3 / 3 / 7 | B 진입, 별도 복귀 이후 A의 0x813b0과 B의 0x81468 실행 |
| 계측 FIFO 63001 | 2152 | 0.616 / 1.010 | 2 / 7 / 10 | 세대 4에서 HIGH 선택. 세대 5에서 중단된 A 프레임 복원 후 작업 진척 확인 |
| 계측 RR 63002 | 1742 | 0.561 / 1.010 | 3 / 3 / 7 | HIGH 종료 뒤 세대 3에서 A의 진척 확인. 세대 4에서 B 진입 및 진척 확인. 세대 5(A)와 6(B)의 새 작업 표본은 없음 |

계측 디스패치의 진입 ELR과 선택한 ELR을 같은 부팅의 외부 예외·ERET 기록에 대조했다. 마지막 유휴 작업 복귀까지 일치했다. IAR 30은 게스트가 기록했고 QEMU가 코어 0의 IRQ와 벡터를 독립적으로 기록했다. 다른 코어의 예외는 관측되지 않았다. 일반 RR에서 HIGH 직후의 첫 복귀는 작업별 추적 범위 밖의 공용 루프에 있었다. 이후 실행 블록으로 A·B를 각각 확인했다. 물리 펌웨어 부팅, 실기 IRQ 위임, 명령 은퇴 시점, 지연 상한, WCET 및 안전 승인은 미확인이다.

## 빌드와 이미지 비교

초기 계획에는 네이티브 ext4 빌드가 명시돼 있었다. 실제 비교 빌드는 고정 Windows Rust 1.95.0 도구 체인으로 동일 소스·타깃 경로에서 매번 타깃을 비우고 수행했다. 네 번의 원본 수집과 패키지 구성은 사용자 소유의 영구 ext4에서 이뤄졌고 다음 부팅 전에 별도 저장소 복사본을 해시로 대조했다. 고정 펌웨어와 설정을 사용했고 QEMU는 패키지의 원시 커널을 직접 적재했다.

일반 main fb7d942와 비교했을 때 두 정책의 .text, 쓰기 가능 PT_LOAD, 세그먼트 배치는 같았다. 각 16672바이트 원시 이미지에서 실행 가능 PT_LOAD의 .rodata 두 바이트가 달랐다. fixed_runtime.rs의 배열 경계 검사 위치에 대응하는 소스 행 번호가 195→210, 181→189로 바뀌었다. 원시 오프셋은 FIFO 0x3800/0x3818, RR 0x3740/0x3758이다. 전체 ELF에는 컴파일러가 생성한 심볼 문자열 차이도 있었다. 일반 이미지에서 계측 버퍼·내보내기 심볼은 검출되지 않았다. 승인된 c388505 소스와 같은 ID(63001/63002)로 비교하면 네 이미지 모두 .text, 양쪽 PT_LOAD 및 원시 이미지가 같다. 전체 ELF 해시는 다르다. 계측 원시 이미지는 두 정책 모두 20768바이트였고 쓰기 가능 세그먼트의 메모리 크기는 19568바이트 증가했다. 일반 UART에는 계측 전후 서비스 시간을 비교할 공통 카운터 끝점이 없다.

## 증거 복원

ZIP에서 restore.py를 꺼내 아래와 같이 새 디렉터리에 복원한다. index.json에는 경로별 SHA-256과 크기가 있다. UART, ELF, 펌웨어 파일 및 전체 예외·실행 블록은 원본 바이트를 담았다. 비공개 호스트 경로를 치환한 기록에는 원본 해시도 실었다. provenance/에는 사전 고정 절차와 실제 빌드 경로 차이가 있다. first/verified.json의 값은 원본 기준이다.

```sh
python3 restore.py pi4-fixed-witness-integration.zip restored
```

integrated/ 아래 각 이미지의 first/에는 UART, 읽기 시각, 실행 인자, 예외 로그, ELF와 패키지가 있다. 계측 결과는 external-ledger.json, score.txt 및 mutations/에, 일반 실행 대조표는 ordinary-ledger.json에 있다. main/과 approved/에는 비교용 빌드 기록이 있다. archive-engineering/, third/, controls-second/에 재생 및 대조 시험을 담았다. second/는 기존 출력 디렉터리 재사용 시험에서 로컬 표준 오류 문자 디코딩 문제로 끊긴 첫 시도를 보존한다. third/에서 완료했다. 잘못된 계측 선택 12건은 모두 거부됐고, 별도 선택 조합 7건의 결과는 main과 같았다. 호스트 수집기 시간 조건 566건, 관측기 API 8건, 모의 포트 4건, 저장소 테스트 7건을 확인했다. 대체 부팅과 실기 부팅은 수행하지 않았다. CHG-073은 별도의 후속 작업이다.
