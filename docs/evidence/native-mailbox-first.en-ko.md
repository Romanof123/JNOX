# IPC-002 independent replay on QEMU virt

Frozen local commit `1f9a56354e5b8fa04251fc5101e28ec0d83dad85` has tree `b50b4ce3969715a3229924011f976ef5fee794eb`. All 12 retained cold boots passed on one Cortex-A72 vCPU under QEMU 6.2.0. FIFO and RR each produced the outcomes below. The UART journal reported zero dropped decisions in every completed case.

| Native test | PID 0 / PID 1 | Observed result |
| --- | --- | --- |
| Supplied C sender and Rust receiver | 51 / 52 | Four slots committed. Immediate overflow returned −11. The timed fifth send blocked, woke with −110, and never appeared. A subsequent indefinite send was promoted by the first dequeue. Sender exited before the remaining drain. Owner terminal occupancy 0, peak 4. |
| Independent original four-only acceptance | 71 / 72 | The sender submitted no replacement after timing out. Only the four committed words arrived, including zero and the maximum u64. The next read returned −11. Both owner reports showed terminal 0, peak 4. |
| Mixed families, opposite directed routes | 61 / 62 | The waiting PID 1 received a copied word directly, with peak 0. In the same package PID 1 made a synchronous call to PID 0 and received 42. Each unauthorized reverse direction returned −13. |
| Owner exits while full | 73 / 74 | Pending indefinite sender resumed with −32 and the next send returned −32. Owner terminal 0, peak 4. |
| Sync-only package without mailbox grant | 75 / 75 | Both mailbox operations returned −38 for both processes. |
| Supplied synchronous C/Rust regression | 41 / 42 | Private RAM held reply 0x000404010101082e and reply attempt statuses −116, 0, −116. |

The C/Rust mailbox pair produced identical terminal words under both schedulers. Private memory contained send statuses `[0,0,0,0,-11,-110,0]`, readings `[300,512,257,1025,88]` with sequence numbers 1–5, sum 2182, and empty status −11. The absolute deadline and resumed time were 103602864 / 104222128 ns under FIFO and 103640720 / 104159040 ns under RR. Terminal RAM was decoded through three levels of the captured translation tables for each process. The UART independently records the timed sender relinquishing the CPU, the timeout interrupt waking it, the indefinite sender blocking and the receiver returning the CPU to that sender. The promotion and exit order are observable in both schedulers.

The independent three-process host driver exercised release one tick before, at, and after both send and receive deadlines, FIFO promotion of two waiting senders, a second submission by an already pending sender, sender death with committed and uncommitted words, owner exit against a deadline, and single-consumption completions. Three repository host tests also passed. Exact equality, forced death of a blocked sender and multiple pending senders have host evidence. The guests cover ordinary process exit, real scheduler wakeups and protected process memory on QEMU virt. Physical hardware, product timing and safety acceptance were outside this replay.

**Retained and preliminary runs.** The first two exploratory C/Rust mailbox boots used a WSL temporary checkout, exited 51/52 and printed terminal 0/4 in both policies. Their temporary raw files expired. The C hash was `d894baed68f543ba9d6ebe5e21d0202db09f2bc5390e80c3eb80713b8bf928bb`; the temporary Rust ELF hash was `7363e14175d91c62f465a24854cc650a89bebd5e100b6e6e0004296f99d5df65`. Rebuilding in the persistent home directory produced the same C hash and Rust hash `ee70e4d641d1b7cf5b2fc6278584a5a297f9ca88d49ebf99e4abfcd46ebec564`. These latter boots have complete raw captures and supply the mailbox results above. The separate initial four-only FIFO harness requested relative sleep. Its receiver returned 83 and its pending sender returned 84 after owner exit. The raw capture is retained as `failed-relative-sleep-fifo`. Using CLOCK_MONOTONIC with TIMER_ABSTIME yielded the reported 71/72 on both policies. The 12 retained passes exclude the preliminary boots and the harness failure.

**재현 결과.** 일반 C/Rust 메일박스 앱은 FIFO·RR 모두 51/52로 종료했고, 실제 큐의 최대 점유량은 4, 종료 후 점유량은 0이었다. 기한 만료로 거절된 단어는 수신되지 않았다. 별도 네 단어 전용 앱은 원래 단어 네 개만 순서대로 받고 71/72로 종료했다. 동기·메일박스 혼합과 방향 권한, 소유자 종료 및 정리, 권한 없는 프로파일, 기존 동기 C/Rust 회귀도 양쪽 가상 부팅에서 확인했다. 정확한 기한 전·동시·후 경계 및 대기 송신자 강제 종료는 호스트 모델에서 확인했다. 예비 실행의 임시 원본은 보존되지 않았으며, 별도 수집한 12회 부팅 원본과 초기 상대 수면 방식 오류의 원본을 패킷에 보존했다.

## Replay

From the unpacked archive use `python3 check.py raw` with GNU `aarch64-linux-gnu-nm` on PATH to recheck all 12 retained guests and walk their memory dumps. The run-time source is available publicly at [ced837c6](https://github.com/Romanof123/JNOX/tree/ced837c6349a62cee081bf537b0d5a347a86995f). The complete kernel, tools, SDK, mailbox example and the synchronous client and Rust server have identical Git object IDs on both revisions, listed in `input-trees.txt`. The public revision adds two synchronous test-case files and documentation. The 72 KiB `local-source.pack` supplies the local commit objects for reproducing the exact tested tree on top of the public repository.

For fresh guest runs, set `JNOX_VERIFY_WORK` to a new checkout directory and `JNOX_VERIFY_OUT` to a new output directory, then run `bash guest_runs.sh` followed by `python3 check.py "$JNOX_VERIFY_OUT"`. The script uses Git, Rust 1.95.0 with the two bare-metal AArch64 targets, clang/LLD 14, Python 3, GNU AArch64 binutils and QEMU 6.2. A local repository containing the public revision may be supplied with `JNOX_VERIFY_GIT`. For host replay, copy `host.rs` and the frozen `kernel/src/mailbox_ipc.rs` into an empty directory, then run `rustc --edition=2024 host.rs -o host && ./host`.
