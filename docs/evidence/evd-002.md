# EVD-002 · 타이머에 의한 스레드 선점

한국어 · [English](evd-002.en.md)

2026-11-24에 새 검증 에이전트가 후보 `d9a1ac81b9bd871c504b823b983b1ff31109862a`를 시험했다. PM이 한 작업 슬롯으로 빌드한 ELF의 SHA-256은 `4d542ef3f7f8eaeb606707714bbb8af6abe9847a01b7421ad874ec62998e7d48`다. 검증자는 QEMU 한 대에서 UART와 CPU 예외 기록을 함께 수집하고 UART 판정을 먼저 고정한 뒤 예외 주소를 후보 ELF의 심볼과 대조했다. [벤치 계약](../m1-scheduler.md) · [소스 후보](https://github.com/Romanof123/JNOX/commit/d9a1ac81b9bd871c504b823b983b1ff31109862a)

| 관찰 지점 | 같은 부팅에서 관찰한 동작 |
| --- | --- |
| LOW 선점 | 낮은 우선순위 스레드가 자발적으로 양보하지 않는 루프에 있는 동안 IRQ가 발생했다. QEMU가 저장한 복귀 주소는 `0x402012bc`다. 커널은 GIC에서 타이머 인터럽트 30번과 타이머의 활성 상태를 확인해야 다음 단계로 진행한다. |
| HIGH 실행 | 두 스레드가 모두 실행 가능한 상태에서 고정 우선순위가 높은 HIGH를 선택했다. 예외 복귀 주소는 HIGH의 진입점 `0x4020134c`다. HIGH는 별도 스택에서 실행하고 `SVC #1`으로 완료를 알렸다. |
| LOW 복귀 | 마지막 예외 복귀 주소는 처음 LOW가 중단된 `0x402012bc`와 일치했다. LOW는 스택 값, 범용 레지스터, SIMD 및 프로세서 상태를 확인한 뒤 `SCHED PASS`를 출력했다. 전체 UART는 7줄, 101바이트다. |

QEMU는 예외 종류와 복귀 주소를 독립적으로 기록했다. 스택·레지스터 값과 타이머 번호는 커널 자체 검사가 판정하며, 검증팀이 해당 명령을 실행 파일에서 대조했다. 호스트에서 기존 부팅 기록, 복귀 줄 누락, 순서 오류 등을 판정기에 재생해 일곱 실패 사례를 모두 거부하는지 확인했다. 이번 실행은 스케줄러 프로파일 한 번이며, 기본 부팅 프로파일은 기존 기록으로 판정기를 확인했다.

`CHG-002` → `REQ-002`, `REQ-005` → `DES-003` → `IMP-002` → `VER-002`, `VER-005`. 이 기록은 에뮬레이터 한 코어에서 스레드 두 개가 보인 한 차례의 선점과 복귀를 입증한다. 실보드의 IRQ 지연 상한, SMP 동작 및 제품 안전 판정은 별도의 근거가 필요하다. [검증 원자료](evd-002.json) · [추적표](../../trace/links.csv)
