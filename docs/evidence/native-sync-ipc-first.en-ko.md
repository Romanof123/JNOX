# #365 native register IPC first verification / 첫 독립 검증

**Twelve fresh single-core QEMU boots passed their first expected outcomes** with the frozen kernel from `6f51e0b138c9dd613a18cddc53495673c7f71c1b`, tree `98151378f61d5a17cb058d509262ad8e9a918f5a`. Each clean package records the commit, CLI, slot arguments and input digests. QEMU 6.2 used stock Ubuntu WSL tools, Cortex-A72, virt GICv2, TCG, one CPU and 128 MiB. The independent plan in `freeze.txt` drew its expected IPC outcomes from issue #365 and the IPC-001 acceptance case at `04d699c8a445fc837a423c96ba35825810550c4b`. No guest or package retry was needed. Every UART terminates with zero dropped fixed decisions and all expected per-slot exits.

Each nested guest reached two simultaneous outstanding calls, established from its nested blocked callers and completed replies. The official two-process guests and single-hop controls reached one. Two and three slot endpoint pools occupied 176 and 256 linked bytes. For every enabled guest, terminal RAM showed every endpoint retired with zero outstanding requests, blocked receives and pending completions. The final scheduler row showed no runnable slot. The check used the linked address of the endpoint pool and target-specific layout verified in `layout-flags.txt`. Each private application report was read via the captured ARM64 page tables.

Compared with the same two ELFs and FIFO configuration without any route, enabling 0→1 added 5740 bytes of .text, 799 bytes of .rodata and 176 bytes of .data. Both .bss and .stack had identical sizes. Alignment increased the captured linked RAM extent by 4096 bytes. Source and raw numbers appear in `size-comparison.txt`. Twelve boots provide observed behavior and timing of these named configurations. Physical board, cross-core, WCET, full-family acceptance and formal release approval remain open.

Three checked-in endpoint-model tests passed. The separately authored host executable in `controls/controls.rs` ran twelve scenarios covering two-waiter FIFO with both arrival orders, queued expiry, reply at equality, server death before/at/after expiry, caller retirement and slot reuse around expiry, rejection of earlier tokens, single completion, inherited and restored priorities and empty queues. Exact-time collisions and caller death/slot restart are host observations. The guest death fixtures used ordinary server EXIT. `controls/operational.c` comes from external fixture commit `2f7b8b2e8fdaf38e17e8a403c812496ddea646c8`, Git blob `5048ebadc64d7e64bccf63bc3e1f279f364e3ca4`. The mixed-language three-slot probes in `independent/` and the host controls were separately authored by the verifier.

단일 코어 QEMU에서 열두 번의 최초 부팅을 확인했다. 동일 C/Rust ELF를 사용한 FIFO·RR 모두에서 파라미터, 응답과 토큰 상태값을 각 프로세스의 RAM에서 직접 읽었다. 세 우선순위 기증 시험은 매체 우선순위 작업이 대기 중일 때 서버가 먼저 실행되고, 응답 후에는 매체 우선순위 작업이 서버보다 먼저 실행되는 순서를 기록했다. 모든 활성 IPC 게스트의 종료 RAM에서 미완료 요청·수신 대기·전달할 완료 건수는 각각 0이었다. 동시 시각 경계와 호출자 종료·슬롯 재사용은 호스트에서 검증했다. 물리 보드 지연 및 제품 출시 승인은 이 결과의 범위 밖이다.

## Offline replay

Extract the archive, run `sha256sum -c evidence-files.sha256` and run `python3 report.py .` with standard Python and `aarch64-linux-gnu-nm` available. The JSON must match `results.json`. All twelve UARTs, RAM dumps, launch records, clean manifests, app and kernel ELFs, source fixtures, build/capture logs, tool command lines and first-observation status records are included. Archive excludes compiler target caches and host executables which can be rebuilt from the retained fixture source.
