# IPC-005 release decision · 공유 페이지 대여 출시 판정

**Independent Release approves CPU-only buffer loans between ordinary AArch64 processes on single-core QEMU virt under FIFO and round robin.** One directed pair among two or three configured processes shares three 4 KiB pages through a two-entry single-producer/single-consumer ring. The third process has no loan rights. The frozen kernel candidate was `66d988a0772fac3fd305b83bb123c5d966ea5f23`, tree `e921bdda13ce358b7adb6386f4a1e0fff4b56e72`. The original IPC-005 criteria and the selected deployment contract were reviewed at `df5260d7048f04dd38ae9499b07b10578826d05b`. [IPC tracker](https://github.com/Romanof123/JNOX/issues/24) · [CHG-306](https://github.com/Romanof123/JNOX/issues/374)

**독립 Release는 단일 코어 AArch64 QEMU virt의 FIFO·RR에서 CPU 전용 버퍼 대여를 승인한다.** 일반 프로세스 2~3개 중 지정한 생산자·소비자 한 쌍에 4 KiB 페이지 3장과 게시 슬롯 2개를 허용한다. 세 번째 프로세스가 네 가지 대여 연산을 호출하면 모두 접근 거부가 반환됐다.

## Evidence and observed ownership / 검증 자료와 소유권 관측

Release extracted the first packet anew, verified every listed SHA-256, and reproduced the original result JSON byte for byte. An independently written Release reader matched each package's kernel, slot ELF hashes and boot UART. It walked all reachable tables in all ten enabled terminal RAM images and all ten intermediate snapshots. For two-slot images each walk visited 18 distinct table pages and for three-slot images it visited 25. None appeared as an EL0-accessible page. The eleventh, disabled guest returned −38 for each selector in each process. All boots used QEMU TCG 6.2 with one Cortex-A72 CPU. [First verification report](native-loan-ipc-first.en-ko.md) · [First packet](native-loan-ipc-first.tar.gz)

| Check / 확인 | Result / 결과 |
| --- | --- |
| Actual payload and mappings / 페이로드·매핑 | Five live checkpoints per policy followed PA `0x40221000` at VA `0x01600000`. The sole EL0 alias changed from writer RW to unmapped to reader RO to unmapped to fresh writer RW. The original 4,096-byte pattern became a 113-byte message with 3,983 zero tail bytes. Regrant yielded 4,096 zero bytes. Every observed user alias had non-global, PXN and UXN attributes. |
| Publication and reuse / 게시·재사용 | C wrote eight messages and Rust checked every byte of each page. Private arrays agreed on handles, addresses, lengths and sums. Both policies hit full three times, retried with the same writer, reached depth two and ended at head/tail 8/8, zero occupancy and all three pages free. A stale return at a recycled VA received −116. The supplied apps exited 73 and 74. |
| Rights, limits and teardown / 권한·한계·정리 | Additional guests exercised fourth acquire, oversized publish, unchanged contents after refusal, 0- and 4,096-byte messages, reversed route and third-process denials. Exiting with a writer preserved committed data and the survivor's read mapping. Exiting with a reader revoked outstanding reader and writer access and retired the queued item. Host tests invoked teardown directly, including retry after a failed mapping callback and duplicate teardown. |
| Ordering and bounds / 순서·상한 | Ownership changes run with IRQs masked on the single CPU. The kernel validates available capacity before revoking RW. Actual kernels contained the descriptor store, DSB ISHST, ASID/VA TLBI VAE1IS, DSB ISH and ISB sequence. Tail clearing precedes release publication of the handle. The consumer acquires publication before mapping RO and releases ring capacity after dequeue. Host controls tested five counter origins, crossed unsigned 64-bit wrap from three of them, and refused allocation after the final handle generation. |

The generic scheduler journal retained its first 128 records and dropped 2,828 subsequent events in the supplied FIFO guest and 2,611 in RR while the reader polled. The dedicated loan journal retained 34 of 34 mapping transitions in each. All ten enabled boots together retained 148 loan transitions with zero loss. The other nine boots had no scheduler drops. Raw virtual counter values are preserved in UART. The guest teardown cases used ordinary process exits with live loans. Direct forced lifecycle calls and integer rollover were exercised on the host. Guest signal delivery or recovery from an unexpected process fault was outside the measured deployment. Physical cross-core visibility, DMA completion and cache maintenance, WCET and product safety require separate evidence.

첫 자료의 해시 전체와 결과 JSON을 독립 재검산했다. 두 정책에서 같은 물리 페이지의 쓰기 전용 소유자, 게시 후 매핑 철회, 소비자 읽기 전용 매핑, 반납 후 철회, 새 쓰기 대여 시 전체 초기화를 확인했다. 공식 앱은 정책별 여덟 메시지를 순서대로 처리했고 재게시·세대 거부·종료 회수 후 남은 대여는 0이었다. 공식 FIFO·RR 일반 스케줄러 기록은 각각 2,828건·2,611건이 넘쳤다. 전용 매핑 기록은 두 실행에서 각각 34건 모두 보존됐다. 나머지 아홉 부팅의 스케줄러 기록 누락은 0이었다. 게스트는 대여를 보유한 일반 프로세스의 종료를, 호스트는 강제 수명 종료 호출과 64비트 경계 순환을 검증했다. 실물 코어 간 가시성, DMA 완료·캐시 정합성, 물리 시간·기능안전은 별도 범위다.

## Resource accounting and reproduction / 자원 계측과 재현

All three backing pages consume 12,288 bytes. Each configured process reserves one 4 KiB loan page table. In the official two-process kernel, the channel object used 168 initialized bytes and the fixed transition array used 8,192 BSS bytes. Enqueue and dequeue transfer one handle and never copy the payload between processes. A grant zeros at most one page. Teardown scans three pool slots and retires at most two queue entries. These operations are nonblocking and do not enqueue a waiting endpoint.

Release built a matched FIFO control using identical official C and Rust binaries, arguments, priorities, compiler and candidate, with the loan route omitted. GNU text/data/BSS were 64,917/1,920/8,699,904 bytes disabled and 72,360/2,088/8,732,672 enabled. The increases were **7,443 bytes text, 168 bytes initialized data and 32,768 bytes BSS**. The writable LOAD memory reservation grew by 32,768 bytes and the complete ELF file by 15,512 bytes. The matched control was built for footprint only. [Release checker, matched binaries and manifests](native-loan-ipc-release-supplement.tar.gz)

같은 두 앱 바이너리·인자·우선순위·도구로 FIFO 커널을 링크해 대여 경로 유무에 따른 차이를 측정했다. text·data·BSS는 각각 7,443·168·32,768바이트, 전체 ELF 파일은 15,512바이트 증가했다. 이 대조 빌드는 메모리·이미지 크기 측정에 사용했다.
