# EVD-018 · 우선순위 상속, 대기 만료와 중첩 천장

[English](evd-018.en.md) · [합격 기준](../m1-mutex.md) · [변경 이슈 #49](https://github.com/Romanof123/JNOX/issues/49)

독립 검증자는 Cortex-A72 가상 CPU 한 개의 첫 부팅에서 스케줄링 결정 34회를 재구성했다. HIGH가 차단되자 LOW가 우선순위 9를 상속받아 MEDIUM보다 먼저 실행됐다. LOW가 잠금을 풀자 HIGH로 소유권이 넘어갔고 LOW는 기본 우선순위로 돌아갔다. 이 사례에서 결정 8회를 확인했다.

연쇄 사례의 결정 14회에서는 HIGH의 우선순위가 LOW를 거쳐 BASE로 전달됐다. 실제 범용 타이머 IRQ가 BASE의 `0x402012fc` 명령을 중단하고 HIGH의 대기를 만료시켰다. 다음 선택 전에 두 소유자의 우선순위가 9에서 2로 내려갔다. HIGH가 저장된 획득 호출로 복귀한 뒤 종료하자 MEDIUM이 실행됐다. 즉시 천장 사례의 결정 12회에서는 LOW가 두 잠금을 획득하며 5와 9로 올라갔고 역순으로 해제하면서 5와 2로 돌아갔다.

모든 예외 진입·복귀 주소가 재구성한 문맥과 일치했다. QMP로 읽은 기록에서 문맥 주소·우선순위·대기자·소유자를 확인했다. 복귀 후 작업의 분기 경로로 획득 성공과 시간 초과를 구분했다. QEMU 예외 원본에서는 명령 주소와 예외 종류를 대조했다. [독립 판정·UART·문맥·예외 원본](evd-018.json)

독립 상속 기준으로 대조한 구성 3,456가지를 포함해 Rust 호스트 시험 70개가 통과했다. Python 응답시간 분석 시험 8개, 순차 게스트 회귀 8회도 통과했다. 뮤텍스 빌드에서는 공용 준비 큐 메서드 하나가 쓰이지 않는다는 경고가 발생했다. [통합 기록](evd-018-regressions.json)

2026-11-24에 Rust 1.95.0, QEMU 6.2.0 virt, GICv2 및 RAM 128 MiB에서 검증했다. ELF SHA-256 `6ee5cbfa1b706c3ef689e7a6ef3de5b6b00cfb79aaf2cc3945764a87ffd3e462`. 실물 간섭 아래의 최대 차단 시간과 제품 합격 기준은 별도 추적한다.
