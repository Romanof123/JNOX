# EVD-105 · 단일 PI 뮤텍스에서 같은 우선순위 대기자의 FIFO 양도

CHG-105 · IMP-105 · POL-014 · [#275](https://github.com/Romanof123/JNOX/issues/275) · [#277](https://github.com/Romanof123/JNOX/pull/277).

기본 우선순위 2인 작업 0이 X를 소유한다. 같은 ELF의 두 구간에서 우선순위 7인 작업 1과 2가 서로 반대 순서로 X 획득을 시도한다. 공용 락 해제 경로가 양도 대상을 선택한다. 각 작업은 저장된 획득 호출에서 복귀한 뒤 보호 값에 자기 숫자를 붙인다. 사전 판정 기준의 값은 각각 4→41→412와 4→42→421이다.

[6f2f903](https://github.com/Romanof123/JNOX/blob/6f2f903623031fee8d81a4413569a8dd74ca0bd4/kernel/src/ordinary_mutex_fifo.rs) · [#275](../ordinary-mutex-fifo-plan.en-ko.md)

QEMU virt 최초 일반·추적 부팅에서 각각 두 구간을 모두 통과했다(4/4). 부팅마다 저널 30건과 프레임 복귀 30건을 기록했다. 독립 재생으로 차단 프레임, 소유자의 우선순위 상속과 복원, 도착순 양도, 획득 호출 복귀와 보호 값 4→41→412 및 4→42→421을 대조했다. 추적 부팅의 순서 있는 ERET 목적지 30건과 SVC 예외 링크 주소 28건을 고정한 명령 및 기록한 프레임과 대조했다.

검사기는 각 부팅 기록에서 역순 구간의 고정 ID 양도, 양도 전 획득 프레임 복귀, 최종값만 맞는 중간값 변조를 모두 거부했다. 기존 판정기로 일반 PI·추적 PI·일반 천장·추적 천장 대조가 각각 통과했다(4/4). 고정 ID의 역순 도착을 포함한 호스트 뮤텍스 시험 8건이 통과했다. 빌드는 Pi 4의 FIFO 선택과 알 수 없는 뮤텍스 앱을 거부했다.

관측 범위는 에뮬레이터 CPU 하나에서의 PI 락 하나다. #236의 시간 만료 연쇄 작업, 실보드 최대 차단 시간, 제품 천장과 중첩 한도, 정책군 출시는 별도 검증 대상으로 남는다.

최초 독립 호스트 검사기는 구간마다 저널 순번이 다시 시작한다고 가정했다. 검증자는 두 구간에 걸쳐 이어지는 J1–J30 순번을 따르도록 검사기를 수정하고 변경 없이 보존한 최초 캡처를 재생했다. 판정에는 처음 실행한 게스트 두 건을 그대로 사용했다. 통합 사전 빌드 ELF와 최초 게스트 ELF의 섹션 중 차이가 난 곳은 심볼·문자열 테이블뿐이었다. PM이 PT_LOAD 항목 두 개를 각각 전체 대조한 결과 주소·배치·권한·바이트가 일치했다. .text, .rodata, .data 섹션도 일치했다. [통합 빌드](ordinary-mutex-fifo-preflight.en-ko.md)
