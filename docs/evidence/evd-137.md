# EVD-137 · 네이티브 앱 추첨과 스트라이드 배정

CHG-137 / IMP-137 / POL-010 / [#337](../native-proportional-applications.en-ko.md) / [#338](https://github.com/Romanof123/JNOX/pull/338)

`f107b60fc1cb5bc83767ee98299d7042a3103b7a`

기본 62.5 MHz 단일 Cortex-A72 QEMU virt/GICv2에서 최초 부팅 7건을 보존했다. 정책 6건은 최종 종료까지 저널 손실이 없었고 기본 CRC 대조는 237로 종료했다. 시드별 48회 전체 배정의 24회 연속 창 25개가 모두 기준을 충족했다. 시드 1의 배정 합계는 11/14/23, 창 최솟값은 5/3/11이었다. 시드 2는 합계 8/17/23, 최솟값 1/7/10이었다. 안정 stride는 접두 48개가 모두 기준을 만족했고 최대 정규화 차이는 634,686틱(M=634,686)이었다. 최초 48회의 슬롯별 서비스는 4,412,618/8,809,860/16,996,099틱이었다.

사설 RAM에서 CRC는 134,217,728바이트와 CRC32 2,124,873,618(종료 237), 히스토그램은 536,870,912바이트와 9개 빈(종료 70), 에너지는 1,073,741,824개 표본과 합 5,864,240,971,776(종료 179)을 확인했다. 보고 앱은 3회 각 256개, 최종 768개로 종료 53이었다. 동적 두 구성 모두 세 번의 40 ms 수면 동안 실제 CRC 실행 PC·양의 서비스와 최종 결과를 확인했다. 각 기상 시점의 중간 RAM 카운터는 수집하지 않았다. 슬롯별 SP/PSTATE는 저장 프레임, 외부 EL0 복귀 PC는 QEMU 기록에서 확인했다.

공개 패키저와 직접 빌드는 모두 [24,48) 창에서 A가 6회 요구에 5회만 배정되는 설정을 거부했다(종료 2/101, 실행 파일 없음). 호스트 대조 11/11 통과. 최초 오프라인 판독은 pyelftools 부재로 실패했고, 별도의 셸 인용 오류는 잘못된 경로를 선택했다. 설치된 의존성으로 최초 기록을 그대로 판독했다. #54·#79·#200·#235의 원래 범위와 판정을 유지하며 #79 실패 분기·피연산자는 미확인이다. 외부 제품 위험 수용 및 실물 시간 보장은 별도 대상이다.

별도 진단 게스트 한 건에서 슬롯 0의 실제 yield에 의도적으로 다른 호출자 1을 전달했다. 거부 지점 17/10, 실제 SVC·ELR·정지 PC와 RAM을 보존했다. 최초 판독은 실패했다. 수정한 오프라인 판독기는 같은 세션(0ca98021)을 재생해 두 848바이트 프레임의 전체 일치를 확인하고 트레일러·해시 변경을 각각 거부했다. 추가 부팅은 없었다. 운영 패키지 일곱 쌍의 PT_LOAD가 모두 일치했다. 이 대조는 #79의 원인이나 실물 보드·운영 위험 수용을 판정하지 않는다.
