# EVD-090 · 최소 AArch64 virt 정적 점유량 1차 검증

지정된 최소 ELF는 REQ-009의 두 엔지니어링 한도를 모두 충족했다. 1차 검증에서 판정기의 배치 처리 두 건은 수정이 필요했다. 이 기록은 #4 및 #21의 VER-009 정적 검증 부분과 소스 `34454f955a30b0d3be0a4dfc73435a344f2dbff9`에 적용한다. [English](evd-090-virt-static-first.en.md) · [소스 PR #185](https://github.com/Romanof123/JNOX/pull/185) · [CHG-090 계획](https://github.com/Romanof123/JNOX/blob/a37f339/docs/scheduling-footprint.md)

| 바이트 | 최소 부트 | 일반 고정 우선순위 RR | RR − 최소 |
|---|---:|---:|---:|
| 코드·상수, RX 전체 | 275 | 14,728 | +14,453 |
| RX 시작부터 RW 끝까지 RAM 예약량 | 20,496 | 115,056 | +94,560 |
| RX와 RW 사이 공백 | 3,821 | 1,656 | −2,165 |
| RW 예약량 | 16,400 | 98,672 | +82,272 |
| PT_LOAD에 적재되는 파일 바이트 | 275 | 15,016 | +14,741 |
| ELF 파일 전체 | 71,128 | 94,096 | +22,968 |

두 ELF 모두 RX는 `0x40200000`에서 시작한다. 최소 구성의 RW는 `[0x40201000, 0x40205010)`이며 RAM 예약량은 275 + 3,821 + 16,400 = 20,496 B다. 일반 RR의 RW는 `[0x40204000, 0x4021c170)`이고 예약량은 14,728 + 1,656 + 98,672 = 115,056 B다. 양쪽 모두 RX 내부 패딩 0 B, RW 내부 패딩 8 B이며 부트 스택 16,384 B는 RW에 포함된다. 일반 RR 태스크 스택 81,920 B는 해당 BSS 81,992 B에 포함된다. 최소 구성은 코드 261,869 B, RAM 2,076,656 B의 여유가 있다. 일반 RR에는 별도 한도가 없다.

변경 없는 소스의 `kernel/`에서 `cargo +1.95.0 build --target aarch64-unknown-none --release --locked -j1`로 두 구성을 하나씩 빌드했다. 빌드 산출물 디렉터리는 구분했다. 공통 선택자는 `JNOX_ARCH=aarch64 JNOX_BOARD=virt`이며 일반 RR에만 `JNOX_PROFILE=fixed JNOX_APP=fixed-rr`를 추가했다. 기록에는 Cargo 기능 미선택, 부트 및 일반 고정 RR 디스패치 결과, Cortex-A72, 릴리스 최적화 s와 LLD 22.1.2가 들어 있다. GNU readelf 2.38 출력에서 파일·주소 바이트 집합을 독립 계산해 10개 지표, 모든 차이와 해시를 대조했다. 호스트 테스트 두 묶음은 각각 3개와 4개를 통과했다.

| SHA-256 | 값 |
|---|---|
| 최소 ELF | `c90b56c85e939df91710124411204c0024ebc054b3a35f314fce7a96967d06be` |
| 일반 RR ELF | `c852c3f0c53af512c9e3320d256459fa9eb1615a6c7857b25e8c15dc9fde07ec` |
| 증거 압축 파일 | `8810c8505a82e821f5532d7ff171155f083c09cc633d23d8863bbb0648d72102` |

저장소 링커 스크립트로 생성한 경계 표본은 코드·RAM이 한도와 같을 때 종료값 0, 코드 1 B 초과 시 1, RAM이 첫 정렬 단위인 16 B 초과 시 1, 둘 다 초과 시 1을 반환했다. 비교 구성만 초과하면 0이었다. 잘린 ELF는 어느 인수로 넣어도 2였다. RX 내부 28 B와 세그먼트 사이 공백 4,045 B를 갖는 표본에서도 각 영역을 사양에 맞게 집계했다.

1차 판정기는 독립 표본 두 종을 두 인수 위치에서 각각 잘못 분류했다. 첫 표본은 변형된 링커 스크립트로 BSS 끝을 `0x40205029`에 두었다. 저장소 스크립트는 부트 시 8바이트 단위로 지울 수 있도록 BSS 끝을 정렬한다. 판정기는 이 표본을 종료값 0으로 승인했다. 둘째 표본은 저장소 스크립트로 링크했고 읽기 전용 `.rodata`에 `SHF_GNU_RETAIN`이 있었다. 이 플래그는 링커가 섹션을 보존하게 하며 메모리 권한과 측정 범위는 그대로였다. 판정기는 종료값 2로 거부했다. 1차 검증 결과 BSS 양 끝의 정렬 확인과 보존 플래그 처리를 수정해야 한다.

압축 파일에는 실제 ELF 두 개, GNU 프로그램·섹션 표, 빌드 선택 및 로그, 판정 결과, 독립 계산 코드, 경계 표본, 최초 실패 기록과 SHA-256 목록이 있다. 실행 중 최대 메모리, 초기화 시간과 실보드 지연은 별도 검증 범위다. [측정 기록](evd-090-virt-static-first.json) · [증거 압축 파일](evd-090-virt-static-first.zip)
