# EVD-139 · 네이티브 배치 작업의 도착과 서비스 추정치

CHG-139 / IMP-139 / POL-003 / [#341](../native-batch-applications.en-ko.md) / [#342](https://github.com/Romanof123/JNOX/pull/342)

`25a41989368d4f76ec7151209e27a448b7b253e2`

14개 네이티브 최초 부팅에서 각 앱의 사설 산출물과 재생 결과가 일치했고 저널 손실은 없었다. 두 앱의 도착 실험에서는 SRTF가 실행 중인 앱을 선점해 짧은 앱을 실행한 뒤 원래 앱에 복귀했다. SJF와 HRRN은 기존 앱을 유지했다. 대기 시간 실험에서 HRRN은 B를 C보다 먼저 선택했고 SJF는 C를 먼저 선택했다. SJF 동순위 큐 최초 부팅에서는 첫 PPI가 E+5,442,243틱에 발생해 이미 세 앱 모두 공개 시각이 지났다. B 다음 C 순서는 확인했지만 A 실행 중 두 피어가 도착하는 장면은 이 부팅에서 관측되지 않았다.

도착 사례 6건에서 A는 각각 128 MiB를 처리해 합계 17,112,760,320과 종료값 17을, B는 8블록에서 경보 2,048개와 종료값 43을 남겼다. SRTF 원본에서 중단·복원된 PC, SP, 매핑 및 프레임과 최종 산출물을 확인했다. 중단 순간의 누적 블록 수나 정수 레지스터 전체에 대한 별도 스냅숏은 없었다. 노화 HRRN의 A 종료 결정은 E+10,124,297틱에서 B를 선택했고 SJF는 E+10,086,152틱에서 C를 선택했다.

기존 링크형 #211 텔레메트리 최초 6건의 순서는 모두 2,1,0이었고 실제 포화 거부 및 산출물을 확인했다. 이전 세 ELF의 적재 세그먼트가 달라 기존 일반 부팅 6건 및 저널 재생 3건의 결과를 별도 보존했다. 기본 시작 대조군은 37로 종료했다. 호스트 191/191, CLI 거부 13건, 직접 빌드 거부 11건, 직접 빌드 성공 2건을 기록했다. 최대 오프셋은 패키징 근거이며 오버플로 및 동시 기상·공개는 호스트 대조다. 고객 배포 용량과 실물 보드 WCET는 별도이며

독립 오프라인 판독은 신규 부팅 없이 원래 14개 세션과 별도의 관측기 세션 4개를 재생했다. 원래 SRTF 두 세션의 보존 RAM에서 x0–x30을 해독했다. PC 0x400808에서 W21과 ELF 명령 순서로 중단 전 완료 블록 13,721/13,619를 추론했다. 원본 SJF 동순위 최초 부팅은 세 앱을 동시에 공개했다.

첫 관측기 쌍은 판독값 2/2를 유지한다. SRTF는 중단 시 13,158블록을 측정했으나 독립 복원 피연산자 표본이 없었다. SJF는 시계 SVC에서 A를 유지했으나 결정 전후의 연속 사설 표본이 없었다. 수정 관측기 SRTF에서는 서로 다른 저장·복원 시점의 x0–x30, PC/SP/PSTATE가 일치했다. B 종료 43 후 A가 0x400808로 복귀해 8,863→8,864블록으로 진행했다. 수정 SJF의 같은 캡처는 처음 판독값 2였으나 EL1 벡터의 시계 SVC 재검사를 구분한 오프라인 판독에서 0이었다. B/C가 준비된 뒤에도 A가 유지됐으며 2,148→2,149블록으로 진행했다.

재해시한 변조 대조 9개 중 오통과는 0건이었다(불일치 1이 5건, 증거 누락 2가 4건). 수정 관측기 두 판독 결과는 0/0이다. 이는 복원 명령의 실제 메모리 피연산자와 외부 ERET PC 근거다. 호스트 콜백과 공유 RAM이 타이밍에 영향을 줄 수 있으며, ERET 시점의 레지스터 파일 직접 측정·실물 WCET·고객 부하 용량은 별도다.

독립 Release는 fd2378decfa8f8f878599d9e5f80e108e531801b에서 지정한 단일 Cortex-A72 QEMU virt/GICv2 기본 시계(62.5 MHz)의 유한 SJF·SRTF·HRRN 구성을 승인했다. 네이티브 프로필은 사전 패키징한 앱 최대 3개와 지정한 공개 오프셋·추정치에 한정한다. 링크형 #211/#214 프로필은 코디네이터와 수용한 작업 3개가 슬롯을 채운 뒤 추가 유효 요청을 포화 상태로 거부했다.

다른 부하, 고객 배포 용량, 실물 보드 WCET, ASIL 적합성 및 캡처 오버헤드 상한은 이 승인 범위 밖이다.
