## Evidence interpretation

audit.py and ledger.py recompute EDF/CBS arrivals, q/d, ready states, action and owner independently. Worker progress is checked using the affine recurrence, checked count, stack, ELF entry and saved ELR; upper service is vector stop minus assembly return sample. Every observed allocation accumulates that upper against its own deadline. Matched traces join external QEMU IRQ/SVC/ERET order and actual return PCs. The expected horizon is 34 slots for W and 10 for S, including idle slots, per-owner exits and final progress. Per-slot and per-allocation numbers are retained in observations.json.

Raw schema 3 emits legacy boot tag 24 and terminal tag 24 at distinct slots. The as-pinned decoder rejects genuine captures as duplicate tag 24. Independent replay selects both by context and validates measured authority word 3, bank 1, generation 1 and owner A before interpreting sealed debit rows 31/32 as committed. Those rows and frame witnesses are terminal-time formatting. Their timestamp is never used to approximate live accounting. Schema 1 uses the original live decision rows where present. The QEMU/guest flags and measured bracket economics cannot qualify an implementation on physical hardware.

## Portable capture

Check the ZIP digest in the JSON. Preserve the original corpus and reproduce the independent audit in a copy with Python 3 and GNU aarch64-linux-gnu-nm.

```sh
unzip evd-053-v3-captures.zip
mkdir corpus
tar -xzf reservation-compact-fresh.tar.gz -C corpus
(cd corpus && sha256sum -c SHA256SUMS)
cp -R corpus replay-copy
(cd replay-copy && python3 audit.py)
```
