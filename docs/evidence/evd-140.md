# EVD-140 · 유휴 재충전 전달의 대조·관측 쌍

CHG-140 / IMP-140 / POL-016 / [#343](https://github.com/Romanof123/JNOX/issues/343) / [#344](https://github.com/Romanof123/JNOX/pull/344)

[Observation design / 관측 설계](../native-idle-delivery-time.en-ko.md)

게스트 최초 쌍은 31a4185에서 동일한 보관 커널·ELF와 62.5 MHz 기본 시계를 사용했다. 대조 부팅은 재충전 29회, 계측 부팅은 30회를 기록했다. 둘 모두 늦음·무효·행 유실은 0이었다. 최대 지연은 각각 22,179틱과 16,244틱으로 기존 한도 1,953,125틱 이내였다. 사설 RAM에서 보고 앱 3/7, 히스토그램 9개 빈, 에너지 5,864,240,971,776을 확인했고 종료는 7/70/179였다.

관측 부팅의 콜백 120개는 재충전 30회의 네 지점과 대응했다. 호스트 표본은 1,530건이며 유실은 없었다. 실행큐 대기 검교정 74,295,378 ns와 74,195,991 ns는 CPU0의 일회용 자식 두 개에서 측정했다. vCPU 자체의 대기값과 구분한다. 발생 측에서 시각을 기록한 IRQ 신호나 새 지연 사건이 없으므로 과거 원인 또는 관측 비용 상한을 도출할 수 없다.

최초 CLI는 실제 Rust 심볼을 식별하지 못해 종료값 2를 반환했다. 같은 자료에 전체 심볼 이름을 지정한 별도 판독과 페이지 테이블 재생에서 앱·원장·예외 결과를 확인했다. 이 결과는 최초 CLI의 실패 판정을 유지한다. 기존 4,201,556·6,487,068·9,989,268틱 초과의 원인은 미확인이며 #339 및 POL-016은 미결이다.

수정 공개 CLI 10d20e0은 두 최초 캡처의 동일한 원본을 읽어 종료 0을 반환했다. 두 RAM 덤프는 각각 15,331,376바이트였다. SPACES의 누락·중복·위치·크기·저장 유형을 바꾼 다섯 대조군은 모두 2로 거부됐다. 잘못된 부팅 ID는 자식 검교정 한도만 제외하고 게스트 결과를 보존했다. 새 부팅이나 재검교정은 없었다. #343의 쌍 비교와 재판독은 공학 관측 근거이며 #339의 원인 또는 POL-016 시간 승인을 제공하지 않는다.
