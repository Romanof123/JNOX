# EVD-040 · Ordinary Rust tasks under MLQ and MLFQ

[한국어](evd-040.md) · [Predeclared acceptance criteria](../ordinary-multilevel.en.md) · [Independent originals and replay](evd-040.json)

CHG-042 / IMP-040 / POL-009. Each ordinary and diagnostic image for MLQ and MLFQ passed its first cold boot on QEMU virt with one Cortex-A72 CPU, GICv2 and TCG. The ordinary boots supplied UART, quiet windows and exception logs. Independent reconstruction of the separate diagnostic boots covered 15 MLQ decisions and 42 MLFQ decisions including initial selection.

**MLQ.** All three tasks began ready. Class-2 tasks 1 and 2 alternated on ten timer IRQs while class-0 task 0 stayed queued with zero service. The high peers exited at rows 11 and 12. Task 0 then dispatched, yielded and exited. Final service for tasks 0/1/2 was 296,589 / 3,936,504 / 4,443,824 counts. This high-class workload was finite. A minimum low-class share under continuing saturation remains unestablished.

**MLFQ.** At 62.5 MHz the top/middle/bottom allotments were 2,500,000 / 3,750,000 / 5,000,000 counts, with a boost every 10,000,000 counts of owner service. The client yielded with 1,709,995 remaining at row 1 and blocked with 937,664 at row 4. The interactive peer woke it at row 5 with that balance intact. Its row-6 yield left 175,889. The row-8 IRQ charged 284,419 and demoted it, charging the 108,530 excess against the middle allotment. The CPU worker reached bottom at row 18.

The row-10 boost preserved [client, interactive peer, CPU] and immediately resumed the client. Rows 20 and 29 selected CPU from [CPU, interactive peer]. Row 29 crossed the boost boundary during a wake SVC. All three exited. Final service for client/CPU/interactive peer was 2,748,419 / 20,437,544 / 15,726,117 counts.

**Observation limits.** All 14/41 diagnostic outgoing frames had aligned 832-byte extents in their owners' separate 16 KiB stacks. The verifier reconciled return PCs and saved frames against external exception order and linked symbols. Terminal QMP PCs were inside idle at `0x4020125c` (MLQ) and `0x40201a5c` (MLFQ). The executed empty-queue path contains a timer-control write of zero. Terminal timer-register readback was outside the capture. Failed wakes targeted the already-ready or exited client. Empty startup, all-blocked stall, invalid configuration/out-of-range ID, forced wrap, buffer failure and multi-period boost coalescing remain unexercised. Product loads, latency limits and hardware approval remain separate.

## Offline replay

From the repository root, run the following Python 3 code, then run `python ml-replay/verify.py` to reconstruct both diagnostic captures. The archive includes all four ELF digests and first-run logs, UART, exceptions, diagnostic memory, register snapshots, symbols, disassembly, task tables and independent verdicts.

```python
import base64, hashlib, io, json, zipfile
from pathlib import Path

record = json.loads(Path("docs/evidence/evd-040.json").read_text())
blob = base64.b64decode(record["zip_base64"], validate=True)
assert hashlib.sha256(blob).hexdigest() == record["zip_sha256"]
root = Path("ml-replay")
root.mkdir(exist_ok=False)
with zipfile.ZipFile(io.BytesIO(blob)) as archive:
    assert set(archive.namelist()) == set(record["files"])
    for name, spec in record["files"].items():
        data = archive.read(name)
        assert len(data) == spec["size"]
        assert hashlib.sha256(data).hexdigest() == spec["sha256"]
        target = root / name
        target.parent.mkdir(parents=True, exist_ok=True)
        target.write_bytes(data)
```
