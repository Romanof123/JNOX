# EVD-001 · First AArch64 Rust boot

[한국어](evd-001.md) · English

**The single-core QEMU boot bench passed.** On 2026-11-24 an agent independent of implementation and integration used a clean checkout and its own observer. It recorded the initial verdict and UART before examining the source and integration runner. The planning baseline is `4ce1e16` and the source candidate is `604b03186841059ce3b4226367824fa923742e88`. [Bench contract](../m1-boot.en.md) · [Source commit](https://github.com/Romanof123/JNOX/commit/604b03186841059ce3b4226367824fa923742e88) · [Change issue](https://github.com/Romanof123/JNOX/issues/13)

| Test | Observation |
| --- | --- |
| Repeatable build | Two clean output directories on Windows x86-64 used Rust 1.95.0, target `aarch64-unknown-none` and Cortex-A72 options. Both ELF files had SHA-256 `60684dd95ab040b125c6e6447b3946314c38df61fdcb19cb180d6db328459861`. |
| Cold boots | QEMU 6.2.0 under WSL Ubuntu loaded the ELF directly using TCG, virt, one Cortex-A72 and 128 MiB RAM. Each fresh QEMU process produced exactly 27 bytes, `JNOX M1 BOOT\nJNOX M1 READY\n`, then remained alive and quiet for one second after the final line. The host stopped each process. |
| BSS clearing failure | The verifier replaced the single BSS clearing store with a pointer increment in a source copy and rebuilt a disposable ELF. This ELF had SHA-256 `1a2b297110b3b55fcc6323d8ecb84255c6434389bf3a0329054234f63cbb6ccb`. In the same configuration it emitted zero UART bytes over one second and remained alive. The public runner returned a deadline failure. |
| Runner controls | The public runner accepted two real boots of the candidate and a well-formed simulated transcript. It rejected nine simulated cases including wrong order, incomplete output and early exit. |

On Windows PowerShell with WSL Ubuntu, run `powershell -NoProfile -File docs/evidence/evd-001-replay/replay.ps1 -Repository .` from the repository root. It rebuilds two kernels and the failure specimen from the pinned commit and collects their logs. Compare the printed ELF hash to the table. [Independent replay script](evd-001-replay/replay.ps1)

`CHG-001` and `IMP-001` link this evidence to the boot implementation in `REQ-016` and part of `VER-016`. The BSS observation covers one probe dirtied before initialization. Physical reset, upper bounds on boot time, scheduling, isolation, application execution, tool qualification and product safety acceptance each need further evidence.
