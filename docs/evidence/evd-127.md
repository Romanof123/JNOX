# EVD-127 · 프로세스 전용 뮤텍스

CHG-127 / IMP-127 / [#317](../native-thread-mutex.en-ko.md) / [#318](https://github.com/Romanof123/JNOX/pull/318)

`f0ef88f8d1796b51801f7f72432545d2d223c34d`

최초 게스트 8회는 모두 종료값 0을 보고했다. 호스트 백업 전에 임시 디렉터리가 사라져 최초 RAM·UART·예외 로그를 다시 열 수 없다. 원래 경로에서 다시 빌드한 앱 ELF와 기본 협력형 커널은 최초 해시와 일치했다. 나머지 커널 패키지 5개의 최초 해시는 남아 있지 않았다.

단일 CPU QEMU virt의 별도 보조 실행 8회에서 다시 읽을 수 있는 원본을 확보했다. 프로세스 RAM에서 C 메인과 Rust 작업자의 집계인 표본 256개, 합 32,896, 제곱합 5,625,216과 조인한 공유 결과 포인터 4,203,552를 확인했다. 작업자는 EBUSY(16)를 받은 뒤 lock에서 차단됐고 직접 소유권을 양도받아 0으로 복귀했다. 메인은 해제 후에도 실행을 이어갔으며 즉시 재시도는 16을 반환했다. 메인과 작업자의 errno는 각각 22와 38이었다. 모든 실행에서 누락 행은 0이었고 외부 추적의 EL0 복귀 PC 순서는 저널의 선택 PC와 일치했다. 짧은 기본 RR 추적에서는 비자발적 순번 교대가 발생하지 않았다.

두 수면 대조에서 소유자가 잠들고 작업자가 대기 중일 때 유휴 EL1 IRQ가 발생해 메인이 재개했다. 자기 trylock과 사용 중 파괴는 16, 비소유자 해제는 1을 반환했고 동일 주소 재초기화로 새 토큰을 받았다. 호스트 수명 검사 14개는 모두 통과했다. 기존 스레드 앱 두 개는 17로 종료했다. 단일 스레드 앱의 초기화는 ENOTSUP를 반환하고 errno 22를 보존했다. 기능 검증 범위는 지정 단일 CPU의 프로세스 전용 뮤텍스다.
