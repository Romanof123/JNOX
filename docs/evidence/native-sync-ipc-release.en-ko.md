# IPC-001 engineering release decision / IPC-001 엔지니어링 승인

**Approve IPC-001 for the named single-core AArch64 QEMU virt FIFO and RR engineering profile. Record 1/10 IPC families accepted under #24 for this scope.** The profile has two or three configured slots, directional local endpoints, one register word per request or reply, and one outstanding call per caller. The applicable contracts are the IPC-001 row in `docs/ipc-mechanisms.en.md`, VER-024 in `docs/verification-plan.en.md`, and `docs/native-sync-ipc.en-ko.md`. IPC-002 through IPC-010 remain open. Physical Pi 4 work under #34, POL-002 board release, product timing/WCET and FuSa/ASIL sign-off remain open.

**단일 코어 AArch64 QEMU virt의 명시된 FIFO·RR 엔지니어링 프로파일에서 IPC-001을 승인한다. #24의 승인 수는 이 범위에서 1/10이다.** 2·3개 슬롯의 방향 지정 로컬 엔드포인트에서 요청·회신은 각각 레지스터 한 워드이며, 호출자당 미완료 호출은 한 건이다. IPC-002~010, #34 실물 Pi 4, POL-002 실물 출시, 제품 타이밍·WCET와 FuSa·ASIL 승인은 미결이다.

| Acceptance evidence | Independent observation |
| --- | --- |
| C/Rust delivery and ownership | Twelve original boots. Four used the same C caller/Rust server bytes with caller-first and receiver-first under both policies. RAM retained the request, computed reply and single-use token. Other boots checked unknown, foreign, duplicate and expired tokens, denied routes and the disabled ABI. |
| Donation | Independent mixed-language FIFO/RR chains rejected cycles and served the donated server ahead of the ready medium worker. In the separate 7/4/1 FIFO and RR probes, high blocked on low with medium ready, low replied and high resumed, then medium ran with low ready. In the supplemental RR boot, the raw owner sequence was 0→2→0→1→2→idle, with exits 51/52/53, zero dropped decisions and medium checksum 133693440. |
| Deadline and loss | Native FIFO/RR mixed-language clients observed an issued-token timeout, a successful fresh call, server loss and rejection on a new call to the dead server. Host controls saturated both eligible callers to one server in the three-slot profile, expired a queued call, tested exact deadline precedence, caller/server death around expiry, single completion and restoration of base priorities. |
| Reply versus caller death | Supplementary controls applied reply and caller exit at timestamp 10 while the deadline was 30. Reply-first committed once. Caller exit discarded any unread completion. Exit-first invalidated the token and reply returned −116. Every restarted slot rejected its previous token while its new call was live, then received exactly one fresh reply. This lifecycle evidence was collected on the host. |
| Resources | Guest traces reached two simultaneous calls, the maximum without a cycle in the three-slot domain. Terminal RAM showed zero outstanding requests, blocked receives or completions. The linked endpoint state occupied 176 or 256 bytes for two or three slots. The matched two-slot FIFO route/no-route comparison measured +5740 bytes text, +799 read-only data and +176 data. |

독립 검증자의 최초 부팅 12회와 Release의 별도 RR 부팅 1회를 확인했다. 두 정책의 C·Rust 게스트 RAM에서 호출자·수신자 각각 선착한 경우의 워드·토큰·오류를 확인했다. 우선순위 7/4/1의 FIFO·RR에서는 중간 작업이 준비된 동안 낮은 서버가 먼저 호출을 처리했다. 회신 후 높은 호출자가 재개되고 종료하자 여전히 준비된 낮은 서버보다 중간 작업이 먼저 실행됐다. 게스트에서 발급 후 만료, 후속 정상 호출, 서버 종료를 확인했다. 수신 전 만료, 동일 시각 만료 우선권, 호출자 종료와 슬롯 재사용은 호스트에서 확인했다. 같은 시각 회신과 호출자 종료의 두 순서를 실행하여 일회성·이전 토큰 거부·우선순위 회수·잔여 상태 0을 확인했다.
