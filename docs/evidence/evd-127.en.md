# EVD-127 · Process-private mutexes

All eight first guests reported exit 0. Their original RAM snapshots, UART and exception logs disappeared from the temporary directory before host backup. The application ELF and normal cooperative kernel matched their original hashes when rebuilt at the original path. The first digests for the other five kernel packages were unavailable.

Eight separately preserved supplemental sessions on single-core QEMU virt supplied the reopenable evidence. Process RAM confirmed the C main and Rust worker accumulated 256 samples, sum 32,896 and sum of squares 5,625,216, and joined the shared result pointer 4,203,552. The worker observed EBUSY (16), then blocked in lock and resumed with 0 after direct ownership transfer. Main retained its turn on unlock and its immediate try returned 16. Main and worker errno remained 22 and 38. Each session had zero dropped rows; in traced sessions the ordered external EL0 returns matched the selected journal PCs. The normal RR trace had no involuntary rotation during this short workload.

In both sleep controls the owner slept while the worker waited and an idle EL1 IRQ returned main to execution. Self-try and busy destroy returned 16, non-owner unlock returned 1, and reinitialization at the same address produced a new token. All 14 host lifecycle checks passed. Two existing threaded apps exited 17. A singleton app observed ENOTSUP on init and retained errno 22. This functional evidence covers a process-private mutex on the named single CPU.
