# EVD-146 · Pi 4 모델 두 코어의 분할 네이티브 프로세스

CHG-146 / IMP-146 / POL-013 / [#355](../pi4-native-smp-applications.en-ko.md) / [#356](https://github.com/Romanof123/JNOX/pull/356)


0297172의 최초 pair·remote·swap 패키지 세 건이 실패해 예정된 SMP 게스트 다섯 건은 부팅되지 않았다. 5d43712 수정 후 같은 세 패키지는 어셈블 단계에서 각각 실패했다. 두 코호트의 기존 단일 코어 FIFO 대조는 별도 기록이다.

[Packaging firsts / 최초 패키징](pi4-native-smp-first-packaging.en-ko.md) · [Assembly firsts / 최초 어셈블](pi4-native-smp-first-assembly.en-ko.md)

60475a0ba7c2b1092305043a65d1f6182625a8ed에서 stock raspi4b QEMU 11.1.3으로 SMP 최초 5건과 별도 FIFO 대조를 완료했다. C/Rust 작업은 각 실행에서 소수 78,498/70,435개와 종료값 12/77을 기록했다. 같은 결과 VA가 서로 다른 물리 페이지·ASID로 연결됐다. pair 일반·추적에서 A는 CPU0, B는 CPU1을 사용했고 마스크 교환 시 A는 CPU1, B는 CPU0을 사용했다. 계산 루프 중 PPI 횟수 A/B는 pair 8/16·8/16, remote 8/17·8/18, swap 8/16이었다. 저장 프레임, 서비스, 스택 가드, 종료 동기화와 저널 손실 0을 확인했다.

remote에서는 CPU0이 CPU1에 SGI1을 보내 B 대신 세 번째 앱 C를 실행했다. C의 결과와 종료값은 모두 32였다. 일반 부팅은 송신 뒤 수신과 셀 2 전 C의 첫 시계 읽기를 확인했고 C 수면 중 B 계산이 진척됐다. 추적 부팅은 실제 SGI 인계와 복귀를 확인했지만 보수적 수신 하한이 송신보다 421틱 앞서 시각 순서는 미확인이다. 다섯 SMP 부팅 모두 양 코어의 보수적 계산 겹침 증거가 부족해 판독은 2였다. 기존 FIFO 대조만 0이었다. 기존 소수 계산 5건에서는 0이 아닌 TLS를 사용하지 않았다. 실물 보드 실행, 호스트 병렬 실행과 제품 간섭은 미측정이다. #47의 원래 짧은 루프 조건과 POL-013 전체 판정은 별개로 미결이다.

## 2026-11-25 · 별도 ABI 작업 최초 부팅

첫 SIMD 어셈블리 빌드가 실패한 뒤 2423f0a에서 SIMD 루틴을 별도로 조립했다. 같은 이미지의 일반·추적 최초 부팅에서 각 CPU가 33,554,432회 계산했다. CPU0 홀수 합 1,125,899,906,842,624와 CPU1 짝수 합 1,125,899,940,397,056은 각각 스칼라·SIMD 결과가 일치했고 종료값은 12와 77이었다. 서로 다른 ASID와 사설 쓰기 페이지에서 TPIDR_EL0는 각각 0x4020a0과 0x4020a8이었다. 실제 PPI30 경계 12건(부팅마다 코어당 3건) 모두 EL0 루프에서 저장한 프레임 816바이트가 해당 복귀 준비 프레임과 일치했다. x19, q16과 FP 제어 상태도 확인했다.

일반 부팅은 동일 소유자로 복귀한 뒤 각 코어가 EL0에서 다시 진입하고 계산을 계속했음을 확인했다. 추적 부팅에서 같은 가상 PC로 돌아가는 ERET 패킷에는 코어 식별자가 없었다. 두 부팅 모두 보수적인 시간 보정 후 실제 계산 구간의 겹침을 확정할 수 없어 판독값은 2였다. 기존 다섯 부팅과 #47 및 실물 보드 판정은 별도로 남는다.
