# 일반 비례 배분 진단 최초 실행

CHG-057 · POL-010 · EVD-055

4a3eccd83b49a7b74d25f9e409c8c1dbe09781f2에서 미리 지정된 두 구성별로 QEMU virt Cortex-A72 게스트를 한 번씩 콜드 부팅했다. 두 실행 모두 기본 62.5 MHz 카운터를 사용했고 PPI 30을 기록한 후 첫 할당에서 종료 행을 출력했다. 기존 EVD-055 수집 환경과 같이 Windows의 Rust 1.95.0으로 AArch64 ELF를 빌드하고 Linux 임시 디렉터리에서 QEMU와 기록기를 실행했다. 각 외부 로그의 IRQ 2회와 ERET 2회는 유휴 작업과 클라이언트 디스패치에 해당한다.

| 이미지 | 작업자 | 시작 / 비교 / 중단 | 정수 단위 + 나머지(카운트) | 작업 진행량 |
|---|---|---|---|---:|
| lottery-miss | B | 721262 / 1971262 / 1978007 | 2 × 625000 + 6745 | 5347472 |
| stride-delay | A | 2580553 / 7580553 / 7591590 | 2 × 2500000 + 11037 | 24611280 |

복권 시드 1에서 원시 난수 10451216379200822465와 티켓 2가 나와 구간 [1,3)의 B를 선택했다. 진단 구성은 두 틱을 요청했고 원래 한 틱 조건이 슬롯 0, 소스 427행에서 실측 2와 기대 1을 기록했다. 이는 계획된 거부 결과다. 스트라이드는 가중치 1인 A만 선택했고 두 단위 사용에 따라 패스가 0에서 1,441,440으로 증가했다. 소스 425행은 세 단위 이상을 요구한다. 종료 필드 425/4/0/0/1의 0과 1은 해당 조건의 실제·기대 불리언 값이다. 세 단위 부과는 관측되지 않았다. 두 실행 모두 비활성 클라이언트의 진척은 그대로였으며 독립 판독에서 UART 구문 오류가 없었다. 기존 일반 구성 세 건의 결과는 별도로 유지한다. 물리 실행 시간과 역사적 4회 IRQ 실패 원인은 미확인이다.
