# EVD-031 · Fixed-priority runtime on the Raspberry Pi 4 model

[한국어](evd-031.md) · [#71](https://github.com/Romanof123/JNOX/issues/71)

The independent verifier cold-booted each raw kernel image twice on QEMU 11.1.3’s raspi4b model. All four ordinary boots passed on the first attempt. Each FIFO boot recorded seven SVCs and two IRQs. B yielded with zero sleep and stayed ready. After HIGH preempted A and exited, A resumed ahead of B. B later slept, woke, continued after its rejected sleep and exited. Each RR boot recorded three IRQs and three SVCs, with the reconstructed sequence A/HIGH/A/B/A/B/idle. UART, linked instructions and exception/return PCs support these task assignments.

Separate debugger replays read CNTFRQ_EL0 as 62,500,000 Hz. The configured RR quantum was 200 ms. A/B/HIGH used stack slots 0/1/2 in FIFO and 0/2/1 in RR, with 16 KiB per slot. Both replays ended at idle PC `0x8125c`, SP `0x98120`. The ordinary traces contain no per-event counter, task SP, interrupt ID or timer-register sample. Exact RR residual service and physical timing are outside these measurements.

The model loaded kernel8.img directly. The offline packages stage pinned firmware, the device tree, overlay and boot configuration. Physical firmware boot, serial behavior, board timing and product safety require separate evidence.
