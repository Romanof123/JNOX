# EVD-001 · AArch64 Rust 첫 부팅

한국어 · [English](evd-001.en.md)

**판정은 단일 코어 QEMU 부팅 벤치 합격이다.** 2026-11-24에 구현·통합에 참여하지 않은 검증 에이전트가 깨끗한 체크아웃에서 독립 관찰 도구로 최초 판정과 UART를 기록한 뒤 소스와 통합 시험기를 검토했다. 기획 기준선은 `4ce1e16`, 소스 후보는 `604b03186841059ce3b4226367824fa923742e88`다. [시험 계약](../m1-boot.md) · [소스 커밋](https://github.com/Romanof123/JNOX/commit/604b03186841059ce3b4226367824fa923742e88) · [변경 이슈](https://github.com/Romanof123/JNOX/issues/13)

| 시험 | 관측 결과 |
| --- | --- |
| 재현 빌드 | Windows x86-64에서 Rust 1.95.0, 타깃 `aarch64-unknown-none`, Cortex-A72 옵션으로 독립된 두 출력 디렉터리에 빌드했다. 두 ELF의 SHA-256은 `60684dd95ab040b125c6e6447b3946314c38df61fdcb19cb180d6db328459861`로 일치했다. |
| 정상 부팅 | WSL Ubuntu의 QEMU 6.2.0, TCG, virt, Cortex-A72 한 코어, RAM 128 MiB에 ELF를 직접 로드했다. 새 QEMU 프로세스마다 정확히 27바이트 `JNOX M1 BOOT\nJNOX M1 READY\n`을 받았고, 마지막 줄 이후 1초간 추가 출력 없이 프로세스가 살아 있었다. 두 번 모두 호스트가 종료했다. |
| BSS 초기화 실패 | 소스 복사본에서 BSS를 지우는 저장 명령 한 개를 포인터만 이동하는 명령으로 교체한 뒤 임시 ELF를 빌드했다. 해당 ELF의 SHA-256은 `1a2b297110b3b55fcc6323d8ecb84255c6434389bf3a0329054234f63cbb6ccb`다. 같은 환경에서 1초 동안 UART는 0바이트였고 프로세스는 살아 있었다. 공개 시험기는 시한 초과로 실패를 반환했다. |
| 시험기 자체 점검 | 공개 시험기가 후보의 실제 부팅 두 번과 정상 모의 출력을 수락했다. 잘못된 순서, 불완전한 출력, 조기 종료 등을 포함한 아홉 가지 모의 사례를 각각 거부했다. |

Windows PowerShell과 WSL Ubuntu에서 저장소 루트를 현재 디렉터리로 두고 `powershell -NoProfile -File docs/evidence/evd-001-replay/replay.ps1 -Repository .`를 실행하면 고정된 커밋에서 두 커널과 실패 시료를 다시 빌드하고 로그를 수집한다. 출력한 ELF 해시를 표의 값과 대조할 수 있다. [독립 재현 스크립트](evd-001-replay/replay.ps1)

`CHG-001`과 `IMP-001`을 통해 `REQ-016`의 부팅 구현 및 `VER-016`의 일부에 이 증거를 연결한다. BSS 관측은 초기화 직전 값을 채운 한 위치에 해당한다. 실제 보드의 리셋, 부팅 시간 상한, 스케줄링, 격리, 앱 실행, 도구 적격성 및 제품 안전 판정은 각각 추가 증거가 필요하다. [원본 관측 기록](evd-001.json) · [전체 추적 관계](../../trace/links.csv)
