# Fixed priorities for packaged native processes / 네이티브 프로세스 패키지의 고정 우선순위

CHG-115 design on #292 (`94bef763dbbcc7419e2d2902361052c6acec1f86`). IMP-115 and EVD-115 reserved. #292 gives each CPU0 process a private address space and saved exception frame. Its timer wakes sleepers into the ready queue. An external program doing arithmetic without system calls can therefore keep a ready peer from running until exit. [POL-002](scheduling-release-cases.en.md) already covers preemption of linked Rust tasks. The missing path is selection and involuntary dispatch for ordinary independently linked EL0 applications. #21 retains its physical-board and approval requirements under #34. Weighted #177 retains its own disposition.

#292에서는 타이머가 잠든 앱을 준비 큐에 넣어도 계산 중인 앱이 계속 실행된다. POL-002의 기존 연결형 태스크 정책을 독립 ELF 패키지에도 적용한다. #21의 실물 보드 검증과 승인, #177의 가중치 정책 판정은 별도다.

## Package / 패키지

Extend `tools/build_native_el0.py` for ordinary `--source` or `--elf` with repeatable `--peer-elf` (zero, one or two occurrences). Proposed examples use `--policy fifo --priority 3 --peer-priority 3` and `--policy rr --priority 3 --peer-priority 3 --quantum-ticks 12500000`. For three slots, package `--elf high.elf --peer-elf a.elf --peer-elf b.elf --policy rr --priority 7 --peer-priority 3 --peer-priority 3 --quantum-ticks 12500000` plus the existing output path. Match repeated peer priorities to repeated peer ELFs by position. The packager records the selected mode, each ELF digest and its priority in slot order. RR uses one explicit common quantum in physical counter ticks, as in `Fixed::new`. Accept priorities 0–255, larger first, and a quantum of 1 through i64::MAX. Require one priority per present slot in fixed mode. Reject orphan or missing fields, FIFO with quantum, invalid numbers and conflicting selectors before boot. Omitted policy selects existing cooperative behavior and accepts existing command lines. Bind validated configuration to the boot image through kernel/build.rs. Ordering ties at startup follow package order.

패키지에서 주 앱과 동료 앱의 우선순위를 각각 지정한다. 큰 값이 먼저 실행되고 동률이면 패키지 순서를 따른다. RR 퀀텀은 실행 대상 앱이 공유하는 카운터 틱 값이다. 잘못된 조합은 패키지 단계에서 거부하고 기존 명령은 협력형으로 실행한다.

## Dispatch / 디스패치

Use kernel/src/fixed_policy.rs and its ready_queue.rs as the sole fixed-mode selection state. Native slots retain frames, mappings and exit statuses. Start each configured slot with zero delay. Replace the native pair installer and peer-specific frame initialization with a count-driven boot table. Slot IDs follow ELF order. Validate all load plans, backing ranges and initial stacks before installing any mapping. Allocate distinct private backing, tables, stacks and saved frames for each slot, including identical user virtual addresses. Use the configured count for user-copy validation, IRQ enablement, dispatch, idle and last-exit handling. Preserve single-app and startup-probe entry points. Three slots suffice for the POL-002 owner, equal contender and higher sleeper. Reject a fourth input in this virt profile. Translate yield, future absolute sleep, exit and timer IRQ into policy events on one monotonic counter. Convert a future clock deadline to a relative delay at the same event sample. Preserve the native ABI's immediate return for elapsed sleeps and its error handling. Sample time, account elapsed service once, admit all due sleepers in deadline/slot order and select. Reprogram the earliest sleeper or eligible RR expiry from `Fixed::deadline`, disable an unused compare, and handle overflow explicitly. On an IRQ from EL0 save the complete interrupted frame, acknowledge the interrupt, activate the selected address space, and restore its frame. Idle IRQs select woken work without saving an EL0 frame.

FIFO retains the owner against equal peers until yield, block or exit. A strictly higher wake preempts either mode. On that interruption keep the outgoing turn at the front of its priority with its remaining RR service. When its slice has expired and an equal peer is ready, the old owner goes to the tail with a new quantum. Admit simultaneous wakes before rotating. Late delivery charges the actual owner once. Only an equal ready peer makes an RR expiry eligible for a timer compare. Inspect arbitration and compare programming on syscall and IRQ paths to avoid a stale owner or compare.

FIFO에서는 동률 동료가 준비돼도 현재 앱이 양보·대기·종료할 때까지 계속 실행된다. 더 높은 우선순위 앱이 깨어나면 즉시 전환하고 중단된 앱의 순번과 잔여 퀀텀을 보존한다. 동일 시점에는 만기 대기자를 먼저 깨우고 동순위 RR 순번을 넘긴다. 유휴 상태와 EL0 실행 상태 양쪽에서 타이머를 처리하고 전체 프레임과 주소 공간을 함께 복원한다.

## Acceptance on ordinary QEMU virt / 일반 부팅 검증

| Package | Required observable result |
| --- | --- |
| Equal FIFO | Two separately linked apps with private data at matching virtual addresses. First performs finite syscall-free computation, then yields. Peer runs and exits. First resumes and returns its expected checksum-derived status. Repeat with first exiting directly, then peer starting. |
| Equal RR | Both execute finite syscall-free arithmetic long enough to overlap multiple quanta. Capture A→B→A timer switches while both remain runnable, interrupted PCs inside the workloads, advancing private results and both expected exits. Keep the same binaries for the FIFO exit control. |
| Higher wake, FIFO and RR | Higher starts first and requests a future absolute sleep. Lower computes without yielding. Record the programmed wake, IRQ sample at or after deadline, lower interrupted in its loop, higher returned from sleep and exited, then lower restored and finished its calculation. Repeat with slot priorities and associated apps reversed to exclude slot preference. Reject a run where lower finished before the wake. |

각 시나리오는 실제 C·Rust SDK로 독립 빌드한 앱, ELF 해시, 패키지 설정, 일반 부팅의 원본 출력과 앱별 결과를 남긴다. 타이머 선점과 자발적 양보를 구분하고 검증 대상인 루프 안에서는 시스템 호출을 하지 않는다. 기존 단일 앱과 두 앱 협력형 동작, 잘못된 설정 거부도 확인한다.

Retain the command line, raw ordinary boot output, package identities and app-owned results. Distinguish wake from quantum expiry using programmed compare, sampled counter, reason, previous and next PID. Record each dispatch sample, active and ready IDs in priority order, saved and restored ELR/SP, charged service, remaining ticks and absolute armed compare. Record decisions in bounded in-memory storage and emit after execution to limit timer perturbation. A truncated causal sequence leaves the case unverified.

## Three-process residual RR / 세 프로세스 잔여 퀀텀 검증

Boot the three-ELF configuration above. HIGH requests a future absolute sleep aimed inside A's first quantum. A and B perform independent, finite, syscall-free loops and return distinguishable checksum-derived statuses. Both are ready when HIGH blocks. A starts first in package order. At the physical timer wake require A still running inside its loop, B waiting and HIGH becoming ready. HIGH must run before either lower app, perform its own finite calculation and exit. At that exit A resumes at the saved PC with its private stack and B still waiting. At residual expiry B takes the CPU while A is still runnable. Capture the later A return and all three expected exits. Match interrupted PCs to the packaged ELF disassembly.

Let S be A's initial dispatch sample, W the actual wake decision and X the dispatch sample when HIGH exits. For common quantum Q require 0 < W−S < Q, residual R = Q−(W−S), and first programmed compare at min(HIGH deadline, S+Q). Record the transition from A to HIGH at W and the exact compare X+R when A resumes. Require a real timer IRQ at or after X+R that selects B before X+Q to distinguish this run from restarting a full quantum. HIGH's execution consumes none of A's service. Replay the chronological event samples through Fixed and compare the owner, service totals and comparator after each decision. An overdue wake, a missing switch or a late expiry beyond this discriminating interval leaves that observation unqualified. Preserve the original capture.

셋째 슬롯까지 독립 ELF·주소 공간·스택·프레임을 준비한다. HIGH가 실제 절대 기한으로 잠들면 같은 우선순위의 A와 B 중 A가 계산을 시작한다. 퀀텀이 남아 있을 때 HIGH가 깨어나 A를 선점하고 종료하면 B보다 A가 먼저 중단 지점으로 복귀해야 한다. 재개 시각과 잔여량의 합으로 설정한 실제 타이머 IRQ에서 B가 선택되고 세 앱의 계산 결과까지 일치하는지 확인한다.

For simultaneous wake and expiry retain the deterministic linked [tie and late controls](fixed-runtime-edges.en.md). In an ordinary capture classify a true tie only when the absolute wake and the running owner's logical expiry are equal before delivery. Replay admission before rotation, then selection by priority. Record overdue distinct deadlines separately even when one IRQ services both. Ordinary sleep and dispatch samples may never produce an exact tie. Report that observation as pending in that case. Use ordinary timer delivery throughout.

동시 만기는 깨어날 절대 시각과 논리적 퀀텀 만료 시각이 같은 경우에만 인정한다. 한 IRQ에서 서로 다른 밀린 기한을 처리한 경우를 따로 기록한다. 실제 일반 부팅에서 동시 만기를 보지 못했다면 그 결과는 미관측으로 남기고 기존 결정적 정책 검증을 인용한다.
