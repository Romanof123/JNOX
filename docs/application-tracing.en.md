# J-NOX application tracing contract

[한국어](application-tracing.md) · [#137](https://github.com/Romanof123/JNOX/issues/137) · CHG-060 · CAP-013 · DES-006 · proposed schema and SDK ABI v1

An engineer investigating a slow request should be able to see when the client issued it, when the kernel accepted it, why the server waited, which driver operation completed, and when the client actually resumed. This design connects application annotations with independently attributed OS events. It defines a proposed interface and acceptance gates. Existing profile-specific captures keep their own schemas and verdicts.

## Events and causality

| Producer | Events and recording point |
| --- | --- |
| Rust/C application | BEGIN opens one named operation instance, END closes that instance with a bounded outcome code, MARK observes a point without changing its state. TYPE is the manifest declaration of a numeric event and its field types. A span may cross threads only by explicit context transfer. |
| Kernel scheduler | Thread create/exit, ready, block (reason/object), wake (cause), dispatch in/out and migration. Wake makes a thread eligible. Dispatch identifies actual CPU ownership at the scheduler boundary. A pre-return sample only bounds subsequent execution; an application marker can independently witness progress. |
| Kernel IPC | Send attempt, enqueue/accept or reject, dequeue/delivery, reply completion, cancellation, timeout, peer death. Record the successful operation at its authoritative state transition. A failed attempt creates no delivery edge. |
| Interrupt/driver | IRQ entry/exit with nesting instance, driver submission/acceptance and actual driver completion/error, deferred-work enqueue/start/end. A hardware interrupt may precede software completion; include a request/cookie association only when the driver can establish it. |

Use a capture/session ID plus boot ID. Identify a process/domain, thread, endpoint, driver object and request by bounded slot/ID **and generation**. Identify image instance and load mapping separately. A newly reused slot, PID, descriptor or restarted service begins a new generation. Declare the counter width, prevent ambiguous reuse within retention, and split the session or emit a discontinuity before rollover. Each record carries CPU and CPU-local sequence. Use typed transaction/span IDs, parent ID and explicit links for fork, handoff and completion (including many-to-one batches). The trusted kernel stamps the true producer/domain and creates or validates scoped correlation tokens. An application-supplied label alone cannot establish cross-domain causality.

For example, a client opens span X and submits request R. A committed queue entry links R to its delivery, whether the server was already running or woke later. A wake can coalesce multiple requests; attach the known set or mark the cause unknown. Server dispatch and receiving R start separate intervals. The server submits driver operation D and blocks. A completion IRQ identifies D only when the driver records the mapping; the deferred completion then makes the server ready. Its later dispatch, reply enqueue/delivery, client wake, client dispatch and END(X) remain distinct. A timeout followed by a late device completion preserves both outcomes and must not invent a reply. Show queue wait, ready-to-run delay and observed processing separately. A filtered-out edge stays unknown.

For safety IPC, annotate sender publication, receiver validation and acceptance/rejection, generation/sequence and bounded reason codes at their own transitions. Delivery or a trace marker cannot authorize a permit, alter freshness, consume rearm or drive an output. Only the functional receiver changes accepted control state. Verify a rejection against independent receiver state and device observation under the applicable safety test. Trace loss does not change the control action; it may make the evidence inconclusive. IPC implementation remains gated by #21/#24. [IPC contract](ipc-mechanisms.en.md) · [Verification plan](verification-plan.en.md)

### Minimum logical dictionary for v1

The following stable names identify event meaning in the proposed v1 dictionary. Every row also has the common record envelope. Here `ref<K>` is a typed, generation-qualified object reference, `type` is an allowlisted u32 dictionary key, `code` a bounded u16 enumeration and `value` an allowlisted u64. Named operands below are required; `none` is an explicit alternative where listed.

| Event | Required operands |
| --- | --- |
| APP.BEGIN / APP.END / APP.MARK | BEGIN: span ref, parent span ref or none, type. END: same span ref, outcome code. MARK: span ref or none, type, value. |
| IPC.ENQUEUE / IPC.DELIVER | Both: message ref, endpoint ref, request ref, direction code (request/reply). ENQUEUE: sending thread ref. DELIVER: receiving thread ref. Each enqueue records an actual commit. |
| THREAD.READY / THREAD.SWITCH | READY: thread ref, cause code, source event ref or none. SWITCH: outgoing and incoming thread refs or explicit idle, CPU from envelope. An event ref is session/boot, CPU and local sequence. |
| IRQ.ENTER / IRQ.EXIT | IRQ line u32 and IRQ instance ref shared by the pair. ENTER also records parent IRQ instance ref or none. |
| DRIVER.SUBMIT / DRIVER.COMPLETE | Operation ref, device ref, request ref or none. SUBMIT denotes accepted submission; COMPLETE adds outcome code. |

Native Rust code can hold a typed span token across a synchronous operation and explicitly transfer it before another task completes it. A C caller retains the corresponding opaque token and calls end on each completion/error path. Both use the same type dictionary and error semantics; the kernel validates the calling domain. The logical names and operands above specify interoperability at decode time. Exact C signatures, Rust bindings, calling convention details, opcode assignments and wire byte offsets await ABI review.

**Invented example, in µs on one calibrated CPU.** Client BEGIN 0, request ENQUEUE 10, server READY 12, SWITCH to server 20, request DELIVER 24, reply ENQUEUE 50, client READY 52, SWITCH to client 60, reply DELIVER 63, client END 70. Assume the two parties are the only participants in R, never migrate, and experience no missing events or intervening switches during their stated processing. End-to-end elapsed time is 70 µs. The disjoint intervals [0,10), [10,24), [24,50), [50,63), [63,70) contribute 10+14+26+13+7=70 µs. Server ready-to-dispatch (8 µs) is contained in the 14 µs request queue interval; client ready-to-dispatch (8 µs) is contained in the 13 µs reply queue interval. Adding either again double counts elapsed time.

At a Linux driver-domain boundary the J-NOX wrapper timestamps the accepted handoff and observed completion using its own counter and operation ref. Record the wrapper/image identity and which side produced each event. An unchanged Linux binary can remain opaque. Link authorized guest telemetry only if its provenance, operation mapping and guest/host clock calibration are established; otherwise show the wrapper-observed interval with an unknown interior.

## Capture interface and resource contract

- **SDK.** Propose fixed-width C ABI calls for capability query, begin(type, parent), end(span, outcome), mark(type, bounded value), and explicit context transfer. A Rust wrapper uses the same ABI with typed IDs and an explicit close for cross-task work. A rejected/disabled begin returns an invalid token and its end is harmless. Fix return codes for unsupported ABI, denied type, invalid token and dropped event. No allocation, name lookup, formatting, blocking I/O or waiting for a consumer on the producer path. Static registration maps numeric IDs to names at build time. Compile-time OFF must elide annotation calls and avoid evaluating annotation-only arguments; runtime OFF takes a bounded enabled check. A compatible prebuilt ELF can supply existing probes if ABI and manifest match. Otherwise trace only OS-visible events, with offline symbols/build IDs where available; internal spans cannot be reconstructed.
- **Wire contract.** Version the SDK ABI separately from the capture schema. The v1 header declares magic, major/minor, byte order, header/record sizes, session/boot/config/build IDs, platform and CPU topology, clocks, filter set, buffer policy and loss counters. Each record has a length/type/version, source ID, CPU/sequence, raw counter, subject/generation, correlation reference and bounded typed data. Specify absent fields explicitly. Reject unsupported major versions or malformed lengths; skip length-delimited unknown minor types and mark dependent intervals incomplete. The manifest pins an immutable type/field dictionary, permitted producers/types, ID namespaces, capacity, clock properties, binaries/load mappings and optional symbol files. Validate schema, manifest and capture digests together.
- **Bounded recording.** Reserve aligned fixed-size slots in a statically sized per-CPU buffer. A nonblocking bounded reservation claims a unique sequence; a nested IRQ must never share its interrupted writer’s slot. Publish the complete body with a release-store commit tag containing the sequence/generation; readers acquire-check the tag before and after copying, using race-safe payload access. Freeze/export only committed, stable records. The simpler v1 full-buffer policy is drop-new until authorized drain/reset; never recycle a slot while a writer or reader owns it. Bounded reservation contention, full buffer and unsupported nesting (including NMI where applicable) drop and count per source/CPU without recursion. Persist sequence discontinuities and saturating drop counters in reserved metadata; flag counter saturation. Physical index wrap after safe reclamation gets a new generation. No spinning on a preempted producer, overwriting in-flight data or logging the logger.
- **Time.** Declare each counter domain, frequency, wrap/reset rules and read-ordering. Capture synchronization pairs and conservative offset/drift/read uncertainty before and after the window. Use CPU-local sequence plus authoritative message links for partial order. For timestamp intervals [L1,U1] and [L2,U2], report elapsed bounds [L2−U1,U2−L1] after verified conversion. Overlapping intervals, migration without calibration and reset/missing samples prevent exact cross-core timing claims. Keep raw ticks. Trace transport or host receipt time cannot timestamp an on-target event.
- **Access and integrity.** Require separate capabilities for configuration, emission, capture start/stop, export and cross-domain inspection. Validate sender identity, type allowlists, generation, field ranges and rate/quota at trust boundaries. Default data excludes raw payloads, keys, addresses and user strings; allow only necessary opaque identifiers, enumerations and bounded measurements. Restrict sensitive symbol/mapping artifacts and PC samples to authorized offline analysis. Version retention/access policy, record configuration changes and access provenance, and protect stored/transferred evidence under the deployment policy. A digest detects mismatch; authenticity requires an authorized independent trust anchor where claimed.
- **Overhead.** Report per-CPU RAM including metadata, nested reservations and any export scratch space; include code/rodata, stack high-water, event cost by context, IRQ latency, scheduling jitter and saturation effects. Reserve exporter CPU/bandwidth separately. Compare compiled OFF, runtime-disabled and capture-enabled images/configurations with equivalent loads and independent timing. Functional Safety and Systems allocate numerical limits per board/profile before qualification. A zero-loss quiet run cannot establish loaded bounds. Optional statistical function profiling samples PCs/stacks at a declared rate with a separate privilege, budget and image mapping; report sampling bias, lost samples and coverage. Samples cannot supply span boundaries or prove request causality.

## Engineer workflow and acceptance

1. Select an authorized manifest, declared workload, clock window, event filters and stop condition. Archive the configuration and exact target image/artifact IDs. Boot/configure the capture, reproduce the workload once, retain the first result, loss counters and terminal state.
2. Export raw binary plus manifest, hashes and clock calibration after capture or via a separately budgeted drain. Decode on the host; check identity, versions, lengths, commit sequences, generations, drops and clock continuity. Preserve the raw original, decoder version and export provenance.
3. Build a timeline grouped by CPU, thread and transaction. Mark absent ends, lost records, unknown joins and uncertain intervals explicitly. Invalidate affected latency, completeness or safety conclusions; report unaffected intervals with their coverage. Optionally export redacted host-side timeline or statistical profile data in an interoperable format. Preserve original IDs/units and conversion notes. The export format is an analysis choice.

| Gate | Required evidence before claiming support |
| --- | --- |
| M1 | Native single-core scheduler/app events, schema decode, OFF behavior, saturation/nesting and malformed streams. Demonstrate a real first launch and independently witnessed dispatch. |
| M2 | Driver IRQ/deferred completion and causal handoff, denial and overload. Add live cross-domain IPC cases only after the existing IPC gate opens. |
| M3 | Per-board/core resource and latency bounds, migration calibration, counter reset, partial buffers, concurrent writers/export and containment under load. Keep QEMU and hardware evidence separate. |
| M4 | Versioned Rust/C SDK and supported prebuilt ELF combinations, service restart/ID reuse, concurrent request/timeout/cancellation timeline, access/redaction and optional export compatibility. |
