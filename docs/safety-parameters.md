# ADR-001 · 가상 벤치의 입력 상실과 출력 차단

한국어 · [English](safety-parameters.en.md)

**결정**　기능안전팀은 아래 값을 첫 벤치의 설계 입력과 합격 기준으로 고정한다. 적용 범위는 QEMU `virt`, Cortex-A72 단일 코어, 가상 출력 `ENABLE`이다. 출력은 시뮬레이션에만 연결된다. 현재 상태는 **벤치 기준 확정 · 시험 대기**다.

## 벤치 값과 근거

| 항목 | 설계값 | 근거와 판정 |
| --- | --- | --- |
| 입력 | 10 ms마다 허가 메시지 1개 | 합성 송신기가 현재 세대, 연속 순번, 발행 시각과 허가 비트를 제공한다. 벤치가 송신 시각과 세대를 통제한다. |
| 제어 태스크 | 주기 5 ms, 릴리스부터 완료까지 기한 5 ms | 입력 주기당 두 번 점검하도록 선정했다. 신선도 검사 완료 사이의 실제 간격도 스케줄링 지터를 포함해 최대 5 ms로 제한한다. |
| 입력 만료 | 발행 후 경과 시간 ≥ 20 ms | 마지막 유효 허가의 발행 시점부터 입력 주기 두 번이 지나면 만료된다. 정확히 경계에서 만료를 먼저 판정한 뒤 동시 도착 메시지를 처리한다. |
| 검출 예산 | `t_detect − t_fault ≤ 25 ms` | 마지막 허가 직후 송신이 끊기는 경우의 20 ms와 다음 검사까지 최대 5 ms를 합친다. |
| 검출 후 출력 차단 | `t_safe − t_detect ≤ 5 ms` | 검출 후 제어 주기 하나 안에 차단값이 가상 장치에 반영되어야 한다. |
| 종단 간 반응 | `t_safe − t_fault ≤ 30 ms` | 검출 25 ms와 이후 반응 5 ms를 이어 붙인 합성 시험 예산이다. 두 구간과 전체를 각각 판정한다. |

부팅 시 `ENABLE=0`이다. 허가 입력이 만료되면 고장을 래치하고 `ENABLE=0`을 유지한다. 시작 또는 복구 시 감독자가 새 세대를 열고, 그 세대의 허가 비트가 설정된 연속 메시지 두 개를 정상 주기로 받는다. 두 메시지가 모두 신선한 동안 별도의 명시적 재가동 명령이 들어와야 출력을 다시 켠다. 이전 세대·미래 시각·중복·역순·만료 메시지는 신선도와 복구 계수를 갱신하지 않는다.

## 독립 검증 인계

1. 정상 입력으로 `ENABLE=1`인 시작 조건을 확인한다. 주입기가 입력 차단을 원자적으로 적용한 시점을 `t_fault`로 기록한다. 이 경계에서 대기 중인 미전달 허가를 무효화하고 이후 송신도 차단한다. 직전에 이미 전달된 마지막 허가의 발행 시각은 보존한다.
2. `t_detect`는 제어기가 고장 래치를 설정한 상태 전이 시각이다. `t_safe`는 독립 관측기가 가상 장치에서 처음 관측한 `ENABLE=1 → 0` 전이 시각이다. 검출 표식과 장치 출력 전이를 따로 기록한다. 주입·검출·장치 이벤트는 서비스 상실 중에도 진행하는 동일한 단조 가상 게스트 시간축의 틱으로 계측한다. 검증팀은 클록 주파수·해상도와 이벤트 순서, 원본 틱을 보존한다.
3. 입력 전달 직후의 상실, 만료 직전의 검사, 만료와 새 허가가 같은 시각에 도착하는 경우를 시험한다. 정상 송신에서 조기 차단이 없는지, 차단 후에도 래치가 유지되는지, 재가동 조건을 하나씩 생략했을 때 출력이 계속 꺼져 있는지도 확인한다. 판정기의 경계 시험은 상한과 같은 값에서 합격, 1틱 초과 시 실패여야 한다. 이벤트가 누락되거나 계측 오차로 경계를 구분할 수 없는 실행은 합격 근거에서 제외한다.

추적 경로는 `OBJ-001`, `OBJ-004` → `ASM-001`, `HAZ-001`, `HAZ-003` → `REQ-002`, `REQ-003` → `DES-003`, `DES-006` → `VER-002`, `VER-003`이다. 새 검증자가 고정된 후보에서 시험한 뒤 증거를 발행한다. 클록 자체의 고장과 실제 액추에이터 반응은 별도 실보드·HIL 검증 범위다. [시스템 요구사항](requirements.md) · [검증 계획](verification-plan.md)

### 경계 조건별 독립 실행

각 시험은 초기 상태를 다시 설정한다. 아래 예에서는 발행과 전달을 같은 게스트 틱에 둔다. 재가동 메시지의 정상 간격은 발행 시각으로 측정한다.

| 사례 | 자극과 기대 결과 |
| --- | --- |
| 최악 검사 위상 | 출력이 켜진 상태에서 마지막 허가를 0 ms에 전달하고 곧바로 차단한다. 검사를 20 ms보다 1틱 앞서 완료시키고 다음 검사는 그로부터 5 ms 뒤에 완료시킨다. 실제 검사 완료 틱을 기록한다. 이벤트가 `t_fault ≤ t_detect ≤ t_safe` 순서인지 확인한 뒤 각 시간 상한을 검사한다. 같은 틱이면 기록된 이벤트 순서로 판정한다. |
| 만료와 도착 경합 | 별도 실행에서는 전달 경로를 열어 둔다. 0 ms에 유효 허가를 전달하고 10 ms 발행을 생략한다. 20 ms 검사와 같은 틱에 다음 연속 순번의 유효 허가를 전달한다. 만료가 먼저 처리되어야 하며, 고장이 래치되고 5 ms 이내에 출력이 꺼져야 한다. |
| 재가동 | 차단 상태에서 새 세대의 연속 허가를 0 ms와 10 ms에 발행한다. 15 ms에 재가동 명령을 주면 출력이 켜져야 한다. 별도 실행에서 20 ms에 처음 명령하면 첫 허가가 만료되어 출력이 꺼진 채여야 한다. 두 번째 허가 전에 보낸 명령은 저장하지 않으며, 이후 새 명령이 있어야 재가동한다. |

## 제품 값의 결정 조건

제품 FTTI는 특정 운용 상황에서 고장이 발생하고 안전 메커니즘이 개입하지 않을 때 위험 사건이 발생할 수 있는 가장 이른 시점까지의 간격이다. 기능안전팀은 제품 정의, 운용 시나리오와 HARA, 실제 시스템의 물리 반응 모델 또는 측정 근거로 해당 구간과 안전 상태를 도출한다. 시스템팀과 함께 검출·통신·스케줄링·액추에이터의 최악 반응시간과 불확실성을 배분하고, 가장 짧은 해당 FTTI 안에 명시적 여유가 남는지 확인한다. 보드 안전 매뉴얼, 실제 I/O 소유권, 실보드·HIL 결과와 적용 가정을 함께 검토한다. 기능안전팀이 근거와 권고안을 제출하면 지정된 아이템 통합 승인권자가 독립 검토 결과를 바탕으로 해당 제품에서의 적용 범위·버전·승인 결정을 기록한다. 제품 FTTI, ASIL과 실제 출력 차단 시간은 현재 미정이다.
