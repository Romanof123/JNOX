# 일반 Rust 뮤텍스 작업과 원시 관측 기록

[English](ordinary-mutex-runtime.en.md)

CHG-067은 기본 시계, 메모리 128 MiB, GICv2 및 물리 타이머 PPI30을 갖춘 QEMU virt의 Cortex-A72 한 개에서 실행한다. kernel/에서 Rust 1.95.0으로 cargo build --locked --release -j1을 사용한다. JNOX_BOARD=virt, JNOX_PROFILE=mutex로 설정하고 JNOX_APP에는 ordinary-pi 또는 ordinary-ceiling을 지정한다. 일반 실행과 외부 예외 추적 실행은 구성별로 동일한 ELF를 쓴다. 앱 누락·미지원 이름, Pi 4, 경쟁 벤치 기능, fixed trace 또는 control case를 지정하면 빌드 선택자가 거부한다. 기존 mutex-bench의 어셈블리 역전·타임아웃·천장 검증 범위는 EVD-018에 기록돼 있다.

작업 ID 0/1/2/3은 LOW/MEDIUM/HIGH/idle이고 기본 우선순위는 2/5/9/0이다. 자원 0은 X, 1은 Y이다. PI 구성에서 LOW와 HIGH는 X를 쓴다. 천장 구성에서 LOW와 MEDIUM은 X(천장 5), LOW와 HIGH는 Y(천장 9)를 쓴다. 기존 LockSet과 안정 순서 ReadyQueue가 실효 우선순위·소유권 이전·다음 작업을 결정한다. 인터럽트로 중단되거나 시스템 호출에서 복귀할 작업은 같은 우선순위의 앞쪽에, 명시적으로 양보하는 작업은 뒤쪽에 넣는다. 천장 구성의 LOW만 128번째 청크 완료 시 한 번 양보한다. 잠금 획득 성공 시 저장 프레임의 x0에 0을 반환하며, 대기자가 직접 소유권을 이어받는 경우도 같다.

LOW가 마지막 필요 자원을 획득한 SVC 끝부분에서 실제 카운터를 읽고 최초 비교값을 시작값+CNTFRQ/10000으로 설정한다. 그 다음 어셈블리 복원 기록으로 복귀 준비 비용을 구분한다. 최초 IRQ가 LOW의 실제 보호 계산 중 발생했는지 해당 ELF의 PC와 레지스터로 판정한다. 진행 플래그만 켜진 복귀 구간이나 양보 호출에 도착한 IRQ는 보호 계산 중단을 입증하지 못한다. 타이머는 한 번만 무장한다. 각 구성에서 최초 일반 실행과 외부 추적 실행을 별도 보존하고 ELF·인자·시계·UART·종료 상태·해당 예외 로그를 함께 남긴다. 호스트 시간 초과도 불완전한 최초 관측으로 보존한다.

## MUTEX RAW 1

모든 수는 부호 없는 16진수다. NA는 모든 비트가 1인 값이다. 정지 시 출력은 MUTEX RAW 1로 시작해 MUTEX END로 끝난다. 마지막 작업 종료 시 IDLE 선택을 기록한 다음 출력하고 정지하므로 대응하는 복원은 없다. 행 누락, 개수 불일치, 예상된 복원 누락, 오버플로 또는 끝 표식 없는 출력은 통과할 수 없다.

| 행 | 전송 순서대로 나열한 필드 |
| --- | --- |
| H | 천장 구성 여부, 정지 사유, E 행 수, R 행 수, 완료 청크 수 |
| T | 카운터 주파수, 무장 시작값, 요청 CVAL, 무장 시 CVAL 되읽기, 무장 CTL, 원시 IAR, IRQ 시 CTL·CVAL |
| S | 작업 ID, 기본 우선순위, 스택 시작 주소(포함), 스택 끝 주소(제외), 프레임 크기 |
| E | 벡터 진입·결정 기록 카운터, 연산, 자원/인자, 호출자, 후속 작업, 나가는 프레임·PC·SPSR·x19, 선택 프레임·PC·x19, 선택 작업 포함 준비 마스크, X·Y 소유자, X·Y 대기 마스크, ID당 한 바이트의 실효 우선순위(LOW가 하위 바이트), 연산 결과, 완료 청크 수, 계산 중 표시, 종료 마스크, 나가는·선택 프레임의 TPIDR_EL1, 선택 프레임에 저장된 x0 |
| R | 어셈블리 복원 프레임, ELR, 최종 일반 레지스터 복원과 ERET 앞의 카운터 |
| C | 완료한 청크별 누적 표본 수와 누적 합 |
| B, HIGH | 보호된 버전·표본 수·합, HIGH가 실제 읽은 동일 세 필드 |
| A | 천장 구성에서 LOW가 X 아래 작성한 감사 버전·완료 청크 수 |
| M | MEDIUM이 읽은 감사 버전·청크 수와 독립 계산 합 |
| K | LOW의 마지막 획득 복귀 뒤, 커밋 뒤, 감사 작성 뒤, HIGH의 획득 시도 전, 실제 획득 복귀 뒤, 데이터 읽기 뒤, MEDIUM의 감사 읽기 뒤, 독립 합 완료 뒤, LOW의 해제 핸들러에서 HIGH로 소유권 이전 뒤의 순서로 저장한 카운터 |

E 연산 1/2/3/4/5는 획득·해제·양보·종료·IRQ이다. 막힌 획득은 NA를 기록한다. 해제 시 소유권을 이전하고 저장 x0를 갱신한 뒤 다음 프레임을 선택한다. 외부 추적이 있으면 R과 실제 예외 복귀를 대조한다. 전체 프레임이 해당 작업 스택 안에 있어야 한다. IRQ 진입부터 HIGH 시도까지, HIGH 차단부터 K[8]까지, K[8]부터 실제 복귀 K[4]까지, LOW 획득·커밋·해제 구간을 개별 산출한다. K[3]은 SVC 직전이다. 미도달 K값은 0이다. 우선순위와 준비 순서, 청크 256개의 누적 결과, 실제 버전·읽기, MEDIUM 합, 각 종료와 재개를 독립 재생한다. 최초 LOW 재개 시 중단 PC와 레지스터가 연결돼야 한다. 정지 사유 0은 게스트 완료를 기록한다.

정지 사유 1–4는 각각 실행 상태 초기화, 준비열 삽입, 빈 선택, 프레임 신원·범위 오류다. 5는 기록 넘침, 6/7은 잘못된 획득/해제, 8은 잘못된 양보, 9는 잘못된 종료, 10은 잘못된 SVC, 11은 작업의 호출 반환 오류, 12는 종료 호출에서 복귀, 13은 무장 오류, 14는 IRQ 신원·되읽기 오류, 15는 해제 자극·차단·소유권 이전 누락, 16은 계산 구간 밖 해제 자극, 17은 예기치 않은 벡터 또는 복원 기록 넘침, 18은 결과·우선순위 복원 불완전이다. 결정 기록은 32개, 어셈블리 복원 기록은 64개, 청크 기록은 256개까지다. 제품 잠금 집합·물리 최대 차단·WCET·보드 간섭은 별도 검증 대상이다.

## 요구사항 추적과 최초 검증 대기

VER-002·005·023에 따른 최초 검증은 대기 중이다. 네이티브 테스트는 소유권 이전과 우선순위 복원 조건을 다룬다. 독립 검증자는 최초 실행 네 건을 보존하고 모든 전이·청크를 재생 결과와 대조해 정지 이유와 관측 누락을 기록한다. [네이티브 테스트 소스](../tools/scheduling_tests.rs) · [검증 계획](verification-plan.md)
