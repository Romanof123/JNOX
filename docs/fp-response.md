# RM·DM 태스크의 응답 시간 분석

한국어 · [English](fp-response.en.md)

[EVD-008 독립 검증 결과](evidence/evd-008.md)

CHG-010은 POL-004, REQ-002, REQ-023의 분석 도구 IMP-008을 DES-003, DES-012에 배정한다. VER-002와 VER-023은 실제 주기 태스크를 실행하는 게스트와 별도로 계산 결과를 확인한다. 기능안전팀과 플랫폼팀은 적용할 보드·클록·빌드·부하의 상한값을 제공한다. 도구는 개발 호스트에서 실행한다. [RM·DM 실행 계약](m1-periodic.md) · [스케줄링 출시 기준](scheduling-policies.md)

저장소 루트에서 `python tools/fp_response.py docs/examples/rm-dm-workload.json`을 실행한다. 예제는 두 태스크의 실행 비용과 기한을 고정하고 DM을 선택한다. `policy`만 `rm`으로 바꾸면 주기가 짧은 태스크가 먼저 실행된다. [입력 예제](examples/rm-dm-workload.json) · [Python 도구](../tools/fp_response.py)

## 입력과 가정

- 처음에는 유휴 상태인 완전 선점형 단일 코어, 서로 독립적인 산발 태스크를 가정한다. 시간은 같은 단위의 정수 틱이다. 태스크마다 고유 ID, 양의 최소 도착 간격 `period`, 주기를 넘지 않는 양의 상대 기한 `deadline`, 양의 최악 실행 비용 `wcet`를 입력한다.
- 선택 입력 `dispatch`는 작업 한 건에 배분한 디스패치·선점 비용의 총상한, `blocking`은 낮은 우선순위 작업 때문에 기다리는 총시간의 상한이다. `jitter`는 명목 도착 시각부터 준비될 때까지 지연의 상한이며 기한보다 작아야 한다. 기본값은 각각 0이다. 적용 구성의 스케줄러·하드웨어 비용을 입력에 반영한다. 작업의 자발적 대기나 코어 이동에는 별도 모델이 필요하다.
- `irqs`의 각 항목은 고유 ID, 최소 도착 간격, 실행 비용 `wcet`, 선택적 지터를 갖는다. 모든 IRQ는 각 태스크를 선점할 수 있다. 입력 전체에서 같은 IRQ 실행 비용은 한 번만 계상한다.
- RM은 주기, DM은 상대 기한이 짧은 순으로 우선순위를 정한다. 선택한 정책의 순위 값이 같으면 동순위 실행·간섭 모델이 필요해 입력을 거부한다. 중복 ID·JSON 키, 소수·음수·불리언 시간 값도 거부한다. 실행 비용, 주기, 기한은 0을 허용하지 않는다.

## 계산 및 판정

태스크 *i*의 첫 계산 구간은 *w = Cᵢ + Bᵢ*다. *Cᵢ*에는 작업당 디스패치 비용이 들어간다. 반복할 때마다 같은 기본 구간에 상위 우선순위 태스크와 모든 IRQ의 간섭을 더한다. 간섭원 *h*의 기여는 *ceil((w + Jₕ) / Tₕ) × Cₕ*다. 구간이 더 늘지 않으면 *Jᵢ + w*가 명목 도착부터 완료까지의 상한이다. 기한과 같으면 통과한다. 선택 JSON 입력 `iteration_limit`의 기본값은 태스크당 1,024회다. [정적 우선순위 응답 시간 상한 연구](https://www.cs.york.ac.uk/rts/publications/Davis2008a.html)

| CLI 종료 코드 | 결과 | 의미 |
| --- | --- | --- |
| 0 | `within_bounds` | 모든 태스크가 입력한 가정에서 기한 이내다. |
| 1 | `deadline_exceeded` | 반복 중 기한을 초과한 값을 제시하고 상한은 비워 둔다. 실제 기한 위반 여부는 실행 관측으로 확인한다. |
| 2 | `inconclusive` 또는 입력 오류 | 수렴 전 반복이 끝났거나 입력을 거부하고 원인을 출력했다. |

예제를 DM으로 분석하면 urgent는 1틱, short는 3틱이다. RM에서는 short의 상한이 2틱이고 urgent의 계산값이 기한 2틱을 초과한다. 독립 시험은 지터·차단·IRQ·디스패치 비용의 조합, 반복 한도 소진과 동기 도착 참조 스케줄도 확인한다. 판정은 전체 태스크 집합에 적용한다. [인수 시험](../tools/test_fp_response.py)
