# Pi 4 native fixed-priority applications / Pi 4 네이티브 고정 우선순위 앱

[#321](https://github.com/Romanof123/JNOX/issues/321) · CHG-129 · POL-002. Prospective baseline efce8a0550cf9b7b877b6065d95b9b7cb050a1b3. Boot two operator-supplied ordinary AArch64 user ELFs under FIFO or RR on the Pi 4 BSP, using the same syscall ABI, virtual addresses and fixed dispatcher as virt. CPU0 runs the processes. Other cores remain parked. [Existing native policy](native-fixed-processes.en-ko.md) · [Pi 4 fixed runtime](boards/pi4-fixed-runtime.en.md)

## Operator workflow / 실행 방법

~~~sh
sh sdk/native-aarch64/build-c.sh examples/native-fixed/prime_low.c low.elf
sh sdk/native-aarch64/build-rust.sh examples/native-fixed-rust/Cargo.toml high.elf
python3 tools/build_native_el0.py --out pi-fifo --board pi4 --policy fifo --elf low.elf --priority 2 --peer-elf high.elf --peer-priority 2
python3 tools/build_native_el0.py --out pi-rr --board pi4 --policy rr --quantum-ticks 1250000 --elf low.elf --priority 2 --peer-elf high.elf --peer-priority 2
python3 tools/package_pi4.py --kernel pi-rr/kernel8.img --output pi-rr-boot --firmware-dir pinned-boot
qemu-system-aarch64 -M raspi4b -accel tcg -display none -serial stdio -kernel pi-rr/kernel8.img
~~~

Produce kernel.elf for inspection, a compact raw kernel8.img and a manifest binding board, load/entry and runtime addresses, policy, priorities, quantum, tool versions, kernel/raw hashes and both ordered ELF hashes. Retain public native input validation and any existing primary C input route. Support arbitrary valid admitted programs under the existing native ABI and fixed policy, including approved ordinary syscalls. Pass existing app arguments normally. For this release the Pi native profile requires exactly two images and FIFO or RR. Reject unsupported board/policy/count/feature combinations at CLI and direct Cargo selection. Default board is virt. Existing Pi linked fixed/serial images keep their original entry and board linker contract.

같은 사용자 ELF 두 개를 다시 링크하지 않고 보드만 선택한다. FIFO·RR과 우선순위·퀀텀은 기존 의미를 따른다. 생성된 원시 이미지로 기존 펌웨어 묶음을 만들 수 있으며 매니페스트가 빌드 입력과 출력 해시를 연결한다.

## Cold load and address spaces / 초기 적재와 주소 공간

Use a dedicated Pi native linker layout. Firmware and QEMU load the contiguous raw bytes at 0x00080000. Place the stackless boot shim within the first 4 KiB; link initialized payload for identity VA/PA 0x02000000 with consecutive load addresses starting at 0x00081000. Export exact source, destination and copy length, including initialized data and embedded ELFs. Assert that the shim fits, load source ends at or below destination, copy endpoints cannot wrap, raw file ends at its last initialized byte, and live kernel including cleared BSS, tables, two 4 MiB private image backings, private stacks and kernel stack ends at or below 0x04000000. This gives 32 MiB of kernel space, enough in layout for two 8 MiB input ELF containers and 8 MiB private image RAM plus up to 8 MiB other kernel state; enforce actual section sizes. Preserve the native ELF parser’s independent 4 MiB VA aperture, segment and file-size guards. Use ELF program/section headers and raw byte comparison to establish the two addresses; do not include a 32 MiB hole or NOLOAD zero-fill in kernel8.img.

Park secondary MPIDRs before any global write, stack setup or relocation. CPU0 handles the existing Pi entry exception levels/masked state and BSP path. Copy initialized bytes before enabling translation, with no references to high data or reliance on an uninitialized stack. Honour the boot cache state, clean copied instructions to point of unification and invalidate the relevant instruction stream with required DSB/ISB before executing the relocated entry. Set relocated stack, zero BSS exactly once and retain reset-state checks. Assert/link-map-check both entry symbols. Keep firmware config kernel_address=0x80000, arm_peri_high=0 and enable_gic=1. After enabling translation the low raw source and stub need no kernel mapping.

For each process TTBR0, root index 0 must lead to that process’s low L2 table. Install private mappings at user image [0x00400000,0x00800000) and user stack [0x01001000,0x01011000), leaving guard pages invalid. Install the shared kernel identity L3 tables at distinct L2 indices 16..31 for [0x02000000,0x04000000); map only live pages. Never overwrite root[0] with a shared kernel-only table. Keep user text RO executable at EL0/PXN, user data/stack RW UXN/PXN, read-only data RO/XN and per-process ASID/non-global mappings. Kernel text/rodata use the established privileged permissions, writable pages and stacks privileged RW/XN. Keep physical backing identity aliases privileged. Preserve frame, TTBR and ordering on dispatch. Test translation permissions by walking saved tables, including same user VA to distinct private PAs, guard holes and device inaccessible at EL0.

Map board-only GPIO (0xfe200000), PL011 (0xfe201000), GICD (0xff841000) and GICC (0xff842000) via the high device root index 3 at EL1, Device/XN, using the established Pi BSP. GPIO/UART share an L2 slot; the GIC pages share another. Use the architectural physical timer PPI30 and its real acknowledge/EOI/compare path. Record CNTFRQ and observed counter values rather than assuming a virt frequency. No virt UART/GIC aliases should be installed. The existing [MMU code](../kernel/src/native_el0_mmu.rs) assumes LINK_START 0x40200000, an independent RAM root and virt device addresses; board-specific population must preserve the ordinary virt configuration.

펌웨어는 0x80000에서 CPU0의 작은 초기 코드를 시작한다. 파일 내 연속된 초기화 데이터를 32 MiB 지점으로 복사한 뒤 그 위치에서 커널을 실행한다. 보조 코어는 복사 전에 정지한다. 32~64 MiB 사이의 실제 커널 페이지만 특권으로 매핑하고 사용자 코드·데이터와 16 MiB 부근 스택은 각 프로세스 전용으로 유지한다. 장치 영역에는 Pi 4 주소와 권한을 사용한다.

## First captures / 최초 관측

Freeze the two stock binaries above before packaging either board. A counts primes below 1,000,000, publishes 78,498 and exits 12. B counts primes from 1,000,001 below 2,000,000, publishes 70,435 and exits 77. Both compute without a scheduling syscall until exit. On virt the short pair showed eight switches at 1,250,000 ticks; this is the selected quantum and historical observation. The Pi case requires actual A→B→A involuntary rotation before either exits; score observed switches. [Previous workload evidence](evidence/evd-115.en.md)

Take the first FIFO plain/traced and RR plain/traced boots using stock raspi4b with raw -kernel kernel8.img, the model's normal multicore reset, TCG and default clock. Add -d int -D path for external exception evidence; retain same raw image in each pair. FIFO must run A until exit and then B with zero equal-priority timer rotations. RR requires timer-driven interruption/restoration within the independently disassembled workers, the correct private stack and continued progress after a peer turn. Check status and full private results in all normal captures via independent read-only physical memory inspection of the mapped words. Record unchanged app hashes, ELF/section map, MMU mappings, counter samples, ready order, raw UART, first results, QEMU version/argv and trace where requested. Require that only CPU0 runs application or scheduler code, allow reset/park execution on other cores. Archive failures without substituting retries. Separately perform unchanged virt FIFO/RR compatibility and existing Pi linked fixed smoke, and compare both staged firmware-directory packages against the pinned hashes/config and original kernel8.img. Include build controls for invalid board/policy and invalid ELF. Inspect maximum-size link/relocation constraints and ensure the normal app-copy, page-walk and guard checks still apply.

Direct raw model boot bypasses VideoCore/EEPROM/SD firmware execution. A staged boot tree yields firmware and kernel identities. Physical power cycles, actual UART wiring/routing, board timing and product acceptance require separate records under [#34](https://github.com/Romanof123/JNOX/issues/34) and [#21](https://github.com/Romanof123/JNOX/issues/21).

동일한 ELF와 원시 이미지로 정책별 일반·추적 부팅을 각각 보존한다. FIFO의 완료 순서, RR의 타이머 선점·동일 프레임 복귀와 두 프로세스의 독립된 산출물을 판정한다. raspi4b 직접 적재와 고정 펌웨어 디렉터리 생성은 각각 별도 근거이며 실물 전원 인가·SD 부팅·물리 시간 판정은 남는다.
