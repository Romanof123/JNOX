# Hard CPU reservations for native applications / 독립 네이티브 앱의 CPU 예산 격리

[#302](https://github.com/Romanof123/JNOX/issues/302) · CHG-119 / IMP-119 / EVD-119 · #12 / #21 POL-008. Prospective design on accepted main `33ee8c35a62ede54987f9af4ae51d3f2fcea3d35`. An operator assigns each independently built C or Rust application a CPU quota. A continuously computing process can exhaust its entitlement while a neighbor continues receiving its own grants. Unused capacity stays idle. [Existing release gate](scheduling-release-cases.en.md)

운영자가 독립 ELF마다 CPU 예산과 보충 주기를 지정한다. 계산량이 많은 앱이 예산을 소진하면 실행 자격을 잃고, 동료 앱은 자신의 예약에 따라 실제 작업을 진행한다. 명목 실행권과 물리 카운터에서 관측한 서비스는 따로 판정한다.

## Packaging and admission / 설정과 수용 판정

~~~sh
python3 tools/build_native_el0.py --out isolated --policy cbs \
    --elf crc.elf --reservation 1,4 --peer-elf histogram.elf --peer-reservation 1,4
~~~

Each tuple is quota Q and implicit-deadline period P, both unsigned u32 **counts of 50 ms slots**. A primary C source or prelinked ELF and zero to two peer ELFs use one tuple each in package order. Require 0<Q≤P, exact reduced-rational Σ(Q/P)≤1, representable intermediates/reduced totals as in the current admission routine, and checked time conversion. Reject missing, duplicate singleton, extra or conflicting options at the CLI and raw Cargo boundary. Bind all tuples, units, ELF hashes and ordering to the image and manifest. Recheck the whole set before CPU0 arms an operational compare or enters any user frame. Record precise refusal categories (invalid, excess capacity, arithmetic). A future common epoch E starts all servers ready. No SDK job-cost declaration is needed. Preserve cooperative, FIFO/RR, weighted, EDF and existing linked server selectors.

[HardCbs](../kernel/src/temporal_policy.rs) already implements exact admission, hard depletion, wake density and EDF arbitration. Its finite `release(id,work)` and `tick()` decrement outstanding synthetic work. Extract the common entitlement/selection operation so existing callers retain that API and the native adapter supplies ongoing runnable/blocked/exited state instead. Each independently loaded process owns its private memory, preserved registers and stack; use the normal CPU0 EL0 exception path. The aligned [PeriodicReservation](../kernel/src/service_policy.rs) has different refill behavior. It remains a distinct policy. [Native packager](../tools/build_native_el0.py) · [Historical linked implementation](https://github.com/Romanof123/JNOX/blob/62ea1ebcb653dc51595eb8361785dd8c12e5e9fe/kernel/src/reservation_jobs.rs)

Q,P의 단위는 각각 50 ms 슬롯 수다. 1~3개의 ELF에 대해 Q/P를 정수 유리수로 더해 1 이하일 때만 전체를 수용한다. 모든 슬롯을 검사한 뒤 실행을 시작한다. 기존 HardCbs의 예산·선택 로직을 공유하고 네이티브 앱의 실행 가능 여부는 실제 차단·종료에서 얻는다. 주기 경계에 맞춰 무조건 보충하는 정렬형 예약은 별도로 유지한다.

## Grant, replenish and wake / 실행권·보충·깨움

At slot t, deadline d is in slot indices, q is the remaining nominal quota. Initial activation sets (q,d)=(Q,t+P). An active depleted server waits until d; at d its next allocation becomes (Q,d+P). On an inactive-to-active transition at arbitration t, renew to (Q,t+P) when t≥d or qP>Q(d−t), otherwise retain both values, including equality and q=0 before d. Use checked/wide integer arithmetic. Choose the eligible server with earliest d, tie by ascending slot ID. Debit exactly one unit once per grant. Keep the server active across budget depletion and normal nonblocking SDK calls. No inactive-wake renewal on a yield or interrupt return.

One grant starts per absolute boundary E+tS. A normal absolute sleep blocks its own process; a wake between boundaries makes it pending for the next selection, with t the first boundary at or after wake. An already-due sleep returns immediately. Yield forfeits the rest of the current grant, returns zero on next selection, and keeps its residual allocation. Sleep, yield or exit midway forfeits the tail to idle. A sleeping/exited process cannot win a grant; other slots cannot borrow the tail. Exit cancels future activation and records the private product and status. A lone continuously ready but depleted process must also idle. Program a dormant idle system for its next relevant boundary or wake. All exit finishes the run. Keep the frame at the interrupted PC or post-SVC continuation and switch process mappings before return.

For this QEMU profile, S=50 ms, F=CNTFRQ exactly divisible by 1000, guard G=F/1000 counts. Arm each long grant's physical cutoff for E+(t+1)S−G (S expressed in counts in counter formulas); idle the guard tail. Freeze E after loader preparation. Record entitlement, compare, actual physical return/entry brackets and positive worker progress. A cutoff arriving late cannot erase executed CPU time. Record full observed excess against the actual outgoing owner. On detected crossed slot end, guard violation or skipped opening that makes the deployment timing contract fail, inhibit further operational grants, retain the original event and report lost opportunities. No synthetic catch-up dispatch or retroactive transfer of service to the neighbor. Distinguish real stop/launch bounds from a nominal tick debit.

예산이 0인 활성 서버는 d까지 기다린다. 비활성 서버의 깨움은 잔여 밀도 qP와 Q(d−t)를 비교하며 등호에서는 유지한다. 가장 이른 서버 마감, 동률이면 작은 슬롯 ID가 이긴다. 양보·차단·종료 후 남은 창은 유휴로 두고 다른 앱에 넘기지 않는다. 양보는 신규 깨움으로 처리하지 않는다. 명목 창 끝 1 ms 전에 컷오프를 설정한다. 늦은 IRQ로 실행된 시간은 원래 실행자에게 기록하며 한계를 넘기면 후속 실행을 억제하고 잃은 동료 기회를 남긴다.

## Deployed configurations and scoring / 배포 설정과 판정

Use one Cortex-A72, QEMU virt/GICv2/TCG, 128 MiB, default clock. Freeze ELF and source hashes, package manifests, exact inputs, qemu command, clock, witness capacity, loop limit, timeout and first plain/traced positions before scored boots. No calibration against the first result. The CPU-bound C client computes CRC-32/ISO-HDLC over complete 4,096-byte ramps; the Rust client accumulates 16 high-nibble histogram bins over the same ramp. Each complete block contains 16 copies of 0..255, so each histogram bin gains 256. Store a private block counter and full result per completed block; independently recompute CRC with zlib from the actual completed block count and all 16 bins arithmetically. Use volatile inputs/results and mapped instruction ranges. To ensure useful work across the declared window, finish at the first block boundary with at least 650 ms elapsed on the ordinary monotonic clock since the app's first dispatch; cap at 2²⁰ blocks with a distinct exhaustion error. Use u64 byte/bin counters. Finish with statuses 17 and 29 only after validating results in replay. Check-clock calls keep the grant intact. Freeze separate short/bursty binaries for SDK edge cases.

At the 3-server table, slot 2 initially has deadline 2; after its slot-0 debit it is depleted until 2. At slot 1 the two deadline-4 servers tie; at slot 2 all three have deadline 4 and slot 1 precedes 2 once slot 0 is exhausted. Replay that ordering and actual EL0 evidence, not just grant totals. Qualify a normal grant only if the conservative upper bracket for first eligible dispatch is within 1 ms of opening, cutoff lateness ≤1 ms where a cutoff is used, upper bound on outgoing stop ≤ nominal end, upper elapsed execution ≤S per grant and ≤Q·S per allocation, and measured progress is positive. For each grant record the software pre-ERET counter as a **lower** bound on the actual EL0 return. Use the first ordinary post-return clock syscall or other verified EL0-origin exception entry for that grant as a conservative **upper** bound, sampling the first such witness only once per grant. An independently measured external upper bound tied to the same return may also be used. A timer entry from idle or EL1 supplies no such EL0 witness. Preserve the private productive loops and existing nonblocking clock reads; a sparse witness may leave a wide bracket. Upper bound ≤ opening+G qualifies the dispatch criterion; lower bound > opening+G proves a miss. Otherwise report that criterion as indeterminate, leaving timing qualification partial. For long cutoffs correlate actual saved PC and restore to the same process. For short grants verify positive useful work and actual early SVC. Store raw entry, post-selection, pre-ERET and following exception samples; if conservative bounds cannot decide, mark unqualified. Counts are entitlements. Record wall-clock time while a slot owns the grant, including applicable exception/restore and kernel residency. Report bounded user execution separately only where independent boundaries support it. Application progress is the private completed work; owner wall time alone does not establish time spent computing or 50 ms of EL0 service. Record terminal/overflow or truncation explicitly and do not score incomplete positions.

Independently retain the historical W arithmetic for scripted inactive activations at 0,4,5,13,22 and 23, B active from 1: equality at 4, zero-budget wake at 5, excess density at 13, expiry at 22, lower density at 23. Under those inputs B wins 1,5,9,13,17,21,25,29,33. Only apply that sequence when releases and workload match the historical profile. For normal native SDK sleeps use recorded real boundaries, classify which branches occurred, and publish any unobserved branch. Exercise equality and one physical count over each guard, invalid duplicated debit, stale owner, no worker progress, post-exit dispatch and arithmetic overflow in deterministic host controls. Synthetic late timestamps establish fault classification only. Keep the guest timer and delivery path unmodified and the late-event observation passive.

C 앱은 바이트 램프 CRC를, Rust 앱은 16구간 히스토그램을 계산한다. 실제 완료 블록 수로 독립 원값을 복원한다. 포화 시 8슬롯 교대, 저부하 설정에서는 A·B·유휴·유휴가 두 번이어야 한다. 9/8은 사용자 진입 전에 거부하고, 세 서버 정상 설정도 별도로 실행한다. 실제 복귀·작업 진행·늦은 정지·ID별 서비스를 원시 카운터와 주소 공간으로 확인한다. 컷오프·창 시작의 1 ms, 실제 종료와 슬롯별·할당별 상한을 보수적 구간으로 각각 판정한다. ERET 직전 표본은 실제 사용자 복귀의 하한이다. 해당 실행권에서 복귀 후 처음 관측한 일반 시계 호출 또는 EL0 예외 진입을 한 번만 기록해 상한으로 쓰며, 독립 측정 상한도 허용한다. 1 ms 경계가 구간 안에 있으면 부분 판정으로 남긴다. 소유 중 벽시계 경과와 사용자 계산량은 구분한다. 정상 타이머에서 자연 발생한 늦은 컷오프만 관측하며 전체 조건이 없으면 미관측이다. 호스트 합성 표본은 오류 분류만 검증한다.
