# 두 CPU에서의 스케줄링과 작업 이동

[English](m3-smp.en.md) · [변경 이슈 #47](https://github.com/Romanof123/JNOX/issues/47)

CHG-019에서 POL-013 및 REQ-002/005/008/023을 DES-003/004/012, IMP-017, VER-002/005/008/023에 연결한다. 대상은 Cortex-A72 가상 CPU 두 개, GICv2, 물리 범용 타이머, RAM 128 MiB, 멀티스레드 TCG를 사용하는 QEMU virt다. 최초 두 작업은 한 번의 상태 변경으로 함께 준비된다.

| 사례 | 수행 동작과 합격 기준 |
| --- | --- |
| 부팅 | CPU0가 EL1에 진입한 뒤 PSCI CPU_ON64로 affinity 1을 기동한다. 두 CPU에서 같은 주소의 RAM을 내부 공유 가능 Normal 메모리로, 주변장치를 Device 메모리로 매핑한다. CPU1은 전용 부팅 스택을 쓴다. 스케줄링 전에 양쪽에서 원자적 요청과 응답을 확인한다. |
| 고정 배치 | M과 P0는 CPU0에, P1은 CPU1에 고정한다. M과 P1이 모두 진입한 후에만 하나라도 종료될 수 있다. M 이후 P0가 CPU0에서 실행된다. |
| 전역 배치 | M은 양쪽 CPU를 쓸 수 있다. CPU1에서 P1을 종료한 뒤 CPU0에서 실행 중인 M을 가져오려 하면 거부해야 한다. CPU0의 물리 타이머 IRQ가 M을 중단하고 문맥을 저장한 뒤 CPU0 고정 작업 P0가 준비된다. P0는 CPU0, M은 CPU1에서 진행해야 한다. 이동 전후 명령 주소, 스택, 레지스터, TLS와 진행 카운터를 대조한다. |
| 클러스터 배치 | CPU 하나씩 논리 클러스터를 구성한다. CPU1이 비어 있을 때 CPU0 전용 M이 준비 상태라도 CPU1의 인수 시도를 거부해야 한다. CPU0에서 P0가 실행되고 M은 원래 클러스터에서 재개된다. |
| 소유권과 회계 | 한 스케줄러 상태 안에서 각 실행권은 작업, CPU, 발급 순번으로 식별한다. 반환 시 발급부터 반환까지 관측한 범용 카운터 간격을 한 차례 더한다. 중복 반환과 덧셈 오버플로는 상태를 보존해야 한다. 나가는 작업의 스택에 문맥을 저장한 뒤 CPU 전용 예외 스택으로 전환하고, 그 후에만 잠금을 잡고 다른 CPU에 문맥을 공개한다. |

부팅 시 커널 이미지·스택·변환 테이블을 담은 2 MiB RAM 블록 하나에 특권 쓰기·실행 권한을 준다. 주변장치는 GIC 분배기, CPU 인터페이스 및 UART 페이지만 매핑한다. 제품용 메모리 보호 설계는 별도 검증 대상이다.

## 재현과 판정

저장소 루트에서 고정 버전 Rust로 빌드하고 가상 시스템을 한 번에 하나씩 실행한다.

```sh
(cd kernel && cargo build --locked --release --features smp-bench -j1)
python3 tools/qemu_boot.py --profile smp --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel
```

신규 검증자는 먼저 이 계약과 고정 소스·이미지 식별자를 받고 첫 실행 결과를 기록한 뒤 구현 및 이전 결과를 열람한다. 같은 실행에서 UART, QEMU 예외 기록, CPU 식별자, 문맥·실행권 기록, 카운터 주파수와 반환·인수 시각을 보존한다. 전체 UART 순서, 100 ms 무출력 구간과 호스트 종료를 확인하고 실행 순서가 달라질 수 있음을 고려해 작업 이력을 다시 구성한다. 호스트에서는 잘못된 일괄 준비 요청, affinity, 인수 경합, 실행권 재사용, 덧셈 한계와 독립 배치 기준을 검사한다.

가상 카운터 간격은 해당 실행에서 측정한 값이다. POL-013의 실물 이동 지연, 정의된 부하에서의 공유 캐시 간섭, 제품별 합격 기준 및 안전 승인은 열려 있다. 실보드 접근을 기다리고 있다. [스케줄링 카탈로그](scheduling-policies.md) · [보드 추적](https://github.com/Romanof123/JNOX/issues/34)

ELF의 smp_audit는 리틀엔디언 64비트 정수 140개다. 0–4번은 버전, 완료 사례 수, 구간 수와 CPU affinity, 5–18번은 인수 거부 두 건, 19–30번은 출발·도착 CPU, 저장·선택 PC, 저장·실행 SP와 레지스터 관측값이다. 31–39번과 40–48번은 사례·작업별 누적 시간과 CPU 마스크다. 49–136번의 11개 행은 각각 사례, 작업, CPU, 발급 순번, 시작, 종료, 간격과 원래 affinity를 담는다. 137–139번은 카운터 주파수, 출발 IRQ 진입 및 목적 작업 콜백 시각이다. 사례 0/1/2는 고정·전역·클러스터이고 작업 0/1/2는 M/P0/P1이다. 기록을 보존하려면 새 경로를 SMP_CAPTURE_DIR로 지정하고 Linux 실행 래퍼에서 python3 tools/smp_capture.py "$@"를 호출하여 관찰기의 --qemu 인자로 전달한다.
