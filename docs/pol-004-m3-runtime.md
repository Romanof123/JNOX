# IMP-042 가상 주기 제어 런타임 사용 안내

[English](pol-004-m3-runtime.en.md) · [시험 설정과 예산](pol-004-m3-runtime.json) · [최초 독립 실행 기록 EVD-042 v1](evidence/evd-042-v1.md)

이 프로파일은 QEMU virt에서 주기 제어 작업과 허가 송신 작업을 독립 스택에서 실행한다. 기준 소스는 `33bb739dfc34c3afcf29799ba72d84bf52bcdab6`이다. 매니페스트의 WCET·지터·마스킹·간섭 상한에는 아직 실증 근거가 없어 실제 작업의 해석적 수용 판정은 거부 상태다.

## 실행 구조

기존 주기 시험은 어셈블리 작업 표시와 논리적 구간, CNTFRQ/20 타이머 퀀텀을 쓴다. 여기서 다루는 일반 작업은 `kernel/build.rs`에서 별도 런타임을 선택한다. 두 경로는 `context.S`, `Frame`, 타이머 PPI와 GIC 초기화, 전용 `Stack`, `ReadyQueue`, `DispatchPolicy`를 공유한다. RM과 DM 모두 제어 작업의 우선순위가 높다.

제어 작업의 주기와 마감은 5 ms이고, 위상은 0과 2.5 ms다. SVC 1은 현재 활성화의 전체 프레임을 보존한다. 다음 절대 반주기 타이머가 같은 작업을 재개하고 SVC 2가 작업을 완료한다. IRQ 핸들러가 릴리스와 디스패치를 담당한다. 송신 작업의 주기와 마감은 10 ms다. 애플리케이션이 허가 발행, 실측 발행 시각, 게이트, 만료, 재무장 및 출력 쓰기를 담당한다. 유휴 작업은 PL061 GPIODATA 비트 0을 독립적으로 읽는다. 이는 가상 주변장치 레지스터 관측이며 외부 핀이나 안전 IPC 전송을 측정하지 않는다.

## 빌드·캡처·판정

Linux에서 저장소가 고정한 Rust 1.95.0과 `aarch64-unknown-none` 타깃을 사용한다. 정책은 `control-rm` 또는 `control-dm`이다. 정책·사례 조합마다 별도의 ELF와 콜드 부팅을 사용한다. 다음은 저장소 루트에서 기본 클록의 RM 손실 사례를 실행하는 예다.

```sh
cd kernel
export JNOX_BOARD=virt JNOX_PROFILE=periodic JNOX_APP=control-rm JNOX_CONTROL_CASE=loss
unset JNOX_FIXED_TRACE
cargo build --locked --release
elf=target/aarch64-unknown-none/release/jnox-kernel
sha256sum "$elf" "$(command -v qemu-system-aarch64)"
qemu-system-aarch64 --version
qemu-system-aarch64 -machine virt,gic-version=2 -cpu cortex-a72 -smp 1 -accel tcg -m 128M -nodefaults -display none -monitor none -serial stdio -kernel "$elf" > rm-loss.uart 2> rm-loss.stderr
```

게스트는 `CONTROL END` 뒤에 대기하므로 UART에서 종료 표시를 수집한 뒤 해당 QEMU 프로세스를 종료한다. 시간 초과로 출력이 끊기면 불완전한 원본을 실패 캡처로 보존한다. `kernel` 디렉터리에서 `python3 ../tools/control_observations.py loss rm-loss.uart`로 판정한다. 일반 사례는 `healthy`, `loss`, `late`, `demand`이며 DM도 같은 방식으로 별도 실행한다. 각 실행에 정확한 소스 트리·변경분, 매니페스트, ELF 해시, 컴파일러, QEMU 실행 파일 해시·버전, 전체 인수, 클록 모드, UART와 stderr를 남긴다.

결정론적 시험은 `-kernel` 앞에 `-icount shift=0,align=off,sleep=off`를 추가한다. 일반 송신, 주입기 인계, 스크립트 전용 시험을 구별하고 실제 사용한 모드를 기록한다. 한 클록 모드에서 측정한 지연을 다른 모드에 적용할 수 없다.

일반 송신은 디스패치 뒤 자기 스택에서 실제 발행 시각을 측정한다. 목표는 작업 시작 후 0.5 ms이며 목표를 놓친 값도 남긴다. 손실 시험에서는 출력 억제로 시작해 허가 2회, 감독 명령, 정상 감시, 네 번째 전달 직후 게이트 닫힘, 만료, 하강 전이 읽기까지 관찰한다. 명령 목표는 첫 실제 발행으로부터 15 ms이다. 양성 판정에는 실제 발행 간격이 정확히 10 ms여야 한다. `late`는 목표 위상 12보다 0.625 ms 늦을 때까지 IRQ를 마스킹한다. `demand`는 위상 12부터 활성화마다 최소 0.3125 ms의 서비스를 소비한다. 두 음성 시험은 해당 주입 원인과 독립적인 억제 읽기가 모두 필요하다. 이미 시작 단계에서 억제됐다면 그 실행으로 주입 원인을 검증할 수 없다.

## 원시 사건 읽기

각 행의 네 필드는 **사건 번호, 카운터, 인자 A, 인자 B** 순서다. 같은 틱에서는 파일에 기록된 순서로 구분한다. 판정 구간에는 UART를 쓰지 않는다. 사건 1은 명목 기준 시각, CNTFRQ와 마지막 위상 번호를 기록하고 25는 별도로 선택한 스크립트 클록 시험을 식별한다.

구간 행은 하한 틱을 카운터에, 상한 틱을 인자 A에 기록한다. 원인 코드는 0 허가 만료, 1 타이머 지연·누락, 2 재개할 작업 없음, 3 서비스 예산 초과, 4 작업 중첩, 5 관측 종료 한계 초과, 6 마감 초과, 7 판정 지연 한계 초과, 8 연속 판정 간격 초과다. IRQ/SVC 진입 시각은 벡터에 진입해 임시 레지스터 두 개를 저장한 직후 측정한다. 그 앞의 실행 비용은 불확실성으로 남는다. 위상 판정에는 보수적인 완료 시각을 사용한다. 장치 표본은 쓰기 명령과 별개로 관측자가 전이를 본 시점을 한정한다. 기록 손실이나 무효 추적은 `CONTROL INVALID`를 출력하거나 종료 표시를 남기지 못한다.

## 서비스 회계와 판정 한계

청구 구간은 선택 작업의 디스패치 끝에서 다음 IRQ/SVC 진입 표본까지다. 복원, 작업 실행과 벡터 표본 준비를 포함하고 일시 중단 시간과 콜백 본체를 제외한다. 선점으로 나뉜 실행 구간은 누적한다. SVC 콜백, IRQ 콜백과 디스패치, 마스킹 구간, 장치 관찰은 해석적 회계에서 따로 귀속해야 한다. 250/250/750 µs는 두 제어 위상과 송신 작업의 반복 서비스 감시값이다. 할당한 감시값과 관측 최댓값으로 WCET를 증명할 수 없다. 타이머 설정·작업 수용·계측 불확실성의 상한, 최장 블로킹, 외부 IRQ 버스트, 간섭의 결합 최댓값, 인계 후 실물 보드 동작 및 VER-019 전송 검증은 미확정이다.

IRQ/SVC 구간은 구간 자체를 기록하고 작업으로 넘기기 직전에 끝난다. 뒤따르는 기록과 복원 준비 비용에는 별도 상한이 필요하다. 최장 마스킹 본체 행은 작업·유휴 루틴이 마스킹된 상태에서 보낸 경과 시간을 재며 마스킹 진입·해제 명령은 제외한다. 전체 오버헤드에 대해서는 관측 하한이다. 한 위상 전체가 누락되면 제어 스택에서 현재 상태를 한 번 판정하고 장치 꺼짐을 읽은 뒤 추적을 중단한다. 불완전한 관측 구간은 통과할 수 없다.

## 스크립트 및 정확 경계 시험

스크립트 선택자는 `worst`, `tie`, `early-command`, `expired-command`, `missing-permit`, `no-command`, `recovery`, `old-generation`, `invalid`, `silence`, `saturation`이다. 일반 작업 경로 밖에서 같은 게스트 카운터와 장치를 사용한다. 포화·입력 거부 시험이 다루는 범위는 제한된 입력 상태다. 요구한 표본 틱이 어긋나거나 동시 사건을 포함한 구간의 폭이 0보다 크면 정확 경계는 미결정이다. 최초 기록에서 `worst`는 완료가 2틱 늦었고 `tie`는 네 번째 발행이 만료 판정보다 6틱 늦었다. [최초 시험 결과](evidence/evd-042-v1.md)

판정기에는 사례명과 실제 UART 파일을 전달한다. 저장소 루트에서 `python3 tools/control_observations.py verdict-boundaries`를 실행하면 합성 입력으로 경계값과 1틱 초과 산술을 검사한다. 게스트 판정은 실제 재무장 발행·명령 시각, 연속 경계 판정, 독립 읽기, 수신 상태 유지와 마지막 관측을 확인한다. 정확 틱 미충족은 실패로 반환한다. 일반 판정기는 10 ms 창별 실제 서비스도 보고한다.

경계 수정 후보의 `worst`·`tie`는 별도 AArch64 코드에서 물리 카운터를 읽고 마지막 수용 허가의 만료와 비교해 실제 결함 래치를 조건부로 설정한 뒤 완료 시각을 읽는다. `tie`는 이어 발행 시각을 표본화하고 준비한 네 번째 허가를 입력 슬롯에 게시한 뒤 저장 완료 시각을 읽는다. 각 동작 양쪽의 동일 틱과 명령 순서로 카운터 해상도에서의 동시성을 판정한다. GPIO 쓰기·읽기와 추적 출력은 뒤따른다. 래치 후 일반 수신기는 네 번째 허가를 거부하므로 수용 기록인 사건 12는 순번 3에서 끝난다. 기존 판정기의 ‘만료 우선 차단과 네 번째 허가 수용’ 동시 요구는 이 수신 동작에 맞지 않았다.

최악 위상 스크립트는 대기 슬롯이 비어 있음을 확인하고 세 번째 허가를 수용한 직후 같은 명령 블록에서 실제 게이트를 닫는다. 기록을 쓰기 전에 폐쇄 완료 시각을 읽는다. 사건 12·16의 순번은 3이어야 하며 사건 29의 폐쇄 전후 시각은 모두 마지막 허가 수용 틱과 같아야 한다. 응답 시간 한계에 들어와도 폐쇄 시각이 늦으면 실패다. 사건 17은 감독 명령 도착, 사건 20은 실제 재무장 성공이다.

사건 47은 스크립트 전용 입력 게시 기록이다. 카운터는 네 번째 허가의 발행 틱, 인자 A는 게시 완료 틱, 인자 B는 순번이다. `control-rm`·`control-dm` 각각에 대해 `JNOX_CONTROL_CASE=worst`와 `tie`를 별도 빌드하고 결정론적 클록으로 부팅한다. 예를 들어 `kernel`에서 `python3 ../tools/control_observations.py tie rm-tie.uart`를 실행한다. 한 틱 차이도 보존한다. 독립 검증에서는 두 경계와 장치 응답을 각각 확인해야 한다.

## 주입기에서 일반 송신 작업으로 인계

두 정책 모두 `JNOX_CONTROL_CASE=handoff-healthy` 또는 `handoff-loss`를 선택하고 전체 사례명으로 컴파일·캡처·판정한다. 최초 독립 인계 시험의 클록은 결정론적 명령 계수 모드였다.

처음에는 유휴 감독 작업이 세대 1을 소유한다. IRQ를 마스킹하고 수신 슬롯을 준비한 뒤 실제 발행 틱을 읽어 슬롯에 게시하고 배리어 후 저장 완료 틱을 읽는다. 두 표본은 기준 시각 +0.5 ms와 그로부터 10 ms 뒤의 각 목표 틱에 정확히 일치해야 한다. 첫 발행으로부터 +15 ms에 명시적 명령을 발행하면 일반 제어 작업이 이를 평가한다. 유휴 작업이 PL061 상승 전이를 독립적으로 읽은 뒤 단독 소유권을 넘긴다. 일반 송신 작업은 처음 두 활성화에서 발행을 보류하고 다음 릴리스에서 세대 1, 순번 3을 인수한다. 손실 시험에서는 순번 3·4를 실제 전달한 뒤 게이트를 닫는다. 발행·게시 후 수신·명령 틱 중 하나라도 어긋나면 해당 부팅의 준비 단계가 미충족이다. 인계는 제어 작업의 명령 수용과 독립 읽기를 모두 요구한다.

## 콜드 부팅 타이머 계측 수정 후보

최초 기본 클록 RM 손실 시험은 기준 시각보다 2.382 ms 먼저 위상 0을 설정했지만 첫 벡터 진입이 2.547 ms 늦어 실제 위상은 1이었다. RM 정상 시험은 2.337 ms 먼저 설정하고도 첫 벡터 진입이 1.972 ms 늦었고 이후에도 지연이 발생했다. 두 실행은 실패 기록이다. 타이머 비교값을 제때 설정했다는 점은 확인됐으나 호스트 스케줄링, 코드 변환, CPU 마스킹과 QEMU 경로 중 어느 것이 지연 원인인지는 이 기록으로 판별할 수 없다.

시작 수정 후보는 런타임을 초기화하고 유휴 작업의 전용 프레임을 만든 뒤 첫 예외 복귀를 거쳐 기준 시각을 한 번 정한다. 첫 목표까지의 준비 시간은 2.5 ms다. 유휴 작업은 다음 타이머 전에 감독 활동이 필요한 구간에서만 폴링한다. 나머지 구간은 IRQ를 허용한 채 WFE로 대기하고 타이머 IRQ는 SEV를 보낸다. 단일 코어에서 대기 결정과 WFE 사이에 도착한 이벤트도 보존된다. 지연 대조군은 목표 시각이 지나도록 의도적으로 IRQ를 마스킹한다. 새 명령과 추적 저장 비용은 수정된 ELF의 측정에 포함해야 한다.

| 시작 계측 사건 | 카운터와 인자 |
|---|---|
| 43 | 전용 유휴 스택 최초 진입, 카운터 주파수와 위상 길이 |
| 44 | IRQ 허용 대기 준비, 다음 요청 위상과 표본 DAIF |
| 45 | 벡터 진입 표본, 중단된 작업 ID와 저장된 복귀 PC |
| 46 | 45와 같은 표본 시각, 저장된 DAIF 마스크 비트와 요청 위상 |

일반 시작 계측에는 43~46, 스크립트 입력 게시에는 47을 사용한다. 캡처한 ELF와 사례에 맞는 정의로 해석한다. 실제 ELF에서 복귀 PC를 대조하고 사건 1·2·3·43·44로 초기 준비, 타이머 설정 선행 시간과 벡터 지연을 구별한다. 준비용 릴리스나 평가에서 제외하는 첫 작업은 없다. 첫 콜드 부팅부터 모든 평가 작업에 기존 시간 한계를 적용한다. 수정 효과에는 해당 ELF의 별도 독립 실행 기록이 필요하다.

전용 tie 사례의 마지막 폴링 비교는 실제 카운터와 직전 수용 허가의 발행 시각 +20 ms를 비교한다. 그 결과로 래치 저장을 실행하고 저장 완료 배리어와 별도 카운터 표본으로 래치 구간을 닫는다. 다시 읽은 카운터 값을 네 번째 허가 발행 시각으로 사용하며, 입력 게시 저장·완료 배리어·게시 후 표본을 이어서 수행한다. 사건 47과 독립 장치 관측의 기존 판정 기준을 적용한다. 직전 RM 실행은 발행이 만료와 같은 틱이었지만 실제 게시 구간이 2658830–2658831이라 실패했다. 최초 기록은 보존하고 새 명령열은 새 콜드 부팅으로 측정한다.

### 불완전한 UART 기록과 대조군 판정

판정기는 기록이 잘렸거나 형식이 잘못된 경우, 다른 차단 원인이 개입한 경우, 시간 조건을 위반한 경우에 JSON과 0이 아닌 종료 코드를 반환한다. CONTROL END는 바이트 스트림의 끝을 표시한다. 모든 필수 위상과 관측도 있어야 한다. 부적격 결과에는 첫 거부 사유, 관측된 사건 수, IRQ 인덱스, 타이밍 결함과 최종 장치 관측값을 남긴다. 정책은 내장 사례 ID로 식별하며 ELF와 보관본의 출처는 독립 검증자가 확인한다. 같은 틱의 사건은 원래 순서를 유지하고 스트림 간 시각 비교는 사건별 규칙을 따른다. 합성 파서 회귀 검사 명령은 `python3 tools/control_observations_regression.py`다.

IRQ 지연 및 실행량 초과 대조군에서 사건 11은 발행, 12는 수신 승인, 24는 수신 거부, 23은 게이트 차단 시도다. 판정기는 실제 타이밍 차단 래치를 기준으로 기록을 나누고 같은 틱에서는 기록 순서를 따른다. 래치 전 입력 승인, 래치 후 발행에 대한 명시적 거부, 이후 승인·재무장 부재와 독립 PL061 읽기로 확인한 상승·하강 전이 및 최종 꺼짐 상태를 요구한다. 마지막 승인 발행 시각은 래치의 증거에서 읽는다. 관측 대상은 가상 장치다.
