# Weighted service for independently packaged native applications / 독립 네이티브 앱의 가중 CPU 서비스

**Prospective scope.** On CPU0, an operator can give two independently built CPU-bound applications different long-run shares of measured service while a third application can sleep, resume and finish. Shares apply while the relevant clients are continuously ready. This is a POL-011 integration design on `c7f88eadf582aba0d350bb444a553426ef01be37` for #12 and #21. Track this work under [#296](https://github.com/Romanof123/JNOX/issues/296), CHG-116 / IMP-116 / EVD-116, linked to #177 and #184. Timing and release verdicts remain prospective.

**제안 범위.** 운영자는 별도로 빌드한 앱의 가중치를 패키지에 지정한다. 계속 실행 가능한 앱들은 가중치에 비례해 CPU0의 실서비스를 받고, 대기 중인 앱은 기한에 복귀해 자기 작업을 마친다. 아래 수치는 구현 전 판정 기준이다.

## Integration / 통합 지점

The historical #178 packager at `663b598e` accepts named applications. Both weighted names build the same monitor source and run two instances. The current ordinary packager already takes one primary C source or ELF and up to two independently linked peer ELFs, snapshots and verifies them, and constructs private slot mappings and native frames. Keep that loader, native-v1 SDK, startup route, absolute clock, yield and exit. Extend its policy selector at the existing CPU0 syscall, EL0 IRQ and idle IRQ dispatch points. [Historical packager](https://github.com/Romanof123/JNOX/blob/663b598e/tools/build_native_el0.py) · [Ordinary packager](../tools/build_native_el0.py) · [Native dispatcher](../kernel/src/native_el0.rs)

Use the existing `VruntimeScheduler<N>` for weights, leases, measured charge, minimum selection and sleep/wake placement. It uses `fair_policy::VirtualTime` for exact fractions. Its ascending slot tie-break is already deterministic. The separate `pick_weighted` snapshot helper and EEVDF deadline selection need no second pass over the ready tasks. The native adapter owns the physical compare, running lease/start, blocked deadlines, terminal state and saved frames. On exit retire the lease and remove the slot from policy readiness via the existing sleep operation, marking it terminal in native state so it can never wake. [Weighted policy](../kernel/src/vruntime_policy.rs) · [Rational timestamps](../kernel/src/fair_policy.rs) · [Existing weighted runtime](../kernel/src/weighted.rs)

#178의 두 선택자는 같은 모니터 소스로 두 인스턴스를 만든다. 일반 패키지의 독립 ELF 로더·사설 주소 공간·프레임·SDK를 그대로 쓰고 가중 정책만 연결한다. 기존 VruntimeScheduler가 실제 서비스 정산, 최소 가상시간 선택, 동률 슬롯 순서, 잠든 작업의 재배치를 담당한다. 네이티브 계층은 실제 타이머, 저장된 문맥, 종료 상태를 맡는다.

## Operator interface / 사용자 설정

~~~sh
python3 tools/build_native_el0.py --out batch --elf checksum.elf \
  --peer-elf histogram.elf --peer-elf reporter.elf --policy weighted \
  --weight 1 --peer-weight 2 --peer-weight 3 --quantum-ticks 625000
~~~

Accept one `--weight` and exactly one `--peer-weight` per supplied peer in package order, each an integer in 1…4,294,967,295 (the policy's u32 input). Require one common physical grant `--quantum-ticks` in 1…i64::MAX. Slot order, filenames, configuration and ELF hashes travel together in the manifest and generated configuration. Validate in the CLI and kernel build script. Reject missing/extra/zero/out-of-range weights, priorities mixed with weights, a quantum without a compatible policy, duplicate singleton selectors, gaps in slot numbering or a fourth ELF. Preserve cooperative defaults, FIFO priorities, RR priority/quantum rules and the startup probe. Arbitrary valid weights are a functional API, while the reference timing cases below qualify specific configurations.

주 앱과 각 동료에 순서대로 양의 u32 가중치 하나씩, 공통 퀀텀 하나를 지정한다. 주 앱은 기존처럼 C 소스도 가능하다. CLI와 커널 빌드 양쪽에서 범위와 개수를 확인하고 정책에 맞지 않는 옵션을 거부한다. 기존 협력형·FIFO·RR·시작 프로브 명령과 매니페스트 키를 유지한다.

## Measured dispatch / 실서비스 정산

Start ready at rational zero. For a selection snapshot use exact whole, remainder and denominator for every runtime and the monotonic ready floor. Stamp the grant just before dispatch and close it at the first handler sample on a scheduling boundary. Charge only the outstanding lease, once, with positive elapsed physical ticks. Exclude stop-to-next-start scheduling gaps and idle. Preserve a grant and its original expiry across ordinary nonblocking syscalls. A future sleep, exit, explicit yield, eligible timer or sleeper wake closes the interval. Yield offers a fresh weighted selection after charging the caller. If the caller remains minimal it may continue. A sole caller can yield successfully. For coincident samples define a zero-length retirement operation that validates and releases the lease without advancing service or runtime; retain the existing positive-charge API and check zero-duration cases separately.

At a boundary charge first, remove blocked/exited owners, admit every due sleeper in deadline then slot order and dispatch the minimum (runtime, slot). Behind sleepers round up to the floor on their own weight grid. Ahead sleepers retain their debt. While peers compete, arm min(grant start + Q, earliest sleeper deadline); with a sole runnable process arm only a pending wake. With only sleepers arm the earliest deadline and idle. Record the actual compared deadline and interrupt cause, including late/coincident delivery, and charge actual elapsed service once. With no live slots finish after the final exit. A journal for scored runs must identify overrun explicitly. Ordinary programs must remain runnable after observation storage fills.

실제 디스패치부터 예외 진입 표본까지 실행권 소유자에게 한 번만 정산하며 유휴·선택 간격은 제외한다. 일반 비차단 호출은 기존 만기를 유지한다. 양보·차단·종료·타이머 경계에서는 정산 후 만기 대기자를 순서대로 깨우고 가상시간 최소 슬롯을 고른다. 같은 카운터 값에서 만난 경계는 0틱으로 처리해 가짜 서비스를 만들지 않는다. 뒤처진 대기자는 자기 가중치 격자에서 바닥 이상으로 올림하고 앞선 대기자의 부채는 보존한다. 경쟁자가 없으면 다음 깨움만 예약한다.

## First positions / 사전 등록할 실행

Freeze source, per-slot ELF hashes and disassemblies, exact app inputs, iteration counts, independently computed results, clock frequency, QEMU argv, memory/journal capacity and first positions before observing results. Use separate C checksum and Rust histogram applications over deterministic private data, with finite syscall-free inner loops. Record volatile progress and the full computed results in private memory and return independently predicted statuses. Observe progress from final RAM and ELF symbols or post-run capture; no benchmark control page or polling contract is required by the applications. Size the fixed inputs in advance for the declared horizon. An early exit, lost row or non-overlapping window leaves that timing case unqualified.

1. **Continuous 1:2 share.** Freeze a pair with 10 ms grants (Q = frequency/100, divisible by four, e.g. 625000 at 62.5 MHz). In the first 36 full timer closures both clients must remain ready. Use H = 5Q/4, G = Q/4. Require each charged interval in (0,H], each full timer interval at least Q and each dispatch gap at most G. For services A,B check −H ≤ 2A−B ≤ 2H at every prefix, and at closure 36 require T=A+B ≥ 36Q and |2A−B|·36Q ≤ 2H·T. Record exit tails separately. Swap app/weight assignments for a separately frozen control. Retain both private products and interrupt PCs.
2. **Timed reporter.** Use a weight-1 continuously computing peer and a weight-2 reporter making three absolute 40 ms waits on the ordinary SDK clock. For each, the peer progresses and receives at least 3Q service while blocked reporter charge stays unchanged. Replay placement, first selection, actual restored instruction and user clock read. For target D, IRQ I, wake admission W, first user return R and clock-sample bracket [L,U], require D≤I≤W≤R≤L≤U, I−D≤G, W−I≤G, R−W≤H+2G, U−R≤G and U−D≤H+5G. Keep bounds on contended/full grants; label a deliberate uninterrupted solo interval to the wake separately from the historical repeated solo leases.
3. **Three slots and boundaries.** Run distinct checksum, histogram and reporter ELFs with weights 1:2:3, then a single returning/yielding app. For 60 contiguous contended grants with all three ready and no blocking, prove exact minimum selection at every boundary, all three make progress and each real interval obeys H/G above. From zero, require max(Sᵢ/wᵢ)−min(Sᵢ/wᵢ) ≤ H/min(w) at every prefix by exact fractions. Once any exits, replay the surviving set and charge until all expected statuses. In a separate sleep/exit control use all-sleep idle, simultaneous due admissions and final solo yield. If ordinary wakes never coincide, keep equality as a deterministic host control and mark guest equality unobserved.
4. **Numeric and compatibility controls.** On the host include weights 1 and u32::MAX, a nonintegral floor mapped to another weight grid, multiple partial-tick charges versus one combined charge, equal fractions with different denominators, stale/duplicate leases and near-u64::MAX carry, accumulated service, sequence and start+Q overflow. Require exact values or explicit checked failure with accounting unchanged; a zero weight, wrap or saturated compare cannot become a valid dispatch. Run normal single startup, cooperative pair and #294 FIFO/RR controls from their frozen recipes. Keep first default and shift=3 icount cases for the 1:2 and wake pair, in share/default, share/icount, wake/default, wake/icount order. Record clocks separately.

최초 부팅 전 바이너리·입력·반복 횟수·기대 계산값·관측 용량·실행 순서를 고정한다. C 체크섬과 Rust 히스토그램은 각자 사설 데이터로 유한한 계산을 마친다. 1:2 연속 실행의 첫 36회는 매 접두 구간과 최종 서비스 오차를 위 식으로 판정한다. 40 ms 절대 대기 세 번은 기한, IRQ, 깨움 수락, 실제 사용자 복귀, 사용자 시계 표본까지 각각 상한을 적용한다. 1:2:3 세 슬롯은 첫 60회 가상시간과 서비스 차이를 유리수로 재생하고, 단독 양보·유휴 깨움·각 앱의 종료와 결과도 확인한다. 최대 가중치·분수 올림·0틱·오버플로와 기존 정책 회귀는 별도 대조한다. 기록 부족이나 너무 이른 종료는 그 최초 실행의 미검증으로 남긴다.

For each event retain previous/next slot, reason, ready set, saved/restored frame and PC, lease sequence, start/stop, due/armed compare, raw and cumulative service, rational runtimes/floor and placement. Replay independently from physical samples, map PCs and private writable locations to the packaged ELFs, and preserve the complete first records including failures. Selection correctness, service-share tolerance and wake latency are separately scored.
