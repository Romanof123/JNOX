# CHG-329 · Original Linux RX buffers / Linux 원본 수신 버퍼

REQ-004/011 · DES-002 · IMP-329 · VER-004/011. The first #432 RX profile uses two functions from Linux v6.18.65. `add_recvbuf_small` prepares and posts the writable span. `virtnet_rq_get_buf` recovers the original cookie and updates the upstream DMA references. A J-NOX FIFO consumer validates the virtio header, copies Ethernet bytes to its caller, releases the buffer reference and posts a replacement. The following descriptions identify implemented source paths and the separate conditions for demonstrating the full poll callback. [Issue #432](https://github.com/Romanof123/JNOX/issues/432) · [Original driver](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/net/virtio_net.c?h=v6.18.65) · [EL0 consumer](../drivers/linux-compat/packet/receive.c)

첫 단계에서 원본 함수 두 개가 수신 버퍼를 게시하고 완료된 쿠키를 회수한다. ELF의 FIFO 소비자는 길이·플래그를 검사하고 이더넷 바이트를 복사한 뒤 버퍼 참조를 반환하고 새 버퍼를 게시한다. 원본 NAPI 폴링 함수 실행은 후속 단계에서 별도로 입증한다.

### Buffer ownership / 버퍼 소유권

- EL0 has 33 preallocated 4 KiB pages for one 32-entry queue. Each typed Linux page keeps its actual reference count. The fragment cache owns one reference. The original allocator takes another for the DMA mapping and one per allocated buffer. Two buffers sharing a page retain separate buffer references. Replacing the cache drops only its reference. The last completion or cache transition drops the DMA reference when the upstream DMA reference count reaches zero. The backing can be cleared and reused only once its Linux page count reaches zero. The first RX fixture supports one process lifetime per binding. [Page provider](../drivers/linux-compat/packet/rx_pages.c) · [Original source adapter](../drivers/linux-compat/packet/include/jnox_rx_page_api.h)
- A service-local handle encodes a page and byte offset. Lookup checks the live page and bounds on every nonempty span. EL1 separately checks owner, epoch, writable grants and descriptor identity. A live page handle alone proves neither DMA ownership nor freshness across reuse. The fixed descriptor span is 1,530 bytes (12-byte virtio header plus 1,518 bytes). The first consumer admits Ethernet lengths 14–1,514 with zero flags and GSO type, returning a length error or bad-message error on rejection. [Queue adapter](../drivers/linux-compat/packet/rx_virtqueue.c) · [EL1 grants](../kernel/src/native_linux_net_packets.rs)

서비스 페이지의 캐시 참조, DMA 매핑 참조, 개별 버퍼 참조를 각각 유지한다. 같은 페이지의 한 프레임이 반환되어도 다른 프레임이 참조하는 메모리는 보존된다. 범위 핸들은 서비스 내부 주소만 식별하며, 장치 소유권과 세대는 별도로 커널에서 검사한다. 현재 소비자가 받는 이더넷 길이는 14–1,514바이트다.

### Next original poll gate / 원본 폴링의 다음 검증

1. Register the real RX `napi_struct` and positive budget, with valid RX and TX queue objects. In `virtnet_poll_cleantx`, the original driver resolves the paired TX queue even when TX NAPI weight is zero. Admit a single nonmergeable small-packet queue with XDP, AF_XDP, DIM, tunnel, RSS and checksum/GSO offloads disabled. Reject incompatible negotiated features, active programs and unexpected virtio headers at the service boundary.
2. The expected call sequence is `virtnet_poll → virtnet_receive → virtnet_receive_packets → virtnet_rq_get_buf → receive_buf → receive_small → receive_small_build_skb → virtnet_build_skb`. Implement bounded `build_skb` and `skb_put` with the original headroom, shared-info alignment and payload length. The SKB takes the existing buffer reference on success. On allocation failure the upstream caller drops that reference. Moving the current FIFO consumer's unconditional final page release into this path would prematurely recycle a live SKB.
3. `virtnet_receive_done` checks checksum/GSO metadata, records the RX queue, calls `eth_type_trans` and submits to `napi_gro_receive` (compiled GRO dependency `gro_receive_skb`). Provide a bounded result sink that preserves protocol, interface, frame bytes and terminal ownership. Count malformed drops separately. A standalone copy from a used descriptor establishes buffer exchange only.
4. `virtnet_receive` may refill when free descriptors exceed half the smaller of budget and ring size. Failed refill returns the budget to force a repoll. On a short poll, preserve the original completion ordering: prepare queue callbacks, run `napi_complete_done`, repoll the used index with `virtqueue_poll`, and reschedule if a completion arrived in the window. Exercise both budget exhaustion and a completion during rearm. Verify callback-PC execution, work counts, refill, SKB delivery and release against independent wire and ring records. Keep CPU IRQ delivery and probe/open as separate claims. [Compiled relocation inventory and prior design](native-linux-net-packet-design.en-ko.md)

핀 고정 원본 오브젝트의 `virtnet_poll` 호출 폐쇄에는 내부 함수 26개, 외부 심볼 78개와 간접 분기 지점 한 곳이 있다. 실제 소형 패킷 경로는 이 중 일부를 실행한다. 다음 단계에서는 스케줄된 NAPI와 예산, 실제 SKB 생성·길이·소유권, 이더넷 프로토콜 판별과 수신 인계, 큐 보충 및 인터럽트 재활성화 경쟁을 각각 검증한다. 할당 실패 시 원본 드롭 경로가 페이지 참조를 한 번만 반환해야 한다.
