# POL-012 · 일반 Rust 원격 계측 작업

[English](ordinary-eevdf-plan.en.md) · [#21](https://github.com/Romanof123/JNOX/issues/21) · CHG-083 · 실행 전 개발 구성

EVD-039는 256회 할당에서 적격 선택, 실행 중 슬라이스·가중치 변경, 기상 응답 20회를 관측했다. 이번 사례는 일반 Rust 작업 셋에 실제 배분된 서비스와 주기 소비자가 실제 릴리스 후 처음 실행한 시각을 확인한다. 제품 부하 수용, 지속 부하 한계, 실보드 시간, M5 승인은 #21에 남으며 #24는 #21 완료에 의존한다. [기존 근거](evidence/evd-039.md) · [출시 사례](scheduling-release-cases.md)

## 입력과 서비스

AArch64 virt, Cortex-A72 vCPU 하나, GICv2 물리 타이머 PPI 30, TCG, 메모리 128 MiB를 사용한다. virt에서 벤치마크 기능 없이 `JNOX_PROFILE=eevdf`, `JNOX_APP=telemetry`를 선택한다. 처음부터 준비된 EL1 태스크 셋은 16 KiB 전용 스택을 각각 소유한다. ID 순서로 가중치는 [2,1,1], 물리 서비스 요청 크기는 [2Q,Q,Q/2]이다. Q는 정확히 CNTFRQ/100 카운트이며 Q/2도 정수여야 한다. 기존 EEVDF의 준비 집합 기준시각, 수면 중 누적된 과거 이득 보정, 적격 태스크 중 가장 이른 가상 기한, 동률이면 작은 ID를 그대로 사용한다. 최초 디스패치 시각 E에 소비자의 Q/2 요청이 가장 먼저 선택된다.

- 배치 작업 0과 1은 각자 입력 수 n, 합, 가중합을 유지한다. 링 [11,7,23,5,19,3,29,13,2,31,17,37,41,43,47,53]의 (3n+5×ID) mod 16번 값을 읽고 값과 값×(1+n mod 7)을 64건 블록 단위로 누적한다. 8번째 응답 완료 뒤 현재 블록을 끝낸다. 입력 수는 2³⁸ 미만인 64의 양의 배수여야 한다. 큰 결과는 112개 읽기 주기로 검산할 수 있다.
- ID 2는 자기 스택에서 k=1…8을 차례로 SVC #1로 요청해 절대 예정 시각 E+8kQ 전에 차단된다. 물리 타이머 IRQ가 해당 요청을 깨운다. 작업은 SVC 복귀 직후 CNTPCT를 읽고 j=0…15에 대해 링[(j+k) mod 16]으로 Rₖ=Σ(j+1)×값을 구한다. 8회 뒤 SVC #2 인수는 (ID,건수,ΣRₖ,ΣkRₖ)=(2,128,27028,115128)이다. 완료 수락 후 배치 작업 둘이 각자 SVC #2로 최종 결과를 제출한다. 호스트에서 일을 제출하거나 깨울 필요가 없다.
- 매 디스패치에서 시작+min(Q,남은 요청량)과 다음 절대 예정 시각 중 이른 시각으로 타이머를 설정한다. 타이머 벡터에서만 깨운다. 타이머 설정·프레임 복원 직전의 디스패치 표본에서 IRQ/SVC 벡터가 x9를 보존한 직후의 표본까지 양의 CNTPCT 차이 전부를 실제 소유자에게 부과한다. 두 표본 사이 설정·복귀·예외 진입 일부를 포함하며, 실행권 사이의 스케줄러 구간은 제외한다. 이 카운트는 배분된 실행 구간이고 체크섬은 작업이 실제로 처리한 결과이다.
- IRQ가 늦으면 측정량 전부를 반영해 정수 개의 요청을 갱신하고 부분 잔량을 보존한다. 차단 시 부분 요청을 보존하고, 기상 시 뒤처진 가상시각을 기존 준비 기준 이상으로 올리며 기한을 같은 양만큼 옮긴다. 준비 작업이 없으면 소유자가 없다. 기존 할당 한도 엄수 호출의 동작은 유지한다. 측정 종료까지 A/B가 계속 준비 상태이고, 세 완료를 처리한 뒤에는 실행권이 남지 않는다.

C가 다섯 번째 대기를 요청할 때 앞선 네 결과가 이미 보고되어야 한다. 현재 실행량을 부과하고 C를 차단한 뒤, 다음 디스패치 전에 준비된 B의 (가중치 1, 요청 Q)를 (가중치 2, 요청 2Q)로 바꾼다. 기존 재설정 함수가 변경 직전 A+B 기준과 부호 있는 서비스 지연을 사용해 한 카운트 미만으로 올림한 새 시각에서 요청을 교체한다. 한 차례만 성공해야 한다. 다섯 번째 대기의 x0, 다음 행의 B 상태·기준과 후속 선택으로 확인한다. 변경을 가로지르는 측정 창은 각 실행권 시작 시의 실제 가중치를 사용한다. 8개 절대 릴리스 시각은 그대로 유지한다.

## 판정과 근거

1. 링크된 이미지, 원시 저널, 같은 프로세스의 예외·복귀 추적으로 각 선택과 시각을 재구성한다. 준비 집합, 정확한 유리수 기준, 적격 최단 기한, 부과량, 전용 스택 안의 전체 프레임, 저장·복원 ELR, 타이머 비교값과 PPI를 대조한다. 두 배치 태스크 각각에서 실제 타이머 중단 및 복귀, 8회의 차단·IRQ 기상·작업 응답, 세 태스크의 결과(건수, 검산한 두 합), 최종 소유자 없음이 필요하다.
2. E+[0,8,16,24,32]Q에서 시작하는 길이 32Q의 겹치는 다섯 벽시계 구간을 고정한다. 각 실행권을 경계에서 분할한다. 겹친 카운트 d를 소유자의 실서비스에, d×가중치/준비 가중치 합을 각 준비 태스크의 이상 서비스에 가산한다. 실행권 사이 공백은 양쪽에서 제외한다. 매 구간 실제 총 서비스 ≥28Q(공백 최대 1/8), 세 태스크 모두 |실제−이상|≤4Q를 요구한다. 양 끝에서 최대 요청 2Q씩을 허용한 개발 목표이다. 부호 있는 15개 오차, 정확한 분수와 분모를 보고하며 판정에 반올림을 사용하지 않는다.
3. 8건의 예정 시각, 기상 수락 시각, 작업 최초 표본을 모두 남긴다. 예정≤수락≤최초 및 최초−예정≤4Q로 8Q 주기의 절반을 후속 작업에 남긴다. 예정→최초와 수락→최초 각각 8개 원자료와 최근접 순위 p50/p95/최댓값, 실제 주파수, 기록 수, 스케줄러 공백을 보고한다. 차단 누락·릴리스 중첩·저널 포화·추적 손실·불명확 구간·한계 초과는 승인할 수 없다. 실패를 포함한 최초 독립 콜드 실행에서 전체 UART, 원시 저널, ELF·심벌·해시, 디스어셈블리, 실제 에뮬레이터 인자·버전과 예외 추적을 보관한다. 종료 마커는 제어 흐름의 완료를 나타낸다.

버전 1 기록은 종료된 실행권 512행과 태스크가 얻은 최초 응답 표본 8개로 한정한다. [필드 순서와 단위](ordinary-eevdf-wire.md) · 추적 REQ-002/005/023 → DES-003/012 → VER-002/005/023. 아직 완료된 EVD는 없다. [검증 계획](verification-plan.md)
