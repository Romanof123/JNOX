# Weighted virtual runtime on a timer-driven CPU

[한국어](m4-vruntime.md) · [Change #55](https://github.com/Romanof123/JNOX/issues/55)

CHG-024 · POL-011 · REQ-002/005/023 → DES-003/012 → IMP-022 → VER-002/005/023. On one Cortex-A72, continuously ready A and B start with weights 1 and 2 and virtual runtimes zero. At each decision choose the smallest virtual runtime, breaking ties by task ID. Each elapsed physical-counter count contributes 1/weight of a virtual count. Track the exact fractional remainder and a monotone minimum. Measure grant-to-IRQ residency from dispatch to the first Rust timer-handler counter read, including exception return and vector save.

Set Q to the integer part of CNTFRQ / 50. The timer compare is start + Q. Each of the 21 interrupts must land at or beyond the compare and before compare + Q. For the first 12 grants both jobs compete. Their measured services must satisfy |2 × A − B| ≤ 4Q. At decision 12 block B and run A alone for three slots. At 15 wake B at the larger of its old virtual runtime and the current minimum rounded up to its own weight grid. B receives no retroactive credit for sleeping. Measure signed lag relative to the floor in physical counter units before and after wake and at the end of six competitive recovery slots. Both jobs must run again. The realized owner sequence depends on timestamps.

Use `cargo build --release --locked --features vruntime-bench -j1` in kernel and `python3 tools/qemu_boot.py --profile vruntime --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel` from the root. For the independent first observation capture QEMU -d int through --qemu and retain UART and exact ELF hash in that same launch. Expect VR BEGIN/CLOCK, 21 SLOT records, SHARE, SLEEP, WAKE, END, STOP and PASS. Each slot records task, ready mask, start, compare, IRQ time, charge, both virtual runtimes and floor in half-ticks, interrupted PC, SP and loop progress. Reconstruct all choices from the inputs and charge deltas. Map the interrupted PCs and returns to the frozen image, and compare private stack ranges and repeated progress. Record scope by image, CPU and run. Product latency, interference and physical timing remain open.
