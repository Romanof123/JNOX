# CHG-077 · CAP-007 파일시스템 계획

[English](filesystem-plan.en.md) · [서비스 및 C ABI 설계](architecture.md) · [Pi 4 부팅 패키지](boards/pi4-p1.md)

## 현재 범위

Pi 4용 FAT 부팅 패키지에는 펌웨어가 읽을 kernel8.img를 담는다. 모델의 직접 로더도 원시 이미지를 받는다. 실행 중인 J-NOX 프로세스가 마운트된 파일을 여는 동작은 별도 검증이 필요하다. EVD-050은 제어 작업과 호스트 수집 경로에 관한 자료다. 대상의 경로 해석·쓰기·복구·영속성을 검증하는 근거는 아직 없다. [제어 실험](evidence/evd-050.md)

## 첫 서비스

1. 정적으로 링크한 C 프로그램 두 개와 예제 파일을 결정적 읽기 전용 루트 이미지에 넣는다. 오프셋·길이·해시를 기록하고 중복 이름, 영역 중첩, 잘림, 미지원 형식 및 루트 이탈을 공개 전에 거부한다. 이 단계는 블록 드라이버 없이 구현할 수 있다.
2. 사용자 공간 이름 서비스가 절대 경로를 구성요소 단위로 가장 길게 일치하는 마운트에 전달한다. 이미지 관리자는 /, RAM 관리자는 /tmp를 제공한다. 상대 경로는 호출자가 권한을 가진 디렉터리에서 해석한다. 현재·상위 디렉터리 및 마운트 경계 규칙을 정한다. 첫 범위는 일반 파일과 디렉터리다. 미지원 링크·특수 파일·마운트 요청은 명시적으로 거부한다. 감독 서비스에만 마운트 등록 권한을 준다. 루트 이미지 쓰기는 EROFS이고 RAM 내용은 재시작 시 사라진다.
3. 프로필별로 경로·이름 바이트, 깊이, 마운트 수, 열린 파일 설명과 디스크립터 수, RAM 노드·바이트, 디렉터리 항목, 큐, 요청 크기 및 미완료 블록 요청의 한도를 고정한다. SDK와 시작 매니페스트에 공개한다. 버퍼를 예약하고 해당 한도에서 ENAMETOOLONG, EMFILE/ENFILE, ENOSPC를 반환한다. 저장장치 대기는 커널 스케줄링 락을 보유하지 않으며 취소·타임아웃 규칙을 둔다.
4. open/openat, read, write, close, stat, mkdir, unlink, 같은 마운트의 rename을 유한 IPC로 전달한다. 디스크립터는 접근 모드·오프셋·백엔드 식별자가 있는 열린 파일 설명을 참조한다. dup는 오프셋을 공유하고 개별 open은 독립적이다. close는 참조 하나를 해제하고 마지막 참조가 사라지면 객체를 회수한다. unlink 후에도 열린 파일은 쓸 수 있는 기존 권한 범위에서 접근 가능하다. 프로세스 종료 시 모두 회수한다. 자식 상속과 close-on-exec를 정의한다. 복제·전달·상대 경로·재시작으로 권한이 확대되지 않게 하고 세대 번호로 옛 핸들을 거부한다. 부분 쓰기·EOF·읽기 전용 오류·같은 마운트 이름 교체의 원자성과 마운트 간 EXDEV를 명시한다.
5. 화면 없이 대상 프로세스에서 이미지 파일을 읽고 /tmp 파일을 생성·쓰기·재개방한다. 용량 한계와 디스크립터 재사용을 확인한다. cat sample.txt | wc -l을 두 외부 프로그램으로 실행하고 모든 쓰기 끝이 닫힌 뒤 EOF를 확인한다. 소스·이미지·실행 대상·SDK 해시, 원본 시리얼, 연산별 결과와 독립 콘텐츠 대조를 남긴다. 펌웨어 출력이나 호스트 파일 접근은 이 검증을 대신할 수 없다.

## 선택형 영속 저장소

매체를 정한 뒤 형식을 확정한다. 검증된 관리형 블록 장치라면 전용 데이터 파티션에 유지보수되는 ext4 등 저널링 구현을 우선 검토한다. 호스트에서 내용을 확인하고 기존 복구 도구를 쓸 수 있다. 펌웨어 파티션 쓰기를 차단한다. 원시 NOR/NAND라면 소거 단위, 불량 블록·ECC 책임과 수명을 파악한 뒤 플래시 전용 백엔드를 고른다. 네트워크 파일시스템은 가용성 조건을 별도로 정하는 후속 마운트다.

이름·권한·복구는 파일 서비스가 담당한다. 블록 서비스는 유한 읽기·쓰기, 용량·논리 블록 크기, 완료 및 명시적 캐시 플러시를 제공한다. 네이티브 Rust 드라이버가 MMIO·인터럽트·DMA를 맡거나 격리 Linux 도메인이 컨트롤러를 전담해 같은 블록 서비스를 제공한다. 쓰기 볼륨의 소유자는 하나다. 버퍼 권한·크기·DMA 매핑·타임아웃·재시작 세대를 제한한다. Linux가 파일시스템까지 담당하면 파일 서비스 어댑터를 사용하고 볼륨을 단독 소유한다. 두 도메인이 같은 볼륨을 동시에 쓰기 마운트할 수 없다.

같은 디렉터리에서 파일을 영속적으로 교체하려면 임시 파일에 부분 쓰기를 처리하며 끝까지 기록하고 파일 디스크립터를 fsync한 뒤 rename으로 대상 이름을 교체하고 부모 디렉터리를 fsync한다. 지연 쓰기·플러시·디렉터리 동기화 오류를 호출자에게 전달한다. 파일 동기화는 데이터와 필요한 메타데이터를, 디렉터리 동기화는 새 이름 연결을 대상으로 한다. 향후 디렉터리를 넘는 이동은 양쪽을 동기화한다. 이름 교체 원자성과 전원 상실 후 영속성은 별개다. 유효한 플러시나 디렉터리 동기화를 제공할 수 없으면 영속 교체를 미지원으로 표시한다. 복구 실패 시 마지막 볼륨을 자동 포맷하지 않는다.

## 검증 및 제품 결정

폐기 가능한 모델 디스크에서 정상 재시작, 서버 중단, 공간 고갈, 손상 이미지, 각 쓰기·동기화·이름 교체 경계의 중단을 검증한다. 재마운트 후 이름·콘텐츠 세대·체크섬·복구 결과를 기록한다. 최종 디렉터리 동기화 전 허용 결과는 백엔드별로 먼저 정한다. 최종 성공 응답 후에는 새 데이터 전체가 남아야 한다. 손상·혼합 내용·확인된 상태 유실은 실패다. 모델은 소프트웨어 절차를 검증한다. 실물 영속성은 명시한 보드·저장장치 부품·펌웨어·캐시·마운트 옵션에서 실제 매체 전원을 경계별로 차단하고 새로 부팅해 독립 확인한다. 모든 시도, 복구 시간, 쓰기 증폭과 실시간 작업 간섭을 기록한다.

제품 책임자는 첫 응용, 쓰기 경로와 용량, 보드와 매체, 재시작 및 갑작스러운 정전의 보장 범위, POSIX 호출과 소유·접근 권한, 최대 허용 유실과 복구 시간, 격리 Linux 허용 여부를 정해야 한다. 영속성 결정 전에도 읽기 전용 이미지와 /tmp 작업은 진행할 수 있다.
