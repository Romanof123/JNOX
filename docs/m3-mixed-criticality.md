# 혼합 임계도 실행 예산 강제

[English](m3-mixed-criticality.en.md) · [변경 이슈 #51](https://github.com/Romanof123/JNOX/issues/51)

CHG-022 · POL-015 · REQ-002/005/023 → DES-003/012 → IMP-020 → VER-002/005/023. Cortex-A72 virt 구성은 CPU 한 개, 작업 슬롯 네 개, GICv2 물리 타이머 한 개, 서비스 슬롯 여섯 개다. Q는 카운터 주파수를 20으로 나눈 정수 몫이다. 슬롯 경계는 시작 시각에서 Q의 정수배로 정한다. 큰 우선순위가 먼저 실행된다.

| ID | 임계도 | LO/HI 예산(슬롯) | 우선순위 | 상대 기한(슬롯) |
| --- | --- | --- | ---: | ---: |
| 0 | LO | 2 | 1 | 3 |
| 1 | HI | 1/3 | 4 | 4 |
| 2 | LO | 2 | 2 | 3 |
| 3 | HI | 1/1 | 3 | 5 |

작업 0으로 시작한다. 시각 1에 이 작업을 완료하고 새 작업 0을 포함해 네 슬롯을 모두 채운다. 작업 1이 LO 모드 허용량을 쓴 뒤 시각 2에서 작업 0~3의 남은 요청은 2·3·2·1단위다. 작업 1에 다음 단위를 주려면 HI 모드 전환이 필요하다. 추가 실행에 앞서 두 LO 작업을 제거하고 새 LO 해제 요청과 HI 작업이 살아 있을 때의 조기 복귀를 거부한다. 작업 1의 누적 서비스 세 단위 이후 네 번째 부여를 거부하고 예산 소진으로 종료한다. 살아남은 작업 3은 기한 안에 계산을 완료해야 한다. 모든 작업이 멈추면 미승인 복귀를 거부한 뒤 승인된 복귀를 수락하고 새 LO 작업을 실행한다. 예상 슬롯 소유자는 0·1·1·1·3·0이다.

실제 IRQ 여섯 번의 만기 및 진입 시각, 선택한 작업의 실행 루프 주소, 전용 스택, 진행량과 결과를 보존한다. 같은 카운터에서 전환 경계·IRQ 관측·상태 변경·HI 문맥 실행 시각의 순서를 대조한다. 이 시험의 최대 이월 부하에서는 네 슬롯이 모두 차 있어야 한다. 제품 시간 상한·제품 최대 부하·시스템 고장 대응은 별도 근거가 필요하다.

kernel에서 `cargo build --release --locked --features amc-bench -j1`, 저장소 루트에서 `python3 tools/qemu_boot.py --profile amc --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel`를 실행한다. 최초 실행에서는 QEMU의 -d int 출력을 별도 파일로 저장하고 같은 프로세스에서 나온 UART를 보관한다. 마지막 줄은 AMC PASS다. 기록된 ELR을 동결 ELF의 amc_lo_initial·amc_hi·amc_survivor·amc_lo_fresh 시작/끝 심볼 및 실제 예외 복귀 주소와 대조한다. IRQ ≤ 커밋 ≤ 재개된 작업의 첫 관측 < 다음 만기 순서를 확인하고 첫 관측과 두 번째 슬롯 경계의 차이를 보고한다.
