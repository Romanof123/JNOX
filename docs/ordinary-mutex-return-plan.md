# CHG-072 · 선택된 LOW의 실제 복귀 경로에서 한 번만 무장하는 뮤텍스 타이머

## 보존한 최초 실행

47ea89049b3efd2dd74642562a9973e15ad26a15의 첫 PI 일반 실행 ELF SHA-256은 100c56a95675c2295f98067a063091139e2cbfa75fb55b52a724f8652fbce9be, UART SHA-256은 b75c00f7a7b2d6d94271dd0bdd2d9912d6f14235529ddc90d4f2ed865b9fd892이다. 게스트는 사유 16으로 종료했다. 호스트는 끝 표식을 읽고 0.125881초 뒤 상태 0으로 기록을 끝냈다. 독립 최초 실행은 4건 중 3건이 적격이다. PI 추적은 청크 38개 완료 뒤 PC 0x40202bc8에서 중단됐다. IRQ는 0x40201280에 진입하고 ERET로 HIGH의 0x40201c54에 복귀했다. 천장 일반·추적 모두 입력 인덱스 루프 0x40202cd8에서 중단됐으며 완료 청크 수는 각각 0·52였다. 천장 추적에서는 IRQ가 0x40201280에 진입한 뒤 ERET로 LOW의 0x40202cd8에 복귀했다. 일반 실행에는 외부 예외 로그가 없다. 적격 세 건은 모두 256청크를 완료했다. PI는 2건 중 1건, 천장은 2건 모두 충족했다. [독립 최초 실행 보고서](evidence/ordinary-mutex-first/README.md) · [상위 이슈 #49](https://github.com/Romanof123/JNOX/issues/49)

62.5 MHz에서 오프셋은 정확히 6250틱이었다. 무장 시 CTL=1, IRQ 시 CTL=5, IAR=30, CVAL=211091이었다. 복원 표본은 비교시각보다 283틱 늦었고 K[0]는 그보다 1207틱 뒤, IRQ 진입은 K[0]보다 9533틱 뒤였다. 비교부터 벡터까지는 11023틱이었다. 이 구간은 계측 비용을 포함한다. 일반 실행에서는 실제 ERET 시각과 IRQ가 처음 pending이 된 시각을 관측하지 못했다.

저장 LOW 프레임은 0x40209ed0, SPSR은 0x345다. PC 0x40202b74는 mutex_batch_compute의 첫 명령 sub sp,sp,#16이다. IN_WORK를 쓰는 0x40202ba0 및 최초 입력 읽기 0x40202bb4 전이다. LOW가 X를 보유했으나 IN_WORK=0이고 완료 청크도 0이었다. HIGH 선택 뒤 복원 행은 없었다. 차단·소유권 이전·커밋·읽기·종료·경합 성공 구간은 미관측이다.

## 추가 실험 설계와 최초 검증 대기

기존 기준은 Rust 최종 획득 핸들러 끝의 표본이다. ERET 근처 표본으로 바꾸면 기준시각도 바뀐다. 기존 구현·100 µs 오프셋·최초 네 시도 및 독립 판정을 그대로 보존한다. Rust 내부 후처리를 줄이는 방법도 있으나 마지막 Rust 쓰기 뒤에도 함수 복귀·프레임 복원·ERET가 남는다. 플래그를 앞당기거나 코드 배치만 바꿔서는 실제 산술 진행을 입증할 수 없다. 추가 구성을 명시적으로 선택하고 보호 계산 진입 요건을 유지한다.

1. IRQ를 가린 획득 경로에서 최종 자원(PI X, 천장 Y), 정상 반환 x0=0, 호출·선택 LOW, 소유자, 프레임 범위·신원·ELR 및 IRQ 허용 SPSR을 확인한다. 선택 프레임·PC·세대·F/10000을 담은 일회성 대기 기록을 준비한다. F가 양수이고 10000으로 나누어떨어져야 한다. 지정 복귀에서 불일치·재사용은 원시 사유를 남기고 정지한다.
2. sched_start_frame의 시스템·일반 레지스터 복원, SP 복구와 CLREX 뒤, ERET 직전에 구성 전용 어셈블리 경로를 둔다. 복원한 SP에서 프레임 크기를 빼 대기 프레임과 비교하고 ELR·TPIDR·저장 결과를 검사한다. 방금 소비한 프레임 범위에 임시 저장해 작업 레지스터·SP·NZCV를 보존한다. 핸들러에서는 인터럽트를 가리고 기존 SPSR은 ERET로 복구한다. 대기 기록이 없으면 통과하며 지정 복귀만 한 번 소비한다. 기존 R 복원 표본은 유지한다.
3. 토큰 소비 후 ISB와 CNTPCT 표본, 넘침 검사가 있는 F/10000 덧셈, CVAL 쓰기, CTL 활성화, ISB, CVAL·CTL 되읽기를 수행한다. 목표·활성·마스크 비트 오류나 넘침은 타이머를 끄고 원시 실패로 종료한다. 실제 레지스터값과 토큰·단계 유효 비트를 유한 기록에 남긴 뒤 마지막 ERET 전 표본을 채취하고 임시 레지스터를 복원한다. 이미 목표 시각이 지났거나 ISTATUS가 올라간 경우도 보존하며 재무장하지 않는다. 새 필드에 버전을 부여한다. 임시 스택·명령·기록 크기와 최종 표본에서 실제 복귀까지 남는 불확실성을 별도 기록한다.
4. 타이머 모드, 오프셋, 작업·청크·입력 수, 양보 지점 및 판정 기준을 유지한다. 대기 루프·사전 예열·재시도는 배제한다. 새 구성을 끈 PI·천장·기존 mutex-bench의 ELF·적재영역·코드를 보존본과 비교한다. 복원 레지스터·스택 경계·유일한 타이머 쓰기 및 타 복귀 미무장을 확인한다. 잘못된 프레임·소유자, 토큰 재사용·중복, 넘침, 되읽기 불일치는 호스트 오프라인 합성 입력으로만 별도 검사한다. 이 대조는 거부 로직을 검사하며 게스트 시각은 관측하지 않는다.
5. 추가 구성의 PI 일반/추적, 천장 일반/추적 네 최초 실행을 새로 동결한다. ELF·소스·Linux 호스트·관측기·15초 제한과 각 최초 종료 또는 시간 초과를 남긴다. PC·타이머·프레임·잠금 순서·모든 청크·결과·종료를 원래 기준으로 독립 재생한다. 기존 구성과 새 구성의 결과·분모는 각각 기록한다. 물리 시간·보드 간섭·제품 판정은 별도 검증 대상이다.

## 기존 Rust 기준을 보존하는 별도 경로

기존 1번 판정을 보존한다. 부팅 중 IRQ를 가린 상태에서 F의 나눗셈 조건을 한 번 확인해 이 F에서 6250틱인 간격을 저장한다. 최종 획득 SVC에서 기존 기준시각보다 앞서 유한 기록 한 칸을 예약하고 성공 연산·소유자·선택 프레임·ELR·복원 순번·세대를 결합한다. 프레임·준비 상태·잠금·일회성 검사를 모두 유지한다. 기존과 같은 논리적 Rust 스케줄링 지점에서 CNTPCT를 채취하고, 준비한 간격의 덧셈 넘침을 검사한 뒤 CVAL·CTL을 쓰고 ISB 후 양쪽을 즉시 되읽어 실제 값을 검증한다. 실제 기준 표본·목표·되읽기 값을 예약 기록에 보존하고 설명 행의 출력과 어셈블리 복원 대응만 첫 IRQ 또는 실패 종료 시점으로 미룬다. 복원은 프레임·PC·순번·세대가 맞을 때만 연결한다.

기존 ELF에서 기준 표본부터 쓰기·되읽기·SVC 함수 복귀·복원 진입·R 표본·ERET까지 연결 경로를 먼저 확인한다. 기존 UART에서 무장→R은 합계 6533틱이다. Rust 처리·레지스터 접근·번역·복원 각각의 비용은 미측정이다. 별도 특성화 구성에서 같은 목표시각을 유지하고 쓰기/되읽기 종료와 복원 진입 표본을 유한 저장한다. 계측 비용을 명시하고 단계 누락 시 판정을 보류한다. Rust 기준 배치안도 자체 ELF와 별도의 최초 실행으로 평가한다. 복귀 직전 기준 실험과 기존 PI 일반 미통과 사례는 각각 추적한다.
