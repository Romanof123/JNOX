# 스케줄링 릴리스 ELF 크기 측정 (#66, #21)

최소 구성과 확장 구성의 실제 링크 결과를 비교한다. 의도한 기능 외에는 타깃, 도구 체인, 프로필, 링커 스크립트와 빌드 설정을 맞춘다. JSON과 함께 빌드 명령, 리비전, 활성 기능을 기록한다. 이름과 해시만으로 빌드 설정을 검증할 수 없다.

```sh
python tools/scheduling_footprint.py --baseline out/minimal.elf --feature extended=out/extended.elf > footprint.json
```

추가 구성마다 --feature NAME=PATH를 반복한다. 성공하면 기준값, 구성별 측정값, 기준값을 뺀 부호 있는 바이트 차이를 단일 JSON 객체로 출력한다. 잘못된 입력은 표준 오류에 사유를 쓰고 코드 2로 종료한다. 일반 프로그램 헤더 표와 이름이 있는 섹션 표를 갖춘 ELF64 리틀엔디언 AArch64 또는 x86-64 실행 파일을 같은 아키텍처끼리 비교한다.

| 바이트 필드 | 산출 기준 |
|---|---|
| file | 헤더, 메타데이터, 끝에 붙은 바이트를 포함한 실제 파일 길이. SHA-256도 파일 전체를 대상으로 한다. |
| load_file | 각 PT_LOAD의 파일 오프셋부터 p_filesz만큼의 구간을 합친 길이. |
| load_memory | 각 PT_LOAD의 가상 주소부터 p_memsz만큼의 구간을 합친 길이. |
| load_backed | 각 PT_LOAD의 가상 주소부터 p_filesz만큼의 구간을 합친 길이. |
| zero_fill | load_memory에서 load_backed를 뺀 값. 겹치는 주소는 파일에 대응하는 매핑을 우선한다. |
| alloc | 비어 있지 않은 SHF_ALLOC 섹션의 가상 주소 구간을 합친 길이. 각 구간은 로드 메모리 범위 안에 있어야 한다. |
| padding | load_memory에서 alloc을 뺀 값. 매핑된 헤더와 섹션 사이 빈 공간도 포함한다. |
| bss | .bss 또는 .bss.* 이름의 할당된 SHT_NOBITS 섹션 구간을 합친 길이. |
| linked_stack | NOLOAD 예약 공간을 포함한 .stack 또는 .stack.* 이름의 할당 섹션 구간을 합친 길이. |

모든 구간은 시작 주소를 포함하고 끝 주소를 제외한다. 지표 안에서는 중복 바이트를 한 번만 센다. 주소 공간이 다르거나 범주가 겹치는 지표끼리 합산하면 안 된다. 길이 0인 구간은 기여하지 않는다. 이름 기반 집계는 링커 명명 규칙에 의존한다. linked_stack은 링크 시 예약량이다. 실행 중 최대 스택 사용량, 힙 사용량, 물리 배치, 스케줄링 비용과 실제 로더 동작은 별도 근거가 필요하다.

## CHG-090 · 최소 virt 구성의 엔지니어링 판정

CHG-090은 아래의 단일 링크 구성에 경계값을 포함하는 두 한도를 정했다(#4, #21). CHG-111(#285)에 따라 두 한도와 비교 절차는 이 기존 참조 벤치마크를 선택해 실행할 때만 적용한다. 제품 프로파일은 DES-001 및 DES-004에 따라 자체 할당량을 검증한다. [REQ-009](requirements.md) · [VER-009](verification-plan.md)

| 구분 | 정확한 구성 |
|---|---|
| 판정 대상 최소 구성 | `kernel/`에서 `JNOX_ARCH=aarch64 JNOX_BOARD=virt`만 지정하고 나머지 JNOX 선택자는 모두 해제한다. Cargo 기능은 지정하지 않는다. 디스패처는 boot를 선택한다. |
| 스케줄링 비교 구성 | 최소 구성에 `JNOX_PROFILE=fixed JNOX_APP=fixed-rr`만 추가한다. 일반 Rust 고정 우선순위 라운드로빈 작업을 사용한다. 비용·관측·추적 선택자와 벤치 기능은 해제한다. 두 구성의 바이트 수와 비교 구성에서 최소 구성을 뺀 차이를 함께 기록한다. |

두 이미지를 각각 `cargo +1.95.0 build --target aarch64-unknown-none --release --locked -j1`로 빌드한다. 저장소의 Cortex-A72 플래그와 릴리스 최적화 설정을 그대로 사용한다. 리비전, 인수, 환경, 컴파일러·링커 식별 정보, ELF SHA-256 및 독립적으로 추출한 프로그램·섹션 표를 보존한다. ELF 배치만으로 작업 구성을 알 수 없으므로 선택 명세도 보존한다. [빌드 선택](../kernel/build.rs) · [타깃 설정](../kernel/.cargo/config.toml)

| 최소 이미지 판정량 | 산식 및 한도 |
|---|---|
| 코드와 상수 | 코드·상수 사이의 정렬 패딩을 포함해 RX 세그먼트의 파일 적재 바이트 전체를 센다. RX 파일 크기와 메모리 크기가 같고 **262,144바이트 이하**여야 한다. |
| 정적 RAM 예약량 | RX 시작부터 RW 메모리 끝(미포함)까지의 물리 주소 범위가 **2,097,152바이트 이하**여야 한다. RX, 두 세그먼트 사이 정렬 공백, 초기화 데이터, 영 초기화 영역과 RW 내부 패딩을 포함한다. 버퍼·풀·부트 스택·BSS 내 태스크 스택은 각각 한 번만 센다. |

virt 링크 스크립트에 맞는 리틀엔디언 AArch64 ELF64 ET_EXEC만 판정한다. 프로그램 헤더는 비어 있지 않고 겹치지 않는 PT_LOAD 두 개가 RX, RW 순서여야 한다. 가상·물리 적재 주소가 같고 파일 오프셋·크기·정렬이 유효해야 한다. 진입점과 RX 시작은 0x40200000이다. RW 시작은 4 KiB 정렬이며 끝은 0x48000000 이하여야 한다. 정렬된 16,384바이트 NOLOAD 부트 스택을 포함한 모든 할당 섹션이 적절한 세그먼트에 속해야 한다. 지원하지 않는 헤더·배치나 귀속을 확인할 수 없는 할당은 판정을 거부한다. 부트 코드는 SP를 스택 상단에 설정하고 링크된 BSS를 초기화한다. 독립 표에서 물리 범위를 재구성할 수 있도록 세그먼트 범위, 내부 패딩, 두 세그먼트 사이 공백을 구분한다. [링크 스크립트](../kernel/link.ld) · [부트 코드](../arch/aarch64/start.S)

엄격 판정 명령은 `python tools/virt_footprint.py --minimal MINIMAL.elf --fixed-rr FIXED.elf`이다. 최소 이미지 배치가 유효하고 두 한도를 모두 만족해야 통과한다. 유효한 최소 이미지가 한도를 초과하면 실패하며 지원하지 않는 산출물은 적합 판정을 받을 수 없다. 비교 구성에는 크기 한도를 부여하지 않는다. 저장공간 산정을 위해 ELF 전체 파일 크기와 실제 적재 파일 바이트를 별도로 보고한다. RAM 적재 방식인 이 virt 구성에는 비휘발성 저장공간 예산이 없다. 펌웨어, 장치 트리용 선두 2 MiB, MMIO, 미할당 게스트 RAM, 호스트 저장소는 커널 예약 범위에서 제외한다. 스택·동적 할당의 실제 최대 사용량, 초기화 시간, 실보드 지연, 다른 포트 및 제품의 메모리 할당은 별도로 검증한다.

### CHG-090 · BSS 정렬 판정 정정

34454f955a30b0d3be0a4dfc73435a344f2dbff9의 최초 독립 게이트에서 BSS 끝 주소가 정렬되지 않은 별도 링크 대조 이미지 두 건이 최소 이미지 입력과 fixed-RR 비교 입력에서 허용됐다. 이 최초 허용 결과는 검사기 실패로 보존한다.

두 입력 모두 [virt 링커 스크립트](../kernel/link.ld)가 출력 섹션 시작을 정렬한 후 __bss_start를 정의하고, 위치 카운터를 8바이트 경계에 맞춘 후 __bss_end를 정의한다. 따라서 할당된 .bss의 실제 시작 주소와 끝 다음 주소(시작 주소 + 크기)는 ELF가 선언한 정렬값과 독립적으로 각각 8의 배수여야 한다. 어느 하나라도 어기면 비교 전에 잘못된 배치로 종료 코드 2를 반환한다. 생략된 .bss와 정렬된 빈 .bss의 할당량은 0바이트다. 기존 크기 산식과 상한의 경계값 포함 규칙은 그대로 적용한다.

같은 링커 스크립트로 만든 보존 대상 .rodata를 기존 검사기가 잘못 거부한 결과도 보존한다. SHF_GNU_RETAIN(0x200000)은 링커의 섹션 보존을 지시한다. 필수 섹션 유형과 접근 권한을 만족하면 이 플래그를 허용하며 바이트 산식은 변하지 않는다.

유효한 최초 최소 이미지와 fixed-RR 이미지의 측정값은 최초 게이트 기록에 유지한다. 수정 검사기는 같은 ELF에서 바이트 수와 차이를 재현해야 한다. 두 입력 위치 모두 시작 또는 끝 경계가 어긋난 BSS 대조를 거부해야 하며, 보존된 읽기 전용 상수는 일반 읽기 전용 상수와 같은 산식으로 계산해야 한다.
