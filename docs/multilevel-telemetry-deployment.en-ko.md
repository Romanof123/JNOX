# M4 telemetry publication under strict and feedback queues / M4 엄격·피드백 큐의 경보 게시

[#329](https://github.com/Romanof123/JNOX/issues/329) · CHG-133 · IMP-133 · EVD-133 reserved. Baseline ac3965d4a0865172b73657cb510c3a4932b096a8. PM adopts one default-clock Cortex-A72 QEMU virt CPU, GICv2, TCG, 128 MiB, 62,500,000 Hz, for the project M4 sensor reporter and background CRC. Each report must publish its complete result within one 40 ms reporting period of its requested release. This cadence-derived deadline applies to all rounds, including the first. The [original POL-009 criteria](scheduling-policies.en.md#L73) and the [native scheduler deployment](native-multilevel-applications.en-ko.md) retain their separate evidence.

## Deployment / 배포

~~~sh
sh sdk/native-aarch64/build.sh examples/native-multilevel/report.c report.elf
sh sdk/native-aarch64/build.sh examples/native-cbs/crc.c crc.elf
python3 tools/build_native_el0.py --out strict-alarm --policy mlq --elf report.elf --arg=--publication-deadline-ms=40 --class 7 --peer-elf crc.elf --peer-class 1 --quantum-ticks 625000
python3 tools/build_native_el0.py --out feedback-alarm --policy mlfq --elf report.elf --arg=--publication-deadline-ms=40 --peer-elf crc.elf --allotment-ticks 625000,1250000,2500000 --boost-ticks 6250000
~~~

Use the existing operator boot path with those packages. Freeze identical reporter/CRC binaries across both modes, package argv and source/tool/kernel/ELF hashes before capture. MLQ is strict class 7 versus 1 with a 10 ms quantum. MLFQ uses top/middle/bottom service allotments of 10/20/40 ms and a 100 ms boost in accumulated **charged CPU service**. Neither policy grants a general minimum background share. The CRC application performs ordinary private stream work across reporter sleeps and verifies its own result. No new scheduling policy, syscall or external service is needed.

The reporter accepts zero arguments beyond argv[0] for the existing behavior, or exactly one --publication-deadline-ms=N with a positive decimal millisecond value convertible exactly to u64 nanoseconds. Reject unknown, duplicate, malformed, zero or overflowing values before creating a report. Keep existing successful status 53, use 106 for invalid setting and 107 if any validly measured round misses its configured bound. Compute representable target timestamps and differences with checked arithmetic; retain distinct existing clock/input failures. The operator option controls the reporting deadline; the original next-release interval stays 40 ms. A valid miss still publishes every available round and its actual samples, then exits 107. A malformed option exits 106 with zero publications. Test syntax, conversion overflow, exact-deadline equality and one-nanosecond-late comparison using fixed arithmetic inputs; use one actual invalid-argument launch to check operator-visible behavior. Do not manufacture a late healthy guest.

일반 실행에는 기존 무인자 동작을 유지한다. 기한 옵션은 밀리초 정수이며 잘못된 입력은 게시 전에 종료값 106으로 거부한다. 정상 입력의 기한 초과는 실제 결과·시각을 남긴 뒤 107로 보고한다. 채택된 두 배포 구성은 모두 40 ms로 고정한다.

## User-visible result and measurement / 사용자 결과 및 측정

Use the existing three independent rounds. Before each wait read monotonic time and request D=now+40,000,000 ns with the ordinary absolute sleep ABI. Retain D and the existing post-wake timestamp. Reduce the full 4,096 samples x[i]=(17i+3+round) mod 256 and count values ≥240. Publish each completed alarm count and cumulative result in private application memory. After writing all output fields and updating totals, publish a per-round completion marker, ordered after those stores. Only then issue a **fresh** SDK CLOCK_MONOTONIC read. The private post-publication sample U, D, marker, round output, cumulative output and actual deadline verdict must be recoverable independently after process exit. Emit an operator-visible summary or documented ordinary status plus a supported result reader; no kernel inspection of app-specific outputs. Use ordinary no-argument behavior for compatibility and preserve its original data symbols.

For each package/round require 0 < U−D ≤40,000,000 ns and an actual result commit after the target; equality at the upper limit passes. The post-publication syscall provides a conservative upper bound on completion. A read immediately after sleep provides only a lower bound on pending work. Reconcile the observed target with the programmed due time, physical IRQ, accepted wake, selected reporter and actual resumed execution. Check ordered publication and syscall in the linked code, private RAM and exception evidence when available; a pre-ERET stamp cannot establish publication. Where guest time conversion is quantized, use the worst consistent endpoint for upper-bound scoring and retain uncertainty. On this frozen frequency a count is exactly 16 ns. A late or ambiguous sample, an unproven result or a missing clock call leaves the quantitative round unqualified. Report each measured value and margin separately.

Require three committed values of 256; cumulative values 256,512,768; 12,288 bytes and three blocks, final reporter status 53. Independently recompute CRC-32 for its actual completed private input, verify byte/block counts and expected exit 17, and confirm real CRC progress during each of the three reporting sleeps via task-owned memory observations or a source-attributable productive counter. The same CRC process must resume after reporter service; isolate private pages/stacks and match saved/restored PC/SP. Retain actual counter frequency, release/wake chronology, gaps and private data. No wall-clock WCET inference follows from four virtual boots.

경보 4,096개 표본을 처리한 뒤 라운드·누적 결과와 완료 표지를 순서대로 쓴 다음 새 단조 시각을 읽는다. 요청 기한 D부터 이 표본 U까지의 양의 차이를 게시 지연 상한으로 판정한다. 4회 실행 각각 세 라운드 모두 점검하고 각 측정값·여유·산출물·백그라운드 진척을 남긴다.

## Family decision / 정책군 판정

1. Take first strict plain, strict externally traced, feedback plain, feedback externally traced cold boots in that order. Every position must satisfy all three release-to-publication deadlines, all outputs, CRC progress and correct actual policy selections. Record all 12 rounds, failing firsts and raw UART, bounded journal/loss counter, appropriate private RAM, disassembly, external exception log when enabled, immutable host/QEMU argv and hashes. Keep the first run for each position irrespective of outcome. A dropped row inside a required live causal or deadline interval makes that interval incomplete. Separate evidence from complete intervals remains usable.
2. Preserve the original strict-class saturation rule. [EVD-040](evidence/evd-040.en.md) independently replayed 15 MLQ decisions: two high peers alternated under actual timer IRQs while the ready low worker got zero service until both high workers exited. [EVD-122](evidence/evd-122.en.md) exercised the native three-ELF case, initial high 0→1→0 and low service after the high pair exited. The new reporter has higher class and three real wakeups. Together these answer different sides of the class rule.
3. Preserve the feedback rule: charge early yields cumulatively, demote on exhaustion, and verify ready order and the immediate next dispatch at boost with CPU-bound and interactive peers. EVD-040 captured all 42 diagnostic decisions including demotion and the row-10 boost retaining the client ahead of both peers. EVD-122 observed demotion on yield 305 and six boost crossings in each main feedback run; its equal/cumulative/solo yield streams retained 512 rows and dropped 15,939/15,905/15,886 later rows. No inference about an unrecorded next dispatch is allowed. In the **new main feedback boots**, independently replay at least one boost under these adopted settings, including preserved ready order and actual next dispatch, and report measured wake and background progress. Reuse the archived demotion prefix and finite saturation controls only for unchanged scheduler semantics; identify original source/hash and exact records. If required evidence is missing or affected by a change, repeat that particular native strict saturation or feedback yield/boost control with adequate capture. Missing proof stays open.
4. Run one unconfigured reporter+CRC ordinary compatibility boot and the malformed option control separately. Preserve the linked bounded MLQ first-service and interactive MLFQ response studies in [EVD-099](evidence/evd-099.en.md) and [EVD-101](evidence/evd-101.en.md) with their original workloads and conditions. Their limits are not the new app's deadline.
5. Independent Release records verdicts for the exact candidates, functional cases, timing, prior controls and limitations on observable journal prefixes. Integration links the actual merged configuration and both language matrices. PM explicitly decides the #21 POL-009 checkbox for this adopted virtual deployment after those records are available. A wider workload, physical hardware or item safety timing requires its own configuration and authority.

엄격 클래스 포화와 유한 상위 작업 종료 후 하위 작업 진입, 조기 양보 누적 강등, 승격 직후 선택을 각 원래 증거의 실제 범위에서 확인한다. 채택한 설정에서는 이번 피드백 부팅의 승격 직후 실제 디스패치를 재생한다. 독립 Release의 결과와 병합된 근거를 바탕으로 PM이 #21의 가상 배포 판정을 명시한다.
