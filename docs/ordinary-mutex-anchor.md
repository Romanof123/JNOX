# CHG-072 · 일반 뮤텍스 타이머 캡처

[English](ordinary-mutex-anchor.en.md) · [승인 계획](ordinary-mutex-return-plan.md) · [기존 최초 실행](evidence/ordinary-mutex-first/README.md)

`JNOX_BOARD=virt JNOX_PROFILE=mutex`에서 `JNOX_APP`으로 `ordinary-pi` 또는 `ordinary-ceiling`을 선택한다. 원래 고정 툴체인과 릴리스 빌드를 사용한다. `JNOX_MUTEX_ANCHOR`를 생략하면 기존 Rust 무장과 RAW 1을 사용한다. 아래 선택값은 모두 자신의 실제 CNTPCT 표본에 정확히 CNTFRQ/10000을 더해 PPI30을 한 번 설정한다. 보호 데이터 계산, 256묶음, 천장 구성의 중간 양보와 실제 작업 중 IRQ 판정은 기존 코드를 사용한다.

| 선택값 | 모드 | 계측 위치 |
| --- | ---: | --- |
| `rust-prepared` | 1 | 부팅 시 간격을 검증한다. LOW의 마지막 잠금 획득 기록을 먼저 준비하고 기존 Rust 스케줄링 지점에서 표본을 읽는다. CVAL/CTL 쓰기와 ISB 이후 실제 값을 되읽는다. 첫 IRQ 또는 종료 시 R과 연결한다. |
| `rust-stages` | 2 | 같은 Rust 기준시각에 쓰기 종료, 되읽기 종료, 선택 프레임 복원 진입 표본을 추가한다. 첫 표본은 쓰기와 ISB 직후이며 두 번째는 실제 되읽기와 ISB 직후다. 세 번째는 복원 프레임 SP 선택과 계측 조건 확인 직후다. |
| `selected-return` | 3 | Rust가 LOW의 성공한 최종 획득을 예약한다. 어셈블리가 레지스터·원래 SP 복원 및 CLREX 뒤에 세대·복원 순번·프레임·ELR·SPSR·TPIDR·x0를 검증하고 한 번 무장한다. 마지막 표본은 임시 레지스터 복구와 ERET보다 앞선다. |

기록은 기존 원장 외에 160바이트를 쓴다. 세대는 성공한 E 행의 1부터 시작하는 순번이다. 최초 LOW 복귀를 포함해 대응 R의 순번은 세대+1이다. 복귀 훅은 x9~x14를 사용한 뒤 원본 프레임 슬롯에서 그대로 되살린다. 새 스필이나 SIMD 변경이 없고, SP·처리기 NZCV·선택 SPSR을 보존한다. 실패 경로는 예외를 가리고 타이머를 끈 뒤 부트 스택에서 출력한다. 마지막 표본 뒤에는 저장, NZCV와 임시 레지스터 복원, SP 복원, ERET 분기가 있다. 실제 ERET 틱과 최종 명령 수·배치는 별도 링크 검증 대상이다.

기존 소스 `47ea890`의 PI/천장에서 CNTPCT 표본은 각각 0x40202780/0x4020287c, CVAL/CTL 쓰기는 0x402027a8·0x402027ac/0x402028a4·0x402028a8, 되읽기는 0x402027b4·0x402027b8/0x402028b0·0x402028b4였다. 성공 에필로그와 RET은 각각 0x402026e4~0x40202700/0x402027b4~0x402027d0이다. 두 이미지의 복원 진입·R 계측·ERET은 0x402019ac·0x40201a54·0x40201aa4다. 기존 PI 일반 실행의 무장→R은 Rust 꼬리와 어셈블리 복원 일부를 합쳐 6533틱이었다.

## RAW 2 및 재생

H/T/S/E/R/C/B/HIGH/A/M/K는 RAW 1의 순서·폭·단위를 유지한다. T 뒤에 W와 P를 각 한 행 출력한다. 숫자는 소문자 16자리 16진수 u64다. R은 원래대로 최종 GPR 복원 전 표본이다. T의 요청값과 실제 읽은 값은 판정 실패 시에도 해당 단계까지 보존한다. 빠진 표본은 유효 비트가 0이며, 최종 표본이 없을 때 경과 필드는 NA(모든 비트 1)다.

| 행 | 필드 순서 |
| --- | --- |
| W (13개) | 버전 1, 모드, 상태, 유효 비트, 세대, 복원 순번, 선택 프레임, ELR, SPSR, TPIDR_EL1, x0, 잠금 ID, 검증한 틱 간격 |
| P (6개) | 쓰기 종료, 되읽기 종료, 복원 진입, 대응 R 표본, ERET 전 마지막 표본, 그 시점 목표 경과 여부 |
| 상태 | 0 비어 있음, 1 준비, 2 사용 시작, 3 타이머 기록 검증, 4 복원 연결 완료 |
| 유효 비트 | 0x001 준비, 0x002 시작, 0x004 목표, 0x008 하드웨어 되읽기, 0x010 쓰기 종료, 0x020 되읽기 종료, 0x040 복원 진입, 0x080 최종 표본, 0x100 R 연결 |
| 추가 종료 사유 | 19 토큰 식별·순번·재사용, 20 되읽기 불일치, 21 카운터 덧셈 넘침, 22 복원 연결 실패 |

통과에 필요한 비트는 모드 순서대로 0x10f, 0x17f, 0x18f다. 되읽은 ISTATUS와 최종 표본 시점의 목표 경과 여부는 그대로 보고한다. 기존 RAW 1의 미적격 실행과 분모는 유지한다.

각 선택값마다 PI 일반·추적, 천장 일반·추적 네 자리를 별도로 고정한다. 새 Linux 기본 파일시스템에서 1코어 Cortex-A72, virt/GICv2/TCG, 128 MiB, 기본 시계, 15초 관측 시간으로 각 자리 최초 실행을 보존한다. 일반·추적은 같은 ELF를 쓰며 완전한 푸터 도착 후 호스트가 중지한다. 종료·시간 초과·부분 출력도 포함해 UART, stderr, argv, PID·종료 상태, 경과 시간, 소스·ELF 해시, 링크 디스어셈블리와 요청된 외부 예외 로그를 남긴다.

예를 들어 `python3 tools/mutex_anchor_replay.py <uart> --app ordinary-pi --anchor selected-return`을 사용한다. 종료 0은 무장 기록·IRQ 표식·완료 데이터를 확인한 경우, 1은 형식이 완전한 게스트 실패, 2는 불완전하거나 모순된 자료다. 한도는 96 KiB, E 32행, R 64행, C 256행이다. 독립 판정에는 기존 잠금·준비·인계 순서, 해당 ELF의 실제 계산 명령에서의 IRQ, 스택·결과·종료 및 추적 실행의 SVC/IRQ/ERET 대조가 필요하다. 기본 PI·천장·기존 mutex-bench의 ELF, PT_LOAD, 텍스트도 보존본과 비교한다. 새 구성의 실행·링크·실보드 결과는 아직 없다.
