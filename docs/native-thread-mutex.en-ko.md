## SDK and object lifetime / SDK와 객체 수명

Expose pthread_mutex_init(m,attr), pthread_mutex_destroy(m), pthread_mutex_lock(m), pthread_mutex_trylock(m), pthread_mutex_unlock(m) from pthread.h. pthread_mutex_t is an opaque aligned 8-byte object; reserve pthread_mutexattr_t as opaque. Only explicit initialization with NULL attributes, process-private, non-recursive, non-robust default mutex behavior is supported. No static initializer or attribute setters in this increment. Non-NULL attr returns ENOTSUP. Return positive error numbers directly and preserve the caller's errno. Outside threaded packages the new services return ENOTSUP. Provide equivalent Rust C ABI declarations with matching size/alignment and demonstrate them with a pinned/static object with a stable address. A successful acquisition is an acquire barrier, unlock is release, including handoff and the resumed lock return. Ensure the C and Rust syscall bindings also act as compiler memory barriers.

Use native-v1 SVC x8=13..17 respectively for init, destroy, lock, trylock, unlock. x0 is the object address; x1 is the opaque token for operations on initialized objects. INIT ignores prior object bytes and takes zero in x1. Return zero or negative errno in x0 and return the new token in x1 on successful INIT. The SDK stores the token only on success and clears it after successful destroy. The caller supplies live, aligned writable storage for the object's entire lifetime and serializes init/destroy against concurrent use. For raw calls validate nonzero 8-byte alignment and the full writable user range before mutation; bad address returns EINVAL. No deferred copy through an application's saved pointer. Content alone cannot authorize a different object address.

Four kernel slots per process, allocated lowest free first. Bind each live slot to its exact object VA, process and token (positive generation shifted left two, OR slot index). Begin each slot at generation 1; advance on reuse with checked arithmetic; permanently retire a slot when its next token would wrap. Scan for a live address before allocating. Capacity/generation exhaustion returns EAGAIN without mutation. Wrong address/token, copied or stale identity returns EINVAL. A second init of a live address and destroy of a held or waited-on object return EBUSY. Destroy an unlocked object to free its slot; process exit discards the whole table, sleepers and waiters. Reuse at the same address must reject the old token. A C application must never read uninitialized object bytes or rely on diagnostics for invalid C object lifetimes.

기본 속성(NULL)으로 명시적으로 초기화하는 비재귀·비강건 뮤텍스를 지원한다. C/Rust ABI 객체는 정렬된 8바이트이며 이동·복제하지 않는다. 함수는 errno를 보존하고 오류 번호를 직접 반환한다. 13~17번 서비스는 순서대로 초기화·파괴·잠금·시도·해제다. 4개 슬롯 중 가장 낮은 가용 슬롯에 프로세스·주소·세대를 결합한다. 초기화는 기존 값을 읽지 않으며 성공 시에만 SDK가 새 토큰을 저장한다. 재사용할 때 세대를 올리고 넘치면 슬롯을 퇴역시킨다. 가득 차면 EAGAIN, 오래되거나 다른 주소의 토큰은 EINVAL, 사용 중 파괴는 EBUSY다.

## Blocking and ownership / 차단과 소유권

In the masked syscall path acquire an unlocked slot immediately. trylock reports EBUSY whenever held, including by the caller. For this default implementation, diagnose blocking self-lock with EDEADLK and non-owner/unlocked unlock with EPERM. These diagnostics and live-object misuse checks are J-NOX choices where POSIX default mutex behavior may be undefined; applications should rely on correct ownership and pair successful init/destroy. Process sharing, robustness/recovery, recursive depth, priority inheritance and ceilings are outside this profile. Existing #49 protocol results retain their own scope.

For a contended lock save the post-SVC frame, register the caller as the sole possible FIFO waiter, mark it MutexWait(token) in the existing thread policy and dispatch the other runnable thread or idle. Never spin or poll. Track owner and waiter by slot **and thread incarnation** (main fixed, worker creation generation). Under the same masked transition, unlock transfers ownership directly to a valid waiter, clears the waiter, assigns success to its saved x0, and enqueues it once at the normal ready tail. The unlocker retains its turn. It cannot steal the handed-off lock with an immediate trylock. Save/restore the existing complete EL0 frame including private SP/TLS/errno locator and retain the process TTBR. A pending IRQ arbitrates normally on return. In RR a true block ends the current turn; immediate or failed operations preserve it. Recompute earliest eligible slice/sleep compare when runnable membership changes. Cooperative execution changes thread only at existing scheduling points or a true block.

An owner may sleep or join while holding a lock. Sleep wakes only when due; join wakes only on its existing completion condition, mutex wait only on handoff. Applications must avoid dependency cycles. On individual thread exit while still owning a lock, leave it permanently held by the departed incarnation until process teardown; a reused worker cannot unlock it. Do not wake its waiter or report recovered ownership. This non-robust rule can strand a process. If all survivors block without a timed wake, leave the timer disabled and remain idle; never fabricate success or a deadline. Existing process EXIT always terminates the entire process even if it holds locks.

경합 시 호출자의 복귀 프레임을 보존하고 기존 정책에 MutexWait 상태를 등록한 뒤 다른 스레드 또는 유휴 경로를 선택한다. 해제 시 같은 임계 구간에서 대기자에게 먼저 소유권을 넘기고 저장된 x0에 성공을 기록한 다음 준비 큐 끝에 한 번만 넣는다. 잠들거나 조인을 기다리는 소유자도 잠금을 유지한다. RR에서 실제 차단만 현재 차례를 끝낸다. 자기 재잠금(EDEADLK), 비소유자 해제(EPERM)는 본 구현의 진단이다. 소유 스레드가 잠긴 채 종료하면 그 세대가 소유한 채로 남아 새 작업 스레드가 인계받지 못한다. 영구 대기가 가능하며 프로세스 종료 시에만 남은 객체를 정리한다. 우선순위 상속·상한과 강건 복구는 이 계약의 범위 밖이다.

## Frozen workload and evidence / 고정 작업과 증거

Build a C main and a Rust worker callback in one ordinary ELF using the same public C ABI. Main initializes the mutex, locks it, creates the worker and yields while holding it. Worker tries once (EBUSY), publishes a release/acquire atomic phase flag, then calls blocking lock. Main yields until the flag and gives the worker a scheduling opportunity; record an actual blocked frame before claiming contention. Main folds samples 1..=128 into protected (count,sum,sum_of_squares), unlocks and immediately tries once while the worker owns the mutex. Record EBUSY as the handoff control in the cooperative run; under RR report the observed ordering, since hardware can preempt between calls. Worker resumes lock successfully, folds 129..=256 into the same fields, unlocks and returns the shared aggregate address. Main joins, checks the pointer and reads the final aggregate under lock: (256,32896,5625216). Check the full fields and return status 0 only on success. Preserve distinct errno sentinels in both threads. No timing threshold or artificial IRQ delay.

Use independent host lifecycle cases for destroy/reinit and stale tokens, four-slot capacity, failed operations preserving state, direct transfer, owner sleep followed by timed wake, exited owner plus worker-generation reuse and terminal cleanup. Use ordinary guest controls for uncontended lock/unlock, self trylock, non-owner unlock, busy destroy, reuse, and an owner sleeping to an absolute deadline while the other waits (idle then actual timer wake). Keep invalid-object controls at the raw ABI using live storage. Freeze build inputs, ELF/disk hashes, guest controls and independent expected products before the first scored run. Run cold plain then external exception-traced virt/GICv2, one Cortex-A72, 128 MiB, default-clock TCG for each mode; RR Q=625000 ticks, record observed CNTFRQ. Acquire ext4 and preserve first stdout, status, complete product, trace and misses. Bounded terminal rows expose object slot/generation/address, operation/result, old/new owner and waiter incarnations, thread states/ready order, saved/selected PC/SP/errno and physical wake/return stamps, with dropped count. Correlate external exceptions and resumed user code. Only claim the actual witnessed handoff, wake and products on that deployment.

C 메인과 Rust 콜백을 한 ELF로 묶어 같은 뮤텍스를 쓴다. 메인은 잠근 채 작업자를 만들고 양보한다. 작업자는 trylock의 EBUSY를 확인한 뒤 lock에서 차단된다. 메인이 1~128을 누적하고 직접 인계한 뒤 작업자가 129~256을 이어서 계산한다. 조인 결과 주소와 전체 (개수, 합, 제곱합)=(256,32896,5625216), 두 errno를 확인한다. 협력형과 RR의 최초 일반 실행 및 독립 예외 추적을 각각 보존한다. 별도 실사용 제어에서 절대 수면 중 소유권, 실제 유휴/깨움, 실패 및 재사용을 확인한다. 실제 저장/복귀 프레임과 커널 소유권 기록을 대조하고 측정된 환경과 관측된 결과만 보고한다.
