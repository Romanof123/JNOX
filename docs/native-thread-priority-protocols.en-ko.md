# Fixed-priority native threads and mutex protocols / 네이티브 스레드 우선순위와 뮤텍스 프로토콜

[#335](https://github.com/Romanof123/JNOX/issues/335) · CHG-136 / IMP-136 / EVD-136 reserved. Baseline 2901b441adc6388002c13ae8f61ee038fc4cd9fd. One native C/Rust process on CPU0 of single-core QEMU virt/GICv2, Cortex-A72, 128 MiB, default clock. [#49](https://github.com/Romanof123/JNOX/issues/49) owns priority inheritance (PI) and immediate ceiling; [#318](https://github.com/Romanof123/JNOX/pull/318) owns default native mutex semantics. The [IEEE/Open Group API reference](https://man7.org/linux/man-pages/man3/pthread_mutexattr_getprotocol.3p.html) describes default NONE, transitive inheritance and the maximum active boost. Role masks and depth limits are J-NOX extensions; this bounded SDK subset carries no broader POSIX conformance claim. Physical maximum blocking on M3 and product-specific ceilings remain under [#34](https://github.com/Romanof123/JNOX/issues/34) and [#21](https://github.com/Romanof123/JNOX/issues/21).

## Admission and thread ABI / 패키지와 스레드 속성

~~~sh
python3 tools/build_native_el0.py --out chain --elf sensor.elf --threads 4 --policy fifo --thread-priorities 1,2,3,4
python3 tools/build_native_el0.py --out mixed --elf sensor.elf --threads 4 --policy rr --thread-priorities 1,2,3,4 --quantum-ticks 625000
~~~

This opt-in profile has four simultaneous slots in one address space: main (slot 0), three independent joinable workers (1..3). Four manifest entries declare the base priority of each role, 1..31, larger wins; duplicates are valid. Main starts with slot 0's base and the package policy. A worker created with explicit priority takes the lowest vacant, unretired matching worker slot; NULL/default attributes take the lowest vacant worker slot with that slot's declared base and package policy. Reuse only after join/reap. No matching configured priority is EINVAL; all matching slots occupied is EAGAIN. Record configuration and actual assignments. Do not change priority dynamically in this increment. Reject missing/extra entries, out-of-range values, conflicting selectors, peer ELFs, unsupported boards and unrelated thread counts in package and raw build validation. Existing two-thread cooperative and equal-RR packages keep their original ABI and behavior.

Provide matching C and Rust representations/bindings for pthread_attr_init/destroy, pthread_attr_setschedpolicy, pthread_attr_setschedparam (struct sched_param with sched_priority) and pthread_attr_setinheritsched. Support PTHREAD_EXPLICIT_SCHED with SCHED_FIFO or SCHED_RR. Keep the default J-NOX role-assignment behavior for NULL or unmodified attributes; reject other requested inheritance modes with ENOTSUP. An explicit configuration must declare policy and priority before creation. RR threads require a package with a valid configured RR quantum. In an RR package a worker may explicitly request FIFO; in a FIFO-only package reject an explicit RR request with ENOTSUP. Reject unsupported selectors without changing the attribute. Marshal by value or copy/validate arguments in kernel space. No writable user attribute can alter a live thread. Return positive errno directly and preserve per-thread errno. On failure leave output handles and shared state intact.

Each thread has a distinct guarded stack, errno/TLS, native integer/SIMD frame, ID=(slot,generation), return value and join lifecycle; main process exit retains its existing cleanup semantics. Kernel-internal ready/wait/deadline/join records carry the incarnation. A stale ID cannot acquire a new slot's authority, wake it or consume its return. Exhaustion must fail before wrap. Apply the same generation/address checks to the four process-private mutex object slots. Do not reuse a zombie's slot/stack while join or lock state still references it. Preserve non-robust lock ownership on owner exit as in #318; no silent release, transfer or recycling into a new owner. Document unavailable resources until process teardown. Update thread-stack range validation for every supported slot and retain invalid holes.

한 프로세스에 메인과 세 작업 스레드를 동시에 실행한다. 슬롯별 기본 우선순위는 1~31이며 큰 값이 먼저 실행된다. 각 스레드의 정책·우선순위와 실행 인스턴스를 구분하고, 재사용한 슬롯에 과거 토큰이나 만료 통지가 적용되지 않게 한다.

## Dispatch / 디스패치

Use the existing fixed-priority rules with effective priority as rank. Recompute transitive donation and held ceilings after each acquire, enqueue, handoff, unlock or timeout, before selecting another owner. A strictly higher runnable effective priority preempts at the current scheduling boundary. Preserve FIFO order among an equal rank: incumbent retains until yield/block/exit or eligible RR expiry; yield queues it last. FIFO has no equal-peer expiry. RR consumes only its delivered service; a higher-priority interruption retains its residual turn and place ahead of equal peers. An expired RR owner with an equal ready peer moves to the tail and receives a new quantum. A selected FIFO peer then retains CPU by its own policy. On effective-rank changes preserve prior order for unchanged equals; newly re-ranked ready threads append at the destination rank in previous ready order, with slot ID breaking simultaneous initial arrivals. Retain the running thread on an equal-rank tie. A donation/revocation alone must not grant an RR thread a fresh quantum.

Use PPI30 and one counter. Program earliest required wake, timed waiter or eligible RR expiry. At a decision sample settle all due deadlines in deadline/slot order before handling an unlock at that same sample. Timed-out waiter removal and donation withdrawal precede handoff/dispatch. Enqueue wakes before equal-peer expiry rotation; stale IRQ cannot charge twice. Sleep, join, mutex wait and idle own distinct states. The ordinary application does not poll the lock. Retain original compare, entry/return counter, IDs, base/effective priorities, saved/restored PC/SP, actual return owner and authoritative causes, using bounded RAM and explicit drop reporting.

## Mutex ABI / 잠금 계약

Expose pthread_mutexattr_init/destroy, pthread_mutexattr_setprotocol (PTHREAD_PRIO_NONE, PTHREAD_PRIO_INHERIT, PTHREAD_PRIO_PROTECT), pthread_mutexattr_setprioceiling (1..31) and J-NOX extension jnox_mutexattr_setusers(attr, mask) for the admitted **logical slots** (bit 0 main). For this single-process deployment the mask is a scheduling contract, not an intra-process memory security boundary. It applies to future incarnations of the configured slot; actual ownership/handoff is always bound to an incarnation. Default mask includes all four. Nonempty subset required; refuse foreign bits and empty mask with EINVAL. A protect mutex must have an explicit ceiling ≥every admitted user's declared base, including uncreated roles. Invalid combinations fail init without occupying an object slot or overwriting the caller's token. Copy protocol/mask/ceiling at init; later changes to attributes affect subsequent initializations only. Keep NULL/default mutexes with PRIO_NONE behavior. Use the existing private-memory range/address and generation checks. Add Rust C ABI declarations and the necessary constants, with identical field sizes/alignment.

~~~c
pthread_mutexattr_t a;
pthread_mutexattr_init(&a);
pthread_mutexattr_setprotocol(&a, PTHREAD_PRIO_PROTECT);
jnox_mutexattr_setusers(&a, 0x3);  /* main and slot 1 */
pthread_mutexattr_setprioceiling(&a, 2);
pthread_mutex_init(&resource, &a);
pthread_mutexattr_destroy(&a);
/* Caller checks each positive error result in production. */
int rc = pthread_mutex_clocklock(&resource, CLOCK_MONOTONIC, &absolute_due);
~~~

Serialize state mutations. Use the existing [LockSet rules](../kernel/src/mutex_policy.rs) for PI and immediate ceilings: two nested owned protocol locks maximum, reverse acquisition release, per-resource wait relation, transitive PI edges, no donation across a protect edge, effective rank=max(base, held immediate ceilings, inherited waiter ranks). Check protocol user membership on lock/try/clocklock (EPERM), cycle/self-wait (EDEADLK), depth excess (EAGAIN), wrong-owner unlock (EPERM), and out-of-order nested protocol unlock (EINVAL). Trylock on a held permitted lock returns EBUSY without joining. For ordinary NONE locks preserve #318 self/try/error behavior. Enforce acyclic waits even if mixed protocols participate; mixed ownership cannot bypass the bounded protocol depth. Preserve legacy two-thread admission behavior. On unlock choose the highest pre-release effective-priority waiter for protocol locks, FIFO for equals, directly transfer ownership before waking. NONE preserves FIFO/direct handoff. A third party cannot steal a handed-off lock. Failed operations must not mutate wait order, ceilings, ownership, generations or active timer except for independently due events.

pthread_mutex_clocklock(m,CLOCK_MONOTONIC,abs) supports normalized absolute timespec only. Invalid clock or fields EINVAL, unreadable input EFAULT, unrepresentable counter target EOVERFLOW; validate before mutating. If immediately acquirable, succeed even when the valid deadline has passed. Otherwise an already expired request returns ETIMEDOUT, never queues; a later deadline inserts one bounded wait. Mark a live waiter ETIMEDOUT and remove its donation at actual expiry. Unlock prior to expiry transfers to it once and cancels its timer; a delayed compare cannot act on a reinitialized object or recreated thread. Provide ETIMEDOUT in both SDK interfaces. Publish protected writes with release ordering; successful lock/clocklock/try or resumed direct handoff has acquire ordering. No real-time clock dependency.

PI는 기다리는 스레드의 유효 우선순위를 소유자에게 전이하고, 즉시 천장은 획득 시 바로 승격한다. 선언된 슬롯·천장·깊이 2를 검사한다. 동률 대기자는 도착순이며 실제 만료 시 기부를 제거한 뒤 다음 실행자를 고른다. 절대 대기는 CLOCK_MONOTONIC만 지원한다.

## Ordinary acceptance / 일반 앱 판정

Use one SDK-built C/Rust application with genuine shared protected work in the process-private image. Publish stage, owner/sequence, full products and per-thread returns. For a fixed payload, each completed reduction of bytes 0..255 yields sum 32,640 and square sum 5,559,680. Have the receiver validate complete producer records and build the ordered handoff ID transcript; check all outputs independently in the final process RAM and joined values, plus ordinary UART exit. Choose fixed blocks large enough to identify ongoing useful BASE/MEDIUM work; freeze count, program hashes and natural absolute wake timings before first launch. Stage readiness through real create/join, sleep, lock and protected handoffs; a high-priority spinner would prevent lower-role preparation. Terminate/record a failed ordering instead of retrying until it fits. Public cases:

1. PI chain, four distinct priorities 1/2/3/4. BASE holds Y, LOW holds X and blocks on Y, MEDIUM is ready, HIGH blocks on X. Establish actual timestamps/frames and show ranks LOW=BASE=4, then productive BASE before MEDIUM, direct Y→LOW then X→HIGH, and restored base ranks at each release. Check Y/X protection and counts. In a separate run HIGH uses an absolute future timeout on X while Y remains held. Require clocklock ETIMEDOUT, BASE/LOW restore to 2 while LOW still waits for Y, MEDIUM outranks them once HIGH ceases competing, terminal payload intact. Never claim timeout priority 1 while LOW still donates 2.
2. Protocol handoff and cycles. With two eligible waiters show higher effective rank first; in an equal-priority package (e.g. 1,2,2,4) reverse arrival between runs and require FIFO within rank. Construct X→Y then attempted reverse wait, reject EDEADLK before adding the edge; original owners unlock and complete. Exercise wrong user, nonowner unlock, nesting depth, stale handle/reinit, busy destroy and thread-generation reuse; refused operations leave subsequent valid work and ordering intact.
3. Protect. Freeze nested X/Y ceilings 2 and 4; users of X drawn only from roles with bases ≤2. Observe immediate boost before contention, 2→4 on nested acquisition, restoration to 2 then base, with an appropriate actual competitor and coherent publication. Reject a ceiling of 2 when a declared user has base 4, reject mask-zero/foreign users, and enforce the selected depth and release order. An owner may enter a lower-ceiling resource only if its configured permitted base/user and ordering rules allow it; do not silently adopt a different ceiling variant.
4. Run real equal-rank RR competition with observed timer preemption and productive resumes, plus FIFO peer retention until release/yield and an unequal-priority preemption with residual RR. Keep controls for NULL mutexes, cooperative/equal RR two-thread #318, one native ELF and joined-return/stale-token behavior. Freeze first plain and externally traced PI-chain, timeout and protect cases and at least one ordinary capture per remaining functional control. Preserve failed starts, bounded journal scope and all first records. Correlate saved/selected frames with actual user returns independently; host-only bookkeeping is insufficient for a live case.
