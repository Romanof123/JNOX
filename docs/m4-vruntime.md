# 타이머 기반 CPU에서 가중 가상 실행시간 스케줄링

[English](m4-vruntime.en.md) · [변경 이슈 #55](https://github.com/Romanof123/JNOX/issues/55)

CHG-024 · POL-011 · REQ-002/005/023 → DES-003/012 → IMP-022 → VER-002/005/023. Cortex-A72 한 개에서 A·B는 가상 실행시간 0, 가중치 1·2로 함께 시작한다. 가상 실행시간이 가장 짧은 준비 작업을 고르고 동률이면 작은 작업 ID가 우선한다. 물리 카운터 한 단위당 1/가중치만큼 가상 시간을 누적한다. 분수 잔여량을 보존하고 기준 최소값을 단조 증가시킨다. 계상 구간은 디스패치부터 Rust의 IRQ 처리기가 처음 읽은 카운터까지이며, 예외 복귀 및 벡터 문맥 저장 시간을 포함한다.

Q는 CNTFRQ를 50으로 나눈 정수 몫이다. 타이머 비교값은 시작 시각 + Q다. 21개 IRQ 모두 비교값 이상이고 비교값 + Q 미만이어야 한다. 첫 12회는 두 작업이 함께 경쟁하며 측정 서비스는 |2 × A − B| ≤ 4Q를 만족해야 한다. 시점 12에 B를 차단하고 A만 3회 실행한다. 시점 15에 B를 깨울 때 원래 가상시간과 현재 기준 최소값을 B의 가중치 격자로 올림한 값 중 큰 값을 쓴다. 수면 중 사용하지 않은 CPU에 대한 크레디트를 소급해서 주지 않는다. 깨우기 전후와 복구 6회 종료 시점에 기준 최소값 대비 부호 있는 지연을 물리 카운터 단위로 기록한다. 복구 중 두 작업 모두 실행돼야 한다. 실제 선택 순서는 관측 시각에 따라 달라질 수 있다.

kernel에서 `cargo build --release --locked --features vruntime-bench -j1`로 빌드하고 루트에서 `python3 tools/qemu_boot.py --profile vruntime --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel`를 실행한다. 독립 첫 관측 시 --qemu 래퍼로 QEMU -d int를 수집하고 동일 실행의 UART와 ELF 해시를 보존한다. VR BEGIN/CLOCK 이후 21개의 SLOT과 SHARE·SLEEP·WAKE·END·STOP·PASS를 순서대로 받아야 한다. 각 슬롯은 작업·준비 마스크·시작·비교·IRQ 시각·계상값·반 틱 단위의 두 가상시간과 기준값·중단 PC·SP·루프 진행량을 기록한다. 입력과 실제 경과량으로 선택을 독립 재구성하고, IRQ·복귀 주소를 고정 이미지에 매핑한 뒤 전용 스택과 작업별 진행을 대조한다. 실물 간섭·제품 지연·물리 시간 근거는 별도 추적한다.
