# 주기 작업 초과 실행 인수 설계

CHG-030 / IMP-028은 POL-004 및 #28·#30·#31을 확장한다. EVD-028은 검증 예정이다. REQ-002/005/023, DES-003/012, VER-002/005/023을 적용한다. [English](m1-periodic-overrun.en.md)

두 구간은 물리 카운터 기준 O와 단위 Q를 공유한다. 틱 k의 비교값은 O+kQ이며 DM은 k=26에서 시작한다. 각 구간에서 A의 주기와 상대 기한은 10과 9, B는 12와 4다. 명목 비용은 각각 1이다. 추가 비용·차단·지터·IRQ 수요를 0으로 둔 [호스트 응답시간 분석](fp-response.md)의 RM 상한은 A=1, B=2이고 DM은 B=1, A=2다. 두 경우 모두 기한 안이다. A의 1번 세대는 의도적으로 비용 가정을 위반한다.

각 작업을 원래 주기의 경계에서 세 번 릴리스한다. IRQ는 경계 완료를 먼저 반영하고 미완료 작업의 기한 위반을 세대당 한 번 기록한 뒤 신규 릴리스와 선정을 수행한다. A0는 유한 루프를 실행하고 틱 9 전에 SVC로 결과를 제출한다. 논리적 완료 시각은 정확히 9다. 실제 SVC 카운터와 경계 IRQ 관측값을 따로 보존한다. A1은 틱 21까지 IRQ를 허용한 채 반복하고 실제 기한 19를 넘겨 SVC로 완료한다. 틱 20에 A2가 고유 릴리스와 기한으로 대기해도 A1은 스택과 세대를 유지한다. 작업별로 가장 오래된 미완료 세대부터 실행한다. DM에서는 B1이 틱 12에 A1을 선점하고 RM에서는 대기하여 16에 기한을 위반한다. 구간 끝 25에서 릴리스와 완료는 각각 6회, 위반은 RM 2회, DM 1회여야 한다.

독립 검증자는 periodic_overrun_witness에서 릴리스·제출·완료·기한 위반·선정 순서를 달력과 대조하고 실제 카운터 및 IRQ·복귀 PC를 ELF 심볼과 비교한다. 복귀 프레임의 진행량과 세대별 완료·위반 횟수도 확인한다. QEMU 단일 CPU 가상 시간 관측으로 물리 보드의 WCET, IRQ 지연 또는 실제 기한 일치를 확정할 수 없다.

## 캡처와 기록 형식

Linux에서 새 디렉터리와 대상 ELF를 지정해 `PERIODIC_OVERRUN_CAPTURE_DIR=/tmp/overrun-01 python3 tools/qemu_boot.py --profile periodic-overrun --kernel "$ELF" --qemu tools/periodic_overrun_capture.py`를 실행한다. audit.bin은 리틀엔디언 u64 배열이다. 헤더 4개 값은 O, Q, 카운터 주파수(Hz), 유효 행 수다. 행당 9개 값은 전체 틱, 이벤트, 슬롯, 명목 릴리스 틱, 절대 기한 틱, 물리 카운터, PC, x20 진행량, 예외 프레임 주소다. 슬롯은 2 × 세대 + 작업 번호(A=0, B=1)이며 구간이 바뀌면 다시 사용한다. 유휴 슬롯 6의 릴리스와 기한은 UINT64_MAX다. 프레임 0은 달력 이벤트다. 이벤트 번호 1~6은 각각 IRQ, 릴리스, 위반, SVC 제출, 논리 완료, 복귀 선정이다. 달력 이벤트는 해당 IRQ 처리 시 읽은 카운터를 사용하고 복귀 선정은 복원 직전에 따로 읽는다. A0 완료 행의 틱은 기한 경계이고 카운터는 IRQ 관측값이다. 그 밖의 완료는 현재 틱 구간과 실제 SVC 관측값을 기록한다. 기대 횟수는 IRQ 52회, 릴리스·제출·완료 각각 12회, 위반 3회, 선정 63회다. 마지막 IRQ는 선정 없이 정지 루프에 들어간다.

실행기는 로컬 Python 수집 스크립트를 현재 Python 인터프리터로 실행한다. Windows 줄바꿈으로 체크아웃한 경우에도 같은 명령을 사용한다.
