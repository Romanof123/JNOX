# Locating virtual idle timer delivery / 가상 유휴 타이머 지연의 관측 구간

[#339](https://github.com/Romanof123/JNOX/issues/339) · prospective design on 2cdbe3bf2e8604be54c6851046d6d95d2e106f7c. The original saturated/plain and swap/plain idle PPI30 entries were 4,201,556 and 6,487,068 ticks late. The health candidate wake/trace reported D=250,487,263 and E=260,476,531, lag 9,989,268 (159.828288 ms). Its masked pre-unmask sample was 241,303,863, arm CVAL matched D, CTL went from 1 at arm to 5 at entry, and the saved PC was WFI+4. All three exceed 1,953,125 ticks. These are three distinct first observations. Their causes remain unknown. [Original firsts](evidence/native-hierarchical-applications-first.en-ko.md) · [Health contract](native-hierarchy-refill-health.en-ko.md)

세 최초 위반은 유휴 재충전 기한부터 실제 IRQ 표본까지의 초과를 보여준다. 세 번째는 올바른 CVAL, 설정·진입 CTL, 마스크 해제 전 표본과 WFI 다음 PC까지 남겼다. 호스트에서 어느 스레드가 언제 준비됐는지, 어디서 지연됐는지는 기존 자료로 결정할 수 없다.

## Two cold acquisitions / 두 최초 실행

Use the exact archived #340 wake/trace kernel and reporter/histogram/energy ELFs from the failing candidate. Freeze actual artifact and QEMU hashes, argv, host/WSL version, ext4 location, observer options and timeout before launch. One ordinary wake/trace cold control, then one observer-enabled wake/trace cold acquisition, on the same single A72 virt/GICv2 default-clock deployment (62.5 MHz). Keep the original exception trace, host settings, package inputs, timer, IRQ mask and QMP cadence in both. The baseline reads three 128-byte private samples and one 2,496-byte frame range with four sequential running-guest pmemsave commands per round, then sleeps 90 ms. Stop only at the original capture termination. Preserve HEALTH END, UART, final RAM, sticky verdict, firsts and incomplete artifacts. No additional QMP polling in the idle interval. In the observer arm identify CPU0's host TID once during setup, recording the actual query interval if used.

Score existing real wake, ledger, products and P/8/8P timing for each first independently. No natural miss in the observation means there is no new late event to attribute. A different control outcome cannot establish a probe cost bound. This pair neither replaces historical evidence nor changes #21 release conditions.

같은 실패 후보의 커널·앱 바이트와 일반 예외 추적을 두 실행에 그대로 사용한다. 먼저 원래 대조, 다음 관측 실행을 각각 한 번 수행한다. 실행 중 QMP는 기존 네 번의 메모리 읽기와 90 ms 간격을 유지한다. 부팅 결과, 누락, 최초 실패를 모두 보존하고 자연 초과가 없으면 원인을 판정하지 않는다.

## Minimal observer / 최소 관측기

Extend the capture wrapper with host CLOCK_MONOTONIC send/response brackets for each existing QMP command, request identity and sampling-round number. Keep ordinary QMP contents. Reuse the [#178 adjacent instruction marker](https://github.com/Romanof123/JNOX/blob/663b598e5976d8d8578153b4716c677d727f80b8/docs/evidence/native-marker-share-first.en-ko.md) at the exact counter-read instructions and their immediately following instruction for the masked idle boundary and earliest idle IRQ entry. Resolve words from this ELF, correlate events with row identity, real PPI30, saved PC, and counter values. Capture monotonic-before, emitting thread CPU clock, monotonic-after, TID and sequence into bounded buffers. Preserve callback omissions, drop counts and unexpected return paths. Restrict translation callbacks to the selected instruction sites. Preflight timestamp resolution, empty bracket cost and marker widths. Never substitute callback wall time for the guest register value.

A same-user observer samples the identified vCPU and main/I/O TIDs through /proc/PID/task/TID/schedstat (execution ns, runnable wait ns, timeslices) and switch counts from status. Record TID/starttime, each read's monotonic brackets and errors. Use a single bounded sampler, for example nominal 5 ms in the observer arm, record actual spacings and CPU cost; no busy wait. Check availability and monotonicity on the actual host and use the [#178 blocked/runnable accounting controls](https://github.com/Romanof123/JNOX/blob/c09622b17b65c22d72575349a9e4a53e0dae5e18/docs/evidence/native-thread-accounting-first.en-ko.md) as precedent for checking counters. If wait accounting is unavailable, zero or unresolved by the calibration, withhold the runnable-wait verdict. WSL guest task counters do not separately measure Windows hypervisor suspension. Affinity, nice level and scheduling class stay at their existing settings.

QMP 송수신을 호스트 단조시계로 감싸고 기존 명령만 사용한다. ELF에서 실제 카운터 읽기와 다음 명령을 확인한 마커로 게스트 값의 호스트 구간을 기록한다. vCPU와 메인/I/O 스레드의 실행·실행큐 대기 카운터를 일반 사용자 권한으로 표본화한다. 읽기 전후 시각과 실제 표본 간격·누락·비용을 보존한다. 카운터가 지원되지 않거나 검교정되지 않으면 실행큐 대기 원인 판정을 유보한다.

## Clock alignment and verdict / 시계 정렬과 판정

For a matched guest tick g, use adjacent host callback observations to enclose its execution in [a,b], including callback uncertainty. At nominal 16 ns/tick each anchor supplies an offset interval [a−16g,b−16g]. Use multiple anchors before and after the same refill and adjacent unaffected intervals to check drift, width and clock continuity. Declare the conversion model and independently measured rate/offset uncertainty, widen each projection by its error over distance, and retain per-anchor bounds. Report overlapping projections for D and E only if the model fits the held-out anchors. An empirical mapping is conditional on the clock relation across idle. If that relation cannot be constrained, use the causal outer bounds from enclosing anchors or report insufficient resolution. No point interpolation through an unexplained WSL clock gap.

Use only host sample intervals certainly inside [latest plausible D, earliest plausible E] for positive post-deadline lower bounds. Count runnable delay conservatively: schedstat may book a whole prior wait when a thread finally runs. A positive counter increment merely booked inside this interval can include waiting before D. Subtract the maximum carry-in consistent with observed runnable/scheduling transitions, or report zero demonstrated post-D runnable lower bound. Report upper bounds and coverage separately. Host wall minus CPU includes voluntary WFI blocking and descheduling. QMP command overlap measures observer activity; it does not prove lock contention, thread suppression or causation.

Use stock passive timer/GIC provider events only where the installed QEMU catalog supports them. Preserve raw emission order, IRQ identity and drops. Plain log lines and collector receipt times alone cannot timestamp assertion. Include emitter-side monotonic event brackets only if a stock accessible provider or user-space collection path is prequalified on this build with a measured capture cost, known event meaning and one-to-one matching; otherwise retain order only, without adding another boot. Do not require privileged kernel tracers. In particular the observed timer-condition log follows line assertion in the historical provider stream and cannot serve as a timer-callback start timestamp.

A demonstrated wrong arm/mask or late guest boundary points to the guest path. A line definitely asserted before the overdue interval ends, followed by a resolved positive assertion-to-entry delay, narrows the vCPU delivery path; validated runnable-wait bounds can locate a contribution from the host scheduler. Late line assertion with a demonstrably active I/O thread narrows investigation to the pre-assertion path, but still needs a matched callback or servicing boundary to isolate QEMU timer processing. Report the actual bracket widths and unresolved intervals before proposing a layer-specific remedy. Assess any remedy separately against the same original threshold and workload.

같은 재충전의 앞뒤 마커로 기한 D와 진입 E의 호스트 시각 범위를 구한다. 오차·드리프트와 시계 연속성을 검증하고 완전히 기한 후에 속하는 표본만 양의 하한에 사용한다. 실행큐 카운터가 이전 대기를 뒤늦게 합산한 경우에는 기한 이전 기여의 최대치만큼 빼거나 판별 가능한 하한을 0으로 둔다. WFI 차단, 호스트 비실행, QMP 겹침만으로 원인을 지목하지 않는다. 타임스탬프를 검증하지 못한 GIC 로그는 순서만 사용한다. 게스트 마스크·타이머 설정, 선 상승 전 처리, 선 상승 후 vCPU 전달을 실제 시계 경계 안에서만 구분하고, 확인된 층의 변경은 원래 한도와 같은 부하로 별도 평가한다.

## Reading the host calibration / 호스트 검교정 자료 해석

The report accepts the raw same-boot blocked/runnable child-trial receipt. It matches the platform, UID, boot ID and allowed CPUs to both preflight and observation, then re-derives the calibration result from the raw trial. A missing, inconsistent or insufficient receipt leaves the demonstrated runnable-wait lower bound at zero. Trial wait times describe the children, not the vCPU.

The independent neighboring refill pairs measure the nominal 16 ns/tick relation outside the candidate interval. The candidate's masked and IRQ markers can contradict that relation at its endpoints. Agreement at both endpoints leaves clock behavior between them unresolved. The captured ELF and QEMU hashes select the build, while the observed counter frequency gives the guest tick duration. Neither supplies a measured bound on the host offset throughout the idle gap. Consequently, the report displays nominal projections as diagnostics and uses only causally ordered host brackets for attribution. When the last observed guest counter before D is the masked read and the next is the IRQ read after D, the upper end of D can overlap the IRQ bracket; such a pair demonstrates no positive post-D host wait. An actual earlier marker already at or past D can tighten that upper end.

동일 부팅의 플랫폼·UID·부팅 ID·허용 CPU 집합을 대조하고 차단 및 실행 대기 대조군의 원시 표본을 다시 계산한다. 검교정이 없거나 불충분하면 vCPU의 입증된 실행 대기 하한은 0이다. 이웃 재충전의 16 ns/tick 관측과 양 끝점의 일치는 그 사이의 시계 오차 상한을 제공하지 않는다. 실제 마커의 인과 순서만 기여 하한 계산에 사용하며 과거 초과의 원인은 미확정으로 유지한다.
