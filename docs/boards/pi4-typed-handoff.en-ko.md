## Existing mechanism and proposed contract

The ownership transaction serializes retirement, placement and claims. The BSP checks SGI 1 and its peer source in IAR, orders earlier stores with DSB ISHST before GICD_SGIR and completes the write with DSB. The sender releases the scheduler lock after the write and the recipient acquires it before reading shared state. Existing dispatch checks the claimed CPU, stack bounds, alignment and canary. The opening request today is inferred from epoch, milestone and an empty peer running slot. Reverse dispatch obtains its lease and pointer from current state. #47 calls for checking the sender's intended generation and frame sequence at the recipient. No archived failure demonstrates stale state or attributes the early finish to these checks.

Use a bounded Rust value per directed edge under the existing transaction. Each slot starts Empty, accepts one immutable Pending payload and becomes Consumed with that same payload after successful validation. Preserve Consumed until terminal inspection. Each payload binds edge kind, epoch, source, destination, target task and target lease. Each task frame installation stores a checked nonzero monotonically increasing version alongside the pointer. Advance only at actual installation, including initial fresh frames, the saved M IRQ frame on its dispatcher stack, and the new P1 frame even if its address repeats. Retain the version across claims and restores. Record installation origin (fresh or IRQ-saved) and the installed pointer. Reject exhaustion before replacing a frame. A journal sequence, lease number or address cannot stand in for installation version.

* Opening, CPU1 to CPU0. Validate the genuine terminating opening P1 SVC, then retire its lease. Publish under the lock the retired P1 lease and intended current CPU0 M lease/epoch before signaling CPU0. CPU0 checks its architectural peer and SGI, the Pending edge, source retirement, current M claim and local live lease, existing epoch/milestone and trapped M stack. This request names the currently running M. CPU0 obtains its newly saved frame from its own IRQ entry, then installs that frame and advances its version under the transaction. No sender guesses the future IRQ frame.
* Reverse, CPU0 to CPU1. After saving M, creating replacement P1, and applying both claims, publish CPU1's actual selected task, lease, pointer, installation version and origin before signaling. Global selects saved M on CPU1. Partitioned and singleton clustered select fresh replacement P1 there. The CPU1 idle handler checks the peer IAR, epoch, idle live word, destination and current claim under the lock. Compare the Pending tuple with the authoritative installed frame record, verify role/stack and consume before making that lease live and returning the verified frame. Capture local CPU0 selection through the existing dispatch record.

Validate slot, tuple, frame and transition preconditions before mutating ownership, the live word, installed record or slot for that transition. Preflight a sender's slot availability and increments before retiring or replacing state. A rejected check preserves the predecessor state and evidence and follows the existing failure path. Preserve earlier legitimately committed transitions. Keep existing summary, retirement, journal, SGIR and EOIR ordering. Release/acquire on the existing lock remains the synchronization mechanism for these fields.

### Frozen MG4 encoding and capture

MG4 adds tag 16 (published) and tag 17 (consumed). Both contain exactly eight unsigned 64-bit words in this order: [edge, epoch, target task, target lease sequence, retired lease sequence, frame pointer, frame installation version, origin]. Edge 1 means opening CPU1/P1 → CPU0/M, epoch 0, with the retired CPU1/P1 sequence and three zero frame words. Edge 2 means reverse CPU0 → CPU1, epoch 1, with retired sequence zero and the selected frame triple. Origin 1 means Fresh, 2 means IrqSaved; zero denotes absent. Source/destination are fully specified by edge, and recording CPU must equal sender for 16 or receiver for 17. Compare all eight words on the pair identified by (session, edge), with at most one of each tag. No fragments. Each CPU can append at most two new rows, so preflight the worst-case existing rows at ≤94 per CPU under each selector. Fail freeze if the total could exceed 96. Existing row, seal, invalid-writer and loss semantics apply.

Under the ownership lock, append 16 after committing Pending and before calling signal; append 17 after acquiring the lock, validating the real receive and committing Consumed, before changing the receiving lease or dispatching. Correlate opening with CPU1 retirement row 3 and send row 7, CPU0 trap row 4 and lease retirement. Correlate reverse with CPU0 plan/claim rows 6/2, M saved trap or replacement P1 fresh construction, send row 7, CPU1 idle trap, dispatch row 11 and external ERET. Compare active destination claim, aligned bounded frame, actual prior M trap pointer or replacement P1 initial entry and its new installation version. Journal order is local; cross-CPU association comes from slot semantics, route, epoch, lease and matching payload. These rows contain no timing samples.

Freeze one ELF object named pi4_handoff_terminal_v1, 256 bytes, 64-byte aligned, little-endian u64 words. Header at byte offsets 0,8,16,24 holds magic 0x3130524554464f48, layout version 1, size 256, reserved zero. Opening and reverse blocks start at 32 and 104. Each has phase at +0 (0 Empty, 1 Pending, 2 Consumed), then the eight payload words at +8 through +64. Empty requires eight zeros. Installed records for M, P0, P1 start at 176, 200, 224; each is [pointer, version, origin], all zeros before first installation. Offset 248 is reserved zero. Initialize before workers start. Maintain this explicit projection from committed transitions inside the transaction, writing payload before the phase (release store) and retaining consumed payloads. Record every actual installation in the corresponding task cell. Require terminal quiescence and independent journal/frame corroboration; mark a stopped mid-transition snapshot partial. Do not interpret Rust enum layout, assume STATE size 200 or rely on an MG2 symbol map.

Preserve the original scored observer and windows for all twelve boots. Separately freeze exactly two diagnostic firsts on the same release images: short clustered position D1 and stream global position D2, in that order, one launch each regardless of outcome. These sample a possible early termination and a possible remote M return. After terminal quiet use the Stage 1 QMP stop, confirm paused and collect the original bounded journal/stack ranges and this exact object from the frozen per-image physical map. Require a single defined symbol with matching size/alignment wholly inside the writable RAM PT_LOAD, checked virtual-to-physical translation, no overflow/overlap with other retained objects, and each requested dump wholly within frozen RAM. Hash and reopen ELF, map, ranges, bytes, session, UART and per-CPU exceptions before advancing. Preserve missing terminal, timeout or failed capture as partial without a replacement. A ranked or diagnostic attempt with absent RAM cannot establish an Empty slot. Report independent RAM phase for both edges, including any unobserved phase. The two diagnostics never count toward the twelve positions.

## 한국어 설계 및 판정

#279 최초 이미지의 증거는 그 코호트에 귀속한다. #280은 #279 통합 뒤 결합 소스에서 검증한다. 기존 스케줄러 락은 반납·배치·점유를 직렬화한다. BSP는 IAR의 SGI 1과 상대 CPU를 검사하며 SGIR 앞에서 DSB ISHST, 뒤에서 DSB를 수행한다. 수신자는 송신자의 락 해제 후 상태를 읽는다. 현재 복귀 경로는 CPU와 프레임 범위·정렬·가드를 확인한다. 추가할 검사는 송신자가 의도한 세대와 수신자가 사용할 프레임 설치 버전의 일치 여부다. 기존 조기 종료 기록으로 이 결함이나 지연 원인을 입증할 수 없다.

두 방향에 독립 슬롯을 두고 기존 락 안에서 Empty → Pending → Consumed를 각 한 번만 허용한다. 종료 시까지 페이로드를 보존한다. 방향·세대·출발지·목적지·작업·리스와 함께 프레임 설치 기록을 관리한다. 실제 초기 프레임, IRQ로 저장한 M, 새 P1을 설치할 때 포인터·출처·검사된 비영 버전을 기록하고 증가시킨다. 같은 주소를 다시 써도 새 설치이며 점유·복귀 때는 버전을 유지한다.

* CPU1은 실제 시작 P1의 종료 SVC를 검증하고 반납한 뒤 반납 리스와 CPU0의 실행 중인 M 리스·세대를 공개하고 SGIR을 쓴다. CPU0은 IAR·슬롯·반납·M 점유·로컬 실행 리스·세대·진행 표식·트랩 스택을 검증한다. 이 요청의 대상은 실행 중인 M이다. CPU0이 IRQ에서 얻은 M 프레임을 디스패처 스택에서 설치할 때 새 버전이 생긴다.
* CPU0은 M 저장, P1 초기화, 양측 점유 확정 뒤 CPU1용 작업·리스·포인터·설치 버전·출처를 공개하고 전송한다. 전역 정책은 저장된 M, 분할·단일 클러스터는 새 P1을 선택한다. CPU1은 유휴 IRQ에서 IAR·세대·실행 리스 0·목적지·점유·프레임 설치 기록 및 스택을 대조한다. 검증된 요청을 한 번 소비한 뒤 리스를 활성화하고 같은 프레임으로 복귀한다.
* 각 전이의 변경 전에 슬롯·필드·버전 증가 가능성·프레임 조건을 확인한다. 거부하면 해당 전이 직전 소유권·실행 리스·프레임·슬롯과 기존 증거를 보존한다. 이전 정상 전이와 종료 요약·반납·저널·송신·EOI 순서를 유지한다.

MG4는 MG3의 14/15번 행 의미를 계승한다. 인계 증거는 TLS 식별자와 독립적으로 추가한다. 두 슬롯과 작업별 설치 기록의 RAM 배치·크기·ELF 주소를 고정한다. 공개·소비 행에 양측 리스, 경로, 세대, 설치 주소·버전·출처를 담고 필요한 8워드 행은 CPU·인접 순번·경로·세대로 연결한다. 최초 실행 전에 태그·단어 배치·최대 행 수·손실 처리를 고정하며 공개 행은 SGIR 전에 기록한다. 종료 RAM의 Empty/Pending/Consumed를 독립 해독하고 실제 CPU별 예외·복귀, 점유·저장, 후속 작업과 대조한다. 종료 스냅샷만으로 중간 전이를 인정하지 않는다. 다른 관측기가 필요한 종료 덤프는 별도 진단으로 둔다.

두 정상 경로, 잘못된 필드·출처, 동일 주소의 오래된 버전, 중복 공개·소비, 버전 소진, 빈 슬롯 소비는 순수 호스트 입력으로 검사한다. 거부 시 전체 이전 상태를 대조한다. 기존 MG1/2/3·CRC 자료를 각 스키마로 재생하고 MG4 버전 강등을 거부한다. 결합 소스의 실제 링크 결과를 검사한다. #278이 부분 충족이면 TLS 판정도 부분으로 남긴다. 결합 전체 충족에는 MG3 의무를 모두 적용하며 공개·소비·원격 복귀·후속 작업의 관측을 각각 보고한다.

기존 QEMU 해시·수집 조건·원래 입력을 유지한다. 짧은 65,536항과 스트림의 정책별 이미지 6개, 각 최초 두 회를 고정한다. 짧은 작업 전역·분할·클러스터 각 두 회에 이어 스트림도 같은 순서로 실행한다. 조기 0x1d·부분 저널·빈 역방향 슬롯을 포함해 최초 시도마다 보관하고 다시 연다. 실제 내부 루프 IRQ PC, 프레임·ERET, 소유권에 귀속된 후속 진행으로 판정한다. 관측되지 않은 수신, 과거 짧은 작업 0/6, 스트림 결과와 실물 보드 검증 상태를 각각 명시한다.

### MG4 고정 형식과 별도 수집

태그 16은 공개, 17은 소비다. 두 태그 모두 부호 없는 64비트 8워드 [경로, 세대, 대상 작업, 대상 리스 순번, 반납 리스 순번, 프레임 포인터, 설치 버전, 출처]를 사용한다. 경로 1은 세대 0의 CPU1/P1 → CPU0/M이다. P1 반납 리스를 기록하고 마지막 세 워드는 0이다. 경로 2는 세대 1의 CPU0 → CPU1이다. 반납 순번은 0, 마지막 세 워드는 선택한 프레임이다. 출처 0/1/2는 각각 없음/새 설치/IRQ 저장이다. 16의 기록 CPU는 송신자, 17은 수신자다. 세션·경로마다 한 쌍까지 허용하며 8워드를 모두 대조한다. 분할 행은 없다. CPU당 추가 최대 2행이므로 각 선택기의 기존 최대가 94행 이하인지 먼저 확인하고 총 96행을 넘을 수 있으면 동결을 중단한다.

락 안에서 Pending 확정 뒤 signal 전에 16을, 수신 락 획득과 실제 검증 및 Consumed 확정 뒤 수신 리스 변경·디스패치 전에 17을 기록한다. 시작 요청은 CPU1의 반납·송신 및 CPU0의 트랩·반납과, 역방향은 배치·점유·M 트랩 또는 새 P1 초기화·송신·CPU1 유휴 트랩·디스패치·외부 ERET와 대조한다. CPU 간 대응은 경로·세대·리스·페이로드와 슬롯 규약으로 검증한다. 행에는 시간 표본이 없다.

고정 ELF 심볼 pi4_handoff_terminal_v1은 64바이트 정렬, 256바이트, 리틀엔디언 u64이다. 바이트 오프셋 0/8/16/24는 매직 0x3130524554464f48, 버전 1, 크기 256, 예약값 0이다. 시작·역방향 슬롯은 32/104에서 시작하며 +0에 상태(0 Empty, 1 Pending, 2 Consumed), +8부터 +64까지 위 8워드를 둔다. 빈 슬롯의 페이로드는 모두 0이다. 176/200/224의 M/P0/P1 설치 기록은 [포인터, 버전, 출처]이며 최초 설치 전에는 모두 0이다. 248은 예약값 0이다. 작업 시작 전에 초기화하고 락 안에서 실제 설치 및 전이를 반영하며 페이로드 뒤에 상태를 release 저장한다. 소비 뒤에도 값을 유지한다. 종료 정지와 저널·프레임으로 교차 확인하고 전이 중 정지는 부분 관측으로 둔다. Rust 열거형 내부 표현이나 이전 STATE 크기에 의존하지 않는다.

채점용 12회는 기존 관측기·시간창을 유지한다. 별도 진단은 같은 이미지로 짧은 clustered D1, 스트림 global D2 순서로 각 1회만 고정한다. 종료 정숙 구간 뒤 Stage 1 방식으로 QMP 정지와 paused 상태를 확인하고 이미지별 물리 주소표에서 지정 저널·스택 범위와 고정 객체만 수집한다. 유일한 심볼·크기·정렬·쓰기 가능한 RAM PT_LOAD·가상/물리 대응·범위·비중첩을 검사한다. 다음 실행 전에 ELF·주소표·덤프·세션·UART·CPU별 예외를 해시하고 다시 연다. 시간 초과·미종료·수집 실패는 부분 관측으로 남긴다. RAM 미수집은 빈 슬롯의 증거가 될 수 없다. 두 슬롯의 실제 상태와 미관측 단계를 따로 보고하며 진단은 12회 점수에서 제외한다.
