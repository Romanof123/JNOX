## Existing mechanism and proposed contract

The ownership transaction serializes retirement, placement and claims. The BSP checks SGI 1 and its peer source in IAR, orders earlier stores with DSB ISHST before GICD_SGIR and completes the write with DSB. The sender releases the scheduler lock after the write and the recipient acquires it before reading shared state. Existing dispatch checks the claimed CPU, stack bounds, alignment and canary. The opening request today is inferred from epoch, milestone and an empty peer running slot. Reverse dispatch obtains its lease and pointer from current state. #47 calls for checking the sender's intended generation and frame sequence at the recipient. No archived failure demonstrates stale state or attributes the early finish to these checks.

Use a bounded Rust value per directed edge under the existing transaction. Each slot starts Empty, accepts one immutable Pending payload and becomes Consumed with that same payload after successful validation. Preserve Consumed until terminal inspection. Each payload binds edge kind, epoch, source, destination, target task and target lease. Each task frame installation stores a checked nonzero monotonically increasing version alongside the pointer. Advance only at actual installation, including initial fresh frames, the saved M IRQ frame on its dispatcher stack, and the new P1 frame even if its address repeats. Retain the version across claims and restores. Record installation origin (fresh or IRQ-saved) and the installed pointer. Reject exhaustion before replacing a frame. A journal sequence, lease number or address cannot stand in for installation version.

* Opening, CPU1 to CPU0. Validate the genuine terminating opening P1 SVC, then retire its lease. Publish under the lock the retired P1 lease and intended current CPU0 M lease/epoch before signaling CPU0. CPU0 checks its architectural peer and SGI, the Pending edge, source retirement, current M claim and local live lease, existing epoch/milestone and trapped M stack. This request names the currently running M. CPU0 obtains its newly saved frame from its own IRQ entry, then installs that frame and advances its version under the transaction. No sender guesses the future IRQ frame.
* Reverse, CPU0 to CPU1. After saving M, creating replacement P1, and applying both claims, publish CPU1's actual selected task, lease, pointer, installation version and origin before signaling. Global selects saved M on CPU1. Partitioned and singleton clustered select fresh replacement P1 there. The CPU1 idle handler checks the peer IAR, epoch, idle live word, destination and current claim under the lock. Compare the Pending tuple with the authoritative installed frame record, verify role/stack and consume before making that lease live and returning the verified frame. Capture local CPU0 selection through the existing dispatch record.

Validate slot, tuple, frame and transition preconditions before mutating ownership, the live word, installed record or slot for that transition. Preflight a sender's slot availability and increments before retiring or replacing state. A rejected check preserves the predecessor state and evidence and follows the existing failure path. Preserve earlier legitimately committed transitions. Keep existing summary, retirement, journal, SGIR and EOIR ordering. Release/acquire on the existing lock remains the synchronization mechanism for these fields.

## 한국어 설계 및 판정

#279 최초 이미지의 증거는 그 코호트에 귀속한다. #280은 #279 통합 뒤 결합 소스에서 검증한다. 기존 스케줄러 락은 반납·배치·점유를 직렬화한다. BSP는 IAR의 SGI 1과 상대 CPU를 검사하며 SGIR 앞에서 DSB ISHST, 뒤에서 DSB를 수행한다. 수신자는 송신자의 락 해제 후 상태를 읽는다. 현재 복귀 경로는 CPU와 프레임 범위·정렬·가드를 확인한다. 추가할 검사는 송신자가 의도한 세대와 수신자가 사용할 프레임 설치 버전의 일치 여부다. 기존 조기 종료 기록으로 이 결함이나 지연 원인을 입증할 수 없다.

두 방향에 독립 슬롯을 두고 기존 락 안에서 Empty → Pending → Consumed를 각 한 번만 허용한다. 종료 시까지 페이로드를 보존한다. 방향·세대·출발지·목적지·작업·리스와 함께 프레임 설치 기록을 관리한다. 실제 초기 프레임, IRQ로 저장한 M, 새 P1을 설치할 때 포인터·출처·검사된 비영 버전을 기록하고 증가시킨다. 같은 주소를 다시 써도 새 설치이며 점유·복귀 때는 버전을 유지한다.

* CPU1은 실제 시작 P1의 종료 SVC를 검증하고 반납한 뒤 반납 리스와 CPU0의 실행 중인 M 리스·세대를 공개하고 SGIR을 쓴다. CPU0은 IAR·슬롯·반납·M 점유·로컬 실행 리스·세대·진행 표식·트랩 스택을 검증한다. 이 요청의 대상은 실행 중인 M이다. CPU0이 IRQ에서 얻은 M 프레임을 디스패처 스택에서 설치할 때 새 버전이 생긴다.
* CPU0은 M 저장, P1 초기화, 양측 점유 확정 뒤 CPU1용 작업·리스·포인터·설치 버전·출처를 공개하고 전송한다. 전역 정책은 저장된 M, 분할·단일 클러스터는 새 P1을 선택한다. CPU1은 유휴 IRQ에서 IAR·세대·실행 리스 0·목적지·점유·프레임 설치 기록 및 스택을 대조한다. 검증된 요청을 한 번 소비한 뒤 리스를 활성화하고 같은 프레임으로 복귀한다.
* 각 전이의 변경 전에 슬롯·필드·버전 증가 가능성·프레임 조건을 확인한다. 거부하면 해당 전이 직전 소유권·실행 리스·프레임·슬롯과 기존 증거를 보존한다. 이전 정상 전이와 종료 요약·반납·저널·송신·EOI 순서를 유지한다.

MG4는 MG3의 14/15번 행 의미를 계승한다. 인계 증거는 TLS 식별자와 독립적으로 추가한다. 두 슬롯과 작업별 설치 기록의 RAM 배치·크기·ELF 주소를 고정한다. 공개·소비 행에 양측 리스, 경로, 세대, 설치 주소·버전·출처를 담고 필요한 8워드 행은 CPU·인접 순번·경로·세대로 연결한다. 최초 실행 전에 태그·단어 배치·최대 행 수·손실 처리를 고정하며 공개 행은 SGIR 전에 기록한다. 종료 RAM의 Empty/Pending/Consumed를 독립 해독하고 실제 CPU별 예외·복귀, 점유·저장, 후속 작업과 대조한다. 종료 스냅샷만으로 중간 전이를 인정하지 않는다. 다른 관측기가 필요한 종료 덤프는 별도 진단으로 둔다.

두 정상 경로, 잘못된 필드·출처, 동일 주소의 오래된 버전, 중복 공개·소비, 버전 소진, 빈 슬롯 소비는 순수 호스트 입력으로 검사한다. 거부 시 전체 이전 상태를 대조한다. 기존 MG1/2/3·CRC 자료를 각 스키마로 재생하고 MG4 버전 강등을 거부한다. 결합 소스의 실제 링크 결과를 검사한다. #278이 부분 충족이면 TLS 판정도 부분으로 남긴다. 결합 전체 충족에는 MG3 의무를 모두 적용하며 공개·소비·원격 복귀·후속 작업의 관측을 각각 보고한다.

기존 QEMU 해시·수집 조건·원래 입력을 유지한다. 짧은 65,536항과 스트림의 정책별 이미지 6개, 각 최초 두 회를 고정한다. 짧은 작업 전역·분할·클러스터 각 두 회에 이어 스트림도 같은 순서로 실행한다. 조기 0x1d·부분 저널·빈 역방향 슬롯을 포함해 최초 시도마다 보관하고 다시 연다. 실제 내부 루프 IRQ PC, 프레임·ERET, 소유권에 귀속된 후속 진행으로 판정한다. 관측되지 않은 수신, 과거 짧은 작업 0/6, 스트림 결과와 실물 보드 검증 상태를 각각 명시한다.
