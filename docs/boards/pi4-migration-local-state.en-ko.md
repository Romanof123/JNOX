# Pi 4 migration CPU-local state and activation TLS / Pi 4 이주 시 CPU 로컬 상태와 활성화별 TLS

#278 · POL-013 (#47) · CHG-106 / IMP-106 / EVD-106. Design baseline 8ec9cef680755062c182793e8823920b3770aa45. This is a prospective stock-model experiment. The parent issue retains the broader migration and board acceptance criteria.

## Register ownership and implementation

In kernel/src/pi4_smp_bsp.rs, restrict the new convention to JNOX_PI4_MIG. Generic kernel/src/smp.S deliberately uses TPIDR_EL1 as a task cookie. Other policy profiles and Pi SW1 retain their current convention. Pi migration fresh() in kernel/src/pi4_migration.rs currently zeroes the entire frame. Its current restoration of zero provides no observation of distinct live CPU bases.

* Give each online CPU a permanent, separately aligned static record containing its existing LIVE atomic lease. In BSP init validate MPIDR affinity and install that record's address in TPIDR_EL1 while IRQs are masked, before the first dependent call or vector entry on either CPU. Bootstrap/fatal reporting before installation uses MPIDR alone. Validate the raw register against the expected linked static address for the current MPIDR before resolving a reference through that known static. Reject mismatch without calling the failing accessor again. Bound affinity before indexing. Mask IRQ around task-side identity/anchor/use observations and restore the prior mask. Keep no CPU reference across a scheduling point.
* Move the operational dispatch store, retire/IRQ lease validation and sparse checkpoint lease lookup to that local record, retaining acquire/release semantics. Planning a remote claim still uses its descriptor under the ownership lock. Only the executing CPU changes its own live word. Preserve boot, idle and handler stacks. In kernel/src/context.S for this profile alone reserve the old EL1 frame word as zero on save and never write TPIDR_EL1 on restore, including first and idle returns. Save and restore adjacent SP_EL0 and the full original task context as before.
* Allocate four permanent, distinct TLS objects for M, P0, opening P1 and replacement P1. At fresh frame construction set TPIDR_EL0 to the exact activation object and TPIDRRO_EL0 to a distinct nonzero immutable activation token (EL1 writes it, EL0 may read it). Idle has a separate explicit zero pair and never uses worker TLS. Preserve both words across traps and restore. Map entry/role to activation independently of register contents. Check token and exact address against the expected static before each reference, with no mutable reference retained across preemption or shared with handler code. Initialize all four before publishing tasks. Keep M's activation across leases and start replacement P1 with a fresh digest/count.
* Move the existing ordered checkpoint digest into the activation TLS, keeping count and other retention fields task-local. Update the TLS digest from the real index and sum or cumulative CRC at the existing checkpoint, and use it as the terminal SVC digest. Keep the same formula, input intervals, milestone and output. Use ordinary atomic word operations on permanent storage, single writer by exclusive lease, and existing frame release/acquire publication at handoff. Do not add a shadow digest as the application's source of truth. The saved registers are read only after a validated bounded frame is exclusively owned. Capture live task registers in task code after ERET at the existing sparse checkpoint; saved frame values alone cannot establish this.

## Freeze, evidence and verdict

Use a new explicitly frozen MG wire version 3, preserving versions 1/2, eight-word rows, original tags and their semantics. Add just two kinds. A saved-state row (14) immediately follows the existing worker trap row on the same CPU and contains [task, activation token, lease, frame address, saved EL0 pointer, saved RO token, observed EL1 base, local live lease]. A live row (15) immediately follows the first sparse checkpoint on each activation/lease, under the same local IRQ mask, and contains [task, activation token, final lease, observed EL1 base, live EL0 pointer, live RO token, index, TLS digest]. Bind to preceding row by CPU/sequence and check all shared fields. Give the two CPU records and four activation objects stable linked symbols, freeze their ELF addresses, size and alignment, verify nonoverlap and compare exact addresses for the identified CPU/activation. Verify each live digest from independently recomputed prefixes, including P1's separate input ranges. Match M source saved pair to destination live pair and the changed base. Check tag 14 only for worker traps at which the live lease is still held, before retire. Preflight maximum rows versus the 96-row per-CPU bound. Missing rows, loss or sealing failure cannot qualify. Bind all original MG2 summary, scheduler, accounting and stream checks to MG3 as well; reject version downgrade against the freeze.

For each frozen candidate compare source and linked opcodes for primary/secondary setup, save, restore, first entry, IRQ, sparse witness and TLS digest use. Record actual linked loop range, CPU and TLS symbols and image hashes, compiler, emulator and capture/replay versions. Check host positive same-CPU and 0→1 histories plus negative controls for swapped CPU bases, foreign or zero TLS, P1 activation reuse, stale lease, wrong prefix digest, absent destination row and forged saved-only crossing. Use immutable fixture copies. Replay historical MG1/MG2 and CRC archives through their original formats. Build/smoke the generic two-core migration task cookie and Pi SW1 BSP/workload regressions separately. Check the original profile selector and all-features fallback.

Use tools/pi4_migration_capture.py freeze/run and tools/pi4_migration_replay.py with pinned stock QEMU raspi4b TCG, independent session hashes, raw UART/exception logs, manifest, ELF/image/disassembly and original limits. Before any scored launch freeze all six images (short/stream × global/partitioned/clustered) and both positions per image. Preflight tools, selectors, binaries, address extraction, and offline controls without consuming or replacing first boots. Run short global 1,2, partitioned 1,2, clustered 1,2, then the independent pi4-stream-v1 cohort in the same order. Preserve every first attempt, failure and partial output. Never wait in M, increase timeouts, add wakeups or tune the original arithmetic/CRC to force crossings.

Score two properties separately for every position. A normal stream crossing requires global M's linked byte-loop IRQ and same-PC ERET, source CPU0→destination CPU1, expected ownership and stack/X21, resumed live TLS prefix, terminal 4 MiB CRC 0x78d22ad1 and all existing replay checks. The verified stream is an independent directed subcase for short-workload misses. Partitioned and clustered resumes on CPU0 validate same-core preservation. A short early finish or out-of-loop return retains its actual disposition, even if stream qualifies. Report 6+6 denominators, crossing and same-core counts, and model-only scope; keep #47 open. Historical MG1 short qualified 1/6, MG2 short 0/6 and historical integrated stream 6/6 with two global cross-core returns. ## 한국어 설계 및 판정

Pi 이주 프로필에서만 TPIDR_EL1을 CPU 소유로 정한다. 각 CPU는 IRQ를 가린 초기화 중 MPIDR을 검증하고 서로 다른 영구 정적 레코드 주소를 설치한다. 이 레코드의 LIVE 리스가 디스패치, 인터럽트·퇴역 검증, 체크포인트에 실제로 쓰인다. 주소를 역참조하기 전에 현재 CPU에 해당하는 정확한 심볼과 대조한다. 태스크 측에서는 IRQ 마스크를 복원하기 전에 관측을 끝낸다. 공통 프레임 배치를 보존하고 Pi 이주 복원 경로만 EL1 기준 주소 쓰기를 생략한다. SP_EL0 및 태스크 소유 레지스터는 계속 복원한다. 일반 SMP의 EL1 태스크 쿠키 및 Pi SW1 동작은 기존 검증 대상으로 둔다.

M, P0, 최초 P1, 교체 P1에 영구 TLS 객체와 독립 토큰을 각각 배정하고 공개 전에 초기화한다. TPIDR_EL0는 객체 주소, TPIDRRO_EL0는 활성화 토큰이며 매 접근 전 실제 활성화와 대조한다. 유휴 프레임은 두 값을 0으로 둔다. 리스가 바뀌어도 M의 객체는 유지되고 두 P1은 개별 누적값으로 시작한다. 기존 체크포인트 순서 다이제스트를 TLS에서 실제 인덱스·합계 또는 누적 CRC로 갱신해 종료 SVC에 전달한다. 태스크만 쓰며 핸들러와 가변 참조를 공유하지 않는다.

MG3은 기존 여덟 필드 형식을 유지하며 태그 14로 작업 트랩의 저장 TLS·실제 CPU 기준 주소·리스를, 태그 15로 각 활성화/리스의 첫 희소 체크포인트에서 ERET 이후 읽은 두 TLS 값·기준 주소·인덱스·다이제스트를 기록한다. 위 필드 순서대로 바로 앞 행에 결합하고 ELF 주소·독립 입력 접두값·소유권과 대조한다. CPU별 96행 용량과 완전 봉인을 확인한다. 과거 MG1/MG2 재생, 주소 교환·잘못된 활성화·리스·누적값·목적지 관측 누락 등의 음성 대조 및 정상 대조를 수행한다.

빌드와 디스어셈블리, 링크 주소, 실행기, 입력과 도구를 사전 고정한다. 기존 짧은 작업과 독립 CRC 스트림을 각각 전역·파티션·클러스터 순서로 두 번씩 stock QEMU에서 실행하고 모든 최초 결과를 보존한다. 원래 타이밍·깨우기·종료 조건을 유지한다. 전역 스트림의 실제 CPU0→1 루프 내 복귀, 동일 PC와 스택/X21, 이주 후 TLS 및 최종 CRC를 함께 확인한다. 단일 CPU 복귀와 짧은 작업의 조기 종료는 별도 판정하며 6+6개 결과를 각각 공개한다. 이 설계는 모델 범위이며 상위 #47은 열린 상태로 둔다.
