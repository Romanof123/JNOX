## Engineering contract

* Leave the ordinary image, scheduler, worker loop count, priorities, timer, UART and original atomic operations intact. Engineer only the RR witness image. Record A_PUBLISHED once after A's actual release store of the acquired positive B counter to b_at_a_done. Record B_CONSUMED once on the successful nonzero acquire that already ends B's work_until. Carry the exact load result out of that iteration without another shared load. B supplies no application acknowledgement store. A and B retain their distinct owner/stack identities. [Worker source](../../kernel/src/fixed_apps.rs)
* Bracket each original operation with generation observations and ordered counter reads. Require the same nonzero dispatch generation before the operation and after collecting its result/site/SP/CPU. Record bounds, role, operation, mailbox identity, value, PC site and actual SP. Pin sites to the corresponding linked operation and inspect generated barriers/instruction order. A preemption within a bracket invalidates attribution even on one core. Preserve the real handoff, flag the ambiguous observation, never replay the application operation. If interrupted only after final validation, commit once to the immutable owner cell with the validated generation. No IRQ masking around application work. Allocate two fixed cells, one per role; commit last with release and export with acquire after quiescence. Report duplicate, partial or ambiguous observations explicitly. No retries, extra iterations or delayed peers.
* For the new RR functional result, retain the original HIGH interruption, exact frame return to A and advancing generation-3-equivalent arithmetic sample. Require actual timer peer rotation and incoming B work, then the later timer return from B to A with the correct saved frame. Match A_PUBLISHED to that incoming A generation and B_CONSUMED to a subsequent dispatch of B, with the exact same positive payload and ordered intervals. Match the original positive B work to the payload as a lower bound; the first recorded increment need not equal the value A acquired. Check every intervening dispatch, boot ID, role-to-slot map, CPU, SP, PC and terminal footer. Distinct dispatches/returns can occur between store and load. Report the actual transitions observed. The functional result can establish completion following rotation while later arithmetic progression remains unobserved.
* Freeze a new version for RR engineering UART, with a distinct row tag, widths, two-cell capacity, status and footer coverage before building. Legacy parser and v1 FIFO/RR fixtures keep their original status. New decoder reports independent structural validity, HIGH resume, legacy loop-only criterion and RR data-handoff criterion. For a declared new functional case return 0 only on all required functional evidence, 2 for well-formed unobserved evidence, 1 for invalid identity/rows/ordering. Preserve the legacy result separately including 2. v1 has no handoff fields and cannot gain retrospective credit. FIFO and normal images retain their existing acceptance. Reject fabricated duplicate rows, swapped roles/value/site, crossed generation and conflicting chronology in host-only replay.
* Predeclare two cold raspi4b boots per engineering RR candidate and corresponding ordinary RR baselines. Preserve all first attempts, raw UART, indexed IRQ/SVC/ERET, source/ELF/image hashes, maps and disassembly. Compare task-owned records against independent dispatch order. Report cells/bytes, actual ELF section deltas, sampled stack usage, probe placement and observed intervals; report unavailable uninstrumented costs. Re-score the frozen original and integrated corpora separately. No workload changes, forced timer placement or physical timing credit. ## Version 2 source and replay

Use the AArch64 target `aarch64-unknown-none` with `JNOX_BOARD=pi4 JNOX_PROFILE=fixed JNOX_APP=fixed-rr JNOX_PI4_WITNESS=1 JNOX_RR_HANDOFF=1` and a nonzero decimal `JNOX_PI4_WITNESS_ID`. Package the image as `pi4-fixed-rr-handoff`. The extra selector enables two ten-word cells and two 64-bit commit words (176 bytes before section alignment). B brackets each existing mailbox load, including unsuccessful polls. This can change timing. Only its first positive load writes a cell. No extra mailbox read or acknowledgement occurs.

Header version 2 retains tags 0–4. Immediately before tag 4, two footer-covered `PW 5` rows carry twelve unsigned decimal words each, in A then B order: operation (0 release, 1 acquire), status (0 absent, 1 attributed, 2 interrupted bracket, 3 duplicate), begin/end dispatch generations, begin/end ordered counter ticks, mailbox address, payload, PC of STLR/LDAR, task SP, MPIDR, owner role. An absent cell has ten zero data words. Address and PC are bound to the packaged ELF. The version 1 profiles retain their original verdicts.

Run `python tools/pi4_fixed_witness.py uart.bin --profile pi4-fixed-rr-handoff --manifest manifest.json --elf kernel.elf --image kernel8.img`. The capture utility accepts the same profile. Decoder exit 0 requires the HIGH continuation and functional peer handoff, 2 indicates missing or ambiguously attributed evidence, and 1 indicates invalid evidence. JSON reports arithmetic observation per A/B dispatch, original loop-only verdict, and both typed cells. Compare two fresh cold engineering boots and ordinary baselines, index ERET/IRQ/SVC independently, inspect atomics and perturbation, and replay the original v1 corpora separately.
