# Pi 4 RR 순환 후 완료 데이터 인계

[English](pi4-rr-handoff.en.md) · [#146](https://github.com/Romanof123/JNOX/issues/146) · [기존 관찰](pi4-fixed-runtime.md)

CHG-073은 공학용 관찰 확장 계획이다. 통합 aa691462c52bcad40a2b17077bd48e9ddfb9bd09의 첫 RR UART(SHA-256 2354712bcc0734a4a7065a1e28e432d6535dd1cc21b3cbb0b4cc7d895a863aa2)는 종료값 2였다. 세대 2에서 HIGH가 A를 선점했고 3에서 재개된 A는 17574330에서 17574331로 증가했다. 4에서 B가 진입해 1을 공개했다. 독립 예외 기록은 5의 B→A(ERET 0x81388), 6의 A→B, 7의 idle을 확인한다. 5와 6에는 작업 표본이 없다. 고정 RR 기록 중 처음 확인한 사례로, 앞선 원본 RR은 수정 디코더에서 0이었다. A가 루프 공개와 acquire 확인 사이에서 재개하면 바로 반환할 수 있다. 소스상 가능한 설명이며 이 기록만으로 acquire 위치나 추가 증가를 확정할 수 없다. DONE 출력·종료 SVC·저장 상태·최종 공유값으로 해당 세대의 연산 시점을 정할 수 없다. 원래 RC2와 [이전 재생](../evidence/pi4-fixed-witness-replay.md)을 보존한다.

## 공학용 계약

* 일반 이미지·스케줄러·루프 횟수·우선순위·타이머·UART·원래 원자 연산을 유지한다. RR 공학용 이미지에서만 A가 읽은 양수 B 카운터를 b_at_a_done에 실제 release 저장한 후 A_PUBLISHED를 1회 기록한다. B의 work_until을 끝낸 실제 양수 acquire에 대해 B_CONSUMED를 1회 기록한다. 해당 반복의 결과를 그대로 전달하며 공유값을 다시 읽지 않는다. B의 응용 확인 저장은 없다. 두 작업의 소유자와 스택을 구분한다. [작업 소스](../../kernel/src/fixed_apps.rs)
* 원래 연산 전후의 세대·순서 보장 카운터를 읽는다. 연산 전과 결과·위치·SP·CPU 확보 후 동일한 0 아닌 세대를 요구한다. 구간 양끝, 역할·연산·메일박스 ID·값·PC·실제 SP를 남기고 링크된 명령과 장벽 순서를 대조한다. 단일 코어라도 구간 중 선점되면 세대 귀속은 불명이다. 실제 인계는 그대로 두고 불명을 기록하며 연산을 반복하지 않는다. 최종 확인 후에만 선점되면 확인된 세대로 해당 역할 전용 셀에 1회 커밋한다. 작업 주변 IRQ 차단은 없다. 역할별 고정 셀 1개씩을 두고 마지막에 release 커밋, 정지 후 acquire 수출한다. 중복·부분 기록·불명을 명시한다. 재시도·추가 반복·상대 지연은 없다.
* 새 RR 기능 판정도 HIGH 선점과 원래 A 프레임으로의 정확한 복귀, 해당 재개 세대(기존 3)의 실제 산술 증가를 요구한다. 실제 타이머 순환과 들어온 B의 작업, 이후 B에서 A로의 타이머 복귀 및 정확한 저장 프레임을 확인한다. 그 A 세대의 A_PUBLISHED와 뒤에 선택된 B 세대의 B_CONSUMED에서 동일 양수와 순서 있는 구간을 확인한다. 먼저 확인된 B 진행은 전달값의 하한이다. 첫 증가값이 전달값과 같을 필요는 없다. 사이의 모든 디스패치·부트 ID·역할/슬롯·CPU·SP·PC·종료 푸터를 확인한다. 저장과 읽기 사이 다른 디스패치·복귀가 가능하며 실제 전이를 기록한다. 기능 판정은 순환 후 인계를 입증할 수 있고 이후 산술 증가는 여전히 미관측일 수 있다.
* 빌드 전 RR 공학 UART 새 버전, 별도 행 태그·폭·2셀 용량·상태·푸터 범위를 고정한다. 기존 디코더·v1 FIFO/RR 기록의 결과를 유지한다. 새 디코더는 구조 유효성·HIGH 복귀·기존 루프 기준·RR 데이터 인계 기준을 각각 보고한다. 새 기능 사례는 필수 기능 근거가 모두 있으면 0, 유효하나 미관측이면 2, 식별·행·순서 오류면 1이다. 기존 판정(2 포함)은 별도로 보존한다. 인계 필드가 없는 v1에 소급 점수를 주지 않는다. FIFO·일반 이미지의 기준은 유지한다. 호스트 재생에서 중복 행·역할/값/위치 교환·세대 경계 침범·시간 모순을 구분한다.
* 공학 RR 후보와 대응 일반 RR 기준 각각 raspi4b 콜드 부팅 2회를 사전 고정한다. 첫 시도 전체, 원시 UART·IRQ/SVC/ERET·소스/ELF/이미지 해시·맵·역어셈블을 보존한다. 독립 디스패치 순서와 작업 직접 기록을 대조한다. 셀 수·바이트, 실제 ELF 섹션 차이, 표본 스택 사용량·위치·구간과 계측 없는 비용의 측정 가능 여부를 보고한다. 고정 원본·통합 기록은 따로 재판정한다. 작업 변경·강제 타이머 배치·물리 시간 판정은 없다. ## 버전 2 소스 및 재생

AArch64 대상 `aarch64-unknown-none`에서 `JNOX_BOARD=pi4 JNOX_PROFILE=fixed JNOX_APP=fixed-rr JNOX_PI4_WITNESS=1 JNOX_RR_HANDOFF=1`과 0이 아닌 십진수 `JNOX_PI4_WITNESS_ID`를 설정한다. 패키지 프로파일은 `pi4-fixed-rr-handoff`다. 추가 선택 시 10워드 셀 2개와 64비트 확정 상태 2개(섹션 정렬 전 176바이트)를 사용한다. B는 실패한 폴링을 포함해 기존 메일함 읽기마다 시간을 측정하므로 실행 시간이 달라질 수 있다. 양수를 읽었을 때만 기록하며 메일함 재읽기나 확인 저장은 없다.

헤더 버전 2는 태그 0–4를 유지한다. 태그 4 직전 A, B 순서의 `PW 5` 두 행을 푸터에 포함한다. 각 행의 부호 없는 십진수 12개는 연산(0 release, 1 acquire), 상태(0 없음, 1 귀속, 2 구간 중 선점, 3 중복), 시작·종료 디스패치 세대, 시작·종료 카운터 틱, 메일함 주소, 전달값, STLR/LDAR의 PC, 작업 SP, MPIDR, 소유 역할이다. 상태 0의 데이터 열 10개는 모두 0이다. 주소와 PC는 패키지 ELF와 대조한다. 버전 1 프로파일은 기존 판정을 유지한다.

재생 명령은 `python tools/pi4_fixed_witness.py uart.bin --profile pi4-fixed-rr-handoff --manifest manifest.json --elf kernel.elf --image kernel8.img`이며 수집 도구도 같은 프로파일을 받는다. 디코더 종료값 0은 HIGH 이후 재개와 실제 데이터 전달 관찰, 2는 관찰 부족 또는 귀속 불확실, 1은 잘못된 근거다. JSON은 A/B 각 디스패치의 산술 진행 관찰, 기존 루프 판정, 두 연산 셀을 구분한다. 공학 이미지와 일반 기준의 최초 콜드 부팅 각 2회, 독립 ERET/IRQ/SVC 순서, 원자 명령과 계측 영향, 기존 v1 기록 재생은 검증 대기 중이다. CHG-073은 생산자와 디코더를 통해 REQ-002/005/008/016/023에 연결된다. ### CHG-082 · 메일박스 명령 직전·직후의 세대

통합 E1/E2 모두 외부 IRQ 로그가 기록한 B의 ELR은 0x8216c였고, 이는 메일박스 LDAR 0x82178 앞의 ISB다. 기존 외부 구간은 세대 4에 시작해 6에 끝났다. 원래 RC2 두 건, 시간 구간과 독립 산술 판정을 보존한다. [실측 결과·원시 추적](../evidence/pi4-rr-handoff-integration.md)

Pi RR 공학용 v3는 JNOX_RR_HANDOFF=2로 선택한다. 값 1은 v2다. 기존 시각·세대 구간 안에 GEN acquire 읽기, 원래의 단일 release 저장 또는 acquire 읽기, 다시 GEN acquire 읽기 순으로 세 명령을 연속 실행한다. 태그 5는 기존 구간 시각·상태·피연산자를 유지한다. 역할별 태그 6에는 역할·상태·직전 세대·직후 세대·실제 메일박스 명령 PC를 둔다. 상태는 0 누락, 1 동일한 양수 세대, 2 불명, 3 중복이다. 검증 후 두 기록을 한 번 공개한다. 기존 B의 양수 읽기만 기록하고 그 반환값을 그대로 쓴다. 연산에 새 시각을 부여하지 않는다. 내부 세대로 연산 순서가 확인되어도 외부 시간 구간은 겹칠 수 있다.

PC−4, PC, PC+4의 링크 명령과 양쪽 GEN 주소의 일치 및 메일박스 주소와의 구별을 확인한다. 실행 위치·역할·스택·손실 없음, 기존 HIGH 선점과 이후 A의 실제 진행, 실제 동급 IRQ 순환, A가 전달한 양수 B 값과 B의 이후 세대 소비를 요구한다. 디스패치 기록과 독립 ERET/IRQ 순서로 인과를 확인한다. 세 명령 사이에 세대가 바뀌면 연산 귀속은 미관측이다. 기존 외부 구간 판정·새 연산 세대 판정·이후 산술 증가를 각각 보고한다. 산술 기준은 실제 증가 표본이 필요하다. 일반 2회·v3 2회의 첫 부팅, 기존 v2 재생, 선택자·이미지·크기 비교를 고정한다. 스케줄 변경·재시도·IRQ 차단·재생 소급 인정은 없다.

태그 6의 여섯째 필드는 PC/SP 관찰 직전 실제 연산의 주소 레지스터에서 복사한 메일박스 주소다. 복사 원본 레지스터와 명령 피연산자, 태그 5 메일박스, 링크된 응용 메일박스 주소를 대조한다. 누락 행의 데이터는 모두 0이다.
