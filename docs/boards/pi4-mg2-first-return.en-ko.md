# MG2 first peer return / MG2 피어 최초 복귀

The first six runs on the paired-journal candidate ended with M already finished. The four earlier clustered captures showed P1's first milestone read succeeded. These records leave open how far CPU1's first frame restoration had advanced when CPU0 left its bootstrap wait. The existing Rust flag publishes a selected frame before assembly changes SP. [Journal cohort](../evidence/pi4-mg2-terminal-journal-first.en-ko.md) · [Milestone read and archived frames](https://github.com/Romanof123/JNOX/blob/2a24bf993a4f326437ad93b1d84bc780410c1417/docs/evidence/pi4-mg2-opening-peer-registers.en-ko.md)

Use the existing migration return sample as the admission point for the primary CPU's first restore. The per-CPU sample starts at zero and a valid lease already requires a nonzero start tick. On each restore, after selecting SP and loading the exception/system and SIMD state, publish the counter sample with an aligned 64-bit release store before the final integer-register loads and ERET. CPU0's existing bounded wait acquires CPU1's sample until it is nonzero. P1 must observe M's original first milestone to finish, so its successful opening return sample cannot have been replaced by a normal P1 retirement before M starts. This establishes an ordering between restore preparation and CPU0 admission. Both actual ERETs remain independently observable. The fixed initial release and claims, worker arithmetic, four-second timeout, P1 retirement, directed SGIR and strict interrupted-PC criterion continue to govern the case.

The two counters retain the last return samples for lease accounting. Give the published array a distinct ELF symbol so the RAM reader can identify either the historical byte flag and counters, or the new sample array. Keep the original byte in archived reports and the raw counter values in new reports. A last sample on terminal capture can be from a later restore. Use the linked instructions and the per-CPU exception history to identify the opening handoff.

Before the six launches, independently check both RAM layouts and protect the original reader output for archived images. Verify address, alignment, initial zeros, the CPU1 word acquired by CPU0, and one per-CPU release store in the linked return path. Check SP, ELR/SPSR, SIMD, the integer restore and ERET ordering. Check that zero holds the existing wait, failure and timeout still terminate it, and ordinary SMP directed-wake still uses its original path. Freeze the original strict M range, SGIR sites and all three rebuilt images. Run global twice, partitioned twice and clustered twice on the original stock model and record each first attempt. Require the original CPU-specific IRQ/ERET, stack, X21, lease and arithmetic evidence to qualify a position. Model observations supply no physical latency bound. 페어 저널 후보의 여섯 최초 실행은 M이 먼저 끝났다. 앞선 클러스터형 네 실행에서 P1의 최초 마일스톤 읽기는 성공했다. 기존 Rust 플래그는 어셈블리에서 SP를 바꾸기 전에 프레임 선택을 알린다. 당시 CPU0이 대기를 종료한 시점의 CPU1 복귀 준비 상태는 측정되지 않았다.

CPU0의 기존 부팅 대기 조건을 CPU1의 실제 복귀 준비 표본으로 정의한다. CPU별 64비트 카운터는 0에서 시작하고, 기존 리스 과금도 0이 아닌 시작 표본을 요구한다. SP 전환, 예외·시스템 레지스터 및 SIMD 복원 후 최종 정수 레지스터와 ERET에 앞서 정렬된 카운터를 release 저장한다. CPU0은 CPU1 표본을 acquire로 읽는다. P1은 M의 첫 마일스톤을 읽어야 종료하므로 M의 시작 전에는 정상 은퇴로 최초 표본을 덮어쓸 수 없다. 실제 양쪽 ERET는 별도의 관측 대상이다. 최초 동시 작업 해제·배정, 작업량, 기존 4초 기한, P1 은퇴 뒤 SGIR 및 중단 PC 기준을 유지한다.

ELF 심벌로 구·신 RAM 배치를 식별한다. 과거 캡처에는 원래 플래그 값을, 새 캡처에는 원래 CPU별 카운터를 제공한다. 최종 RAM에서는 후속 복귀가 같은 칸을 갱신할 수 있다. 검증팀은 최초 실행 전에 기존 이미지 판독 결과와 새 배열의 주소·정렬·초깃값, CPU1 슬롯과 복원 명령 순서, 0·실패·시간 초과 경로, 기존 SMP 이미지 호환성을 대조한다. 원래 모델에서 전역·고정·클러스터 배치를 순서대로 각 두 번 실행하여 모든 최초 결과를 남긴다. 지정 코어 IRQ·ERET, 스택·X21·리스·산술 결과를 모두 만족한 위치만 인정한다. 실보드 지연과 제품 판정은 미결이다.
