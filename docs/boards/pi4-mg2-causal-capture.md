# Pi 4 MG2 이주 · 인과관계 관측 계획

**기존 최초 6회는 0/6이다.** P1의 SGI 쓰기, GIC 모델의 pending 전환, M의 마지막 산술 연산 사이의 순서는 기존 기록만으로 확정할 수 없다. 두 진단 단계 모두 기존 커널 이미지와 실제 작업을 유지한다. [#47](https://github.com/Romanof123/JNOX/issues/47) · [영문 상세 계획](pi4-mg2-causal-capture.en.md) · [원래 판정 기준](pi4-smp-migration.md) · [기존 최초 결과](../evidence/pi4-migration-mg2-first.md)

기준 main `0e21061e841261ea49da14e1ced5327320759e73`에서 관련 작업·BSP·저널·캡처 소스를 검증 당시의 `559449c673ac55a0a2bf34f3e8ae680d99e72f09`와 대조했다. 오프라인 판독기는 ZIP의 82개 해시, 여섯 공개 세션 해시, CPU별 예외 이력, 원시 이미지의 관측 명령어와 동결된 루프 범위를 검증했다. CPU0은 IRQ 허용 상태에서 M 종료 SVC에 들어갔다. CPU1은 첫 이정표를 확인하고 P1 SVC에서 리스를 반납한 뒤 SGIR를 쓰고 유휴 프레임으로 복귀했다. 같은 스케줄러 잠금 때문에 SGIR 쓰기는 CPU0의 실패 **판정**보다 앞선다. CPU0이 이미 산술을 끝내고 SVC에 들어간 뒤 잠금을 기다렸을 가능성이 있다. PEER_READY는 P1 첫 ERET보다 앞선다. 타깃 설정 오류나 커널 수정의 효과를 뒷받침하는 측정값은 아직 없다. [실행별 PC·해시](../evidence/pi4-mg2-causal-sites.json) · [판독기](../../tools/pi4_mg2_retained_sites.py)

1. **종료 후 RAM 보존.** 동일 QEMU·이미지·MTTCG·기존 예외 관측기를 고정하고 전역, 분할, 클러스터 순으로 각각 처음 두 관측을 사전 등록한다. 모델 CPU 4개 중 0/1만 온라인이다. 30초 상한과 종료 후 1초 정숙 구간을 유지한다. 종료된 모델을 QMP로 정지한 뒤 두 CPU의 저널, 행 개수·유실 수, 프레임, 스택, 스케줄러 상태를 링크 주소와 함께 저장한다. 0x1d는 M의 최종 요약과 직렬 내보내기를 생략한다. 커밋된 부분 행과 SVC 프레임 인자를 판독하여 실제 인덱스·합·체크섬·리스·SGIR 값과 예외 기록을 연결한다. 타임아웃·미봉인·누락도 그대로 보존한다.
2. **기존 프로그램 지점과 GIC 경로 관측.** 동일 게스트에서 CPU0의 실제 M 시작, 기존 희소 체크포인트 16·32·65536, 첫 이정표 공개, 종료 SVC 또는 IRQ, ELR/X21 및 ERET를 기록한다. CPU1에서는 실제 P1 시작, 이정표 acquire 성공 분기, SVC, 잠금 획득, 리스 반납, SGIR 인자·쓰기·장벽 완료, 유휴 ERET를 기록한다. 모델의 기존 GIC 쓰기 처리와 pending 비트·IRQ 출력·CPU0 예외 수락을 송신원·대상·그룹·SGI ID로 결합한다. 실제 IAR/EOI 접근을 보존하고 추가 IAR 판독은 하지 않는다.
3. **순서와 시간 판정.** 생산자별 순번과 로컬 시각으로 CPU1 시작→이정표, SVC→잠금→반납→SGIR 및 CPU0 시작→작업→종료/IRQ 구간을 구한다. CPU마다 단독 기록하는 유한 버퍼를 사용하고, 한 생산자가 완료 표식을 release로 공개하면 다른 생산자가 기존 희소 지점에서 acquire로 읽은 양의 순번만 인과 간선으로 쓴다. index 32에서 완료된 SGIR 표식을 읽으면 이후 작업이 남았음이 확인된다. 반대로 모델의 SGIR 처리 시 최종 M 표식이 이미 관측됐다면 마지막 합은 쓰기 전이다. 중첩된 범위, IRQ pending 전환이나 P1 진입 관측 누락은 판정 유보로 남긴다. 서로 다른 CPU 카운터의 차, 파일 순서, 같은 주파수, 공통 표식이 없는 시각으로 순서를 추정하지 않는다.
4. **최초 결과 유지.** 진단 관측의 모델·소스·설정·해시와 부하를 보존한다. M의 루프에 대기·패딩·체크포인트 추가를 하지 않고 원래 트리거와 SGI, 리스, 합과 X21을 유지한다. 수정 근거가 생기면 수정 후보의 세 이미지·루프를 다시 고정해 원래 관측기로 별도 최초 6회를 진행한다. 엄격한 루프 PC, 실제 해당 CPU ERET, 복귀 작업과 네 활성화 요약이 필요하다. 실제 보드와 CPU 간 지연 상한은 미검증이다.

## 1단계 수집기

Linux와 pyelftools가 있는 Python에서 `tools/pi4_mg2_terminal.py freeze 새_경로 QEMU경로`를 실행해 원래 QEMU와 세 이미지 해시·RAM 범위·여섯 순번을 먼저 고정한다. 이 명령은 모델을 기동하지 않는다. 출력된 코호트 해시로 `run 새_경로 코호트해시 순번`을 순서대로 한 번씩 수행하고, 각 세션 해시로 `replay 새_경로 코호트해시 순번 세션해시`를 실행한다. Linux 네이티브 파일시스템에 기록한다.

QMP는 원래 종료 표식 이후 1초 정숙 구간이 끝난 뒤에만 연결한다. 종료 표식이 없는 타임아웃·조기 종료는 최초 부분 기록으로 보존하고 실행 중인 M을 멈추어 덤프하지 않는다. 정지 확인 후 ELF의 쓰기 가능 적재 세그먼트만 덤프하고 모델 CPU 4개의 PC·스레드 번호를 남긴다. CPU별 6,944바이트 저널에서 release로 확정된 72바이트 행만 판독한다. 보고서는 M의 SVC 프레임 인자, 산술·체크섬, 실제 스레드별 예외와 P1의 리스·SGIR를 대조한다. 게스트 결과와 캡처 성공 여부를 별도로 출력하며, 최종 PC·RAM으로 GIC pending 시각이나 M의 마지막 더하기와 SGIR 사이의 순서를 확정할 수 없다.
