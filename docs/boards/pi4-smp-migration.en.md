## Work and transition

* Freeze three cases with identical input and three ordinary EL1 Rust workers M, P0 and P1. P0 is restricted to CPU0 and P1 to CPU1. M sums i=1..65536 in unsigned 64-bit arithmetic, maintaining its index and accumulator across interruption. Its only output writer publishes 2147516416 once. At 16-item boundaries publish the actual index and partial sum. P1 first sums 1..16 (=136), waits for the first positive M milestone, then requests one directed SGI to CPU0 from its terminating SVC, after switching to its private dispatcher stack and retiring its opening lease. Publish the request before SGIR and wait on CPU1's private idle stack. M must still be inside its linked input loop at IRQ with work remaining. An early finish, late IRQ or non-loop ELR is unobserved; retain it. No spinning inside M to force a favorable PC.
* CPU0's valid SGI IAR must identify CPU1. Save M's complete architectural frame, take the scheduler lock on a per-CPU dispatcher stack and retire the exact source lease to Ready. In that same critical section call release for dormant P0 and P1 together. Snapshot the three Ready tasks, online mask 0b11 and epoch before planning. P0 sums 1..32 (=528); P1's new activation sums 17..32 (=392). Require distinct progress and terminal commits by each pinned owner. No timer or polling path can synthesize the ready transition.
* In the global case M allows 0b11. Rank [P0,M,P1] so P0 runs on CPU0 and M takes CPU1; P1 remains runnable and runs after M retires. In partitioned and singleton-cluster cases M allows 0b01. The same ranking places P0/P1 on their own CPUs and leaves M ready for CPU0 when P0 retires. Limit online candidates to CPUs 0 and 1. Record configured cluster membership {0},{1}, CPU1's ineligibility for M at the contested decision and all later claims. This is a logical grouping within one physical A72 cluster. The partitioned case expresses task affinity directly; the clustered case derives its effective mask from configured membership. Require the source pin/cluster result even if CPU1 becomes free early. ## Frame and evidence

Use one serialized Ownership instance for release, ranked plan, claim and retire. Apply both planned claims to the same snapshot under the lock and publish generation-tagged per-CPU dispatch descriptors with release/acquire ordering. Order descriptor publication before any directed SGI. Consumers revalidate epoch, lease, destination and frame sequence once before restore. No task may claim its own destination. Record both SGIs separately, with full IAR/source/EOI and acquired epoch. Source must have stopped executing on M's stack, saved all live state and switched SP **before publishing the portable frame**. Handler locals, nested returns and root idle frames must never reference reclaimed M stack storage. Use dedicated guarded task stacks, per-core boot, dispatcher and idle stacks; check ranges and high-water observations. Prove equivalent CPU-local register setup on destination (e.g. per-CPU base/TLS), restore only task-owned registers. Refuse unsupported floating-point or other unsaved state unless it is fully saved/restored.

Independently match outgoing IRQ and saved ELR/SP/registers to selected frame and actual CPU-indexed ERET into the same instruction. Verify the task-owned first subsequent input checkpoint on the selected CPU, then monotone index/triangular partial sums and the unique terminal sum. Bind each committed checkpoint to one live lease, with a generation bracket or an explicit ambiguous record if preempted. Preserve stack-local address, callee-saved witness and peer results. Scheduler serialization establishes exclusive ownership only when source relinquishment and actual destination return are corroborated. Record all intervals per lease from actual dispatch/stop observations on that CPU, with counter and frequency; describe included dispatch/handler cost. Debit one checked local interval per retired lease and reconstruct each per-task total from unique lease IDs. If frequencies differ, report per-CPU units separately or reject pooled tick accounting. Cross-core latency needs a measured offset bound even at equal frequency. Do not subtract counters from different CPUs for service.

Freeze one immutable manifest per case and platform. On raspi4b retain the first two cold launches per case, model/ELF/raw/map hashes, tagged exception/return traces, terminal records and peers' quiescent acknowledgements before CPU0 exports. Reuse the 30 s capture ceiling and 1 s quiet interval. Missing quiescence, overflow, bad frame/lease or mismatched arithmetic precludes completion. Preserve each first failure and classify an unobserved interruption separately from invalid evidence. On the 1 GB Pi 4 use separately pinned firmware/card/revision and two witnessed power cycles per case. Device records can establish causal task progress; independent physical instruction history requires external trace. Physical results, migration limits, shared-cache interference, WCET and energy are open. At opening release M and P1 together and claim M on CPU0 and P1 on CPU1. CPU1 keeps IRQ masked through its opening SVC handoff until its private idle SP and dispatch mailbox are valid, so a queued return SGI cannot run on the retired worker stack.

## CHG-075 revision 2 · Worker-owned checkpoint retention

The original six first boots met the loop criterion once. Global position 2 resumed on CPU1 outside the linked loop. Preserve each original capture. The original per-checkpoint LAST swap and SEEN fetch-add operate on shared cache lines although one lease executes each task. Reading MPIDR followed by a CPU-indexed lease also permits an intervening migration. Their individual wall costs are unknown. [First cohort](../evidence/pi4-migration-first.en.md)

Keep the arithmetic routine, X21 cookie, tasks, input values, checkpoint interval of 16, first milestone and directed interrupts. Each activation carries its own retention counters on its task stack across restores. The dispatcher publishes the lease by task ID at dispatch. Sample that task-specific word before work and at checkpoint selection. Recheck it against the actual CPU lease with local IRQ masked only while emitting the existing sparse witness. Attribute a crossing to both lease endpoints. Never report an intermediate observation as an entire single-CPU chunk.

MG2 retains every arithmetic checkpoint in a bounded summary per activation. Starting at zero, fold each observed (index,sum) in order as (rotate_left(hash,7) XOR index) + sum modulo 2^64. Count each checkpoint exactly once. On SVC completion emit kind 13 with task, epoch, lease, count, digest, last index, last sum and zero. Require 4096 checkpoints for M, two for P0 and one for each P1 activation. Replay every expected input independently, join summaries to their actual finishes and report the existing sparse row coverage separately. A digest is finite evidence, not a trace of all intermediate instructions. Bind wire_version=2 to the new freeze. Keep MG1 replay for historical manifests.

Freeze the new linked loop, return sites, images and observers before the same six first positions. Report actual IRQ ELR/ERET, X21, ownership, return, arithmetic coverage and missing observations, including continuations outside the loop. No added wait, widened PC range or changed send trigger. Only a verified inner-loop interruption with the required independent CPU history counts toward the original criterion.
