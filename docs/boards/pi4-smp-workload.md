# Pi 4 지향 깨움 작업과 SW v1 출력

[English](pi4-smp-workload.en.md) · [CHG-070 계획](pi4-smp.md)

kernel/에서 벤치 기능 없이 `JNOX_BOARD=pi4 JNOX_PROFILE=smp JNOX_APP=directed-wake cargo build --release --locked -j1`로 전용 이미지를 만든다. 최초 실행 전에 ELF·링크 역어셈블리/맵·원시 이미지·패키지 해시·펌웨어·옵션을 고정한다. 계획의 4코어 raspi4b에서 CPU별 예외·복귀 트레이스를 보존한다. 콜드 실행마다 새 프로세스와 디렉터리를 사용하고 호스트 제한 30초와 종료 후 1초 정숙을 적용한다. 실패·부분 출력도 보존한다. BSP가 기동·MMU·전체 IAR EOI·CPU1 해제를 담당한다. 작업은 독립 가드 스택과 공유 Normal 메모리를 사용한다. CPU1이 최종 SVC로 정지한 후 CPU0만 출력한다. 상대 코어 정지를 확인하지 못하면 로컬 실패 한 줄만 허용한다.

역할 0/1/2는 각각 CPU0 생산자, CPU1 배경 작업과 수신자다. 최초 수신자는 SVC 1로 차단된다. CPU0는 배경 작업의 진행 표본과 그 이후 16회 증가 묶음을 확인하고 합·세대를 게시한 뒤 SGI를 한 번 보낸다. IRQ만 차단→준비 전이를 수행한다. 수신 작업이 실제 복귀 후 준비→실행을 한 번 수행하고 합의 두 배를 응답한 후 재차 차단되거나 종료한다. 복귀한 배경 작업에서 세대가 바뀌지 않은 전체 증가 묶음을 관측해야 다음 송신을 허용한다. 두 번째 복귀 표본 이후 CPU1은 SVC 2로 IRQ를 차단하고 정지를 게시한다. 각 카운터 감시 시간과 CPU0의 실패 후 정지 대기는 유한한 시험 제한이다.

**원시 형식.** ASCII 십진수와 LF다. HEADER는 버전·코어별 용량 32·프레임 바이트, STACK은 역할·하한·미포함 상한·가드 상태다. CORE는 코어·예약한 행 수·손실·작업 오류 코드와 기동/GIC 각 8워드다. 기동 순서는 MPIDR·진입 EL·현재 EL·TTBR0·TCR·MAIR·SCTLR·CPUECTLR(BSP 인코딩)이다. GIC는 TYPER·로컬 ITARGETSR·IGROUPR0·분배기 CTLR·CPU CTLR·PMR·SGI 우선순위·ISENABLER0이다. ROW는 CPU·1부터 증가하는 게시 순번·종류·세대·로컬 CNTPCT·피연산자 5개다. 미사용 뒤쪽 값은 0이다. END는 게스트 절차 성공·최종 응답 세대·응답 값·배경 진행량을 담는다. 푸터만으로 실행을 적격 처리하지 않는다.

| 종류 | 피연산자 순서 |
|---|---|
| 1 | 원시 MPIDR, 원시 CurrentEL, CNTFRQ, 로컬 카운터, 프레임 크기 |
| 2, 8, 10, 12, 14, 15 | 역할, 프레임 주소, ELR, 프레임 위 SP, 게시된 배경 진행량. 각각 최초 선택, IRQ 저장, IRQ 선택, 수신자 SVC 저장, 배경 선택, 마지막 배경 SVC 저장. |
| 3 | 실제 역할, 인라인 표본 PC, 실제 SP, 값, 원시 MPIDR. 생산자는 합, 수신자는 응답(최초 0), 배경은 증가 횟수. |
| 4 | 합, 이전 진행량, 이후 진행량, 0, 0. SGIR 전 게시. |
| 5 | 송신 함수 전후 로컬 틱, 실제 SGIR 워드, 대상 비트마스크, 합 |
| 6, 7 | 합, 두 배 값, 0, 0, 0. 생산자의 응답 관측 또는 수신자 소비. |
| 9 | 전체 IAR, 소스 CPU 인터페이스 ID, 메일박스 합, 차단 상태, 준비 상태 |
| 11 | BSP EOI·배리어 후 원래 IAR, 선택 역할, 0, 0, 0 |
| 13 | SVC 번호 1, 새 상태 4g, 0, 0, 0. g=3은 수신자 종료. |

**독립 판정.** 코어별 순번과 세대별 release/acquire 전이로 인과 순서를 연결한다. 두 코어의 실제 affinity·EL·주파수, ELF 스택 범위·가드, 연속 게시 순번·손실 0을 검증한다. SGIR는 그룹 1의 ID 1로 CPU1만 대상으로 삼고 IAR는 확인한 CPU0 GIC 인터페이스에서 와야 한다. EOI는 전체 IAR와 일치해야 한다. GIC 인터페이스 ID와 MPIDR Aff0는 구별한다. 세대별 차단→준비, 수신 실행, 응답을 각각 한 번 확인하고 136→272 및 392→784를 대조한다. IRQ ELR을 링크된 배경 루프 및 실제 CPU별 예외 로그와 맞춘다. 수신자 선택 프레임은 직전 SVC 저장, 배경 재선택 프레임/PC/SP는 해당 IRQ 저장과 일치해야 한다. 각 작업의 실제 스택·링크 표본 PC·추가 진행을 확인한다. g=3의 SVC 1은 종료이며 최종 SVC 2는 복귀하지 않는다. 누락·잘못된 순서·상태·스택·affinity·시간초과·예기치 않은 IRQ는 합이 맞아도 실패다. 각 코어 시간은 자체 CNTFRQ로 해석한다. SGIR 전후 구간에는 소프트웨어 비용이 포함된다. 코어 간 지연은 공통 에포크 또는 오프셋의 상한을 따로 입증해야 한다. 이 소스에는 실행이나 실물 판정이 없다.
