## 작업과 전이

* 같은 입력과 EL1 Rust 작업 M·P0·P1을 쓰는 세 사례를 고정한다. P0/P1은 각각 CPU0/1에 고정한다. M은 부호 없는 64비트로 1..65536을 합산하며 중단 전 인덱스·누계를 이어간다. 단일 작성자가 최종 2147516416을 한 번 공개한다. 16항마다 실제 인덱스와 부분합을 공개한다. P1은 먼저 1..16(136)을 합산하고 M의 첫 양수 진행을 확인한다. 종료 SVC에서 전용 디스패처 스택으로 전환하고 최초 임대를 반납한 다음 요청을 공개하고 CPU0에 SGI 한 번을 보낸다. CPU1은 전용 idle 스택에서 대기한다. IRQ 시 M의 실제 ELR은 링크된 입력 루프 안이고 남은 입력이 있어야 한다. 선행 완료·늦은 IRQ·루프 밖 ELR은 미관측으로 보존한다. M에서 유리한 PC를 만들기 위해 대기하지 않는다.
* CPU0의 SGI IAR 송신자는 CPU1이어야 한다. M의 전체 아키텍처 프레임을 저장하고 코어별 디스패처 스택에서 스케줄러 잠금을 얻어 정확한 원본 임대를 Ready로 반납한다. 같은 임계 구역에서 dormant인 P0/P1을 한 release로 함께 준비시킨다. 세 Ready 작업과 온라인 마스크 0b11, 세대를 고정한 뒤 배치한다. P0은 1..32(528), 새 P1 활성화는 17..32(392)를 합산한다. 두 고정 소유자 각각에서 진행·종료 커밋을 확인한다. 타이머나 폴링으로 준비 전이를 대신하지 않는다.
* 전역 사례에서 M 허용은 0b11이다. 순위 [P0,M,P1]이면 P0은 CPU0, M은 CPU1이며 P1은 실행 가능 상태를 유지하고 M 반납 후 실행한다. 분할·단일 코어 클러스터에서는 M 허용이 0b01이다. 같은 순위로 P0/P1이 각 코어를 쓰고 M은 P0 반납 후 CPU0에서 재개한다. 후보 CPU는 0,1뿐이다. 클러스터 구성 {0},{1}, 경합 결정 때 CPU1이 M에 부적격인 사실과 이후 모든 점유를 기록한다. 이는 한 A72 물리 클러스터 안의 논리 그룹이다. 분할은 작업 마스크를 직접 사용하고 클러스터는 구성된 소속에서 유효 마스크를 계산한다. CPU1이 먼저 비어도 M의 소스 고정/클러스터 제한을 만족해야 한다. [배치 정책](../../kernel/src/domain_policy.rs)

## 프레임과 근거

하나의 직렬화된 Ownership에서 release·순위 배치·claim·retire를 수행한다. 같은 스냅샷에서 두 임대를 잠금 아래 확정하고 세대가 있는 CPU별 디스패치 기술자를 release/acquire로 공개한다. 지정 SGI보다 먼저 기술자를 공개한다. 소비자는 복귀 전 세대·임대·대상·프레임 순번을 한 번 확인한다. 작업 스스로 목적지를 점유하지 않는다. 두 SGI의 IAR 전체·송신자·EOI·획득 세대를 별도 기록한다. 소스는 M 스택 실행을 끝내고 전체 상태를 저장하고 SP를 바꾼 뒤에만 이동 가능 프레임을 공개한다. 핸들러 지역변수·중첩 복귀·idle 프레임에서 이미 넘긴 M 스택 영역을 참조하지 않는다. 보호된 작업 스택, 코어별 기동·디스패처·idle 스택 범위와 관측 사용량을 확인한다. 목적지의 CPU별 기준 레지스터/TLS 설정을 확인하고 작업 소유 레지스터만 복원한다. 부동소수점 등 전체 저장·복구하지 않는 상태는 허용하지 않는다.

원본 IRQ·저장 ELR/SP/레지스터, 선택된 프레임, 동일 명령으로 돌아가는 실제 CPU별 ERET를 독립 대조한다. 선택 CPU에서 작업이 직접 기록한 다음 입력 진행, 단조 인덱스·삼각수 부분합·유일한 최종합을 확인한다. 각 커밋을 유효 임대 하나에 연결하고 세대 전후 확인 중 선점되면 불명으로 표시한다. 스택 지역 주소·callee-saved 레지스터·고정 작업 결과를 보존한다. 직렬화된 소유권은 실제 소스 이탈과 목적지 복귀를 확인해야 실행 배타성의 근거가 된다. 임대별로 동일 CPU의 실제 디스패치·정지 관측점과 카운터·주파수 및 포함된 디스패치/핸들러 비용을 기록한다. 반납한 임대당 검증된 로컬 구간을 한 번만 부과하고 고유 ID로 작업 누계를 재구성한다. 주파수가 다르면 CPU별 단위를 따로 쓰거나 틱 합산을 거부한다. 같은 주파수여도 코어 간 시간은 오프셋 범위 보정이 필요하다. 서비스 계산에 서로 다른 CPU의 카운터 차이를 쓰지 않는다.

사례·플랫폼별 매니페스트를 고정한다. raspi4b에서 사례당 첫 두 콜드 부팅, 모델/ELF/원시 이미지/맵 해시, CPU별 예외·복귀, 종료 기록과 CPU0 출력 전 양쪽 정지 확인을 보존한다. 캡처 30초·종료 후 정숙 1초를 사용한다. 정지 확인 누락·기록 초과·잘못된 프레임/임대·산술 불일치는 완료할 수 없다. 첫 실패를 보존하고 중단 미관측과 기록 오류를 구분한다. 1 GB Pi 4는 별도 고정 펌웨어·카드·리비전으로 사례당 입회 전원 재인가 2회를 요구한다. 장치 기록은 인과적 작업 진행을 뒷받침하며 독립 물리 명령 이력에는 외부 추적이 필요하다. 실물 결과·이동 한계·공유 캐시 간섭·WCET·에너지는 미확정이다. [REQ-002/005/008/023](../requirements.md) · [DES-003/004/012](../architecture.md) · [VER-002/005/008/023](../verification-plan.md)

최초 release에서 M과 P1을 함께 준비시키고 CPU0에 M, CPU1에 P1을 배정한다. CPU1은 최초 SVC 인계 시 전용 idle SP와 디스패치 메일박스가 준비될 때까지 IRQ를 차단해, 대기 중인 회신 SGI가 반납한 작업 스택에서 실행되지 않게 한다.
