# Pi 4 directed-wake replay / Pi 4 코어 간 깨우기 재생

Use Python 3 with pyelftools. Keep one acquisition directory per cold launch or witnessed power cycle. Run `python tools/pi4_smp_replay.py DIRECTORY TRUSTED_SESSION_SHA256`. Preserve the complete output and input files even for incomplete sessions. [Board contract](pi4-smp.en.md) · [보드 기준](pi4-smp.md)

The manifest is session.json. Record mode (model or physical), nonempty run_id, elapsed_ns, quiet_ns and a sha256 object keyed by kernel.elf, kernel8.img and uart.bin. Preserve original bytes and seal the manifest digest independently. The decoder checks each file against that digest chain and reconstructs the raw load image from allocated ELF sections. The input ceilings are 64 MiB ELF, 512 KiB image, 1 MiB UART, 64 KiB metadata, 30 s observation and at least 1 s quiet.

A complete journal requires 32-row per-core capacity, contiguous sequences, clean guards/loss counters, matching boot and GIC data, two published/received sums, live source IAR, full EOI callback, saved/reselected continuations and progress after each wake. Receiver SVC save uses the earlier acknowledged generation, the following blocked-state publication uses the requested generation. Background save/return must agree at the same generation. Per-core frequency and local send-call ticks accompany the software result. No cross-core latency is computed.

For an independent CPU-tagged observer, external.log can contain its complete task interval in ASCII with one record per line, e.g. `CPU 1 irq 0x81040`. Use lowercase irq/svc/eret and the saved ELR or actual return PC. Begin each core at its initial task ERET, include every intervening IRQ/SVC/ERET and stop at quiescence. Hash this file in the manifest. When mapping native observer bytes to these lines, retain the original hash, CPU tag, exact line/packet offsets, observer identity, extraction tool and interval boundaries in the acquisition ledger; validate that mapping independently. Untagged QEMU log lines cannot establish the return CPU. External instruction history and the software SGI/IAR evidence address different questions.

For an interrupted background PC beyond the main background symbol, the default output records a gap. An independent linked call-graph review can supply background-review.json and disassembly.txt (both hashed). The review contains elf_sha256, disassembly_sha256, reviewer and sites. Each site names a numerical pc, its exact ELF symbol, exclusive_root equal to pi4_smp_background, true all_callers_accounted and continuation_preserved fields, and a proof citing all incoming paths, indirect entries and saved continuation. The reader joins these reviewed assertions to the symbol extent and paired saved frame; the reviewer owns call-graph completeness. Shared or unresolved PCs remain gaps.

Exit 0 means the software rows satisfy this single-run contract. Inspect external and qualification separately. Two independent cold model launches require CPU-indexed observer evidence. Physical claims require separate power-cycle, board, firmware, package and SD readback evidence. The footer or a selected frame cannot establish actual work or physical ERET.

원본 실행마다 별도 디렉터리에 ELF·이미지·UART를 보존하고 위 명령에 독립적으로 봉인한 session.json 해시를 전달한다. 메타데이터는 모드, 실행 ID, 관측 시간, 마지막 무출력 시간, 각 파일 SHA-256을 담는다. 도구는 원본 바이트·링크 범위·코어별 순서·SGIR/IAR/EOI·스택과 저장 복귀 프레임·실제 작업 및 재개 후 진척을 검사한다. 정상 데이터는 136→272와 392→784 두 건이다. 누락·잘못된 코어·순번·세대는 실패로 남긴다.

독립 관측기가 CPU를 기록한 경우에만 외부 명령 이력을 연결한다. 원본 로그, 해시, 코어 태그, 줄 또는 패킷 위치와 변환 도구를 보존한다. 외부 자료가 없거나 CPU 식별이 불가능하면 추가 관측이 필요하다. 공유 함수의 PC를 역할만으로 추정하지 않는다. 소프트웨어 판정과 별도로 모델은 서로 다른 첫 부팅 2회, 실물은 같은 보드와 카드의 완전 전원 재인가 2회 및 펌웨어·SD 검증 자료가 필요하다.
