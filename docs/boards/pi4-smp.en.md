## Entry and reserved memory

Use the EVD-011 executable digest and four-core, 2 GiB raspi4b TCG machine with the raw kernel8.img passed to -kernel. Its AArch64 raw loader selects the Linux-style boot setup even for this freestanding payload. With PSCI disabled and multiple CPUs, model reset starts secondaries at 0x300 in a WFE/load/branch loop. The four little-endian 64-bit spin slots at 0xd8, 0xe0, 0xe8, 0xf0 index MPIDR Aff0. Preserve [0,0x80000) for boot handoff, except the one explicit CPU1 slot store. On firmware the CPU3 slot aliases magic/version at 0xf0/0xf4; 0xf8 and 0xfc are the 32-bit DTB and kernel-entry fields. Do not repurpose these bytes, the live DTB or other firmware reservations. CPU0 alone clears BSS. Link all image data, private aligned stacks, guards and page tables within [0x80000,0x100000), reject overlap or overflow. Physical Pi 4 Model B 1 GB uses the pinned firmware, low peripherals and default GIC-aware stub. The published stub source describes expected behavior; record the effective firmware/stub and DTB cpu-release-addr values on the actual unit before authorizing the write. The direct model bypasses EEPROM, SD and VideoCore. No PSCI call or legacy mailbox substitute. CPU0 completes initialization, publishes an aligned physical secondary trampoline to 0xe0 (clean to PoC when cached, DSB SY then SEV). CPU1 verifies full MPIDR affinity and supported entry EL before selecting its own stack without calling Rust or clearing BSS. Establish EL1h, VBAR, masked startup and matching translation/cache attributes on both paths; verify EL2 timer access where applicable. Keep CPUs 2/3 parked with unwritten slots. Configure coherent Normal inner-shareable memory before runtime atomics and Device mappings for GIC; verify coherency setup and never mix cached/uncached aliases. ## Work, ownership and acceptance

1. CPU0 producer and CPU1 background/receiver each use distinct fixed-affinity EL1 Rust frames and guarded stacks. Receiver outranks background and blocks for generations 1 and 2. No polling path may mark it ready. One outstanding mailbox transaction at a time. For generation g, producer computes the sum of 16 consecutive integers starting at 16(g−1)+1 (136,392). Receiver consumes exactly once and returns twice the sum (272,784). Background performs a private increasing count in an ordinary Rust loop and publishes a progress sample after each chunk of 16 increments. Require a new sample before each send and further committed progress after each handler/receiver yields or blocks. Freeze a bounded journal and an abort deadline to avoid indefinite waits.
2. Once CPU1 publishes BLOCKED(g) and background has run, CPU0 release-publishes (g,sum), orders normal stores before the distributor write (DSB ISHST), sends exactly one Group 1 SGI 1 via GICD_SGIR targeting CPU1 only, and waits for an acquire-checked acknowledgement. GICD=0xff841000, GICC=0xff842000. CPU0 initializes the distributor once; each CPU sets/verifies its own banked group, priority/mask, CPU interface and target identity before IRQ unmask. Confirm actual Group 1 access/delegation and usable target bit, fail closed on mismatch. CPU1 must acknowledge SGI 1 from CPU0 in GICC_IAR, acquire matching mailbox, atomically transfer BLOCKED→READY once, retain background frame and EOI the full original IAR. Dispatch receiver by exception return and resume background at the saved continuation after receiver blocks/exits. Only then release the next generation. [GIC wiring](https://github.com/qemu/qemu/blob/005c61c0ef6f6ae615283440b4bb7be51b2c6ddd/hw/arm/bcm2838.c)
3. Retain disjoint per-core bounded records with commit sequence and loss count. Join CPU0 publication and actual SGIR write, CPU1 IAR/source, outgoing background ELR/SP/progress, selected frame, receiver's actual entry/continuation PC/SP, generation/result, SVC and resumed background PC/SP/progress. Join by generation and causal edges. Distinguish store instruction brackets from bus delivery. Read MPIDR, CurrentEL, CNTFRQ and CNTPCT on each CPU, report intervals in ticks with per-core frequency. Report cross-core elapsed time only with a justified common epoch or a bounded offset calibration. USB arrival is transport time. Missing IRQ/source, bad guard, duplicate owner/sequence, orphan claim, lost row or absent resumed progress fails the case regardless of final sums.
4. Freeze hashes of source, executable, ELF/disassembly, raw/package/config and observer before first capture. Run two first cold model launches of this image, all four CPUs present, two participating. Require both generations in both runs with CPU-indexed QEMU IRQ/SVC/ERET and linked PCs corroborating on-target events; if log lacks CPU attribution require an independent CPU-tagged capture. Export bounded rows after quiescence from CPU0 only; 30 s host capture ceiling and 1 s terminal quiet are observation rules. Retain all failures. Host replay must reject swapped CPU/source, generation, or missing IRQ. For actual hardware require two separately witnessed full power cycles on the same recorded board/card, raw serial and software records, board revision, EEPROM/firmware/config hashes and SD readback. Physical instruction history needs an external trace facility. Physical timing, migration, shared-cache interference, energy, WCET and product allocation remain open.
