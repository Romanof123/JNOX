# Pi 4 directed-wake BSP source contract

[한국어](pi4-smp-bsp.md) · [Normative CHG-070 plan](pi4-smp.en.md)

Select JNOX_BOARD=pi4, JNOX_PROFILE=smp, JNOX_APP=directed-wake, with benchmark features and other workload controls unset. The raw image loads at 0x80000. The existing Pi 4 linker window ends at 0x100000, including NOLOAD objects and the CPU0 boot stack. Resolve the complete ELF with the companion pi4_smp_workload module before freezing a build.

## Entry and mapping

CPU0 alone clears BSS. Both participants require cold identity-addressed handoff with translation and caches off. The secondary trampoline validates all architectural affinity fields and entry EL before using its private 16 KiB stack. EL2 enables NS EL1 physical counter/timer access before entry to EL1h. A direct EL1 entry depends on an already delegated physical counter. CPU2/3 stay in the loader loop. Both cores use the same TTBR0, TCR, MAIR and EL1 mappings, and share an aligned VBAR with core-private interrupted stacks. The image window uses Normal inner-shareable WBWA memory and the GPIO, UART and GIC pages are Device-nGnRnE. The spin table occupies a separate Normal, execute-never page. Access in the low handoff region consists of checking the single empty CPU1 slot and writing its little-endian 64-bit entry once at 0xe0, cleaning that line to PoC, DSB SY, SEV. The binary expects an authorized spin-table layout. Confirm the live DTB, firmware, security configuration and reservations before physical use. The BSP reads CPUACTLR-family CPUECTLR.SMPEN and records its readback. Hardware with GIC SecurityExtn requires the set bit; the pinned model can expose a RAZ/WI implementation. Early boot before usable stacks/translation can park silently.

## Workload interface

After boot state, banked GIC and VBAR setup the BSP enters pi4_smp_workload::start(0 or 1) with IRQ masked. CPU0 calls release_cpu1 once after initializing the shared workload state. Each workload sets up and starts its guarded EL1 frames through context::sched_start_frame. The single expansion of context.S belongs to the BSP. On a valid CPU1 SGI it calls irq(core, outgoing_frame, full_iar), writes that full IAR to GICC_EOIR, issues a barrier, calls eoi_done(core, iar), and returns the selected frame to assembly. For an EL1 AArch64 SVC it calls svc(core, outgoing_frame, immediate). A malformed source/ID is captured in failure_iar(); valid nonspurious foreign interrupts are EOI'd before fatal stop. CPU0 alone prints. A surviving producer can report failure() on timeout.

Both ticks() and frequency() return raw architectural counts; identity() returns MPIDR and the architected CurrentEL value (4 for EL1). boot_state(cpu) returns MPIDR, incoming CurrentEL, current EL, TTBR0, TCR, MAIR, SCTLR and CPUECTLR. gic_state(cpu) returns TYPER, banked target mask, IGROUPR0, distributor CTLR, CPU CTLR, PMR, SGI1 priority and ISENABLER0. These arrays are published with the discovered core target. Zero target denotes an unpublished interface. The nonsecure interface on hardware may read the banked group as zero; do not infer delegation solely from this read. The model's combined interface explicitly sets and reads Group 1. Combined EOI mode, interrupt priority and mask and a unique one-hot target bit are checked. IRQ acceptance also requires the SGI1 IAR's source CPU number to match CPU0's discovered bit. send_sgi1() returns the actual SGIR word after DSB ISHST, the distributor write and a completion barrier. Its destination field is CPU1's observed mask, target filter zero, SGI 1, NSATT 1. Caller counter brackets include both barriers.

Existing Pi 4 selectors retain their earlier startup assembly through conditional assembly. Rebuild and compare their linked images before making byte-identity claims. Firmware startup, two-core execution, SGI visibility, correct return, physical coherency/timing and workload verdicts require separate evidence.
