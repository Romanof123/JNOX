# CHG-061 · Cost of observing the OFF-only permit workload / OFF 전용 허가 작업의 관측 비용

[#94](https://github.com/Romanof123/JNOX/issues/94) · [#131](https://github.com/Romanof123/JNOX/pull/131) · [EVD-054 / English](evidence/evd-054.en.md) · [EVD-054 / 한국어](evidence/evd-054.md) · [Runtime contract](ordinary-permit-phase-runtime.md)

## English

**Question.** Does excluding external per-read logging change the *observed* first control debit or phase delay in an otherwise identical default-clock OFF run? In the eight original default A1/A2 characterization boots seven latched service reason 3 and one phase reason 7 before the first publication; all 56 sender opportunities were unattempted. The four deterministic boots reached seven deliveries and stayed OFF. Keep those cohorts, operational refusals and missing costs intact. Their clocks and denominators differ.

**Evidence for the comparison.** Reading the eight archived mechanism files gives 983–1,315 PL061 read records each (982–1,314 masked bit-zero data reads at offset 0x004 plus one direction read at 0x400). Mechanism files span 62,735–83,257 bytes; runner elapsed times span 64.04–141.14 ms including host polling/termination. For DM default order 12/A1 the raw write sequence was (0x004,0), (0x400,1), (0x004,0), alongside reset and bit-zero output notifications. The guest uses physical 0x09030004 and 0x09030400. A direction write of 1 configures output direction; it is distinct from writing an ON data bit. Those measurements motivate suppressing one observer event class only. They do not measure its cost. The original launcher inspected its mechanism stream after exit; the new supervisor must inspect it live and parse the actual “setting output 0 to 1” syntax.

| Arm | QEMU 6.2 log options from process start |
| --- | --- |
| F (full) | `-d int,trace:pl061* -D <native-run>/mechanism` |
| R (reduced) | `-d int,trace:pl061_reset,trace:pl061_write,trace:pl061_set_output,trace:pl061_update,trace:pl061_input_change,trace:pl061_update_istate -D <native-run>/mechanism` |

The frozen installed /usr/share/qemu/trace-events-all declares those six names plus pl061_read. Archive its hash and matching lines, the exact filter expansion/backend and QEMU executable SHA-256 (original 0a63468782d096485932acf6aa0a69d358b3e3a6f68f655e960e9f5e3fc578d8). Unexpected event catalog or unavailable required provider invalidates the planned comparison. R suppresses **only** pl061_read; every modeled GPIO write including config/reset-related activity, device output update, input/IRQ state and IRQ/SVC/ERET stream remain observable. The same guest executes all original MMIO reads and its bounded write/readback records in both arms. Per-read external values/counts in R are unavailable by design and cannot be reconstructed from F.

1. **Freeze before launch.** Use the four existing, hash-verified A1/A2 × RM/DM OFF binary artifacts and hashes from EVD-054 builds.json/freeze.json. Same bytes within each pair; no selector/build/source change, firmware warm-up, runtime log patch or positive device stimulus. One Cortex-A72, one vCPU, original virt/GICv2/TCG and RAM/options/CPU affinity, default clock only. Same software versions, command line except the filter and per-run paths, native Linux filesystem, buffer and monitoring resources. Preallocate bounded capture quotas, explicitly record byte/capacity/truncation status. Give both arms identical limits with adequate full-stream headroom; reject truncated/rotated/lost or overwritten data. Preserve raw UART, mechanism log, stderr, argv, host-timestamped first/stop signals and hashes before decoding. Use fresh directories and sequential processes; include first launch errors and no substitutions.
2. **Cohort.** Per policy and sender arm run one F→R pair and one R→F pair (4 images × 4 launches = 16), alternate starting order between adjacent image groups in a frozen manifest. Set original 10-second host limit per position; stop on terminal/earlier containment alarm, retain incomplete positions and the planned denominator. Record host scheduling/load, I/O space, drain lag and number of bytes/events. If live suppression/filtering or same-resource monitoring cannot be established, mark blocked/unqualified, do not replace it by deleting reads offline. No new deterministic or operational position is needed.
3. **Containment first.** Start a bounded incremental live consumer before guest execution in both arms, process complete lines across partial reads, keep detection and stop host timestamps, and retain undrained bytes. On first observed bit-zero ON in any masked-data write targeting bit zero (including aliased offsets), an output-0-to-1 notification, driven-high update, full-arm high read, or a guest containment alarm, immediately stop the emulator and abort remaining launches. Preserve raw event, device ID, offset/value and last guest bracket; if the guest already executed its hard-OFF trap, preserve its own detect/request/readback ticks. A stopped emulator cannot attest a later guest write. Sampled boot/final OFF cannot erase a transient. Missing terminal boundary, monitor overrun, wrong device instance, absent reset/config or ambiguous write/edge inventory is incomplete coverage. No real ON injection. Use archived/offline synthetic parser controls for split-line ON, aliased-data ON, direction-only writes, missing/reset/reordered records, missing ERET, truncated terminal and deliberate omission of per-read records in R.
4. **Join without fabricated time.** Parse complete IRQ/SVC/ERET sequence against the exact ELF, PC, worker/stack and ordered guest rows. Reconstruct requested IRQ lateness from its preceding row 2 absolute compare and row 3 entry, never from phase index. Join guest ordered write ordinals, before/after counter readbacks, boot/final OFF and row 84 hypothetical action against the independent per-device write/update transcript. Full arm also cross-checks modeled read values; R independently corroborates writes/output edges but cannot independently verify each guest read. QEMU's text trace supplies event order, not guest-counter timestamps. Do not infer an exact transition tick, continuous electrical OFF, cross-stream latency or physical response from this join. Export available/absent fields per arm.
5. **Discriminate the next change.** Save actual first and subsequent requested compare, IRQ, dispatch/return bracket, decision begin/end, row 6 slices, total row 8 service, first latch reason/time and pending indices. If reached, retain each actual sender issue/store bracket, sleep/wake, receiver delivery/rejection and command ingress/visibility independently; terminal and first-fault observations take priority over an intended event that never ran. Report signed R−F deltas for matched finite intervals only, counter resolution/uncertainty and per-position first failure; a missing phase is not zero. Keep 250 µs control, 750 µs sender, 0.5/1/5/10 ms limits and original 250/25/50/15/50/25 µs characterization guards. Exact 625000-tick first issue gap and 937500-tick command offset at 62.5 MHz require classifiable actual brackets; no shift/retry/widening. No admission or positive outcome, even if a hypothetical path completes. If R and F both fail early, prioritize the dominant *measured* cold interval in a separately frozen source study. If R changes outcomes, repeat under controlled host conditions before attributing interference; pure log volume, identical nominal scheduling, task identity or shorter host duration cannot establish a causal speedup. Same-counter device-edge timing remains a separate observation need. REQ-002/003/005/023 → DES-003/006/012 → VER-002/003/005/023. No new qualified cost or product evidence.

## 한국어

질문은 게스트를 그대로 두고 외부 읽기 로그 하나만 제외할 때 첫 제어 서비스·위상의 **관측 결과**가 달라지는지다. 이전 기본 시계 OFF 8건은 발행 전 7건 사유 3, 1건 사유 7로 중단되어 56번의 송신 기회를 수행하지 못했다. 결정적 4건은 별도다. 기존 원시 파일당 PL061 읽기 983~1,315회(0x004 데이터 982~1,314회와 0x400 방향 1회), 로그 62,735~83,257바이트, 호스트 종료 포함 64.04~141.14 ms였다. DM A1의 쓰기는 데이터 0, 방향 1, 데이터 0이었다. 방향 1은 ON 쓰기와 다르다. 실제 주소는 0x09030004/0x09030400이다. 이 수치만으로 로깅 비용을 산정할 수 없다.

- 위 표의 F는 모든 PL061 및 예외를, R은 pl061_read만 빼고 같은 나머지를 수집한다. QEMU 6.2 바이너리와 설치 사건 카탈로그·필터 확장·백엔드 해시를 고정한다. reset, write, set_output, update, input_change, update_istate 및 IRQ/SVC/ERET를 유지한다. 게스트 자체의 읽기와 쓰기 전후 제한된 표본은 동일하다. R의 독립 읽기 목록·값은 미관측이다.
- 원래 RM/DM × A1/A2 OFF ELF 네 개를 빌드 색인으로 확인하고 같은 바이너리로 각 F→R/R→F 두 쌍, 최초 실행 16회를 사전 고정한다. 인접 구성의 시작 순서를 교차한다. 기본 시계, 한 코어, 원 옵션·메모리·CPU 배치·호스트/도구·Linux 저장소·버퍼·감시 비용을 맞춘다. 실행당 10초, 직렬·새 디렉터리·대체 실행 없음이다. 유한 저장 한도와 잔여 용량, 유실·절단을 확인하고 원본 UART/기전 로그/실행 명세/표준 오류·호스트 감지/종료 시각과 해시를 남긴다. R은 실행 시 필터링하며 사후 삭제로 대체하지 않는다.
- 양쪽 모두 부팅 전부터 같은 실시간 증분 감시를 사용해 분할된 줄을 조립한다. bit0을 대상으로 한 마스킹 데이터 별칭에 ON 쓰기, 실제 “setting output 0 to 1”, 출력이 활성인 high 갱신, F의 high 읽기, 게스트 차단 경보 중 하나라도 관측하면 즉시 QEMU를 멈추고 나머지 실행을 중단한다. 첫 원본 줄·장치·시각과 사용 가능한 게스트 독립 OFF 처리 구간을 남긴다. 종료한 에뮬레이터의 사후 읽기를 추정하지 않는다. 부팅/마지막 OFF만으로 중간 ON을 지우지 않는다. 감시 손실·리셋/방향 누락·장치 귀속 불명은 미입증이다. ON 실제 주입 없이 합성/보관 스트림으로 분할 줄·별칭 ON·단순 방향 쓰기·리셋/순서·ERET/종료 누락과 R 읽기 생략을 대조한다.
- 실제 예외 순서·ELF PC·작업·프레임을 게스트 기록에 연결하고 IRQ 지연은 위상 인덱스 대신 이전 행 2 절대 비교와 행 3 진입을 쓴다. 게스트 쓰기 순번·전후 readback·시작/끝·가상 행 84를 장치 쓰기/단자 사건과 대조한다. QEMU 로그에는 게스트 카운터 시각이 없으므로 실제 전이 틱·전기적 연속 OFF·교차 스트림 지연은 미입증이다. R은 외부 읽기 값을 검증할 수 없다.
- 첫 비교→IRQ→선택/복귀→판정→과금 및 첫 차단, 이후 도달한 단계와 미실행 기회를 따로 기록한다. 발행·수면·깨움·전달·명령을 실제로 관측한 경우만 짝별 R−F 차이를 산출한다. 제어 250 µs·송신 750 µs, 0.5/1/5/10 ms 및 진단 가드 250/25/50/15/50/25 µs를 유지한다. 62.5 MHz에서 625000/937500틱의 실제 단일 시각 증거를 요구한다. 이 시험은 OFF 전용이며 수용·재무장·제품 성능 판정이 없다. 두 팔이 같은 지점에서 실패하면 가장 큰 실측 콜드 구간을 별도 소스 변경 대상으로 삼는다. 결과 차이가 나더라도 호스트 부하와 저장소 효과를 통제하기 전에는 로그량·동일 스케줄·호스트 경과만으로 인과를 결론내리지 않는다.
