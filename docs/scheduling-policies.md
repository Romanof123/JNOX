# 스케줄링 정책과 출시 검증 기준

[English](scheduling-policies.en.md) · [계열별 출시 사례와 남은 검증](scheduling-release-cases.md)

J-NOX는 프로파일마다 다음 스레드를 고르는 규칙, 선점 시점, 실행 가능한 CPU, 사용할 수 있는 CPU 시간을 정한다. 예를 들어 제어 프로파일은 스레드를 한 CPU에 고정하고 주기로 우선순위를 정한 뒤, 동순위에서는 FIFO를 적용하고 공유 뮤텍스에는 우선순위 상한을 둘 수 있다. 확장 프로파일은 서비스 그룹에 CPU 시간을 예약하고 그 안에서 가중치에 따라 스레드를 실행할 수 있다. 실제로 조합한 구성마다 검증 기록을 남긴다.

`CHG-005`의 제품 범위는 `OBJ-004 → REQ-023 → DES-012 → VER-023`으로 추적한다. 시간·격리 요건은 `REQ-002 → DES-003 → VER-002`, 스레드 동작은 `REQ-005 → DES-003 → VER-005`와 함께 확인한다. `POL` ID는 계열을 가리킨다. 결과에는 시험한 세부 정책, 검증한 계층, CPU 수와 구성을 적는다. [요구사항](requirements.md) · [아키텍처](architecture.md) · [검증 계획](verification-plan.md)

QEMU `virt`에서 기능을 여러 개 켜면 한 부팅에 한 검증 프로필만 실행한다. 현재 선택 순서는 `coop → batch → deadline → aperiodic → smp → mutex → multilevel → amc → proportional → vruntime → eevdf → hierarchy → power → extension → partition → cbs → periodic-preempt → periodic → rr → priority-resume → periodic-overrun → cbs-wake → fifo → edf → scheduler → boot`이다. 특정 정책을 검증하려면 해당 벤치 기능만 지정하고 같은 이름의 관찰기를 사용한다.

하드 CBS는 이상적인 단일 코어의 독립 서버에 대해 주기당 예산 비율의 합을 검사한다. 서버는 정수 틱, 주기와 같은 기한과 미완료 작업 최대 하나를 전제한다. 기약분수로 줄인 중간 합도 정수 표현 범위를 넘으면 보수적으로 거부한다. 스트라이드 후보는 길이가 같은 할당량을 배정한다. MLFQ는 양보 전후 실행량을 세 단계에서 누적하고 호출자가 요청할 때 우선순위를 올린다. 복권 후보는 추첨값을 입력으로 받는다. 가상 실행시간과 EEVDF는 이미 가상 시간축에 배치된 요청들의 스냅샷에서 다음 대상을 고른다. 위 단일 코어 프로파일에서는 실제 수면·깨움과 타이머에 의한 디스패치를 검증했다. 코어 간 이동은 별도 통합 검증 대상이다. [시간 정책](../kernel/src/temporal_policy.rs) · [예약과 스트라이드](../kernel/src/service_policy.rs) · [피드백과 추첨](../kernel/src/feedback_policy.rs) · [공정 배분 선택](../kernel/src/fair_policy.rs)

표의 마일스톤은 통합 또는 출시 목표다. M1은 단일 코어의 기반 기법, M2는 서비스 부하와 시간 격리, M3는 SMP와 실보드 측정, M4는 확장형 범용 서비스를 다룬다. M5에서 동결한 안전 구성을 심사하고 M6에서 추가 포트에 해당하는 시험을 반복한다. M4 정책도 M1에서 선택 함수 일부를 먼저 검증할 수 있다. [제품 단계](product-plan.md) · [정책별 출시 추적](https://github.com/Romanof123/JNOX/issues/21)

| POL-002 · 고정 우선순위(FP), FIFO, RR | 준비된 스레드 중 최고 우선순위를 고른다. 비선점 FP는 다음 전환점까지 기다리고 선점형 FP는 실행 중인 하위 스레드를 중단할 수 있다. 동순위에서는 FIFO 또는 시간 할당량 만료 시 교대하는 RR을 적용한다. 우선순위가 한 단계면 일반 RR이다. M1 선택 후보, M4 배치 서비스. | 4단위가 남은 작업을 실행할 때 2단위짜리가 도착하면 SRTF는 교대하고 SJF는 기존 작업을 계속한다. HRRN은 10단위 기다린 5단위짜리를 방금 온 1단위짜리보다 먼저 고른다. 동률, 잘못된 추정값, 과소 추정한 긴 작업도 시험한다. [EVD-091](evidence/evd-091.md) |
| POL-004 · 주기 단조(RM), 기한 단조(DM) | RM은 짧은 주기, DM은 짧은 상대 기한에 높은 고정 우선순위를 준다. M1 주기 작업 실행 순서·호스트 분석, M3 주기 제어. | A와 B의 (주기, 상대 기한)을 각각 (10, 9), (12, 4)로 놓고 동시에 준비시킨다. RM은 A, DM은 B를 골라야 한다. 후속 주기와 기한 위반을 시험하고 수용한 태스크 집합의 차단 시간, 지터, IRQ, 디스패치 비용을 응답시간 분석에 포함한다. | POL-005 · EDF, LLF | 최단 기한 우선(EDF)은 개별 작업의 절대 기한이 가장 이른 순서로 실행한다. 최소 여유시간 우선(LLF)은 `절대 기한 − 현재 시각 − 남은 실행량`이 가장 작은 작업을 고른다. M1 선택 후보, M3 실행량에 상한이 있는 실시간 구성. | 시각 0에서 (절대 기한, 잔여 실행량)이 (8, 1), (10, 8)이면 EDF는 첫째, LLF는 둘째를 고른다. 실행 중 더 이른 기한 도착, 최저 여유시간 작업의 변경, 동률, 음의 여유시간을 시험한다. 재평가 간격을 정하고 전환 빈도의 상한을 확인한다.  일반 작업 8개 이미지의 선점·복귀, 소진 뒤 서비스와 기한 내 완료. | POL-006 · 주기 실행기, 정적 시간표, 시간 파티션 | 주기 실행기는 반복 프레임 안에서 미리 정한 작업을 호출한다. 시간 파티션은 주 프레임의 실행 구간을 도메인에 할당하고 도메인 내부에는 별도 정책을 적용할 수 있다. M1 정적 구간 선택 후보, M2 통합, M3 실보드. | POL-007 · 폴링·이연·산발 서버 | 폴링 서버는 조회 시 대기가 없으면 남은 용량을 잃을 수 있다. 이연 서버는 같은 주기 안에서 미사용 예산을 보존한다. 산발 서버는 사용량과 해당 서버의 보충 규칙에 따라 보충을 예약한다. M1 후보는 폴링·이연 서버의 실행 허용량과 보충 큐 길이를 제한한 산발 서버의 허용량을 계산한다. | POL-008 · CPU 예약, EDF와 일정 대역폭 서버(CBS) | 주기별 상한 예약은 실행량을 차감하고 주기 경계에서 예산을 복원한다. 하드 CBS는 서버의 스케줄링 기한에 따라 적격 서버를 고르고, 소진 시 실행을 제한하며 기한·예산 갱신을 제어한다. M1에서 두 서버의 수용 판정, 예산 회계와 하드웨어 타이머로 구분한 다섯 슬롯을 확인했다. M2 통합, M3 실보드. | 마지막 단위를 소진한 뒤 다시 실행을 요청하고 정확한 보충 시각을 본다. CBS는 일찍·늦게 깨어날 때의 기한 갱신, 경합 시 적격 서버 우선순위를 확인한다. 프로파일 출시 시 수용 불가능한 부하를 거부하고 초과 실행한 클라이언트가 이웃 예약량을 소비할 수 없는지 본다. [하드 CBS 깨우기와 기한 갱신](m2-cbs-wake.md) |

| POL-014 · 우선순위 상속·상한 프로토콜 | 상속은 대기 스레드의 유효 우선순위를 잠금 소유자에게 전파한다. 상한 프로토콜은 자원별로 선언한 우선순위 상한을 사용한다. 즉시 상한 등 적용할 변형과 중첩 한도를 고정한다. M1 후보는 대기자와 소유자의 관계 및 보유한 잠금의 상한으로 유효 우선순위를 계산하고, 연쇄 상속을 반영하며 순환 대기를 거부한다. M1 통합에서 실제 뮤텍스 대기·깨우기·해제를 연결하고 M3에서 실보드 차단 시간을 분석한다. | MEDIUM이 준비된 상태에서 LOW가 잡고 있는 잠금을 HIGH가 기다리게 한다. 상속, 연쇄 상속, 시간 초과·해제 후 복원을 확인한다. 즉시 상한 구성에서는 HIGH가 대기하기 전 잠금 획득 시 우선순위 상승, 중첩 해제, 잘못된 구성 거부를 확인한다. |
| POL-015 · 혼합 중요도, 적응형 혼합 중요도(AMC) | 중요도 모드마다 실행 예산과 초과 후 계속 실행할 수 있는 작업을 정한다. M1 후보는 두 모드(LO·HI)의 예산에 따라 실행을 허용하고 지정한 초과 조건에서 LO에서 HI로 전환한다. 작업이 없는 상태에서 승인을 받아야 모드를 초기화할 수 있다. M3에서 실제 태스크 실행과 타이머에 의한 예산 집행을 연결하고 M5에서 시스템 대응을 심사한다. | 중요도가 높은 작업을 하위 모드 예산의 경계까지 실행한 뒤 초과시킨다. 모드 전환, 낮은 중요도 작업에 대한 조치, 상위 모드의 기한, 규정한 재시작·복귀 조건을 확인한다. 앞선 모드에서 넘어온 작업량을 최대로 두고 전환 구간을 검증한다. |
| POL-016 · 계층형 스케줄링 | 상위 정책은 그룹이나 도메인에 시간을 배정한다. 하위 정책은 상위 할당량 내에서 적격 스레드를 고른다. M1 후보는 그룹과 자식의 예산을 모두 적용해 실행 허용량을 제한하고 두 단계에 각각 차감한다. M2에서 실행 중 시간 격리를 적용하고 M4에서 중첩 서비스 그룹을 통합한다. | 하위 그룹 둘을 포화시키고 상위 그룹을 먼저 소진시킨다. 보충 전까지 두 하위 그룹이 실행되지 않고 다른 상위 그룹은 할당량을 받는지 본다. 중첩 깨우기, 빈 그룹, 해당 계층마다 한 번씩 차감하는지 시험한다. 그룹 수와 깊이에 상한을 둔다. [EVD-092](evidence/evd-092.md) |
| POL-017 · 에너지·기한 인식형 배치 | 실보드에서 측정한 처리 능력, 전력, 기상 지연을 이용해 허용 코어·주파수·유휴 상태를 비교한다. 프로파일의 기한 여유를 지키는 선택을 허용한다. M1 후보는 입력으로 주어진 동작점 표에서 기한을 충족하는 선택지 중 모델상 에너지가 가장 적은 항목을 고른다. M3에서 보드로 표를 보정하고 실제 전환을 측정한다. M4에서 선택형 전력 구성을 통합한다. | 같은 부하를 허용한 동작점마다 반복한다. 발열로 인한 성능 제한과 공유 부하에서 에너지, 기한 위반, 기상 지연, 응답시간 여유를 측정한다. 모델이나 필요한 처리 용량을 사용할 수 없을 때 규정한 대체 동작을 시험한다. |
| POL-018 · 확장형 정책 | 선택형 확장 프로파일에서 위임받은 작업에 실행량이 제한된 정책을 적용한다. CPU 마스크, 예약과 대체 정책 권한은 커널이 가진다. M1 후보는 미리 컴파일한 정책이 데이터로 제시한 선택을 검사하고 필요한 경우 대체 선택을 적용한다. 정책의 실행량과 진척을 감시하는 선택형 실행 환경은 M4 시제품으로 검증하고 채택을 판단한다. | 유효한 선택, 허용 범위 밖 CPU, 만료된 스레드 ID, 과도한 계산, 진척이 없는 정책을 시험한다. 문제 감지와 정해진 한도 내의 대체 정책 전환, 독립 예약 작업의 지속을 확인한다. [EVD-093](evidence/evd-093.md) |

## 자원 비용, 시간 검증과 안전 구성 심사

- **최소 단일 코어 구성.** 구성 명세에 정책, 선점 지점, 동률 처리, IRQ 시간의 귀속, 스레드·큐·타이머의 최대 개수를 적는다. 선택 기능을 켰을 때와 껐을 때의 이미지 크기, 정적 RAM, 스택 최대 사용량, 디스패치·회계의 최장 관측 시간을 비교한다. 타이머 주파수·해상도와 산술 표현 한계도 기록한다. [풋프린트 요구사항](requirements.md)
- **확장·SMP 구성.** 활성화한 조합의 CPU별 큐, 이동·프로세서 간 인터럽트(IPI) 비용, 스레드별 회계 상태, 그룹 깊이, 공유 잠금, 추적 비용과 유휴 상태 기상 비용을 기록한다. 큐 포화, 동시 준비, 반복 차단, 늦거나 중복된 타이머 이벤트와 표현 한계 부근의 산술을 시험한다. 태스크 집합, 기댓값, 빌드와 원시 관측값을 보관한다. [플랫폼 프로파일](platform-capabilities.md)
- **틱리스 동작.** RR 벤치는 최초 스레드 깨우기와 동순위 스레드의 시간 할당량 만료에 일회성 인터럽트를 설정한다. 계획된 틱리스 프로파일에서는 예산 보충과 파티션 경계도 예약해야 한다. 같은 정책·부하로 주기 틱과 틱리스 구현을 비교한다. 더 이른 이벤트 삽입, 취소, 동시 만료, 긴 유휴와 기상을 확인하고 해상도, IRQ 부하와 관측한 최장 전달 지연을 기록한다.
- **안전 구성 후보.** ASIL D 안전 목표를 지원하려는 제품은 정책 조합, 태스크 주기·기한, 실행시간 상한, 차단, IRQ·공유 자원의 간섭, 과부하 조치와 하드웨어를 고정한다. 허용 최악 부하와 유도한 예산 초과에서 실보드 동작을 분석과 대조한다. 관측 최댓값과 근거가 있는 분석 상한을 따로 기록한다. M5 독립 심사의 범위는 명시한 사용 사례·빌드·보드다. [안전 개념](safety-security-concept.md) · [검증과 근거](verification-plan.md)
