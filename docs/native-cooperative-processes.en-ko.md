# Cooperative scheduling for ordinary native applications / 일반 네이티브 앱의 협력형 스케줄링

[#291](https://github.com/Romanof123/JNOX/issues/291) · CHG-114. IMP-114 and EVD-114 are reserved for implementation and observed results. 기준은 #290 소스 446b5d57이며 구현 및 실행 검증은 후속 작업이다.

On main ee0249c4 and the #290 branch, the ordinary packager selects one C source or one linked ELF. On #290 a future sleep saves the sole process and enters idle. Exit parks the system. Neither native SDK exports yield. The user-visible change is that two independently built applications can share CPU0, voluntarily hand it over, and complete independently while retaining private memory.

현재 일반 패키저는 앱 하나만 받으며 #290의 미래 기한 대기는 CPU를 유휴 상태로 보낸다. 두 앱을 독립적으로 빌드해 같은 부팅 이미지에 넣고, 한 앱이 대기하거나 종료해도 다른 앱이 실행되도록 한다.

1. Extend tools/build_native_el0.py and kernel/build.rs to accept an optional independently linked peer ELF for the ordinary process selector. Snapshot, hash and validate each image through the existing packaging and load paths before starting either one. Retain existing single-input and startup-probe entry points. 시작 전 두 ELF를 각각 검증하고 각 앱의 진입 주소와 초기 스택을 구성한다.
2. Make process identity own the complete exception frame, private stack, address-space root and runnable, blocked or exited state. Adapt the install, switch and active-process user-copy primitives from #178 (663b598e, kernel/src/native_process_mmu.rs) and its full-frame restore. Omit the monitor completion mapping from ordinary spaces. Keep CPU0 kernel mappings accessible across switches and honor translation invalidation or ASID discipline. Each app may use identical virtual addresses for different private data. 프로세스별 문맥과 페이지 테이블을 복원하고 사용자 메모리 복사는 호출자의 주소 공간에서 수행한다.
3. Use kernel/src/ready_queue.rs for stable FIFO selection among equal peers. At yield, put the current process behind waiting peers and return zero when it resumes. With no ready peer, return zero immediately. A future absolute sleep blocks only its caller and selects a ready peer. Program the earliest pending deadline, wake due sleepers once, and rearm for the next. Handle timer delivery from EL0 as well as idle. Waking joins the ready queue under cooperative scheduling. Exit saves the app's status and dispatches the next ready app. Idle when only sleepers remain and finish after the last exit. 양보·대기·종료는 같은 디스패처를 거친다. 대기 중에는 준비된 앱이 일하며 타이머가 만료된 앱은 다음 협력형 선택에 참여한다.
4. Expose C int sched_yield(void) in <sched.h> and safe no_std Rust yield_now() with native error propagation. Use native-v1 SVC 0x4a01 with x8=8 (JNOX_CALL_SCHED_YIELD), no arguments and result 0 on success, including a yield by the only runnable caller. Keep capabilities of #219's weighted/partition selectors scoped to those profiles. C와 Rust 모두 동일한 커널 서비스를 사용하며 기존 가중치·파티션 모니터의 역할이나 공유 주소에 의존하지 않는다.

For normal boot acceptance, package ordinary C and Rust applications with separate private writable globals at matching virtual addresses. Collect process-attributed dispatch and exit statuses plus values computed by each app. Observe handoff to an already-ready peer and return to the caller; observe useful peer work between a future sleep and the sleeper's resumption; observe a surviving app yielding alone after peer exit. Preserve existing startup, single-app clock/sleep and unsupported-service controls. Use ordering and the caller's deadline for these claims. #178 and #219 retain their independent dispositions.

일반 부팅에서 각 앱의 계산 결과와 종료 상태를 확인한다. 준비된 동료에게 양보한 뒤 원래 호출로 복귀하고, 한 앱이 잠든 사이 다른 앱의 계산이 진행되며, 동료 종료 뒤 단독 양보가 성공해야 한다. 기존 단일 앱과 미지원 호출 동작도 유지한다.
