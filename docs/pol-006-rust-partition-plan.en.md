Each table uses the same two ordinary Rust task bodies on private EL1 stacks. A continuously updates a wrapping integer accumulator and iteration count with IRQ enabled and no yield. B starts blocked, becomes ready at entry to the first explicit idle slot, then stays runnable, updating a different deterministic accumulator. Idle has its own context. Preserve each task’s private state across preemption. At window close suspend unfinished work and carry its context into its next owned runnable interval. No borrowing, donation or work in an explicit idle slot. A blocked owner selects idle; in this fixture release during explicit idle changes readiness only. In P the first B window is blocked; in Q the opening B window is blocked. Compare actual progress and saved/resumed stack, registers and PC at preemption against the ELF and return trace.

## Timing contract and recovery

At E+k·frame+offset use an absolute compare. Independently reconstruct nominal owner on the raw counter, including boundary−1, boundary, boundary+1 and wrap. On an exact tie, apply readiness changes for that tick first, then select by the current half-open slot; explicit idle always wins. Reader must be able to distinguish programmed target d, actual IRQ entry i, outgoing task and interrupted PC, actual dispatch and return to the chosen context, and first independent in-context observation x. Use one monotonic counter for d,i,x, record frequency, bracket uncertainty and event order; calibrate any separate exception trace to these events. Normal acceptance requires d ≤ i ≤ x, x−d ≤ F/1000 (1 ms) including observation uncertainty, correct context/slot and positive attributed worker progress in each runnable window. At a same-owner boundary require an actual post-return observation. This bench-only envelope is 1/50 of the smallest slot and leaves 49 ms for work in the shortest nominal slot. It is a test target. Insufficient counter evidence, trace loss, ambiguous attribution or uncertainty crossing a limit yields no pass.

Time spent by a task past a boundary is charged to that outgoing task as measured spill, even when its IRQ is masked. Trace IRQ/dispatcher CPU separately; use conservative brackets for uncertain switch edges. Account idle, task execution, kernel service and transition uncertainty exactly once across elapsed intervals. At IRQ entry recompute the live window from E and current time. Before return recheck it, select idle for blocked/idle, and arm the next strictly future absolute boundary. Never extend, shift, repay or replay a missed window. Record every crossed boundary, skipped runnable interval and lost service. Intentional runnable work continuing throughout its own slot is legal; late execution into another owner’s slot is spill. With IRQ masked there is no software guarantee of immediate reclamation, and unbounded masking admits no finite switching bound. Detect a missed runnable window or bound violation as a timing failure even if recovery dispatch succeeds.
