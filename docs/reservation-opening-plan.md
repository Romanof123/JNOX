## Evidence / 관측 근거

Eight ordinary W/S cold boots stopped at slot 0. All first Rust generation markers missed 62,500 ticks (1 ms at 62.5 MHz); none witnessed B run or complete the manifest. Both R refusals succeeded before startup. The two late cases recorded post-boundary A progress and loss of B’s opportunity, but their first opening already failed. ## English decision

1. Stage a private, bounded **conditional transition** for slot 0 after successful admission and immutable epoch initialization while idle owns the CPU. Use the existing pure scheduling steps on a private copy of Jobs, the frozen manifest and a snapshot of the authoritative generation. Precompute policy arithmetic, candidate grant/after-state, deadline, expected action, checked goals/cutoff, and the already-created frame identity and bounds. This is a proposal only. Keep the frame in its live owner slot; neither pop a live ready queue nor take its frame, arm the operational cutoff, publish readiness, release a job, charge an entitlement or execute a client before the actual boundary. Do not predict counter timestamps. R cases still reject before timer, operational frames or preparation. Keep the original E (set before preparation), first timer compare, release targets and slot horizon; measure setup start/end and actual time remaining to E. No epoch reset to hide late setup.
2. At a genuine boundary IRQ validate actual monotonic t≥nominal opening, current timer source/kind/compare and lateness, sole idle owner, slot/epoch, generation, current saved-frame identity/range, no outstanding grant, blocked/exited state and both clients’ observed progress against their last trap. Keep checks of saved register/PC and ledger arithmetic. With IRQ serialization, publish the already-validated transition exactly once and record the **actual** commit, verified releases/q/d and frame transfer. Only now update GOAL/ACTION/generation, debit one entitlement, arm the original absolute cutoff with readback, and restore the actual chosen context. Emit actual first worker sample unchanged. On stale input discard the proposal; a single ordinary synchronous decision on the current state may proceed only within the original time checks. Otherwise fail visibly. No duplicate release/debit, retrospective log time, retries or calling worker code early. Trace overflow or an ambiguous return is unqualified.
3. First isolate slot-0 preparation; use v1’s synchronous path at all later openings. A later, separately identified extension may prepare the next slot only in genuine idle time after the current grant closes, accounting that CPU and remaining interval. Invalidate the prepared transition on any SVC block/exit, frame return/change, ownership or ledger generation change; revalidate actual post-trap state and progress at commit. A candidate planned before a block or exit cannot resurrect a client. Compare independent q/d, wake release, real SVC/ERET and neighbor positive progress throughout W/S. No multi-slot speculative queue advancement or banked charge.
4. Capture full boot-to-first-worker and setup→E intervals, IRQ→commit, commit→arm/return, nominal→actual Rust marker and every later slot. Tag optional internal probes separately; keep both arms’ essential accounting, original 1 ms limits and first-attempt procedures. Conservative service upper = actual trap sample − actual pre-ERET sample; retain per-allocation cumulative charge and account setup/IRQ/idle separately. A shorter handler with greater startup latency or lost idle capacity must report both deltas. Specify a static per-slot storage/time bound before use; no admission or WCET inference from the eight observed maxima.
5. Fix source/ELF and default-clock native Linux capture paths. Compare archived-equivalent baseline and candidate with the eight normal W/S traced/plain cases and both pre-start R refusals per source (10 each) for the first iteration, using counterbalanced pair order and no first-launch exclusions. Confirm frozen v1 executable identity or keep rebuilt baseline a separate cohort. Retain all 12 v1 records. A new live late diagnostic belongs to a separate rollout step after the healthy opening is addressed; it is not an entry or completion condition for the W/S code iteration. Full-profile late qualification remains open. [First cohort](evidence/evd-053-v1.en.md) · [Canonical evidence](evidence/evd-053.en.md). In late cases preserve row 14 end/actual-stop/lost-B/excess (125763 and 125757 ticks in v1), rows 16/20 and committed counts, even when status 2/reason 2 reports the earlier marker miss. Do not relabel the first cause; distinguish earlier fail, independently witnessed spill, and a clean injected failure after a timely dispatch. Verify the cutoff target at nominal end−1 ms, real post-end progression, checked outgoing charge and subsequent inhibition. Negative controls include stale generation, frame ownership swap, duplicate commit, still-blocked/exited client, candidate ready after E, one tick beyond the opening bound and an absent return. Full qualification requires all original criteria and independent replay. Product guarantees remain open.

## 한국어 결정

1. 수용 후 원래 E를 정하고 유휴 문맥에서 **0번 슬롯만 조건부 준비**한다. 고정 명세와 권위 상태 세대, Jobs 복사본으로 정책 연산·후보 q/d·작업·목표·컷오프·기존 프레임 신원과 범위를 미리 계산한다. 실제 큐·프레임·준비 상태·차감·타이머·작업에는 손대지 않는다. 거부 사례는 준비 전 종료한다. E와 첫 비교 타깃을 고정하고 준비 전후 실제 시각 및 남은 여유를 기록한다.
2. 실제 경계 IRQ에서 시각·타이머·지연·유휴 소유자·슬롯·세대·프레임·차단/종료·양 작업 진행·미완료 할당을 검증한다. IRQ 직렬화 하에서 조건이 맞을 때만 권위 상태와 실제 프레임 인계를 한 번 커밋하고, 실제 시각으로 릴리스·차감·컷오프 및 레지스터 되읽기를 남긴다. 기존 첫 Rust 표식을 유지한다. 무효 후보는 버리고 기존 시간 검사를 지킬 수 있을 때만 동기식 실제 상태 판정을 한 번 수행한다. 사전 릴리스·워밍업·소급 시각·이중 차감·재시도는 허용하지 않는다.
3. 첫 변경은 이후 슬롯을 v1 동기 경로로 유지한다. 별도 후속 버전에서만 직전 할당 종료 뒤 진짜 유휴 시간에 준비할 수 있다. SVC 차단·종료, 프레임·원장·소유자 변경은 세대를 무효화한다. 실제 경계에서 다시 검사하고 종료 작업을 재개시키지 않는다. 전체 W/S에서 독립 q/d·SVC/ERET·이웃 작업 진행을 확인한다.
4. 부팅부터 첫 작업, 준비 구간과 E 여유, IRQ부터 커밋·복귀, 명목 경계부터 실제 작업 표식과 이후 슬롯을 계측한다. 원래 1 ms를 유지한다. 실행량 상한은 실제 트랩 표본−ERET 전 표본이며 할당별 누적과 부팅·IRQ·유휴 이동 비용을 분리한다. 초기화 비용이나 유휴 손실이 늘면 함께 기록한다.
5. 첫 수정은 기준·후보별 정상 W/S 일반·추적 8회와 타이머 설정 전 R 거부 2회씩 총 10회를 기본 시계·Linux 저장소에서 순서를 교차한다. v1 최초 12건과 ELF 신원을 그대로 보존한다. 추가 라이브 지연 진단은 정상 개방 수정 뒤의 별도 단계다. W/S 소스 수정의 착수·완료 조건에 포함되지 않으며 전체 프로파일의 지연 판정은 미완료다. [최초 실행](evidence/evd-053-v1.md) · [증거 색인](evidence/evd-053.md). 지연 2건은 선행 2/2 개방 실패와 별도로 실제 A 진행 및 B 기회 손실 125763·125757틱을 14/16/20과 함께 유지한다. 제때 열린 뒤 주입한 실패와 구별한다. 세대 무효·소유자 교환·중복 커밋·차단/종료 작업·준비 지연·1틱 초과·복귀 누락을 대조한다. 원래 모든 기준의 독립 통과 전 전체 프로파일 또는 제품 보장은 미확정이다.

## IMP-053 conditional opening candidate / 조건부 시작 구현 후보

Ordinary W/S builds execute one bounded preparation in the initial idle frame. Boot fixes E, initializes the two worker frames and arms the original opening compare. Idle masks IRQs while preparing one private Jobs transition (two clients, one EDF arbitration), one frame identity per client, one checked goal and the original absolute cutoff. No client frame is removed before the genuine boundary. Finishing setup at or after E stops the run. One outstanding candidate is statically reserved; its construction and copying are charged to the measured idle/setup and IRQ paths. There is no measured WCET claim.

The live Jobs slot counter is the opening generation: every successful opening advances it, and a trap requires a previous grant. Only the unreleased zero-demand ledger at generation zero can publish the matching manifest/policy transition. The real IRQ checks the physical comparator, timer status and idle frame, both original client frame addresses and CPU state, pristine published progress, ledgers, release generation and action/goal, and the measured time before and after commit. Any stale candidate, inconsistent state or missed boundary fails visibly. Later slots use ordinary synchronous arbitration. R rejects before preparation. The v1 diagnostic retains synchronous first arbitration. Its earlier opening failure and its measured spill remain separate results; it supplies no qualified revised-opening fault observation.

Raw row 24 timestamp is sampled after admission, with fields (first runtime counter sample, E, 0, 0). Row 22 is sampled after idle has stored the candidate, with fields (setup start, E, nonnegative remaining ticks, 0). The mask set and return from preparation extend outside that inner bracket. Row 23 is sampled just after authoritative publication, with fields (actual vector entry, pre-publication sample, E, new generation). It precedes the ordinary 5/6 state records, cutoff arm/readback and 7/10/12 selection, worker and return records. Report the complete boot-sample-to-first-worker interval and setup/IRQ subintervals, keeping their unknown edges. Excess, wrap, or a missing return remains unqualified. No performance result is attached.

일반 W/S 이미지는 부팅에서 E와 최초 타이머 목표를 고정한 뒤 최초 유휴 프레임에서 한 번만 준비한다. IRQ를 마스킹한 동안 두 클라이언트·한 번의 EDF 판정을 대상으로 비공개 원장 전이, 프레임 신원, 목표와 절대 컷오프를 계산한다. 준비 완료가 E 이상이면 중단한다. 실제 경계 IRQ가 비교값, 유휴 복귀, 두 프레임과 작업 진행·원장·세대·시간을 대조한 뒤에만 한 번 커밋한다. 최초 세대는 슬롯 카운터 0이다. 후속 슬롯은 동기 판정하며 R은 준비 전에 거부한다. 기존 지연 진단의 첫 디스패치는 동기식이다. 해당 진단의 이전 지연·초과 실행으로 수정된 최초 경계의 결함 시험을 통과했다고 판정할 수 없다.

24행은 수용 뒤 표본이며 필드는 최초 런타임 표본·E·0·0이다. 22행은 준비 완료 표본이며 필드는 준비 시작·E·남은 틱·0이다. 마스킹 시작과 함수 복귀는 이 구간 밖이다. 23행은 실제 원장 커밋 직후 표본이며 필드는 실제 IRQ 진입·커밋 직전·E·새 세대이다. 기존 작업·상태, 컷오프와 복귀 표본도 유지한다. 최초 표본부터 실제 작업 표식까지의 전체 경과와 유휴·커널 이동 비용을 함께 기록한다. 후보의 실행 결과와 WCET 검증은 미결이다.
