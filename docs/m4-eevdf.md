# EEVDF 실행 요청과 가중치 변경, 두 차례의 깨우기

[English](m4-eevdf.en.md) · [변경 이슈 #56](https://github.com/Romanof123/JNOX/issues/56)

CHG-025 · POL-012 · REQ-002/005/023 → DES-003/012 → IMP-023 → VER-002/005/023. 검증 기록 번호는 EVD-023으로 예정되어 있다. 아래 표는 Cortex-A72 가상 CPU 한 개와 GICv2, 비보안 EL1 물리 타이머를 쓰는 시험의 기대값이다. 깨우기부터 작업 코드 복귀까지의 실제 카운터 값은 게스트에서 수집한다.

## 유한 텔레메트리 배포 실행

Linux 또는 WSL의 저장소 루트에서 실행한다. Python 3와 pyelftools, Cargo, 커널이 지정한 Rust 도구 체인과 `aarch64-unknown-none` 타깃, `qemu-system-aarch64`, AArch64 GNU binutils의 `aarch64-linux-gnu-nm`과 `aarch64-linux-gnu-objdump`가 필요하다. 새 출력 디렉터리를 지정하면 잠금 파일 기준으로 릴리스 이미지를 빌드하고 기본 시계의 QEMU virt/GICv2에서 Cortex-A72 한 개, RAM 128 MiB로 한 번 부팅한다.

~~~sh
python3 tools/eevdf_telemetry.py run --out first-run
~~~

출력된 세션 SHA-256을 별도로 보관한다. 오프라인 재생 시 아래 DIGEST 자리에 그 값을 넣고 같은 실행 디렉터리를 지정한다. 재생은 빌드나 부팅 없이 보관한 원본을 확인한다.

~~~sh
python3 tools/eevdf_telemetry.py replay --run first-run --session-sha256 DIGEST
~~~

`first-run/build.json`과 `build.log`에서 빌드 정보를 확인한다. `first-run/capture/`에는 UART 원본 `uart.bin`, RAM 저널 `journal.bin`, 예외·복귀 기록 `exceptions.log`, ELF, 심볼, 역어셈블리, `session.json`이 있다. 실행 디렉터리 바로 아래에는 `session.sha256`과 `result.json`이 있다. 엄격 재생은 두 배치 작업 각각의 처리 개수·합·가중합, 소비자의 최종 값 `(2,128,27028,115128)`, 서비스량 비교 15개와 기상 응답 8개를 대조한다. [텔레메트리 배포 기준](eevdf-telemetry-deployment.en-ko.md)

`QUALIFIED`는 통과로 종료값 0이다. 해시 불일치 등 검사 실패는 `INVALID`와 종료값 1, 필수 증거 누락은 `UNOBSERVED`와 종료값 2다. 세션 생성 전 빌드·도구·기동 오류는 `ERROR`와 종료값 1을 반환한다. 실패해도 부분 파일을 포함한 최초 디렉터리를 보관하고 이후 실행에는 다른 경로를 지정한다.

## 실행 자격과 요청 변경

작업의 가중치를 `w`, 가상 실행시간을 `n/w`라 한다. 스케줄러는 선택할 때마다 준비된 작업들의 값을 합산해 기준 가상 시간 `V = sum(n) / sum(w)`를 정확한 분수로 구한다. `n/w ≤ V`인 작업에 실행 자격이 있다. 이 중 가상 마감이 가장 이른 작업을 고르고, 마감이 같으면 작업 ID가 작은 쪽을 고른다. 시작 분자가 `s`, 요청량이 `q`이면 마감은 `(s+q)/w`다. 물리 실행량 한 단위를 사용하면 `n`이 1 증가한다. 요청을 일부만 실행하면 마감이 유지되고, 요청량을 모두 쓰면 기존 마감에서 새 요청이 시작된다. [선택 함수](../kernel/src/fair_policy.rs) · [실행 요청 정책](../kernel/src/eevdf_policy.rs)

요청 설정은 배정 사이에서 바꾼다. 슬라이스를 변경하면 현재 가상 실행시간에서 새 요청을 시작한다. 가중치를 `w`에서 `w′`로 바꿀 때 시작 분자는 `ceil(n + (w′−w) V)`다. 변경 전 V를 기준으로 작업이 받아야 할 실행량과 이미 받은 실행량의 차이를 보존하며, 분자를 올림하는 오차는 실행량 한 단위 미만이다. 잠든 작업을 깨우면 분자를 `max(n, ceil(w V))`에 두고 마감 분자도 같은 만큼 옮긴다. 남은 요청량은 그대로다. 모든 작업이 잠들면 마지막 작업이 잠들기 직전의 V를 다음 깨우기에 사용한다.

## 열두 번의 실행 배정

A, B, C의 ID는 각각 0, 1, 2다. 처음에는 세 작업 모두 가상 시간 0에서 준비 상태이며 가중치는 `[1,2,1]`, 슬라이스는 `[1,8,4]`다. 실행량 한 단위는 카운터 `Q = floor(CNTFRQ_EL0 / 100)`회에 해당한다. 매 배정마다 비교값을 한 번 설정하고 물리 타이머 IRQ에서 실행량을 정산한다. C가 두 번 수면을 요청하는 시스템 호출은 각각 정산이 끝난 뒤 타이머가 꺼진 구간에서 실행된다. [게스트](../kernel/src/eevdf.rs) · [작업 루프](../kernel/src/eevdf.S)

| 행 | 선택 직전 변화 | 준비 작업 | V | 작업 × 실행량 | 누적 실행량 오차 × 20 (A, B, C) |
|---:|---|---|---|---|---|
| 0 | 최초 배정 | ABC | 0/4 | A × 1 | 15, −10, −5 |
| 1 | A의 요청 갱신 | ABC | 1/4 | B × 1 | 10, 0, −10 |
| 2 | C의 슬라이스를 4에서 2로 변경 | ABC | 2/4 | C × 1 | 5, −10, 5 |
| 3 | C 수면. A의 (가중치, 슬라이스)를 (1,1)에서 (2,2)로 변경 | AB | 3/4 | B × 3 | −25, 20, 5 |
| 4 | C를 깨움. 남은 요청량은 1 | ABC | 8/5 | A × 2 | −1, 4, −3 |
| 5 | 가상 실행시간이 같고 A와 C의 마감도 같아 A를 선택 | ABC | 10/5 | A × 2 | 23, −12, −11 |
| 6 | C가 첫 수면에서 실행 재개 | ABC | 12/5 | C × 1 | 15, −20, 5 |
| 7 | C가 2단위 요청을 갱신한 뒤 다시 수면 | AB | 10/4 | B × 1 | 5, −10, 5 |
| 8 | C를 깨움. 기존 가상 실행시간 유지 | ABC | 14/5 | B × 1 | −3, 2, 1 |
| 9 | A와 B의 마감이 같아 A를 선택 | ABC | 15/5 | A × 2 | 21, −14, −7 |
| 10 | B가 최초 요청량 8을 모두 사용 | ABC | 17/5 | B × 2 | 5, 10, −15 |
| 11 | C가 두 번째 수면에서 실행 재개 | ABC | 19/5 | C × 1 | −3, 2, 1 |

1행에서 A의 마감은 2로 B와 C의 마감 4보다 이르다. 하지만 A의 가상 실행시간 1은 V인 1/4을 넘으므로 자격이 없다. B와 C 중 ID가 작은 B가 실행된다. 2행에서는 B의 가상 실행시간이 V인 1/2과 정확히 같고, C의 마감이 2로 앞당겨져 C가 실행된다. C가 잠든 뒤 V가 2/3일 때 A의 가중치를 바꾸면 시작 분자는 `ceil(1 + 2/3) = 2`다. C를 처음 깨우기 직전 V는 6/4이며 C의 (가상 실행시간, 마감)은 (1, 2)에서 (2, 3)으로 옮겨진다. 두 번째 깨우기 직전 V는 11/4이고 C는 (3, 5)를 유지한다.

각 배정에서 실행한 작업에 실제 실행량을 더하고, 준비된 각 작업의 잔액에서 `배정량 × 작업 가중치 / 준비 가중치 합`을 뺀다. 총 18단위 중 A는 7, B는 8, C는 3을 사용한다. 누적 오차의 절댓값은 최대 25/20단위이며 마지막 오차는 `[−3,2,1]/20`이다. 깨우기부터 C의 첫 배정까지 기다리는 실행량은 각각 4단위와 5단위다. 이 오차와 두 표본은 표의 부하에서 구한 값이다. 제품의 시간 한계와 실물 보드 응답은 별도 측정 대상이다.

## 공개 저널과 검증 기준

`eevdf_witness`는 리틀엔디언 64비트 워드 500개, 총 4,000바이트다. 행 번호와 필드 위치는 0부터 센다. 부호 있는 오차는 2의 보수로 저장한다.

| 레코드 | 레코드 안의 워드 위치와 의미 |
|---|---|
| 워드 0부터 헤더 8개 | 버전 1, 행 수 12, 수면 횟수 2, 응답 횟수 2, 카운터 주파수, Q, 총 실행량 18, 최대 절대 오차의 20배인 25. |
| 워드 8부터 12행, 행마다 39개 | 0–4는 작업 ID, 배정량, 준비 비트 마스크, V의 분자와 분모다. 5–16은 배정 직전 세 작업의 상태다. 17–23은 배정 카운터, 타이머 비교값, IRQ 카운터, 중단된 PC, 저장 프레임 주소, 복귀 PC, 작업 진행 카운터다. 24–35는 정산 직후 세 작업의 상태, 36–38은 부호 있는 누적 오차의 20배다. 작업 상태는 가상 실행시간 분자, 가상 마감 분자, 가중치, 남은 물리 실행량 순이다. |
| 워드 476부터 깨우기 기록 2개, 각각 12워드 | 0–3은 수면 직전 계산 행, SVC 카운터, SVC 복귀 PC, SVC 프레임이다. 4–7은 깨우기 직후 배정할 행 번호, 깨우기 카운터, 깨우기 직전 V의 분자와 분모다. 8–11은 C가 실행을 재개한 행, 그 배정까지의 누적 실행량, 복귀 직후 C가 읽은 카운터, 기다린 실행량이다. |

저널의 분자와 분모로 12회의 선택을 다시 계산한다. 같은 부팅의 예외 추적에서 PPI 30 IRQ 열두 건을 각 작업의 루프와 대조하고 두 `SVC #1`의 호출자가 C인지 확인한다. 실제 예외 복귀 명령(`ERET`)이 선택된 작업의 PC로 돌아가는지 추적한다. C는 두 번 모두 `ee_c_wake`로 돌아와 작업 코드에서 `CNTPCT_EL0`를 읽어야 한다. ELF로 작업별 프레임 주소와 진행 카운터의 증가도 확인한다. 각 행에서 `compare = start + Q × grant`, `compare ≤ IRQ < compare + Q`여야 한다. 각 복귀 행에서 `wake_at ≤ start ≤ first_work < compare`를 확인한다. 두 개의 `first_work − wake_at`을 카운터 틱으로 기록하고, 저널의 주파수로 시간으로 환산한다. 이 실측값과 스케줄링 대기량 4·5단위를 함께 보고한다.

호스트에서는 잘못된 ID와 설정값, 중복 깨우기·정산, 다른 작업에 대한 정산, 남은 요청량을 초과한 정산, 실행 중 설정 변경, 음수로 투영되는 시작점, 타임스탬프 범위 초과를 검사한다. 연산을 거부하면 기존 요청과 실행량이 보존되어야 한다. 선택된 작업이 다르거나 자격이 없을 때, 작업 진행이 멈췄을 때, SVC가 누락됐거나 복귀 PC가 맞지 않을 때는 해당 게스트 기록을 검증 근거로 쓸 수 없다. [분수 연산 호스트 검사](../tools/eevdf_tests.rs) · [표현 범위 검사](../kernel/src/eevdf_policy.rs)

## 재현

커널 도구 체인, QEMU, AArch64 binutils가 설치된 Linux에서 저장소 루트를 기준으로 실행한다. 첫 부팅을 새 디렉터리에 캡처한다. 래퍼는 실행 인자를 그대로 넘기며 예외 추적과 QMP 저널 덤프를 활성화한다. [실행기](../tools/qemu_boot.py) · [캡처 도구](../tools/eevdf_capture.py)

```sh
(cd kernel && cargo build --release --locked --features eevdf-bench -j1)
run_dir=$(mktemp -d)
export EEVDF_CAPTURE_DIR="$run_dir/capture"
cat > "$run_dir/qemu-eevdf" <<'SH'
#!/bin/sh
exec python3 -B tools/eevdf_capture.py "$@"
SH
chmod +x "$run_dir/qemu-eevdf"
python3 tools/qemu_boot.py --profile eevdf --runs 1 \
  --kernel kernel/target/aarch64-unknown-none/release/jnox-kernel \
  --qemu "$run_dir/qemu-eevdf"
```

소스·ELF 해시와 함께 같은 실행에서 나온 `launch.json`, `uart.bin`, `int.trace`, `audit.bin`, `qmp.json`, `exit.json`을 보존한다. 부팅 메시지 두 줄 뒤에 기대하는 EEVDF 메시지는 `BEGIN`, `EARLY INELIGIBLE`, `SLICE CHANGE`, `WEIGHT CHANGE`, `TWO WAKES`, `STOP`, `PASS` 순이다. 다시 실행하더라도 최초 캡처는 보존한다.

독립 가상 게스트 결과와 시험 이미지 식별자는 다음 기록에서 확인할 수 있다. [EVD-023](evidence/evd-023.md)
