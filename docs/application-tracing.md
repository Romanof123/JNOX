# J-NOX 애플리케이션 추적 계약

[English](application-tracing.en.md) · [#137](https://github.com/Romanof123/JNOX/issues/137) · CHG-060 · CAP-013 · DES-006 · 스키마 및 SDK ABI v1 제안

느린 요청을 조사할 때는 클라이언트의 요청 시점, 커널 수락, 서버 대기 원인, 드라이버 완료 및 클라이언트의 실제 재개를 구분할 수 있어야 한다. 이 설계는 앱의 명시적 표식과 OS가 자체 관측한 사건을 연결한다. 기존 프로파일별 캡처의 형식과 판정은 각각의 증거에 귀속된다.

## 사건과 인과관계

| 기록 주체 | 사건과 기록 위치 |
| --- | --- |
| Rust/C 앱 | BEGIN은 작업 인스턴스를 열고 END는 같은 인스턴스를 제한된 결과 코드로 닫는다. MARK는 상태 변화 없는 한 시점의 표식이다. TYPE은 수치 사건 ID와 필드 형식의 매니페스트 선언이다. 스레드 간 span 이전은 명시한다. |
| 스케줄러 | 스레드 생성·종료, 준비·차단(사유/객체)·깨움(원인), 디스패치 진입/이탈, 코어 이동을 기록한다. 깨움은 실행 자격 획득이며 실제 디스패치와 구분한다. 예외 복귀 전 표본은 실행 범위만 제시하며 앱 표식은 실제 진행을 증언할 수 있다. |
| 커널 IPC | 송신 시도, 큐 삽입 수락/거부, 꺼냄·전달, 응답 완료, 취소·시간초과·피어 종료를 권위 상태 전이 지점에서 기록한다. 실패한 시도에는 전달 연결을 만들지 않는다. |
| IRQ/드라이버 | 중첩 인스턴스별 IRQ 진입·복귀, 드라이버 요청·수락·실제 완료/오류 및 지연 작업 등록·시작·끝을 기록한다. 하드웨어 IRQ와 소프트웨어 완료를 구분하고 드라이버가 확인한 요청만 연결한다. |

세션·부팅 ID와 함께 프로세스/도메인·스레드·종단점·드라이버 객체·요청의 제한된 슬롯/ID 및 세대를 기록한다. 재시작과 슬롯·PID·핸들 재사용에는 새 세대를 준다. 이미지 인스턴스와 적재 매핑은 별도로 식별한다. 비트 폭을 명시하며 관측 보존 중 모호한 재사용 전에 세션을 분할하거나 불연속을 표시한다. CPU와 코어 내부 순번, 타입이 있는 트랜잭션/span ID·부모와 분기·인계·완료 연결을 쓴다. 다대일 배치도 지원한다. 신뢰 커널이 실제 생산자/도메인을 부여하고 범위 제한 상관 토큰을 생성·검증한다. 앱이 제공한 이름만으로 도메인 간 인과를 확정하지 않는다.

예를 들어 클라이언트가 X를 열고 R을 송신하면 커밋된 큐 항목으로 전달을 연결한다. 서버가 이미 실행 중이거나 여러 요청이 한 번에 깨워도 요청 식별을 보존한다. 확인할 수 없는 깨움 원인은 미상으로 남긴다. 서버 디스패치와 R 수신은 별개다. 서버가 드라이버 D를 보내고 차단된 뒤, 드라이버가 실제로 확인한 D만 완료 IRQ에 연결한다. 지연 처리, 서버 준비·재디스패치, 응답 삽입·전달, 클라이언트 깨움·디스패치·END(X)를 구분한다. 시간초과 뒤 늦은 장치 완료도 그대로 보존하고 가상의 응답을 추가하지 않는다. 큐 대기·준비 후 대기·처리를 각각 보이며 필터로 빠진 연결은 미상이다.

안전 IPC는 송신 게시, 수신 검증·수락/거부, 세대/순번과 제한된 이유 코드를 각각의 실제 전이에서 관측한다. 허가 승인, 신선도 갱신·재무장 소비·출력 제어는 기능 수신자의 책임이다. 추적기는 제어 권한이 없다. 거부는 해당 안전 시험의 독립 수신 상태·장치 관측으로 확인한다. 추적 누락은 제어 동작을 바꾸지 않으며 증거 판정을 제한한다. #21/#24의 IPC 구현 선행 조건을 유지한다. [IPC 계약](ipc-mechanisms.md) · [검증 계획](verification-plan.md)

### v1 최소 논리 사건 사전

다음 이름은 제안한 v1 사전에서 사건 의미를 고정한다. 모든 행에는 공통 헤더가 붙는다. `ref<K>`는 타입·세대가 있는 객체 참조, `type`은 허용된 u32 사전 키, `code`는 범위가 정해진 u16 열거형, `value`는 허용된 u64다. 아래 피연산자는 필수이며 명시된 경우에만 값 없음(none)을 허용한다.

| 사건 | 필수 피연산자 |
| --- | --- |
| APP.BEGIN / APP.END / APP.MARK | BEGIN은 span 참조·부모 span 참조 또는 none·type, END는 동일 span 참조·결과 code, MARK는 span 참조 또는 none·type·value를 갖는다. |
| IPC.ENQUEUE / IPC.DELIVER | 공통으로 메시지·종단점·요청 참조와 요청/응답 방향 code를 갖는다. ENQUEUE는 실제 커밋과 송신 스레드 참조를, DELIVER는 전달과 수신 스레드 참조를 기록한다. |
| THREAD.READY / THREAD.SWITCH | READY는 스레드 참조·원인 code·원천 사건 참조 또는 none, SWITCH는 나가는/들어오는 스레드 참조 또는 명시적 유휴를 갖는다. CPU는 헤더에 있다. 사건 참조는 세션/부팅·CPU·로컬 순번이다. |
| IRQ.ENTER / IRQ.EXIT | IRQ 선 번호 u32와 쌍을 이루는 같은 IRQ 인스턴스 참조를 갖는다. ENTER는 부모 IRQ 인스턴스 참조 또는 none도 기록한다. |
| DRIVER.SUBMIT / DRIVER.COMPLETE | 작업·장치 참조와 요청 참조 또는 none을 갖는다. SUBMIT은 수락된 제출이며 COMPLETE에는 결과 code가 추가된다. |

네이티브 Rust에서는 타입 있는 span 토큰을 동기 작업 동안 보유하거나 다른 태스크가 종료하기 전 명시적으로 인계한다. C 호출자는 대응하는 불투명 토큰을 보관하고 정상/오류 완료 경로에서 end를 호출한다. 두 언어는 사전·오류 의미를 공유하고 커널이 호출 도메인을 검증한다. 위 이름과 피연산자는 디코딩의 논리 계약이다. 정확한 C 시그니처·Rust 바인딩·호출 규약 세부사항·opcode 번호·바이트 오프셋은 ABI 검토 후 확정한다.

**가상 예시, 보정된 단일 CPU에서 단위 µs.** 클라이언트 BEGIN 0, 요청 ENQUEUE 10, 서버 READY 12, 서버로 SWITCH 20, 요청 DELIVER 24, 응답 ENQUEUE 50, 클라이언트 READY 52, 클라이언트로 SWITCH 60, 응답 DELIVER 63, 클라이언트 END 70이다. R에는 두 당사자만 참여하고 이동·누락·명시한 처리 중 추가 전환이 없다고 가정한다. 전체 70 µs는 서로 겹치지 않는 [0,10), [10,24), [24,50), [50,63), [63,70)의 10+14+26+13+7이다. 서버 준비→디스패치 8 µs는 요청 큐 14 µs에, 클라이언트 준비→디스패치 8 µs는 응답 큐 13 µs에 이미 포함된다. 다시 더하면 중복이다.

Linux 드라이버 도메인 경계에서는 J-NOX 래퍼가 자체 카운터와 작업 참조로 인계 수락과 관측한 완료를 기록한다. 래퍼·이미지 신원과 각 사건의 생산 측을 남긴다. 수정하지 않은 Linux 바이너리 내부는 관측되지 않을 수 있다. 승인된 게스트 측 계측은 출처·작업 연결·게스트/호스트 시계 보정이 확인된 경우에만 합친다. 그 밖에는 래퍼가 본 구간과 내부 미관측을 표시한다.

## 수집 인터페이스와 자원 계약

- **SDK.** 고정 폭 C ABI로 기능 조회, begin(type,parent), end(span,outcome), mark(type,value), 명시적 문맥 인계를 제안한다. Rust 래퍼는 같은 ABI와 타입 있는 ID를 사용하며 작업 간 인계는 명시적으로 닫는다. 거부·비활성 begin은 무효 토큰을 주며 그 end는 안전하게 무시한다. 미지원 ABI·권한 거부·무효 토큰·누락 오류를 정의한다. 생산 경로는 동적 할당·이름 조회·서식화·블로킹 I/O·소비자 대기 없이 제한된 동작만 한다. 이름은 빌드 시 사전에 등록한다. 컴파일 OFF는 표식 전용 인자 평가까지 제거하고, 런타임 OFF는 제한된 활성 검사만 한다. 기존 ELF는 ABI·매니페스트가 맞는 기존 프로브만 사용한다. 그 밖에는 OS 경계와 사용 가능한 오프라인 심볼만 관측하며 내부 span을 복원할 수 없다.
- **형식.** SDK ABI와 캡처 스키마를 독립 버전으로 관리한다. v1 헤더에는 매직·주/부 버전·엔디언·헤더/레코드 크기·세션/부팅/구성/빌드 ID·토폴로지·시계·필터·버퍼 정책·손실 수를 둔다. 각 레코드에는 길이/타입/버전·주체·CPU/순번·원시 카운터·객체와 세대·연결 토큰·제한 필드를 두며 값 없음도 명시한다. 미지원 주 버전·비정상 길이는 거부하고 모르는 부 버전 타입은 길이로 건너뛰되 의존 구간에 누락을 표시한다. 매니페스트에 불변 타입 사전·권한·ID 범위·용량·시계·실행 파일·매핑·선택 심볼을 고정하고 캡처 해시와 함께 확인한다.
- **버퍼.** CPU별 정적 정렬 슬롯을 제한된 비차단 방식으로 예약해 고유 순번을 얻는다. 중첩 IRQ는 중단된 작성자와 슬롯을 공유하지 않는다. 본문 완성 뒤 순번/세대 태그를 release-store로 게시하고 소비자는 경쟁에 안전한 본문 접근과 복사 전후 acquire 검사로 완전한 슬롯만 읽는다. v1은 가득 차면 새 사건을 버리고 승인된 배출/리셋까지 점유 슬롯을 보호한다. 경합·가득 참·미지원 중첩/NMI는 재귀 없이 CPU/생산자별로 계수한다. 순번 공백·포화 손실 카운터와 포화 여부를 예약 메타데이터에 남긴다. 안전한 회수 뒤 인덱스 순환은 새 세대를 사용한다. 선점된 작성자를 기다리거나 미완료 슬롯을 덮어쓰지 않는다.
- **시계.** 도메인·주파수·순환/리셋·읽기 순서와 관측 전후 동기 표본, 오프셋·드리프트·읽기 불확실성을 보존한다. CPU 순번과 권위 있는 메시지 연결로 부분 순서를 만든다. 보정한 두 사건 [L1,U1], [L2,U2]의 차는 [L2−U1,U2−L1]이다. 구간이 겹치거나 이동 중 보정·리셋 정보가 없으면 코어 간 정확한 시간 판정을 보류한다. 호스트 수신 시각으로 타깃 원시 틱을 대체하지 않는다.
- **권한·무결성.** 구성 변경·사건 발행·시작/종료·반출·도메인 간 열람 권한을 구분한다. 경계에서 생산자·허용 타입·세대·필드·빈도/할당량을 검사한다. 기본 데이터는 불투명 ID·열거값·필요한 수치만 허용하고 원시 페이로드·키·주소·사용자 문자열은 배제한다. 민감한 심볼·적재 매핑·PC는 승인된 오프라인 분석에서만 사용한다. 보존/접근 정책 버전과 변경·열람 출처를 남기고 저장·전송은 배포 정책으로 보호한다. 진본성 주장은 해시와 별도의 승인된 신뢰 근거를 필요로 한다.
- **비용.** 코어별 RAM(메타데이터·중첩·반출 임시 공간), 코드/상수·스택·문맥별 발행 비용·IRQ 지연·지터와 포화를 측정한다. 반출 CPU·대역폭을 별도로 할당한다. 동일 부하의 컴파일 OFF·런타임 OFF·ON을 독립 시계로 비교한다. 기능안전팀과 시스템팀이 보드·프로파일별 수치 한계를 승인 전에 배분한다. 선택적인 통계 함수 프로파일은 별도 권한·예산·비율로 PC/스택을 표본화하고 적재 매핑·편향·손실·범위를 보고한다. 표본으로 span 경계나 요청 인과를 증명할 수 없다.

## 엔지니어 사용 절차 및 수용

1. 승인된 매니페스트·부하·시계 구간·필터·종료 조건을 정하고 구성과 이미지 식별자를 보존한다. 캡처를 시작해 부하를 재현하고 최초 결과와 손실 수·종료 상태를 남긴다.
2. 종료 뒤 또는 독립적으로 예산을 배정한 배출 경로로 원본 바이너리·매니페스트·해시·시계 보정을 내보낸다. 호스트에서 신원·버전·길이·커밋 순번·세대·손실·시계 연속성을 확인하고 원본·디코더 버전·변환 출처를 보존한다.
3. CPU·스레드·트랜잭션별 타임라인을 만든다. 끝 표식 누락·손실·확인할 수 없는 연결·시간 불확실성을 표시한다. 영향을 받은 지연·완결성·안전 판정을 보류하고 그 외 구간은 관측 범위와 함께 보고한다. 필요하면 호스트에서 식별 정보를 제한한 상호운용 타임라인·프로파일로 변환하며 원래 ID/단위와 변환 방법을 명시한다.
