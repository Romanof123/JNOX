# Legacy CBS first failure / 기존 CBS 최초 실패 조건

Prospective engineering observation on #172 at `49d7891d52a78aba04515b5130efd56f3343200c`. Kernel Development owns the diagnostic proposal. Systems owns any later change to the CBS contract. ## Where the observations first differ

The original basic fixture runs A, B, idle, A, B with one 50 ms slot per grant. On `259aaebb`, IRQ 4 interrupted A’s post-resume increment at `0x402012c8` and entered the EL1 IRQ vector at `0x40200a80`. The next event in the distinct passing control at `12a98a91` was an ERET to B’s saved `0x402012fc`. The 83-byte candidate UART stream ended in `CBS FAIL` before any return to B. This localizes the divergence to handling IRQ 4 before B’s return. B’s resumed task marker had no opportunity to run. The trace identifies the exception class and address. It supplies neither the interrupt acknowledge token nor the handler’s counter, frame or policy operands. The separate wake fixture passed 34 rows and 78 ordered PC events. [Archived comparison, ELFs and raw traces](evidence/ordinary-cbs-integrated-compat.en-ko.md) · [Original basic run](evidence/evd-006.en.md) · [Wake reference](evidence/evd-029.en.md)

The two original source revisions share the basic fixture, task assembly and exception path. The policy revision factors effective credit into `HardCbs::available`. Applying either implementation at slot 4 gives A zero credit until 6 and B one replenished unit with deadline 8. Selecting B leaves B with zero credit and one unit of pending work. In the archived binaries `Bench::dispatch` starts at `0x40201b6c` in both, with sizes `0x1cc` (candidate) and `0x1c4` (control). Stack-array bases are `0x40203480` and `0x40203490` respectively. Use each ELF’s symbols. This code comparison explains the expected scheduling decision. The first failed comparison in that boot remains unknown. ## First decision and ownership

1. **Kernel Development** prepares an opt-in image for the legacy `cbs-bench` only. At the first existing failed predicate, latch its stable site ID and the actual operands that determined it, then emit one bounded diagnostic row before the ordinary `CBS FAIL` and park. Map IDs to individual comparisons, including the members of compound guards and returned policy errors. Use only values available on that path. A presence mask distinguishes an unavailable value from zero. Reuse each original counter sample, IAR token and volatile stack-word read. An additional read can change a timing verdict or acknowledge another interrupt. Preserve the original decisions, compare programming, EOI order and UART on the plain image. Diagnostic code layout and spills can change time even on a successful path.
2. **Integration** freezes one revision and its plain basic, diagnostic basic and original wake ELFs, hashes, loadable ranges, symbols, selectors, original observer settings and 1-vCPU virt/GICv2 TCG configuration. Compare plain loadable bytes with the same source before adding the selector and report any differences. Publish the site/operand dictionary with the freeze. The following comparisons distinguish failures reachable on the historical IRQ-4 path.

   | Site group | Operands that distinguish failures |
   |---|---|
   | IRQ and absolute window | Original IAR and timer control vs PPI 30 and control bits 5. For the window guard, actual counter sample vs the checked half-open bounds. Identify arithmetic errors separately. |
   | Outgoing A | Current owner and marker count vs logical boundary, empty saved-frame slot, actual frame address vs private-stack address, saved ELR vs work interval, SPSR, x19, TPIDR and x20 vs required witness and previous progress. Distinguish the two stack-word checks. |
   | Selection and incoming B | Policy error or returned owner vs expected B, selected frame present, frame ELR vs previously saved B PC, and the original dispatch counter sample vs the next absolute deadline. Report a failure before the bench state is available as such. |

3. **Independent Verification** preserves one first ordinary cold launch per image in the frozen order plain basic, diagnostic basic, original wake. Correlate raw UART with that process’s exception trace and ELF. Keep the original basic verdict of nine UART lines, five IRQs, both saved-PC returns, timer stop and 0.1 s quiet. Keep the original wake verdict, 34 rows, 78 PC events and its accepted 15 s observer setting. A diagnostic failure identifies only the site and operands of that launch. Missing or inconsistent records leave the cause open. A plain pass and a diagnostic pass establish the outcomes of those launches only. No retry, added stimulus or adjusted timing limit is part of this comparison. [Basic procedure](m1-cbs.en.md) · [Wake procedure](m2-cbs-wake.en.md)
4. **PM and Kernel Development** link all three first outcomes back to #176, #172 and #123. Decide first which comparison, if any, has direct evidence of failure. A guard exposing incorrect state goes to its owning component with that evidence. A late counter sample establishes a missed interval and still needs evidence to attribute latency. A normal pass can satisfy the current candidate’s basic criterion while the original cause stays unknown. The eight ordinary reservation runs retain their separate verdict.

## 한국어

이 계획은 #172의 위 커밋에서 기존 CBS 벤치의 첫 실패 조건을 관측하기 위한 제안이다. 최초 후보는 A가 재개된 뒤 네 번째 IRQ를 받았고, 보존된 대조 실행과 같은 A 명령 `0x402012c8`에서 같은 벡터로 진입했다. 대조 실행은 곧바로 B의 저장 PC `0x402012fc`로 복귀했으나 후보는 그 전에 실패했다. B의 재개 표식은 실행되지 않았다. 당시 기록에는 실제 IAR, 카운터, 저장 프레임 피연산자가 없다. 두 버전의 수식을 4번 슬롯에 적용하면 A는 6까지 예산이 없고 B는 기한 8에 예산 1을 받아 선택된다. 디스패치 함수 크기와 스택 절대주소가 다른 두 ELF의 기록에서 원래 실패 원인을 하나로 특정할 수 없다. 별도 깨우기 벤치는 34행 및 78개 PC 이벤트 기준을 충족했다. [최초 기록](evidence/ordinary-cbs-integrated-compat.en-ko.md) · [기본 근거](evidence/evd-006.md) · [깨우기 근거](evidence/evd-029.md)

1. **커널 개발팀**은 기존 기본 CBS 전용 선택형 진단을 준비한다. 기존 검사 중 최초 실패한 비교의 고정 ID와 그때 실제 비교에 사용한 값을 한 번 보관하고, 원래 실패 표식 직전에 유한한 한 행으로 출력한다. 복합 조건과 정책 오류를 구분하고 사용할 수 없는 값은 유효성 비트로 표시한다. IAR, 카운터와 스택의 휘발성 값은 원래 읽은 값을 이용한다. 일반 이미지의 결정, 타이머, EOI, UART 및 시간 기준을 유지한다. 진단 이미지에서는 코드 배치나 레지스터 저장 비용이 달라질 수 있다.
2. **통합팀**은 일반 기본·진단 기본·기존 깨우기 이미지 세 개의 같은 소스 리비전, ELF 해시, 적재 범위, 심볼, 옵션, 관측기 및 가상 장비를 고정한다. 선택자 도입 전 같은 소스와 일반 이미지의 적재 바이트를 비교한다. 위 표와 같이 IRQ 번호·타이머 상태·절대 시간 창, A의 소유/표식·프레임/스택·PC/레지스터·진행값, B 선택·저장 프레임·다음 절대 기한 검사를 각각 구별하는 ID와 피연산자 사전을 제공한다.
3. **독립 검증팀**은 위 순서로 각 이미지를 한 번씩 콜드 부팅하여 같은 실행의 UART와 예외 추적을 해당 ELF와 대조한다. 일반 기본은 원래 9행, IRQ 5회, 저장 PC 복귀 두 번, 타이머 정지와 0.1초 무출력 기준으로 판정한다. 깨우기는 원래 34행, PC 이벤트 78개 및 승인된 호스트 관측 15초를 적용한다. 진단의 첫 실패는 그 실행에만 귀속한다. 기록 누락·불일치는 원인 미확정으로 남긴다. 추가 자극, 재시도 또는 시간 기준 변경은 계획에 없다. [기본 절차](m1-cbs.md) · [깨우기 절차](m2-cbs-wake.md)
4. **PM과 커널 개발팀**은 세 최초 결과를 #176·#172·#123에 연결하고 실제로 어느 비교의 실패를 확인했는지 먼저 판정한다. 잘못된 상태가 관측되면 담당 컴포넌트에 원자료를 넘긴다. 카운터 기한 초과는 해당 구간이 늦었음을 보여 주며 지연의 원인은 별도 근거가 필요하다. 새 일반 실행이 통과해도 과거 실패 원인은 미확정일 수 있다. 일반 예약 여덟 건은 별도 결과로 유지한다.
