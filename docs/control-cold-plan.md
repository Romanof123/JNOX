# CHG-049 · #94 cold timer experiment / 콜드 타이머 비교 실험

Systems and Functional Safety, single-core QEMU virt only. Proposed experiment, pending execution. [ADR-001](safety-parameters.en.md) · [FS-M3-01](pol-004-m3-control-plan.md) · [#94](https://github.com/Romanof123/JNOX/issues/94)

## Decision and prior observations

Baseline v1 (d17ce2d) inhibited on all eight default-clock ordinary boots. Four deterministic handoffs passed and two exact boundary cases missed. On v2 (e0f0ce6) epoch setup already ran on the restored idle stack. All eight default-clock primary cases still exceeded the 0.5 ms first IRQ allowance and later skipped a phase. The reported first delays span about 1.79–1.98 ms. All v2 substantive boots used exception logging. Deterministic handoffs on complete captures and the worst-gap case passed, while the tie ingress upper bracket missed by one tick. Preserve the incomplete first handoff, retry, raw traces and original verdicts. Current evidence does not attribute lateness to the logger, translation, host scheduling, timer setup or handler entry.

1. **Cold comparison first.** Use the exact frozen v2 healthy ELF for each policy, default clock, same QEMU 6.2.0 executable, virt/GICv2/A72/TCG/one CPU/128 MiB, no NIC. For each RM and DM run eight sequential cold pairs, alternating OFF→ON and ON→OFF by pair number; OFF omits exception logging, ON uses the prior -d int and per-run log file. Fresh QEMU process and output directory every launch. Pin all other argv, executable and ELF hashes, capture path/storage class, host CPU/power settings and host load collection. Record actual UTC and host monotonic launch, first UART, terminal and process exit, exit status and timeout (10 s host from launch). Keep every attempt and paired delta. Diagnose truncation separately; no replacement in the primary denominator. The common guest evidence must work in both arms. Give counts, individual samples, range and failures, with host time and guest counter in separate columns. A paired difference indicates an association with this logging setup. A null difference cannot exclude TCG or host effects.
2. **Locate the delay.** Next repeat that fixed matrix with one hashed instrumented ELF per policy, including equal-cost bounded RAM samples in both arms and no live debugger stops. Record first reset-entry counter B and frequency; bracket E0 calculation, CNTP_CVAL/CTL write+ISB and readback, IRQ unmask/idle entry (DAIF, GIC PPI enable/priority and CPU interface mask), earliest vector sample, existing handler sample, ACK ID, worker dispatch, real decision and terminal. Preserve ELR, order and raw same-clock bounds. Reconstruct programmed compare minus E0, arm/unmask margin to compare, vector-minus-compare and handler-minus-vector. Flag late arm, wrong readback, ineffective unmask or pending PPI separately. A vector marker after instruction execution includes entry cost; a pending-bit sample is not a hardware assertion timestamp. If instrumentation changes behavior disclose the difference against stock. If raw brackets cannot separate translation from host descheduling, report the interval unresolved; supplementary timestamped host scheduling/TCG diagnostics constitute another named arm. Do not subtract estimated instrumentation or translation time from a scored interval.
3. **Prospective preflight decision.** Permit one separately named experimental profile as a boot design only. At earliest guest counter B fix E0=B+250 ms, one self-test compare at B+200 ms and independent preflight completion cutoff B+220 ms. These are chosen diagnostic inputs, pending measurement. Require exact representability. Record the reset-to-B blind interval explicitly or bound it with a reset observer before claiming a reset-to-ready time. Record first observed device OFF and enforce initial gate closed, no permit/command consumption, sender stopped, output OFF throughout boot, and no latched request carried into rearm. Use exactly one real IRQ on the operational timer/PPI/idle-vector path. Require correct comparator/control readback, IRQ ID, no early entry, completed acknowledgement, deassertion/EOI and cleared pending/active timer state before cutoff. Record self-test delay even if greater than 0.5 ms. Fail closed on missed milestone, early/duplicate/spurious IRQ or late initialization; external host timeout catches a guest unable to advance. No retries or epoch adjustment. Arm phase zero in advance at the predeclared E0, record the transition from boot to operational state and verify the first real control job and every later phase. Scoring starts at the fixed E0 regardless of self-test success; failed startup is an unsuccessful run. The one boot probe cannot count as a control decision or satisfy an operational timing requirement.
4. **Interpretation.** Run the preflight variant in the same fixed cold matrix, retaining the original cold no-preflight results. For causal attribution to self-test execution versus extra boot lead time use a matched E0=B+250 ms no-probe control with the same image/configuration and idle path. Expose the selected mode and hashes. A pass would apply solely to this explicit boot contract. Both RM and DM still require actual 0–0.5 ms IRQ and 0–1 ms decision envelopes, ≤5 ms job completion and check spacing, independent 25/5/30 ms response, exact ADR cases and negative controls. Continue monitoring while inhibited after E0. An IRQ-only probe cannot replace a missing default-clock scored case. Qualified deployment requires a separately justified startup availability requirement, clock/reset and physical safe-output evidence.

## 한국어 결정 및 실험 절차

v1(d17ce2d)의 기본 클록 일반 작업 8회는 활성화 전에 차단됐다. 결정적 인계 4회가 통과했고 두 경계 시험은 목표 틱을 놓쳤다. v2(e0f0ce6)는 복원된 idle 스택에서 기준 시각을 설정했으나 기본 클록 최초 IRQ가 약 1.79–1.98 ms 지연되어 8회 모두 0.5 ms 기준을 넘고 이후 위상이 누락됐다. 실질적 v2 실행에는 예외 로그가 모두 켜져 있었다. 결정적 인계의 완전한 기록 및 최악 위상은 통과했지만 동시 도착 완료 상한이 한 틱 늦었다. 최초 불완전 기록·재실행을 포함하여 원본 판정을 보존한다. 지연 원인은 미확정이다.

1. 동결한 v2 RM·DM healthy ELF와 QEMU 6.2.0 virt/GICv2/A72/TCG/단일 CPU/128 MiB, 기본 클록, NIC 없음으로 정책별 콜드 8쌍을 순차 실행한다. 쌍마다 OFF→ON과 ON→OFF 순서를 교대한다. OFF는 예외 로그를 끄고 ON은 기존 -d int와 개별 로그 파일을 사용한다. 매번 새 프로세스·출력 디렉터리를 사용한다. 나머지 인자·해시·저장장치·호스트 CPU/전원 조건과 부하 수집을 고정한다. UTC·호스트 단조 시각으로 시작·첫 UART·종료 표식·프로세스 종료와 상태를 기록하고 호스트 시작 후 10초 제한을 둔다. 모든 시도, 쌍별 차이, 범위·누락·실패를 보고하고 불완전 기록을 바꿔치기하지 않는다. 게스트 카운터와 호스트 시간을 구별한다. 로그 유무에 따른 차이는 해당 조건의 연관성을 나타내며 번역 비용을 단독 특정하지 않는다.
2. 정책별 동일 계측 ELF로 매트릭스를 반복한다. 양쪽 모두 고정 RAM 계측을 사용하고 실행 중 디버거 정지를 피한다. 초기 카운터 B·주파수, E0 계산·비교기/제어 레지스터 설정·ISB·읽기, IRQ 허용·idle 진입(DAIF·GIC PPI/우선순위·CPU 마스크), 최초 벡터와 기존 핸들러, ACK ID, 태스크 선택·실제 판정·종료의 원시 구간과 ELR·순서를 보존한다. 목표값 오차, 설정·IRQ 허용 여유, 비교값→벡터, 벡터→핸들러를 재구성한다. 늦은 설정·잘못된 읽기·마스크·pending을 구별한다. 벡터 계측에는 진입 명령 비용이 포함되며 pending 표본은 하드웨어 발생 시각을 확정하지 못한다. 계측 영향과 분리 불가 구간을 공개한다. 추가 호스트 스케줄링·TCG 계측은 별도 구성으로 취급하고 추정 비용을 합격 시간에서 빼지 않는다.
3. 별도 실험 프로파일에 한하여 최초 게스트 시각 B에서 E0=B+250 ms, 자가시험 비교값 B+200 ms, 완료 한계 B+220 ms를 사전 고정한다. 이는 측정 전 시험 입력이며 각 시각은 정확한 틱으로 표현해야 한다. 리셋부터 B까지의 미관측 시간을 밝히거나 독립 계측한다. 최초 실제 장치 OFF 및 부팅 중 계속 OFF, 게이트 닫힘·송신 중지·허가/명령 미소비·재무장 요청 미승계를 요구한다. 실제 운영 타이머/PPI/idle 벡터로 정확히 한 번 IRQ를 실행하고 비교값·제어값·IRQ ID·조기 진입 부재·ACK·소스 해제/EOI 및 마감 전 pending/active 해소를 확인한다. 0.5 ms를 넘은 자가시험 지연도 남긴다. 누락·조기·중복·이상 IRQ·늦은 초기화는 차단 상태 실패이며 게스트 정지는 호스트 시간 제한으로 기록한다. 재시도나 E0 이동 없이 위상 0을 미리 설정한다. 고정 E0부터 첫 작업과 모든 후속 위상을 판정하고 부팅 실패도 전체 실패에 포함한다. 자가시험은 제어 판정 횟수에 포함하지 않는다.
4. 자가시험 구성도 같은 콜드 매트릭스로 비교하고 원본 결과를 보존한다. 같은 E0=B+250 ms와 idle 경로·이미지에서 시험 IRQ만 생략한 대조군으로 추가 준비 시간 효과를 구별한다. 모드·해시를 남긴다. 통과 범위는 이 부팅 계약에 한정한다. 두 정책 모두 실제 IRQ 0~0.5 ms·판정 0~1 ms, 작업 마감·판정 간격 5 ms 이하, 25/5/30 ms 독립 반응 한계와 ADR 경계 및 음성 대조를 검증한다. E0 이후 차단 중에도 판정을 계속한다. 제품 부팅 가용성·클록과 리셋·실제 출력 안전성은 별도 요구와 근거가 필요하다.

## Capture filesystem crossover / 계측 파일시스템 교차 실험

**CHG-049 addendum · #94/#99/#101.** The standalone and integrated default-clock A-PS records report the same executed ELF (SHA-256 prefix ee8d6) and QEMU 6.2 executable digest. The earlier first IRQs were 2.08–5.86 ms late; eight later complete healthy observations fell within 1 ms. The ELF pathname and serial/exception log destinations differed. This motivates a controlled comparison. Preserve both first evidence sets, including failed and incomplete runs.

1. Freeze two independent strata: stock v2 RM healthy from EVD-042 and frozen A-PS healthy. For each, validate the full ELF and QEMU SHA-256 against its original manifest, then launch every cell from the same read-only ELF at the same absolute Linux path. Use identical QEMU executable and default clock, machine, device, CPU, RAM, network and all other options for that stratum. Enable -d int on every run. Only the two output path arguments vary. Use -serial file:<path> and -D <path>, with identical frontend/backend and flush settings across cells. A change from an original frontend is a named difference applying to the entire stratum. Freeze runner, WSL distribution/kernel, QEMU version, working directory, environment, vCPU/host affinity, power mode, observer polling and timeout, any existing seed (otherwise record N/A), and background host load sampling. Do not add new guest instrumentation.
2. Use four cells, listing UART destination first and exception log second: A=(native,native), B=(native,DrvFs), C=(DrvFs,native), D=(DrvFs,DrvFs). Use real Linux native storage beneath /tmp and the mounted Windows volume beneath /mnt/d; record actual mount types/options and sufficient space. Paths use fresh per-run directories, the same basenames and no pipes, live mirroring or cross-volume redirection. Within each stratum run four blocks in the exact order **ABDC, BCAD, CDBA, DACB**. Each position and ordered adjacent pair within blocks occurs once across the design. Interleave whole blocks by stratum, RM first for blocks 1 and 3, A-PS first for 2 and 4. Total 32 sequential fresh QEMU processes, four observations per cell and stratum. Cold refers to process restart; retain host cache state without flushing or artificial warm-up. Capture elapsed idle gap between launches, host CPU/load, host monotonic launch/first serial observation/terminal/exit and UTC. Use one predeclared terminal observer and fixed 10 s host timeout. Keep launcher stdout/stderr and metadata on a third fixed native directory for every cell. Record actual argv, exit reason, phase of any truncation and every attempt in its assigned cell.
3. After exit copy closed original raw UART and exception logs to the evidence directory; hash at source and destination and retain originals, sizes, per-run manifest and independent decoder version. Decode guest counter frequency, phase-zero target/observed IRQ and signed difference; decode every later matching target/IRQ and completeness, maximum later lateness, skipped phases, task outcome and terminal state. Use the original profile's exact limits and integer comparison (RM phase-zero 0.5 ms, A-PS 1 ms first-IRQ criterion); preserve unavailable markers as missing. Never substitute host first-byte time for IRQ timing. Report all four replicates, failure counts and within-block differences for UART at fixed log path, log path at fixed UART and the difference between those effects across cells. Quantify partial results and clock/marker uncertainty. A filesystem-route association in this small design leaves host scheduling, translation and other shared effects unresolved.
4. **Run decision.** The diagnostic slot can run after the two frozen payloads, QEMU hash, mounts and manifests match. Keep the original #109 eight logging-off/on cold pairs per policy and its separate instrumented and boot-probe controls. This always-logging extension supplies additional diagnostic evidence only. Original failures, deployment admission, product latency and board qualification retain their own verdicts.

**한국어.** 기본 클록 A-PS 단독·통합 관측의 ELF(SHA-256 앞자리 ee8d6)와 QEMU 6.2 실행 파일 해시가 일치했지만 ELF 경로와 UART·예외 로그의 저장 경로가 달랐다. 앞선 최초 IRQ 지연은 2.08~5.86 ms, 이후 정상 완주 8회의 최초 IRQ 지연은 1 ms 이내였다. 두 최초 기록과 실패·불완전 기록을 보존하며 원인은 미확정이다.

1. 기존 v2 RM healthy와 동결 A-PS healthy를 별도 층으로 고정한다. 원본 매니페스트의 전체 ELF/QEMU SHA-256과 대조하고 층 안에서는 읽기 전용 ELF의 절대 Linux 경로를 통일한다. 기본 클록과 -d int를 유지하고 UART 파일과 -D 파일의 경로만 바꾼다. 장치·인자·프런트엔드/백엔드·플러시, 러너·WSL/커널·작업 디렉터리·시드(없으면 해당 없음)·호스트 CPU 선호도·전원·부하 관측·종료 조건을 고정한다. 원본과 프런트엔드 차이가 있으면 명시한다. 게스트 계측은 추가하지 않는다.
2. UART, 예외 로그 순서로 A=(Linux,Linux), B=(Linux,DrvFs), C=(DrvFs,Linux), D=(DrvFs,DrvFs)이다. /tmp와 /mnt/d의 실제 마운트 종류·옵션·여유 공간을 확인한다. 실행마다 새 디렉터리와 동일 파일명을 사용하고 실시간 복제를 피한다. 층별 4블록 순서 ABDC, BCAD, CDBA, DACB를 고정한다. 홀수 블록은 RM 먼저, 짝수는 A-PS 먼저로 교대한다. 셀·층별 4회, 총 32개 새 프로세스를 순차 실행한다. 호스트 캐시를 강제로 비우거나 예열하지 않는다. 실행 간 대기, 호스트 부하, UTC와 단조 시작·첫 직렬 관측·종료 표식·종료 시각, 실제 인자와 종료 상태를 기록한다. 동일 관찰기와 호스트 10초 제한을 사용한다. 러너 표준 출력·오류·메타데이터는 고정된 별도 Linux 디렉터리에 둔다. 실패·잘림은 원래 셀의 시도로 계산한다.
3. 종료 후 닫힌 UART/예외 로그의 원본·복사본 SHA-256과 크기·매니페스트·해석기 버전을 보존한다. 게스트 주파수·첫 목표/관측 IRQ 및 부호 있는 지연, 이후 각 목표/IRQ·최대 지연·위상 누락·완전성·작업 결과·최종 상태를 추출한다. 프로파일별 원래 기준(RM 첫 0.5 ms, A-PS 첫 1 ms)을 정수로 비교한다. 누락은 누락으로 남기고 호스트 첫 바이트 시각을 IRQ 시각으로 대체하지 않는다. 모든 반복값·실패 수·블록 내 다른 한 경로 고정 시 경로별 차이와 두 효과의 교호작용·계측 불확실성을 보고한다. 작은 실험에서 경로와 지연의 연관성이 관찰돼도 번역 비용·호스트 스케줄링 등의 영향이 남는다.
4. 두 ELF·QEMU 해시와 마운트·매니페스트를 확인하면 진단을 실행할 수 있다. 기존 #109의 정책별 로그 OFF/ON 콜드 8쌍 및 계측·부팅 자가시험 대조군은 각각 수행한다. 이번 결과는 별도 진단 범위에 한정되며 기존 최초 결과와 제품 배치·실보드 승인 판정은 별도 근거가 필요하다.
