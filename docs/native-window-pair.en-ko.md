# Two local window clients on one JNOX display / JNOX 로컬 화면과 두 클라이언트

REQ-015/024 · CHG-318 · IMP-318 · VER-015/024 · EVD-318. On AArch64 QEMU virt, run the display owner in slot 0, two independent content-producing processes in slots 1 and 2, and the existing AF_UNIX stream broker in slot 3. All four run under FIFO. Only the owner may present rows or poll PL011 input. Freeze the three client-to-broker routes in the package. Preserve other accepted selectors and the current IPv4 profile.

Use locally produced surface descriptions with bounded lengths. Connect each client separately, identify the surface, and draw overlapping surfaces with the focused one on top. Record a stable external QMP frame before the first action. Send `x` to the focused client, switch focus with `n`, send `x` again and finish with `q`. Compare complete 320×240 pixel buffers with an independent oracle. Check the responses from both clients, denial of direct display calls, and termination of the broker. The service reads normal application requests. This stage uses a small local protocol. Standard Wayland shared files, file descriptor transfer, restart recovery, Xwayland and product safety acceptance remain tracked in [#412](https://github.com/Romanof123/JNOX/issues/412). [Implementation and verification #413](https://github.com/Romanof123/JNOX/issues/413)

AArch64 가상 이미지 한 개에 화면 소유 서비스, 콘텐츠를 만드는 앱 두 개, AF_UNIX 브로커를 분리된 프로세스로 배치한다. 각 앱이 보낸 내용으로 겹치는 창을 그리고 실제 시리얼 입력을 포커스된 앱에만 전달한다. 포커스 전환과 양쪽 앱의 응답을 외부 화면 캡처 및 프로세스 종료 기록으로 확인한다. 앞선 네이티브·원격 X11 구성과 로컬 Wayland/Xwayland의 인수 범위는 구분한다.
