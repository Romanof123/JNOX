## English

Planning baseline d8aebaf. QEMU virt, one Cortex-A72, GICv2, TCG, 128 MiB. Freeze emulator, options, binary/hash, counter mode and workload before independent replay. The current periodic fixture uses CNTFRQ/20 (nominal 50 ms); its short logical RM/DM epochs, assembly workers and SVC traces establish dispatch only. The preemption case demonstrates interrupted work resumes. Neither supplies a 5 ms control loop or a device observer. [Periodic implementation](../kernel/src/periodic.rs) · [Exact releases](pol-004-exact-periodic.md) · [Preemption](m1-periodic-preempt.en.md)

1. **Execution.** Use absolute releases from one epoch and real ordinary schedulable workers with private stacks and measured execution. Timer IRQs acknowledge/release; the control worker itself evaluates freshness and updates the latch, then completes. Use RM and DM in separate runs. Control T=D=5 ms, synthetic sender T=10 ms; FS-M3-01 fixes D=10 ms for this fixture's sender, distinct from permit freshness. Both order control first. Use a bounded test-only stimulus record and virtual output register, with a separate device-side transition hook. No endpoint, mailbox or safety transport is needed for this scheduling experiment. Record actual issue/delivery; delayed sender dispatch cannot silently turn into on-time issue. Use a separately identified scripted stimulus for exact ties and distinguish it from ordinary sender runs.
2. **Admission.** Freeze each worker’s execution bound C, period/minimum separation T, deadline D, release jitter J, priorities/ties, IRQ costs and arrival bounds, longest nonpreemptible section B (including masked IRQ time), observer overhead, and overload policy. Count every cost once. From nominal release bound response by J_i + w, iterating w = C_i + B_i + IRQ(w) + sum over higher priority h of ceil((w+J_h)/T_h) C_h; use integer ticks and include scheduler/trace costs. Reject if assumptions are missing, recurrence exceeds D, release is skipped, or a previous job is still active at its next release. Observed maxima calibrate candidate bounds; retain their provenance and qualify any analytical result by the assumed bounds. Compare idle, simultaneous sender/control release, longest blocking just before release, bounded preemption/IRQ bursts and combined maximum declared interference. Include an intentionally over-budget configuration and confirm refusal or a recorded failure.
3. **Spacing.** For release r_k, actual freshness-check completion f_k and job finish e_k, require e_k−r_k ≤ 5 ms and f_k−f_(k−1) ≤ 5 ms for every consecutive pair, including startup-to-steady and fault handling. Record f at the freshness decision, separately recording finish; no synthetic deadline marker. With exact releases and f_k=r_k+L_k, every positive increase in latency breaches spacing. A deadline response bound alone cannot admit the profile. A candidate implementation may execute additional actual checks within each 5 ms job (for example at two phases 2.5 ms apart), as authorized below by FS-M3-01. Bound every inter-check gap including the job boundary, and charge both checks to the budget. Alternatively demonstrate an enforceable fixed check phase and account for timer/IRQ uncertainty. If neither is substantiated leave spacing admission open. Never shorten the approved task period or relax the limit.
4. **Oracle.** Timestamp atomic normal gate closure plus queued-undelivered invalidation, actual latch set and independent device-side first 1→0 after starting enabled. Preserve last delivered issue time, raw same-clock counter ticks advancing during service loss, frequency, resolution, ordered tie identifiers, release/start/check/finish, IRQ/masking and device observations. Compare ticks by exact cross multiplication; document read/trace uncertainty and discard ambiguous boundary or missing/overflowed records from passes. Check ordered fault ≤ detect ≤ safe, then detection ≤25 ms, subsequent inhibition ≤5 ms, total ≤30 ms independently. Test each verdict at equality and one tick over. A controller write, UART time or presumed observer sampling time cannot substitute for the device transition.
5. **Independent cases.** Reset per case. Healthy 10 ms permits keep output enabled after valid rearm. Close immediately after last delivery, place an actual check one tick before age 20 ms and the next 5 ms later in the ADR worst-phase case. Separately keep gate open, skip 10 ms issue, coincide next arrival/check at age 20 ms, evaluate expiry first and latch. Preserve measured phases; a fixture with extra checks needs a separately declared ADR boundary run. Boot off; after fault hold off through single missing rearm prerequisites, prior generation, duplicates, future/expired or reordered input. New generation with consecutive set permits issued at 0/10 ms and explicit command at 15 ms enables; first command at 20 ms or before second permit fails; require fresh command. Separate silence, invalid flood and saturation. A real independently generated valid frame, correct CRC for mutated semantic fields, unauthorized channel, corruption, queue full and next rejection, unchanged receiver state and restart replay belong to gated VER-019. Scripts can exercise timing/state rules only.
6. **Delivery sequence.** Systems freezes the ordinary worker/admission manifest and applies FS-M3-01 phasing; Functional Safety has approved the added check semantics and preserves ADR boundary cases. Implement the isolated workload/observer and tick oracle as future software work, then an independent verifier records first frozen run, negative controls, trace, hashes and assumptions. Compare each policy’s admission and measured bounds separately in #21. PM opens IPC development only after #21 per-profile completion and applicable board evidence are linked. Actual board CPU/IRQ/DMA/bus interference, failing clocks, physical actuator response and product HARA/FTTI require separate evidence and authorities. ## 한국어

- 단일 Cortex-A72 QEMU virt에서 RM·DM을 각각 실행한다. 기존 CNTFRQ/20 타이머는 명목 50 ms이며, 기존 짧은 논리 틱 시험은 5 ms 제어 작업의 근거가 될 수 없다. 절대 릴리스 시각을 사용하고 IRQ는 작업을 깨운다. 일반 태스크가 직접 신선도를 판정하고 래치를 갱신한다. 제어 주기·마감은 5 ms, 허가 발행 주기는 10 ms이며 FS-M3-01에서 시험용 송신 마감을 10 ms로 정했다. 전송 계층 없이 유한 시험 입력과 별도 가상 장치 전이 관찰기를 사용한다.
- 태스크별 실행 상한·근거, 주기·마감·릴리스 지터, IRQ 비용·최소 간격, 마스킹·블로킹, 스케줄러·관찰 비용을 고정한 뒤 위 응답시간 반복식으로 두 작업을 검토한다. 유휴·동시 릴리스·최장 블로킹·IRQ 집중·복합 간섭과 의도적 과부하를 비교한다. 측정 최대치는 관측 범위에만 적용된다. 미정 상한·마감 초과·릴리스 누락·이전 작업 미완료는 수용 근거가 될 수 없다.
- 실제 판정 완료 간격과 릴리스부터 작업 종료까지를 각각 5 ms 이하로 확인한다. 정확히 5 ms마다 한 번 판정하면 직전보다 지연이 한 틱만 늘어도 위반한다. 일정 위상 보장의 근거를 제시하거나, FS-M3-01에 따라 같은 5 ms 작업 안에서 추가 판정을 수행하고 작업 경계를 포함한 최대 간격과 비용을 입증한다. 원 ADR의 최악 위상 시험은 별도로 보존한다.
- 정상 허가 후 게이트 원자 차단·미전달 허가 무효화, 래치 설정, 별도 가상 장치 관찰기의 첫 하강 전이를 같은 단조 카운터로 기록한다. 주파수·해상도·동일 틱 순서와 계측 오차를 보존한다. 사건 순서와 25/5/30 ms 각 한계를 개별 판정하고 경계와 한 틱 초과를 검사한다. 모호하거나 누락된 기록은 합격에서 제외한다.
- 각 사례를 초기화한다. 마지막 전달 직후 차단, 20 ms 직전 판정 후 5 ms 뒤 판정, 20 ms 만료·도착 동시 발생 시 만료 우선, 정상 운전 중 조기 차단 부재를 확인한다. 복구는 새 세대의 연속 허가(0/10 ms)와 명시적 명령이 필요하다. 15 ms 명령은 성공하고 최초 20 ms 명령이나 두 번째 허가 전 명령은 실패한다. 누락 조건별 차단 유지와 구세대·역순·중복·미래·만료 입력 거부를 확인한다.
- 시스템팀의 실행 명세, 기능안전팀이 승인한 추가 판정 규칙, 향후 독립 관측기·판정기 구현과 동결 후보 재현을 분리한다. 무응답·무효 트래픽·포화 실제 프레임과 큐 검증은 VER-019 및 #24에서 수행한다. #21 정책별 승인과 해당 보드 근거 연결 후 PM이 #24 구현을 개시한다. 실보드 간섭·물리 출력·제품 FTTI는 별도 판단 대상이다. [ADR-001](safety-parameters.md) · [검증 계획](verification-plan.md) · [개발 순서](product-plan.md)

## Functional Safety decision FS-M3-01 / 기능안전 결정 (virtual bench only)

<a id="decision-en"></a>

### English decision

Authorize implementation of a single 5 ms control job, deadline 5 ms, with two real freshness decisions per job. ADR-001 sets a maximum gap and permits an earlier expiry decision at or after age 20 ms. Additional observations must have no effect on sequence, generation, permit count or explicit command consumption merely because an unchanged input is read again. Both phases run the same expiry-first logic on current state, use the actual decision time and can latch inhibition immediately. Freeze sender T=D=10 ms for this workload. Retain every ADR-001 fault, rearm and verdict boundary in sections 4–5. A separate declared single-check boundary configuration must actually realize the specified consecutive 5 ms gap straddling expiry. Record its configuration and evidence separately from the two-phase workload.

1. Fix phase targets at job release and +2.5 ms from a common epoch. Require each programmed target, actual timer IRQ entry, worker ready/resume, completed decision and job finish in the raw trace. Use a counter supporting exact targets. For this bench assign a maximum 0.5 ms target-to-IRQ lateness and a 1 ms target-to-completed-decision envelope inclusive of all delays and timestamp uncertainty. Early completions fail. These are test requirements. Consecutive completed decisions then have a maximum gap of 3.5 ms under the envelope, including across jobs. Independently check every actual gap ≤5 ms and each job finish by its own nominal deadline. Anchor the first check to the first nominal release while inhibited. Continue checks in the inhibited state. End with a declared observation horizon, a subsequent actual check covering the final gap, completion of the last scored job and independent confirmation of the required output state. Score all phases of all scored jobs.
2. Use a timed continuation of the same worker at phase two. Freeze per-phase recurring CPU-service budgets, sender service, timer/other IRQ minimum separation, jitter, masking and interference before scoring. Log positive worker CPU service on each activation, separating preemption and sleep, and verify demand per phase, job and repeating 10 ms interval, including both phase IRQs per job where applicable. Attribute timer programming, entry/exit, scheduling and observer costs once. The existing host recurrence excludes self-suspension. Require a justified segmented or conservative interference analysis covering both phase windows, carry-in and sender response before analytical admission. Raw maxima and assigned envelopes alone establish no execution bound.
3. On late wake read current time, perform one actual safety evaluation and record lateness and any skipped indices. Fail a missed phase, violated envelope, overlap or unobservable edge. Request inhibition on timing failure and verify the device is off, preserving its actual transition time if previously enabled. Keep timing-failure cause distinct from permit expiry and never score a forced stop as a successful expiry response. Do not replay missed decisions, backdate events, reset the epoch to hide delay or silently rearm. Restore only through the approved new-generation sequence. Negative controls must expose excessive IRQ delay and recurring CPU demand independently.
4. Freeze inputs and independently replay each policy. Implementation is authorized on the simulator. Analytical admission, independent execution evidence, all applicable board cases and the full-profile #21 decision remain open. IPC #24 remains gated.

### 한국어 결정

QEMU 벤치에서 주기와 마감이 각각 5 ms인 단일 제어 작업에 실제 신선도 판정 두 회를 구현한다. ADR-001은 판정 간격의 최댓값을 정하므로 나이 20 ms 이상에서 더 일찍 만료를 발견할 수 있다. 같은 입력을 다시 읽어도 순번·세대·연속 허가 수·명령 소비 상태가 추가로 진행되어서는 안 된다. 두 위상 모두 현재 판정 시각으로 만료부터 검사하고 즉시 차단을 래치할 수 있다. 이 작업의 송신 주기·마감은 10 ms로 고정한다. 4–5절의 차단·재무장·한계 판정 사례를 모두 유지한다. 만료 한 틱 전부터 정확히 5 ms 간격인 연속 판정은 별도 단일 판정 구성에서 실제로 재현하고 두 위상 구성과 구별하여 기록한다.

1. 공통 기준 시각에서 작업 릴리스와 그 2.5 ms 뒤를 위상 목표로 정한다. 정확히 표현 가능한 카운터로 타이머 목표, IRQ 진입, 준비·재개, 실제 판정 완료와 작업 종료를 남긴다. 시험 입력으로 목표 대비 IRQ 지연 0.5 ms 이하, 계측 불확실성과 모든 지연을 포함한 판정 완료 지연 0~1 ms를 요구한다. 이 조건에서 작업 경계를 포함한 연속 판정 간격 상한은 3.5 ms이다. 실측 간격 5 ms 이하와 각 명목 릴리스부터 종료까지 5 ms 이하를 별도로 검증한다. 부팅 시 차단 상태에서 첫 릴리스를 첫 판정의 기준으로 삼고 차단 중에도 계속 판정한다. 종료 관측 시각을 사전에 지정하고 그 이후 실제 판정까지 마지막 간격을 확인한다. 평가 대상 작업은 마지막 작업까지 모든 위상 및 종료를 기록하고 최종 장치 상태를 독립 확인한다.
2. 같은 작업이 두 번째 위상에서 타이머로 재개한다. 위상별 반복 CPU 실행 예산, 송신 비용, 각 IRQ의 최소 간격·지터, 마스킹·간섭을 평가 전에 고정한다. 매 활성화에서 선점·대기를 분리해 양의 실제 CPU 실행량을 확인하고 위상별·작업별·반복 10 ms 구간별 수요 및 위상 IRQ를 대조한다. 타이머 설정, 진입·복귀, 스케줄러와 관찰 비용을 한 번씩 반영한다. 기존 호스트 도구는 작업 자체 대기를 모델링하지 않는다. 두 위상 창, 이전 구간에서 넘어온 간섭과 송신 응답을 포괄하는 분할 분석 또는 정당화된 보수 분석이 있어야 해석적으로 수용한다. 측정 최대값과 시험 입력만으로 실행 상한을 확정할 수 없다.
3. 늦게 깨어나면 현재 시각으로 한 번 실제 평가하고 지연과 누락 위상을 기록한다. 위상 누락·허용 지연 초과·작업 중첩·관찰 불능 경계는 불합격이다. 타이밍 실패 시 차단을 요청하고 장치 꺼짐과 직전 활성 상태였다면 실제 하강 전이를 확인한다. 타이밍 실패와 허가 만료 원인을 구분하며 강제 차단으로 만료 응답 시험을 통과시킬 수 없다. 밀린 판정 재생, 과거 시각 부여, 기준 시각 이동과 자동 재무장을 금한다. 복구는 승인된 새 세대 재무장 절차를 따른다. IRQ 지연 초과와 반복 CPU 수요 초과를 각각 주입해 검출을 확인한다.
4. 입력을 동결하고 두 정책을 각각 독립 재현한다. 이번 결정은 시뮬레이터 구현을 승인한다. 해석적 수용, 독립 실행 증거, 해당 보드 사례와 #21 전체 프로파일 판정은 미완료이며 IPC #24의 선행 조건은 유지된다.
