# OS 기반 완성 후 선택형 윈도 시스템

[English](window-system-plan.en.md)

CHG-077의 기본 AArch64 이미지는 화면 없이 동작한다. JNOX는 virt에서 스케줄러와 스택 사용을 측정했고, Pi 4 모델에서 두 코어 사이의 지정 깨우기를 관찰했다. 이 기록으로 표시된 프레임, 실물 입력, 윈도 서비스 복구를 확인할 수는 없다. 그래픽은 격리된 프로세스, 한도가 있는 IPC와 공유 메모리, 장치 소유권 및 프로세스 재시작이 갖춰진 뒤 추가할 사용자 서비스다. [스케줄러 근거](evidence/evd-041.md) · [Pi 모델 근거](evidence/evd-056.md)

| 단계 | 구현 범위 | 단계 완료를 확인할 관찰 |
|---|---|---|
| 화면 없는 기준 | 그래픽을 제외한 이미지로 부팅해 선정한 제어 작업을 실행한다. | 이미지 식별값, 메모리 사용량과 제어 작업의 마감 준수 여부를 기록하고, 표시 장치를 분리한 상태에서 반복한다. |
| AArch64 표시·입력 장치 각 1개 | 표시 서비스가 화면 출력을 소유하고 소프트웨어로 그린 픽셀 버퍼를 받는다. 입력 서비스는 실제 포인터·키·터치 이벤트를 전달한다. 화면 출력, 버퍼 반환, 입력 인터페이스를 윈도 프로토콜과 분리한다. | 지정 입력으로 번호가 붙은 픽셀 패턴을 바꾼다. 모델 화면과 선정한 실물 패널의 사진 또는 영상 캡처를 각각 남기고 입력과 프레임 식별값을 대조한다. 버퍼 제출만으로는 화면 표시를 확인할 수 없다. |
| 네이티브 윈도 | 선택형 Wayland 컴포지터와 크기가 제한된 공유 메모리 버퍼에 그리는 JNOX 네이티브 Rust 클라이언트 2개를 추가한다. 컴포지터가 화면 배치, 포커스에 따른 입력 전달, 버퍼 반환을 맡는다. | 두 창을 겹치고 포커스를 바꾼다. 버퍼 반환 전 클라이언트를 종료하고 컴포지터도 재시작한다. 자원 회수, 핸들 폐기, 재접속, 실제 화면 복구와 제어 서비스 지속을 확인한다. [Wayland 구조](https://wayland.freedesktop.org/architecture.html) |
| X11 호환 | 대상 앱이 X11을 요구하면 Xwayland와 컴포지터의 X 윈도 관리자 연동을 추가한다. 소스가 있는 클라이언트와 필요한 라이브러리를 JNOX용으로 빌드한다. | 네이티브 창과 함께 실행해 두 창의 픽셀·포커스·입력을 확인하고 Xwayland 재시작 후 반복한다. 하나의 X 서버를 공유하는 클라이언트끼리는 통신할 수 있으므로 격리가 필요한 앱에는 별도 인스턴스를 검토한다. [Xwayland 구조](https://wayland.freedesktop.org/docs/book/Xwayland.html) |

장치 접근 권한은 표시·입력 서비스에만 부여한다. 클라이언트는 자신이 소유한 버퍼의 회수 가능한 핸들을 받으며 입력은 좌석과 포커스에 따라 전달한다. 클라이언트마다 표면 수, 버퍼 수와 총 바이트, 이벤트 큐 깊이, 미완료 제출 수를 제한한다. 초과 처리와 반환 전 재사용 금지를 명시하고 과대 버퍼, 폐기한 핸들, 대량 이벤트를 시험한다. 장치·버퍼 수명·동기화 계약이 맞으면 네이티브와 X11 경로가 같은 출력·입력 드라이버를 사용한다. GPU 가속은 소프트웨어 화면 출력을 확인한 뒤 평가한다.

연속 화면 갱신 및 입력 부하를 걸고 같은 제어 작업을 화면 없는 기준과 비교한다. 마감 위반, 관측 최장 응답, 표시 서비스 CPU·메모리 사용량, 누락 이벤트, 입력부터 실제 표시까지 걸린 시간을 기록한다. 매 시험 전에 보드, 부하와 수용 한계를 확정한다. 안전 경고등은 선정한 표시 경로에서 고장 시 동작, 독립 감시와 별도 적격성 검증이 필요하다.

**제품 결정 사항.** 첫 패널·입력 장치, 필수 네이티브 및 X11 앱, 상호작용 목표와 자원 한계를 선정한다. 특정 요구가 Xwayland로 제공할 수 없는 확장·장치 인터페이스·동작에 의존할 때 X.Org 직접 이식을 검토한다. 기존 Linux 실행 파일에는 호환 로더·ABI·시스템 호출·라이브러리 또는 별도의 Linux 실행 환경도 필요하다. 기존 Linux 바이너리의 직접 실행은 REQ-021에서 추적한다. 첫 정적 CLI 이후 대상 X11 바이너리와 인터프리터·라이브러리 버전을 고정하여 직접 실행 경로에서 검증한다. Linux 도메인에서 실행한 결과는 별도 호환성 증거로 기록한다. [앱 요구사항](requirements.md)
