## Additive comparison pending implementation and first verification

The existing arm uses the sample at the tail of the Rust acquire handler. Moving it creates a distinct anchor. Retain that implementation, its fixed +100 µs compare, all four original attempts and all qualifications or rejections. A smaller Rust-only variant could reduce handler bookkeeping after the sample; even the last Rust write precedes the function epilogue, frame restore and ERET. Moving the work flag to the prologue or changing code layout cannot establish completed arithmetic. Keep the actual-work predicate and freeze a separate, opt-in return-path cohort.

1. Under masked exceptions validate the successful final acquisition (PI X, ceiling Y), protocol, caller=selected=LOW, owner, result x0=0, full frame bounds, saved LOW identity, ELR and IRQ-enabled SPSR. Publish a one-use pending descriptor containing the exact selected frame, return PC, generation and exact F/10000. Check F is nonzero and divisible by 10000. An unmatched or reused descriptor on its designated return fails closed with a raw reason. Normal SVCs and later IRQ restores cannot arm.
2. At the tail of sched_start_frame after the architectural restore, general register reload, restored SP and CLREX, add only a configuration-gated assembly hook immediately before ERET. Preserve all scratch registers, SP and NZCV across the hook, e.g. with bounded temporary spills in the just-consumed frame. Keep exceptions masked in the handler and let ERET reinstate the original SPSR. Derive the selected frame from restored SP minus frame size and compare with the pending frame, ELR, TPIDR and saved result. This path includes initial and subsequent restores: idle state falls through, a matching pending token is consumed exactly once. Leave existing R timestamp and semantics intact.
3. With the token claimed, ISB and sample CNTPCT, checked-add exactly F/10000, program CNTP_CVAL, enable CNTP_CTL, ISB, read CVAL and CTL, and reject target mismatch, wrong enable/mask bits or overflow. Save requested/actual values and token state in bounded storage, then take an ordered final pre-ERET sample; restore scratch and ERET. Report already elapsed target at that sample explicitly. An already asserted ISTATUS is observable and never permits another arm. On failure disable timer and enter a masked nonreturning raw stop preserving original evidence. Allocate separate versioned arm/return fields, including phase validity, and measure added instructions, spills and storage. The final counter still precedes ERET. Quantify the remaining gap from guest and external observations where available.
4. Keep the original timer mode, duration, workload, chunk/input counts, midpoint yield, eligibility predicates and board scope. Exclude busy waiting, warm-up and retries. Build original defaults with hook absent and compare ELF, PT_LOAD and .text against the retained PI/ceiling images and legacy mutex-bench. Inspect linked restored registers and stack bounds, verify the timer has exactly one eligible writer and that other returns never fire it. Use separate, offline host-only synthetic inputs for wrong frame/owner, reused or duplicate tokens, overflow and mismatched readbacks. These controls exercise rejection logic and supply no guest timing observations.
5. Freeze four fresh positions for the additive arm (PI plain/trace, ceiling plain/trace), the exact binaries, source, native host, observer and 15 s allowance. Preserve every first launch, raw footer/timeout and missing stage. Replay timer, actual work PC, restored frame, lock ordering, chunk ledger, all data and exits against the original criteria. Report the cohorts and their denominators separately. Physical timing, board interference and product qualification remain open.

## Separate route for the original Rust anchor

Retain position 1 as observed. At masked boot validate F and exact divisibility once and store the nonzero 6250-tick interval for this F. In the final-acquire SVC prepare a bounded witness slot before the existing arm site. Bind it to this successful operation, owner, chosen frame, ELR, restore ordinal and generation. Preserve all current frame, ready, lock and one-use checks. At the same logical Rust scheduling point sample CNTPCT, checked-add the prepared interval, write CVAL and CTL, issue ISB, read both back immediately and validate the actual values. Cache the three real samples/values in the reserved record; delay descriptive formatting and the assembly-return correlation until first IRQ or terminal failure. Never substitute a later read or recomputed compare. A return can be linked to the witness only by the recorded frame, PC, ordinal and generation.

Before adopting this layout, map the existing linked path from the sample to the timer writes, readback, SVC epilogue, restore entry, existing R sample and ERET. The retained UART measures the aggregate arm→R interval of 6533 ticks. It cannot partition that time between Rust, timer operations, translation and restoration. In a separately labeled characterization arm collect write/readback-end and restore-entry samples with bounded stores; keep the same compare, retain measurement overhead and reject missing stages. Assess this Rust-anchor layout with its own fresh immutable ELFs and first captures. The later return-anchor sibling remains a distinct question. Original PI/plain qualification remains open.
