# IPC 방식과 프로파일별 인수 기준

한국어 · [English](ipc-mechanisms.en.md)

## 현재 릴리스 범위

**이번 릴리스의 스케줄링 7개 계열 중 6개가 지정 범위에서 승인됐다(6/7).** POL-002 고정 우선순위는 FIFO와 라운드로빈(RR) 두 방식 모두 미결이다. 기존 승인은 POL-003 배치(지정 네이티브·링크형 프로필), POL-005 기한 기반 스케줄링(유한 M1/M3 EDF·표본 LLF), POL-009 다단계 큐(텔레메트리 배포), POL-010 비례 배분(네이티브 구성 6개), POL-011 가중 스케줄링(지정 구성), POL-012 EEVDF(링크형 EL1 텔레메트리)에 적용된다.

REQ-023은 18개 전체 계열과 기존 검증 기록을 유지한다. POL-001, POL-004, POL-006부터 POL-008까지, POL-013부터 POL-018까지는 이번 릴리스에서 목록으로만 관리한다. 실물 Pi 4 검증 [#34](https://github.com/Romanof123/JNOX/issues/34), 고객 작업 부하와 최악 실행 시간(WCET) 검증, ASIL 적격성은 미결이다. CHG-302에 따라 #363의 가상 FIFO·RR 재생 결과를 근거로 #24 IPC 구현을 시작한다. 승인된 IPC 계열은 0/10이다. [IPC-001 계약](native-sync-ipc.en-ko.md) [스케줄링 이슈 #21](https://github.com/Romanof123/JNOX/issues/21) · [IPC 이슈 #24](https://github.com/Romanof123/JNOX/issues/24)

**CHG-007 → REQ-024 → DES-013 → VER-024.** IPC 10개 계열은 다음 릴리스 순서에 따라 개발할 계획이다.

| ID | 범위·소유권·서비스 규약 | 상한과 판별 사례 |
| --- | --- | --- |
| IPC-001 | 로컬 동기 송신·수신·응답. 서버가 일회용 응답 토큰을 소비해 응답하거나 취소가 확정될 때까지 호출자가 대기한다. 허가된 고정 우선순위 호출 사슬을 따라 유효 우선순위를 기부하고 순환은 거부한다. 모든 종료 경로에서 기부를 회수한다. | 대기자 수, 메시지 크기, 사슬 깊이를 제한한다. 높은 우선순위 호출자와 낮은 우선순위 서버 사이에 중간 우선순위 실행자를 둔다. 응답과 시간 초과·호출자 사망을 경합시켜 단일 종료 결과, 우선순위 복원, 뒤늦은 토큰 거부를 확인한다. |
| IPC-002 | 로컬 비동기 메일박스. 송신 성공 시 메시지 전체를 종단이 소유한 FIFO 슬롯으로 복사한다. 가득 차면 즉시 대기 필요를 반환하거나 기한까지 기다린다. | 슬롯·본문·대기 송신자 수를 제한한다. N개 슬롯을 채우고 다음 송신자를 시간 초과시킨 뒤 순서대로 비워 취소된 메시지가 나타나는지 확인한다. |
| IPC-003 | 로컬 펄스·이벤트. 펄스는 레코드를 큐에 넣고 포화 시 실패를 알린다. 비트 이벤트는 소비 전까지 같은 비트의 반복 설정을 합친다. 종단이 미처리 상태를 소유한다. | 펄스 슬롯과 비트 수를 제한한다. 빈 슬롯 두 개를 두고 수신 전에 두 번 신호를 보낸다. 펄스 두 개와 같은 비트의 이벤트 한 개를 구별한다. |
| IPC-004 | 로컬 대기 집합. 허가된 등록 항목은 데이터를 소비하지 않고 종단의 현재 준비 상태를 관찰한다. 깨어난 뒤 준비 상태를 재확인한다. 해제하면 등록 세대를 무효화한다. | 등록 수, 스캔량, 한 번에 반환하는 준비 항목 수를 제한한다. 등록 중 준비 상태 전환, 해제 중 슬롯 재사용을 경합시켜 지속된 준비 상태의 누락과 새 등록으로의 오래된 통지를 검사한다. |
| IPC-005 | 로컬 공유 메모리·고정 버퍼 대여. 매핑 권한을 제한하고 게시로 소유권을 넘기기 전까지 단일 작성자에게 버퍼를 대여한다. 단일 생산자·단일 소비자 링은 release/acquire로 게시하고 포화 시 대기 필요를 반환한다. 진행 중인 접근이 끝난 뒤 회수한다. | 페이지·대여·링 슬롯 수를 제한한다. 인덱스를 순환시키고 보유자를 종료한 뒤 재사용된 슬롯에 대한 과거 대여 반환을 거부한다. 코어 간 공유는 보드에서 가시성을 확인한다. DMA 매핑은 재사용 전 장치 완료와 해당 플랫폼의 캐시 정리·무효화 및 배리어 규칙을 확인한다. |
| IPC-006 | 소켓 종단. 로컬 스트림은 바이트 순서를, 데이터그램은 메시지 경계를, 연결형 seqpacket은 레코드 경계와 순서를 보존한다. 네트워크 TCP 스트림·UDP 데이터그램은 별도 네트워크 전송 계층을 사용한다. 버퍼·연결 대기열·본문을 제한한다. 역압 시 스트림은 부분 쓰기를 허용하고 로컬 레코드·데이터그램은 레코드 전체를 거부하거나 대기한다. | 두 레코드를 보내고 스트림 읽기를 나누어 레코드 모드와 구별한다. 스트림 쓰기 종단을 닫은 뒤 잔여 데이터와 EOF를 확인한다. 선언한 주소·전송 프로파일에서 TCP 연결 리셋, UDP 손실·재정렬을 시험하며 UDP 전달을 보장하지 않는다. |
| IPC-007 | 로컬 익명 파이프·이름 있는 FIFO. 열린 핸들이 유한 바이트 스트림의 각 끝을 소유한다. 작성자가 있는 빈 파이프는 차단하거나 대기 필요를 반환한다. 마지막 작성자가 닫히고 데이터가 소진되면 EOF이다. 판독자가 없으면 쓰기는 실패한다. | 용량과 원자적 쓰기 크기를 고정한다. 작성자 둘이 상한 이내에서 경쟁하도록 하고 파이프를 가득 채운 뒤 복제된 끝을 닫아 원자성과 EOF 시점을 확인한다. 활성 프로파일에서는 네이티브 C 파이프라인을 포함한다. |
| IPC-008 | 발행·구독. 허가된 발행자가 구독자별 유한 큐로 전달한다. 포화된 구독자의 최신 도착 표본을 버리고 그 구독자의 손실 계수를 올린다. 구독 해제는 해당 세대를 폐기한다. 기본 범위는 로컬이며 원격 중계에는 전송 프로파일을 선언한다. | 토픽·구독자 수, 표본 크기, 활성화당 전달량을 제한한다. 한 구독자를 정지시키고 해당 손실 계수, 정상 구독자의 순서 보존, 재구독 후 과거 표본 차단을 확인한다. |
| IPC-009 | 로컬 권한 핸들 전달·수명. 복사 또는 이동을 지정하고 전달 권한을 축소한다. 이동은 수신자 설치와 송신자 핸들 무효화를 원자적으로 확정한다. 실패하면 송신자가 소유권을 유지한다. 닫기·사망은 참조를 해제하고 세대 검사는 오래된 핸들을 거부한다. | 핸들 수, 권한 기술자 수, 메시지당 전달 수를 제한한다. 수신 핸들 표를 채우고 이동 중 상대를 종료한다. 원상복구 또는 단일 소유자 확정, 권한 축소, 슬롯 재사용 뒤 과거 핸들 거부를 확인한다. |
| IPC-010 | 로컬 또는 명시적으로 허가한 중계를 통한 종단 간 안전 채널. 수신자가 유효성·신선도를 검사하고 중계기는 보호된 바이트를 그대로 전달한다. 종단·데이터 ID·세대를 결부하고 무결성·순번·발행 시각·유효 기간을 검사한 뒤 제어에 사용한다. CRC는 우발적 손상을 검출한다. 악의적 상대에 대한 진위 확인에는 별도 인증 수단과 키 수명 관리가 필요하다. | 큐 깊이와 활성화당 수신 작업량을 제한한다. 무효 프레임으로 포화시키고 정확한 만료 시점에 유효 프레임을 넣는다. 만료 우선, 거부 시 승인 상태 보존, 출력 억제와 새 세대 재무장을 [ADR-001](safety-parameters.md) 및 [REQ-019](requirements.md) 기준으로 확인한다. |

## 프로파일과 검증 기록

종단별로 활성 방식, 방향, 권한, 기한, 순서, 포화 동작, QoS를 고정한다. 최대 메시지·레코드 크기, 풀 개수와 총 바이트, 코어별 상태, 복사 횟수, 깨우기 비용, 최대 전달 대상 수를 기록한다. 큐와 대여분의 비용을 소유자에게 귀속한다. 할당 전 수용 거부 조건을 정하고 종료·지연 회수 작업량을 제한한다. 각 차단 연산의 확정 시점을 정의하고 그 전후에 시간 초과·취소·닫기·상대 사망을 경합시킨다. 확정된 연산은 한 번만 집계하고 미사용 용량을 반환한다. 예비 풀을 포함해 REQ-009 대비 커널 RAM과 이미지 크기 증감을 공개한다.

VER-024에서는 독립 검증자가 실행 전 리비전·설정·토폴로지·용량·예상 결과를 고정하고 동결된 이미지 해시를 대조한 뒤 동시 실행 종단으로 선정 사례를 재현한다. 실제 결과·시간·최대 점유량·종료 후 잔여 수를 원시 추적 및 산출물 해시와 함께 기록한다. 제외한 방식과 해당 프로파일도 명시한다. 시간 상한·코어 간 간섭·DMA에 관한 주장은 해당 보드에서 측정한다. Linux 도메인 네트워크 프로파일에는 수정 없이 사용하는 드라이버와 실행 도메인을 식별한다. Linux 바이너리에 소켓을 제공할 때는 별도로 ABI 지원 범위를 선언한다. [플랫폼 프로파일](platform-capabilities.md) · [검증 계획](verification-plan.md)
