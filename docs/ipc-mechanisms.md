# IPC 방식과 프로파일별 인수 기준

한국어 · [English](ipc-mechanisms.en.md)

**IPC-001 출시 판정.** 독립 배포팀이 단일 코어 AArch64 QEMU virt의 FIFO·RR에서 로컬 동기 호출·수신·응답을 승인했다. 승인 범위는 2~3개 프로세스, 방향 지정 호출 권한, 8바이트 요청·응답이다. 기존 12회와 추가 RR 1회에서 두 도착 순서, 우선순위 상속·회수와 정리를 확인했다. 응답과 호출자 종료가 같은 시각인 순서는 호스트에서 검증했다. [독립 승인](evidence/native-sync-ipc-release.en-ko.md) · [추가 원본](evidence/native-sync-ipc-release-supplement.tar.gz) · [현재 계열별 판정](https://github.com/Romanof123/JNOX/issues/24).

**IPC-002 출시 판정 · IMP-303 · EVD-303.** 독립 배포팀은 단일 코어 AArch64 QEMU virt FIFO·RR에서 네이티브 앱 두 개 사이의 우편함을 승인했다. #24의 당시 승인 수는 2/10이었다. 원자료를 보존한 게스트 부팅 12회에 더해 FIFO·RR 각 1회에서 유한 기한 내 대기 송신의 큐 진입과 빈 우편함 수신을 확인했다. 최초 엄격 대조 앱은 지원되지 않는 상대 수면을 사용해 84/83으로 종료했고 절대 수면으로 수정한 앱은 71/72로 종료했다. 임시 캡처 두 건은 원자료가 남지 않았다. 정확한 기한 동시성, 두 송신자 동시 대기, 차단 송신자의 강제 종료는 호스트에서 확인했다. 실물 및 기능 안전 승인은 미결이다. [First report / 최초 보고서](evidence/native-mailbox-first.en-ko.md) · [First archive / 최초 자료](evidence/native-mailbox-first.tar.gz) · [Release decision / 출시 판정](evidence/native-mailbox-ipc-release.en-ko.md) · [Supplement / 추가 자료](evidence/native-mailbox-ipc-release-supplement.tar.gz)

**IPC-003 출시 판정 · IMP-304 · EVD-304.** 독립 Release는 단일 코어 AArch64 QEMU virt FIFO·RR에서 일반 네이티브 앱 두 개의 알림을 승인했다. 이 승인으로 #24에서 3번째 계열을 승인했다. 최초 열 번 중 아홉 번이 예상과 일치했다. 한 건은 실제 EACCES를 시험의 예상값에서 누락했으며 예상값을 수정한 열한 번째 실행을 별도로 보존했다. 추가 RR 실행에서는 통신 권한을 반대로 설정하고 75/76으로 종료했다. 같은 펄스 두 건은 따로 수신됐고 반복 설정한 이벤트 비트는 하나로 합쳐졌다. 정확한 기한 동시성, 강제 종료와 모든 비트 검사는 호스트 사례다. [First report / 최초 보고서](evidence/native-notify-ipc-first.en-ko.md) · [First archive / 최초 자료](evidence/native-notify-ipc-first.tar.gz) · [Release decision / 출시 판정](evidence/native-notify-ipc-release.en-ko.md) · [Supplement / 추가 자료](evidence/native-notify-ipc-release-supplement.tar.gz)

**IPC-004 출시 판정 · IMP-305 · EVD-305.** 독립 Release는 단일 코어 AArch64 QEMU virt의 네이티브 FIFO·RR 대기 집합을 승인했다. 이 판정으로 #24에서 네 번째 계열이 승인됐다(4/10). 최초 콜드 부팅 16회 뒤 Release가 FIFO·RR 이미지를 다시 빌드해 각각 한 번 부팅했다. 추가 두 부팅에서 앱 종료값은 71/72였고 스케줄러 기록 누락은 없었다. 스케줄러 기록 33행을 사설 RAM과 대조해 준비 조회 후 데이터 보존, 실제 송신에 의한 깨움, 슬롯 재사용 후 이전 핸들 거부, 만료 상태 −110을 확인했다. 기한이 정확히 일치하는 경우, 강제 종료 및 세대 상한은 호스트에서 검사했다. 실물 및 일반 인증은 별도 범위다. [First report / 최초 보고서](evidence/native-waitset-ipc-first.en-ko.md) · [First archive / 최초 자료](evidence/native-waitset-ipc-first.tar.gz) · [Release decision / 출시 판정](evidence/native-waitset-ipc-release.en-ko.md) · [Release supplement / 추가 자료](evidence/native-waitset-ipc-release-supplement.tar.gz)

**IPC-005 출시 판정 · IMP-306 · EVD-306.** 독립 Release는 단일 Cortex-A72 코어의 QEMU virt에서 FIFO·RR로 실행한 CPU 전용 공유 버퍼 대여를 승인했다. #24에서 지정 범위로 승인한 다섯 번째 계열이다(5/10). 부팅 11회에는 기능을 끈 대조군 1회가 포함됐다. RAM 캡처는 21개였고, 기능을 켠 10회에서 대여 전용 기록은 소유권 전환 148건을 모두 보존했다. 폴링 부팅에서 일반 스케줄러 기록은 FIFO 2,828건, RR 2,611건을 누락했으며, 두 대여 전용 기록은 각각 34건을 모두 보존했다. 게스트 자원 회수는 정상 프로세스 종료로 확인했다. 게스트 결함·강제 종료 복구, 물리 코어 간 가시성, DMA, WCET 및 ASIL 적격성은 이번 승인 범위 밖이다. [First report / 최초 보고서](evidence/native-loan-ipc-first.en-ko.md) · [Release decision / 출시 판정](evidence/native-loan-ipc-release.en-ko.md)

## 현재 릴리스 범위

**이번 릴리스의 스케줄링 7개 계열 중 6개가 지정 범위에서 승인됐다(6/7).** POL-002 고정 우선순위는 FIFO와 라운드로빈(RR) 두 방식 모두 미결이다. 기존 승인은 POL-003 배치(지정 네이티브·링크형 프로필), POL-005 기한 기반 스케줄링(유한 M1/M3 EDF·표본 LLF), POL-009 다단계 큐(텔레메트리 배포), POL-010 비례 배분(네이티브 구성 6개), POL-011 가중 스케줄링(지정 구성), POL-012 EEVDF(링크형 EL1 텔레메트리)에 적용된다.

REQ-023은 18개 전체 계열과 기존 검증 기록을 유지한다. POL-001, POL-004, POL-006부터 POL-008까지, POL-013부터 POL-018까지는 이번 릴리스에서 목록으로만 관리한다. 실물 Pi 4 검증 [#34](https://github.com/Romanof123/JNOX/issues/34), 고객 작업 부하와 최악 실행 시간(WCET) 검증, ASIL 적격성은 미결이다. CHG-302에 따라 #363의 가상 FIFO·RR 재생 결과를 근거로 #24 IPC 구현을 시작한다. 착수 당시 IPC 계열 승인 수는 0/10이었다. ## 프로파일과 검증 기록

종단별로 활성 방식, 방향, 권한, 기한, 순서, 포화 동작, QoS를 고정한다. 최대 메시지·레코드 크기, 풀 개수와 총 바이트, 코어별 상태, 복사 횟수, 깨우기 비용, 최대 전달 대상 수를 기록한다. 큐와 대여분의 비용을 소유자에게 귀속한다. 할당 전 수용 거부 조건을 정하고 종료·지연 회수 작업량을 제한한다. 각 차단 연산의 확정 시점을 정의하고 그 전후에 시간 초과·취소·닫기·상대 사망을 경합시킨다. 확정된 연산은 한 번만 집계하고 미사용 용량을 반환한다. 예비 풀을 포함해 REQ-009 대비 커널 RAM과 이미지 크기 증감을 공개한다.

VER-024에서는 독립 검증자가 실행 전 리비전·설정·토폴로지·용량·예상 결과를 고정하고 동결된 이미지 해시를 대조한 뒤 동시 실행 종단으로 선정 사례를 재현한다. 실제 결과·시간·최대 점유량·종료 후 잔여 수를 원시 추적 및 산출물 해시와 함께 기록한다. 제외한 방식과 해당 프로파일도 명시한다. 시간 상한·코어 간 간섭·DMA에 관한 주장은 해당 보드에서 측정한다. Linux 도메인 네트워크 프로파일에는 수정 없이 사용하는 드라이버와 실행 도메인을 식별한다. Linux 바이너리에 소켓을 제공할 때는 별도로 ABI 지원 범위를 선언한다. [플랫폼 프로파일](platform-capabilities.md) · [검증 계획](verification-plan.md)
