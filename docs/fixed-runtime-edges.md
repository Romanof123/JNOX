# 고정 우선순위 RR 시간 경계

[English](fixed-runtime-edges.en.md)

CHG-034 / IMP-032, 예정 증거 EVD-032. #72의 REQ-002/005/023 및 VER-002/005/023에 대해 실행 전에 다음 합격 조건을 정한다.

두 앱은 우선순위 2, 물리 카운터 Q = 12,500,000틱의 RR을 사용한다. 부팅 표본 T 기준으로 테이블 순서는 C(슬롯 0, T+Q), A(슬롯 1, T), B(슬롯 2, T+Q/2)이다. A만 즉시 실행 가능하다. UART 각 줄은 FIXED TIES 또는 FIXED LATE 뒤에 START, A START, B RUN, C RUN, A RESUME, A DONE 순이다. 두 동료는 트램펄린으로 복귀해 종료한다. A는 진입부터 12Q 이내에 동료가 완료되지 않으면 실행권이 있을 때 FAIL을 출력한다. 실행권 자체가 돌아오지 않는 경우 호스트 캡처 시간 제한을 별도로 적용한다.

* **fixed-ties**. 첫 비교값 T+Q/2의 IRQ가 T+Q 전에 도착해 A를 유지하고 잔여 슬라이스로 T+Q를 설정한다. 이 비교값에서 C의 논리적 해제와 A의 만료가 겹친다. 이미 대기 중인 B 뒤에 C, 마지막에 A를 넣는다. B로 전환하고 B 종료 시 C, C 종료 시 중단했던 A로 복귀한다. 타이머 IRQ는 정확히 두 번이다. 실제 도착 표본과 예정 비교값은 구분한다.
* **fixed-late**. 시험용 A가 진입 시 IRQ를 마스크하고 카운터 표본부터 4Q 동안 작업한 뒤 해제 직전 표본을 기록하고 마스크를 해제·동기화한다. 마스크 시작은 T+Q/2 이전, 관측한 길이는 4Q 이상 5Q 미만이어야 한다. 지연된 첫 IRQ에서 이미 기한이 지난 B, C를 슬롯 번호와 무관하게 기한순으로 등록한다. 단 한 번의 타이머 결정으로 B에 전환한다. 마스크 동안 경과한 시간은 전부 A에 귀속한다. 이후 B, C의 종료로 차례로 C, A를 선택한다. 타이머 IRQ는 정확히 한 번이다.

fixed_app_observations는 리틀엔디언 u64 16개다. 순서대로 A/B/C의 SP, A 진행량, B와 C가 각각 읽은 진행량, A 진입 카운터, 마스크 시작·종료, B와 C 진입 카운터, A 재개 카운터, 단계, 실패, 예약값 0 두 개다. 세 스택은 정렬되고 서로 달라야 한다. 두 동료가 읽은 양수 진행량은 서로 같고 최종 진행량보다 작아야 한다. 표본은 시간순이며 최종 단계 3, 실패 0이다. ties 마스크 표본은 모두 0이고 late 동료 진입은 마스크 종료 이후다.

일반 ELF와 JNOX_FIXED_TRACE=1 진단 ELF를 각각 빌드·캡처하고 심볼, 해시, QEMU 예외 PC, UART, 관측 메모리, 최종 idle PC를 보존한다. 진단 행은 [고정 런타임 명세](fixed-runtime.md)로 해석한다. 최초·복원 ELR을 실제 작업 및 중단된 A와 대조하고 SP/프레임 연속성, IRQ 소스, 타이머 레지스터, 종료 SVC 및 마지막 idle 타이머 비활성화를 확인한다. 인접 표본의 차를 실제 직전 실행자별로 누적해 서비스 열과 비교한다. B의 첫 ERET 전까지 지연된 시간은 모두 A에, 각 동료의 서비스는 실제 디스패치부터 귀속한다. 일반 ELF는 실행 순서와 문맥을, 진단 ELF는 각 결정의 표본·비교값·서비스까지 입증한다. 표본 불일치나 누락 및 추가 전환은 해당 판정을 보류한다. 범위는 단일 코어 에뮬레이터다.

일반 및 계측 이미지에서 깨움과 퀀텀 만료가 겹쳤을 때 IRQ 두 번, IRQ 마스킹 중 두 작업의 깨움이 밀렸을 때 한 번을 관측했다. 계측 재구성에서 지연 중 경과한 CPU 시간은 중단된 작업에 귀속됐다. [EVD-032](./evidence/evd-032.md)
