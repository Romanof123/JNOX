# #426 Native virtio-net probe and open / 네이티브 장치 등록과 개방

**Evidence boundary / 검증 범위.** Separate existing profiles demonstrate original TX, queue discovery, RX NAPI and IRQ-driven packet delivery. The replacement fixture still constructs a netdev in `rx_poll.c` and calls selected queue routines. The next gate must let the pinned Linux v6.18.65 probe allocate and publish its own device, then use the ops pointer that device registered. Replacement evidence is being sealed separately. No probe/open run is claimed here. [Current fixture](../drivers/linux-compat/packet/rx_poll.c) · [Retained IRQ evidence](../docs/evidence/native-linux-net-irq/result.json)

기존 프로필은 송신·큐 발견·수신 poll·IRQ 전달을 각각 검증했다. 이번 목표는 수동 netdev 초기화를 제거하고 원본 probe가 할당·등록한 객체의 ops로 실제 open을 수행하는 것이다.

1. **Select the original driver and constrain the bus.** Match the typed virtio driver ID and invoke its original validate/probe through a bounded service bus. Admit one CPU, one split RX/TX pair, VERSION_1, a real MAC and optional validated MTU. Supply actual config reads, queue setup, affinity decisions and status transitions. All feature queries from probe must consult the negotiated bitmap, including false answers for control queue, mergeable RX, MQ/RSS, link-status reporting and offloads. Preserve driver-assigned netdev flags separately from bus features. Record immutable negotiated features through remove. The stock direct-relocation closure reports probe 14 functions/74 imports/18 indirect sites and open 7/33/0; following data brings probe to 198 imports. Use symbol-specific service adapters and actual branch evidence. A referenced ethtool ops table alone does not demonstrate ethtool execution. [Measured per-entry graph](../docs/native-linux-net-packet-design.en-ko.md#L11)

   원본 등록 테이블에서 드라이버를 선택하고 검증·probe를 호출한다. 단일 CPU와 분할 큐 한 쌍에서 실제 MAC·MTU·기능 비트를 사용한다. 데이터 테이블을 경유한 의존성과 실행된 호출은 따로 기록한다.

2. **Allocate, register, and make ready in upstream order.** Implement the backing operation for `alloc_etherdev_mq` with one aligned netdev/private allocation, RX/TX queue arrays, mutable MAC storage, queue/NAPI configuration, locks, lists and real object ownership. Let probe set `netdev_ops`, MTU, header length, work and per-device state, run `init_vqs`, and set real queue counts. Provide a single-owner RTNL lock and one-device registry. The exact call is `rtnl_lock → register_netdevice(dev) → virtio_config_driver_disable → virtio_device_ready`. Reject duplicate registration and withhold administrative up until probe has succeeded. Also implement CPU-hotplug instance registration/removal for the fixed CPU (including online and dead nodes), carrier and work enable/disable with observable state. Preserve genuine TX NAPI policy or select the driver's real parameter before probe; the fixture's post-allocation weight override must go. [Probe](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L6839) · [Registration](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L7110) · [CPU notifications](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L4127)

   정렬된 netdev와 private 영역, 송수신 큐, MAC 저장소, 잠금과 소유권을 실제로 제공한다. 원본이 큐를 찾고 ops를 채우게 한다. RTNL 안에서 register_netdevice를 먼저 수행하고 DRIVER_OK를 설정한다. 두 CPU 알림 등록, 작업 상태, 중복 등록 거부와 해제를 구현한다.

3. **Separate DRIVER_OK from RX availability.** The current native startup couples device activation to 32 preposted originals. Split that contract: probe's ready operation sets/read-backs status 15 after queue setup, with zero available RX buffers permitted. Administrative up checks the registered device/epoch, serializes with remove, and invokes `dev->netdev_ops->ndo_open(dev)`; publish UP only after success. Original `virtnet_open` enables refill, calls `try_fill_recv`, registers XDP RX queue identity and the PAGE_SHARED memory model even with no XDP program, enables NAPI and sets carrier. Support the initial scheduled poll and later genuine IRQ wake. Verify actual posted spans, kicks and used returns before reporting packet readiness; open's source does not directly test the boolean from its first refill. [Native start](../kernel/src/native_linux_net_packets.rs#L136) · [Queue enable](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L3176) · [Open](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L3227)

   장치 준비와 수신 버퍼 게시 시점을 분리한다. 관리 요청은 등록 객체의 ndo_open을 호출하고 성공한 뒤 UP을 게시한다. 원본이 보충·킥·PAGE_SHARED 등록·NAPI 활성화를 수행한다. 최초 보충 실패가 곧바로 open 오류가 되지 않으므로 실제 게시 수와 패킷 전달을 따로 검증한다.

4. **Unwind and prove the lifecycle.** Inject allocation failure, registration failure, second CPU notifier failure after DRIVER_OK and XDP memory-model failure during open. For each, verify the upstream error and label-specific ownership delta. On close/remove dispatch the registered stop callback when up, cancel/drain pending work and callbacks, reset hardware, reclaim posted fragments and invalidate the epoch before reuse. Failed reset retains quarantined DMA. Capture original callback PCs, registry/lock transitions, negotiated bits, queue/IRQ receipts and external nonce PCAP → registered RX callback → native consumer; run a second administrative down/up and a fresh bind after remove. Record any IRQ from the initial catch-up separately. [Probe unwind](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L7216) · [Remove](https://github.com/gregkh/linux/blob/4700e3adf3b24b39dd4929e9c6d62811ba3ccea8/drivers/net/virtio_net.c#L7253)

   자원 할당·등록·두 번째 CPU 알림·XDP 메모리 모델의 실패를 주입해 단계별 반납을 확인한다. close/remove 후 이전 세대를 거부하고 리셋 실패 자원은 격리한다. 외부 일회값의 실제 PCAP와 원본 콜백·소비자 바이트를 연결한 뒤 down/up 및 remove 후 재등록을 반복한다.
