# 시스템 시간과 타이머 서비스 계획

[English](system-time-plan.en.md) · CHG-077 · [CAP-001·CAP-012](platform-capabilities.md)

기존 AArch64 작업은 물리 카운터를 읽고 비교 인터럽트를 설정한다. EVD-014는 Pi 4 모델에서 PPI 30의 선점과 저장 PC 복귀를 관측했고 EVD-017은 가상 CPU 2개를 사용했다. 이 결과를 이식 가능한 시계 서비스의 출발점으로 삼는다. 단일 코어 AArch64 QEMU virt에서 네이티브 SDK를 통해 EL0의 C·Rust 응용 프로그램이 단조 시계를 읽을 수 있다. 같은 구성의 네이티브 SDK는 단조 시계 절대 기한까지 대기하는 호출도 제공한다. 실제 날짜·시각, RTC 영속성, 상대 대기 및 타이머 객체 API는 계획 단계다. [절대 기한 대기](evidence/evd-113.md) [응용 프로그램 시계 근거](evidence/evd-112.md) [Pi 타이머 근거](evidence/evd-014.md) · [SMP 근거](evidence/evd-017.md)

## 시계 계약

| 시계 | 기준과 용도 | 갱신 규칙 |
| --- | --- | --- |
| 단조 시계 | 부팅부터 감소하지 않는 경과 시간. 검증된 시계 영역에서 마감·상대 대기·추적 순서에 사용한다. 연속 읽기 값은 같을 수 있다. | 읽기 전용이다. 실제 시각을 바꾸어도 단조값과 기존 단조 마감은 유지된다. 최초 구성은 깨어 있는 상태를 지원한다. |
| 실시간 시계 | POSIX Epoch부터의 부호 있는 64비트 초와 정규화된 나노초. 표시 형식·현지 시간대는 응용이 담당한다. | 일관된 단조 기준과 버전이 있는 오프셋·속도로 계산한다. 출처·마지막 동기화·불확실성·유효성을 기록한다. 부팅 시 날짜를 모르면 미설정으로 둔다. |
| 보드 RTC(선택) | 보드 드라이버가 부팅 시 실시간 시계를 초기화하거나 승인된 날짜를 전원 차단 후까지 보존할 수 있다. | 출처·범위·읽기 일관성과 확인 가능한 발진기/배터리 상태를 점검한다. RTC 저장은 별도 권한 요청이다. 읽기 불가·거부를 기록한다. |

포트는 순서가 보장된 카운터 읽기·폭·주파수·비교기·IRQ 경로·절전 동작·코어 간 공유 범위를 제공한다. AArch64는 CNTPCT_EL0와 검증된 CNTFRQ_EL0, BSP가 허용하는 비보안 물리 비교기를 사용한다. 원시 틱과 부팅/영역 ID를 남긴다. 충분히 넓은 정수로 범위를 검사하고 읽기는 내림, 마감은 표현 가능한 틱으로 올림한다. 잘못된 나노초·주기 재설정을 포함한 오버플로를 거부한다. 좁은 카운터 확장은 판독 간격과 래핑 한계를 입증해야 한다. 해상도·동기화 불확실성·실제 깨우기 지연을 각각 측정한다.

기준 틱·오프셋·속도 보정·유효성·세대를 일관된 스냅샷으로 공개한다. 읽기와 갱신이 겹치면 세대를 확인해 재시도하고 한도에서 커널 경로를 사용한다. 이동 가능한 CPU 사이의 공통 주파수·기준 시점·읽기 순서를 검증한다. 전역 단조성을 확보할 수 없으면 검증된 시계 영역으로 구성을 제한한다. 절전 전 체크포인트를 저장하고 카운터 정지 여부를 명시한다. 연속성 및 경과 시간 산정 규칙을 확인한 뒤 복귀를 지원한다. 재부팅은 새 단조 세대다. 실제 시각 출처 상실 시 마지막 동기값을 유지하고 측정한 드리프트 상한으로 불확실성을 늘린다. 허용 범위를 넘거나 상한이 없으면 미동기 상태로 전환한다.

## 접근과 만료

일반 응용은 시계와 품질을 읽을 수 있다. 구성 책임자가 실제 시각 설정·한도 내 점진 보정·RTC 쓰기 권한을 각각 부여한다. 요청자·출처·이전/새 세대·변경량·결과를 감사 기록한다. 네트워크나 호스트에서 자동으로 시간을 받지 않는다. 즉시 설정은 시각을 뒤로 옮길 수 있다. 점진 보정은 최대 속도와 양의 유효 진행률을 지키고, 교체·취소는 실제 변경 시점에 직렬화한다. 안전 타임아웃은 단조 시간을 사용한다. 미설정 실시간 읽기/절대 마감은 출처가 승인될 때까지 문서화된 사용 불가 상태를 반환한다.

POSIX 범위를 단계화한다. clock_gettime/getres, 권한 있는 실시간 clock_settime, 상대/절대 clock_nanosleep을 먼저 제공하고 timer_create/settime/gettime/delete와 초과 만료 횟수 보고를 추가한다. 구성별 시계 ID·오류·ABI 범위·중단/재시작 동작·유한 객체/알림 용량을 공개한다. 실제 시각 변경 시 실시간 절대 대기를 재평가한다. 앞으로 건넌 마감은 만료되고 뒤로 변경하면 대기 중인 마감은 늦어진다. 상대 대기는 원래 경과 시간 목표를 유지한다. 주기 타이머는 이전 마감에서 전진하며 알림 수를 제한하고 놓친 주기를 보고한다. 객체 세대로 취소·재설정·만료를 직렬화하고 재사용 핸들에 이전 세대 알림을 전달하지 않는다. 명목 마감·실제 IRQ·준비·작업 복귀를 각각 기록한다.

## 최초 검증과 결정

1. 결정론적 카운터와 독립 정수 오라클에서 3 Hz의 첫 틱은 333333333 ns, 333333334 ns 마감은 두 번째 틱으로 설정되어야 한다. 잘못된 주파수·래핑 한계·2038년 이후 날짜·오버플로·설정 권한 거부·동시 취소/만료를 확인한다.
2. 단조 10초에 실제 시각을 100초로 설정하고 5초 상대 대기와 실제 시각 105초 절대 대기를 건다. 1초 후 실제 시각을 110초로 변경하면 절대 대기는 만료되고 상대 대기는 단조 15초에 만료된다. 이전 시각 설정·한도 내 점진 보정·출처 상실·RTC 오류·재부팅도 확인한다. 첫 결과와 원시 입력을 모두 보존한다.
3. AArch64 virt와 Pi 모델에서 정확한 이미지의 주파수·비교기 재읽기·실제 IRQ/복귀·응용 타임스탬프를 수집하고 부하 중 만료 순서 및 코어별/이동 후 읽기를 확인한다. 실물 보드의 발진기 드리프트·RTC 전원 유지·절전 복귀·정확도·비용·독립 시계 고장 감지는 별도 검증한다.

**제품 결정 사항**은 신뢰할 시각 출처/RTC, 보정 승인 주체, 최대 즉시 변경량/보정 속도와 동기 상실 시 허용 불확실성, 절전 요구, 필수 동기 정확도다. 개발팀은 결정 전에도 단조 시계·미설정 실제 시각 처리와 산술·권한 시험을 구현할 수 있다. 모델 틱은 제품 시간 할당의 근거가 되지 않는다. [REQ-005/008/014/018](requirements.md) · [DES-003/004/005/006](architecture.md) · [VER-005/008/014/018](verification-plan.md)
