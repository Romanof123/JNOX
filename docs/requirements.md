# 시스템 요구사항 초안

각 행은 승인 전 후보 요구사항이다. 제품별 수치는 안전 분석이나 보드 평가에서 배정하고, 배정 근거를 추적한다. `DES`는 [아키텍처](architecture.md), `VER`은 [검증 계획](verification-plan.md)에 정의한다.

| 요구사항 | 출처 | 요구와 합격 기준 | 설계 · 검증 |
| --- | --- | --- | --- |
| `REQ-001` 공간 격리 | `HAZ-002`, `THR-001` | 허가된 통로를 제외한 CPU·DMA 쓰기와 장치 접근은 제어 영역에 도달하지 않는다. 잘못된 접근은 봉쇄되고 안전 영역의 상태가 보존돼야 한다. | `DES-001`, `DES-002` · `VER-001` |
| `REQ-002` 시간 격리 | `HAZ-001`, `HAZ-004`, `THR-001`, `OBJ-004` | 구성마다 태스크 주기·기한·예산·IRQ 한도를 선언한다. 허용 부하 및 동시 간섭에서 각 응답시간이 할당 한계 이내여야 하며, 초과 시 정한 상태로 전이해야 한다. | `DES-003`, `DES-006` · `VER-002` |
| `REQ-003` 제어 데이터와 고장 반응 | `HAZ-003`, `HAZ-004`, `THR-001` | 제어 입력의 길이, 범위, 버전, 순번과 신선도를 검사한다. 종료·무응답·재시작은 유한 시간 안에 호출자에게 전달하고 안전 동작을 수행한다. | `DES-002`, `DES-006` · `VER-003` |
| `REQ-004` Linux 드라이버 이관 | `OBJ-003` | 선정한 장치에서 기존 소스와 드라이버 바이너리 변경 없이 호환 Linux 구성으로 기능을 재현한다. 커널·모듈·펌웨어·장치 설정 버전과 SHA-256을 남긴다. | `DES-002` · `VER-004` |
| `REQ-005` 스레드와 SMP | `OBJ-004`, `HAZ-001` | 같은 주소 공간에 스레드 여러 개를 실행한다. 스레드 생성·종료·대기·취소, CPU 친화도, 동기화, 동시 종료 및 큐 경합 동작을 시험한다. 안전 구성은 승인된 CPU·개수·정책으로 실행한다. | `DES-001`, `DES-003` · `VER-005` |
| `REQ-006` 병행 소켓 | `OBJ-006`, `THR-003` | 확장 구성에서 여러 프로세스와 스레드가 로컬 소켓과 TCP/UDP IPv4·IPv6 소켓을 동시에 사용한다. 비차단 I/O, 준비 알림, 동시 읽기·종료, 연결·버퍼 상한과 역압을 문서화한다. | `DES-005` · `VER-006` |
| `REQ-007` 스크립트 | `OBJ-006`, `THR-003` | 호스트 빌드·시험 자동화와 타깃 사용자 모드 스크립트를 제공한다. 타깃은 CPU·메모리·권한 한도를 적용하고 중단 가능해야 한다. 안전 설정은 빌드 시 정적으로 검증한다. | `DES-005` · `VER-007` |
| `REQ-008` 포터빌리티 | `OBJ-005` | 각 포트는 CPU, 보드, 메모리 보호, 부트, IRQ, 타이머, SMP, DMA, 실시간 및 드라이버 지원 수준을 선언하고 공통 계약 시험을 통과한다. | `DES-004` · `VER-008` |
| `REQ-009` 경량성 | `OBJ-004` | 최소 이미지의 코드·상수, 커널 RAM·스택·정적 풀, 초기화 시간과 물리 보드 지연을 측정한다. 참조 크기 목표는 AArch64 최소 이미지 코드·상수 256 KiB, 최소 커널 RAM 2 MiB 이내로 제안한다. | `DES-001`, `DES-004` · `VER-009` |
| `REQ-010` 부팅·업데이트 신뢰 | `OBJ-002`, `THR-002` | 부트 이미지·설정과 업데이트를 인증한다. 위조·폐기·정책 위반 버전을 거부하며 전원 손실 후 승인된 이미지로 복구한다. | `DES-007` · `VER-010` |
| `REQ-011` 최소 권한과 자원 상한 | `OBJ-002`, `THR-001`, `THR-003` | 모든 서비스·장치·소켓·스크립트의 권한과 자원 상한을 선언한다. 잘못된 요청이나 과부하에서 권한 위반과 안전 영역 고갈이 발생하지 않아야 한다. | `DES-001`, `DES-002`, `DES-005`, `DES-007` · `VER-011` |
| `REQ-012` 개발·검증 추적 | `OBJ-007` | 출시 후보의 모든 적용 요구에 원천, 설계, 구현, 시험, 근거와 승인 상태가 연결돼야 한다. 변경으로 영향을 받는 근거를 기한 없이 재사용할 수 없다. | `DES-008` · `VER-012` |
| `REQ-013` 안전 구성 적합성 | `OBJ-001`, `OBJ-007`, `HAZ-004` | 안전 매뉴얼과 적용 가정, 정확한 하드웨어·컴파일러·부트·코드·설정 버전, 독립 검증 결과와 잔여 위험을 검토할 수 있어야 한다. | `DES-006`, `DES-008` · `VER-013` |
| `REQ-014` 개발·관측 API | `OBJ-006`, `OBJ-004` | 선택한 POSIX API와 자체 IPC의 버전·오류·지원 구성을 정의한다. 제한된 진단 로그와 플랫폼 시간 계측을 제공하고 관측 기능의 비용을 측정한다. | `DES-005`, `DES-006` · `VER-014` |
| `REQ-015` 네이티브 Rust 드라이버 | `OBJ-008`, `HAZ-002`, `THR-001` | 비특권 Rust 서비스가 SDK로 요청·응답, 장치 레지스터 접근, IRQ와 허용된 DMA 버퍼를 관리한다. 권한 없는 매핑과 재시작 전 요청은 거부되고 다른 서비스가 계속 동작한다. | `DES-009` · `VER-015` |
| `REQ-016` Rust 구현·툴체인 신뢰 | `OBJ-008`, `OBJ-001`, `THR-002` | 커널 핵심은 `no_std` Rust로 작성한다. `unsafe` 전제와 위치, 라이브러리·컴파일러·링커 범위, 고정 버전과 재현 빌드 근거를 검토한다. | `DES-001`, `DES-008`, `DES-009` · `VER-016` |

`REQ-009`의 용량 목표에는 부트 펌웨어, 사용자 서비스와 Linux 이미지가 포함되지 않는다. 커널 RAM에는 설정 프로파일에 포함된 커널 객체, 페이지 테이블, 스택, 예비 풀이 포함된다. 빌드 시 이미지의 크기 산정 기준과 링크 맵을 기록한다.
