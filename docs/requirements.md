# 시스템 요구사항 초안

한국어 · [English](requirements.en.md)

각 행은 승인 전 후보 요구사항이다. 제품별 수치는 안전 분석이나 보드 평가에서 배정하고, 배정 근거를 추적한다. `DES`는 [아키텍처](architecture.md), `VER`은 [검증 계획](verification-plan.md)에 정의한다.

| `REQ-019` 안전 IPC 채널 | `OBJ-001`, `HAZ-003`, `THR-001` | 안전 채널은 허용된 엔드포인트·데이터 ID로 묶고 수신자가 메시지 무결성, 세대, 순번, 발행 시각과 유효기간을 확인한 뒤에만 제어 태스크에 값을 전달한다. 거부된 프레임은 마지막 유효 값·시각·순번과 재가동 카운트를 갱신하지 않는다. 송신 중단, 유효하지 않은 메시지의 연속 수신, 큐 포화 중에도 수신자는 자기 시간 예산 안에 만료를 판정한다. | `DES-010` · `VER-019` |

CHG-300은 이번 출시 요구를 POL-002·003·005·009·010·011·012에 적용한다. 승인은 기록된 작업·대상·한도에 한정한다. [출시 범위](scheduling-release-cases.md) | `DES-012`, `DES-003` · `VER-023` |
| `REQ-024` IPC 프로파일 | OBJ-001, OBJ-004, OBJ-006, THR-001 | 각 종단의 권한, 전달·소유권, 용량, 대기·기한, 취소·상대 종료 경합의 단일 결과, 자원 회수 한도를 명시한다. 최소 프로파일은 선택한 기법에 필요한 자원만 할당한다. CHG-302의 최초 대상은 가상 FIFO·RR에서 실행하는 로컬 동기 호출이다. [IPC-001](native-sync-ipc.en-ko.md) | DES-013, DES-010 · VER-024, VER-019 |
| `REQ-025` 선언형 네이티브 태스크 | `HAZ-001`, `OBJ-004` | 앱·태스크 선언을 전부 적용하거나 패키지를 거부한다. 앱을 격리하고 주기별 작업 마감, 선택적 완료 감시, 즉시 자체 오류 중단을 독립적으로 처리한다. [정책 v1](native-task-policy.en-ko.md) | DES-014 · VER-025 |

커널 RAM에는 프로파일의 커널 객체, 페이지 테이블, 스택과 예비 풀이 포함된다. 대상 장비의 할당량을 검증할 때 부트 펌웨어, 사용자 서비스와 Linux 이미지는 별도로 산정한다. CHG-111(#285)에 따라 OS 전체에 공통 이미지 크기 목표를 두지 않으며, 크기 측정이나 보고를 정례화하거나 출시 조건으로 삼지 않는다. 선택적으로 실행하는 최소 virt 참조 벤치마크에는 자체 기준을 적용한다. [CHG-090](scheduling-footprint.md)
