# 검증 계획 초안

검증팀은 제품 기획과 승인된 요구사항으로부터 합격 기준을 검토한다. 최초 실행에서 구현팀의 시험 결론은 공유하지 않는다. 독립 판정을 기록한 뒤 구조·커버리지·도구 검토를 수행한다. 시험 환경, 명령, 입력, 원본 로그, 실패 관찰·재현 방법을 남긴다.

| 검증 ID | 검증 요구 | 환경과 합격 판정 |
| --- | --- | --- |
| `VER-001` | `REQ-001` | CPU의 타 영역 쓰기와 읽기를 가상·실기기에서 점검한다. 실보드에서는 Linux 장치에 배정된 DMA와 차단 범위를 확인하고, 잘못된 접근 뒤 제어 데이터와 경계 소유권이 보존됨을 확인한다. |
| `VER-002` | `REQ-002` | 선점, 일정·예산 고갈, 락 경합, 타이머 감시를 QEMU에서 기능 검증한다. 실보드에서는 CPU·IRQ·DMA·버스 경쟁을 함께 재현하고 최악 응답시간·간섭 분석을 제품 한계와 대조한다. |
| `VER-003` | `REQ-003` | 정상 왕복 뒤 Linux·서비스 중단, 지연·중복·오래된 데이터, 재시작을 각각 주입한다. 기한 및 제품별 상태 전이, 이전 세대 요청의 폐기, 회복 절차를 확인한다. |
| `VER-004` | `REQ-004` | 실제 Linux에서 기존 장치의 기준 동작과 통합 이후를 비교한다. 커널, 설정, 펌웨어, 드라이버 바이너리 SHA-256과 장치 기능 시험이 일치해야 한다. |
| `VER-005` | `REQ-005` | 단일 코어에서 멀티스레드 생명주기·동기화와 순서를 검증한다. SMP에서 코어 친화도, 경쟁, 종료·취소 동시 발생, 인터럽트와 장시간 실행을 점검한다. |
| `VER-006` | `REQ-006` | 여러 프로세스·스레드가 AF_UNIX/TCP/UDP를 동시에 쓴다. 준비 상태와 타임아웃, 부분 읽기, 종료 중 I/O, 포화 상태에서 오류·자원 반납을 확인한다. |
| `VER-007` | `REQ-007` | 같은 스크립트 입력으로 동일한 정적 설정을 만들고 잘못된 설정을 거부한다. 타깃 스크립트의 무한 실행, 할당 한도와 권한 요청을 시험한다. |
| `VER-008` | `REQ-008` | CPU·BSP별 부팅부터 예외, 메모리 보호, 타이머, SMP와 해당 장치까지 지원 범위를 기록한다. QEMU·실보드·안전 구성 결과를 각 상태로 남긴다. |
| `VER-009` | `REQ-009` | 고정 핵심 구성의 링크 맵, 부팅과 메모리 기준을 기록한다. 실기기에서 부팅, 인터럽트→태스크, 문맥 전환 및 IPC 지연을 계측하고 시험 조건과 최대 관찰치를 남긴다. |
| `VER-010` | `REQ-010` | 변조·미승인 버전·폐기된 키의 이미지를 거부하는지 확인한다. 업데이트 단계별 전원 손실과 승인 이미지 복구를 확인한다. |
| `VER-011` | `REQ-011` | 도메인별 권한·큐·핸들·할당량을 확인한다. 비정상 요청과 과부하에서 안전 큐·메모리·처리 시간이 예약된 한도 안인지 확인한다. |
| `VER-012` | `REQ-012` | 요구의 모든 상하위 링크와 고아 노드를 양방향으로 확인한다. 변경된 요구·가정에 대해 영향 분석과 다시 실행된 시험을 검토한다. |
| `VER-013` | `REQ-013` | 실제 적용 가정, 단일·종속고장 분석, 실기기 결과, 툴 신뢰·커버리지·잔여 위험, 구성 해시와 독립 검토 기록을 점검한다. |
| `VER-014` | `REQ-014` | 승인한 API 목록의 정상·오류 동작을 검증한다. 로그가 포화돼도 안전 실행과 증거 해석이 유지되는지 계측한다. |
| `VER-015` | `REQ-015` | 가상 UART 등 네이티브 Rust 드라이버의 요청·IRQ·오류를 확인한다. 지원되는 물리 장치에서 DMA 버퍼 회수·차단, 종료 후 재시작과 다른 서비스의 독립 동작을 검증한다. |
| `VER-016` | `REQ-016` | 독립 리뷰어가 `unsafe` 목록과 불변식, 선택한 컴파일러 타깃·호스트·옵션·라이브러리 범위를 대조한다. 같은 입력의 재현 빌드와 변경 시 다시 검토할 근거를 확인한다. |

## 판정과 증거

검증 수준은 문서·설계 검토, 호스트 단위 시험, QEMU 통합 시험, 실제 보드, 제품 HIL 및 독립 검토로 기록한다. QEMU는 논리 동작과 재현에 쓰며, 실제 시간 상한과 보드의 DMA·리셋·전기적 독립성은 적합한 환경에서 검증한다. 측정 지연 분포는 분석으로 정한 시간 상한과 나란히 보고한다. 커버리지는 선택한 안전 요구와 분석 방법을 기준으로 기록한다.

검증 결과에는 `EVD` ID, 기준선, `VER`·`REQ` ID, 시험 주체와 날짜, 소스 커밋 및 이미지 SHA-256, 보드·펌웨어·계측기·툴 버전, 절차·입력·기대치, 원본 로그 경로, 판정 및 예외를 담는다. 상태는 `계획`, `통과`, `실패`, `차단`, `재검증 필요` 중 하나로 관리한다. 현재 문서는 시험 계획이며 제품 증거 `EVD`는 승인된 검증 절차에서 발행한다.
