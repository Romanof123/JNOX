# 검증 계획 초안

한국어 · [English](verification-plan.en.md)

검증팀은 제품 기획과 승인된 요구사항으로부터 합격 기준을 검토한다. 최초 실행에서 구현팀의 시험 결론은 공유하지 않는다. 독립 판정을 기록한 뒤 구조·커버리지·도구 검토를 수행한다. 시험 환경, 명령, 입력, 원본 로그, 실패 관찰·재현 방법을 남긴다.

### Linux 바이너리 기준 시료

`VER-021`의 시료는 Debian trixie arm64의 `busybox-static` 버전 `1:1.37.0-6+b9`다. 패키지 SHA-256은 `c833be48abfa16bc19c4966ec93e289ff1ce5d2f1476cad3a57bd105378cd15c`, 추출한 `usr/bin/busybox`의 SHA-256은 `7d93682be37cf6ed46699f6fff546b80bf133cf8ec342c2d04bc23387f78bc34`다. 실행 파일은 1,975,064바이트이고 `PT_TLS`가 있으며 `PT_INTERP`는 없다. 검증 증거에는 게스트가 꺼진 부팅 구성, J-NOX 사용자 프로세스의 실행·종료 기록과 양쪽의 출력 원본을 첨부한다. [Debian 기준 패키지](https://deb.debian.org/debian/pool/main/b/busybox/busybox-static_1.37.0-6+b9_arm64.deb)

## 판정과 증거

안전 IPC 허가 채널 시험(`VER-019`)은 `ADR-001`의 가상 벤치 예산을 따른다. 주입 시점에 정상 송신 경로를 닫고 아직 전달되지 않은 유효 프레임을 무효화한다. 무송신, 지속적인 불량 입력, 큐 포화를 별도 실행한다. 뒤의 두 실행에서는 별도 시험 주입기가 닫힌 경로의 수신측에서 정상 수신 큐로 불량 프레임을 공급한다. 포화 사례에서는 큐가 가득 찬 시점과 새 송신의 거절을 기록한다. 순번·시각·채널 ID 검사 사례는 해당 필드를 바꾼 뒤 올바른 CRC를 생성해 그 검사 자체의 거부 여부를 확인한다.

세 실행 각각에서 신선도 검사 완료 간격은 최대 5 ms, 주입부터 검출까지 25 ms, 검출부터 가상 출력 차단까지 5 ms, 전체 30 ms 이내여야 한다. 수신 오류 횟수, 거부 이유, 유효 데이터 전달과 실제 가상 출력 전이를 독립적인 시험 기록에 남긴다.

`VER-002`와 `VER-003`의 첫 벤치 사례는 `ADR-001`의 시간 예산을 사용한다. 검증팀은 같은 단조 시계로 고장 주입(`t_fault`), 고장 래치 설정(`t_detect`), 가상 장치에서 독립 관측한 출력 전이(`t_safe`)를 각각 기록해 두 구간과 총시간을 판정한다. 실보드 또는 적합한 HIL에서 수행하는 클록·리셋 고장 시험은 `VER-018`에서 다룬다. [벤치 판정 기준](safety-parameters.md)

검증 수준은 문서·설계 검토, 호스트 단위 시험, QEMU 통합 시험, 실제 보드, 제품 HIL 및 독립 검토로 기록한다. QEMU는 논리 동작과 재현에 쓰며, 실제 시간 상한과 보드의 DMA·리셋·전기적 독립성은 적합한 환경에서 검증한다. 측정 지연 분포는 분석으로 정한 시간 상한과 나란히 보고한다. 커버리지는 선택한 안전 요구와 분석 방법을 기준으로 기록한다.

검증 결과에는 `EVD` ID, 기준선, `VER`·`REQ` ID, 시험 주체와 날짜, 소스 커밋 및 이미지 SHA-256, 보드·펌웨어·계측기·툴 버전, 절차·입력·기대치, 원본 로그 경로, 판정 및 예외를 담는다. 상태는 `계획`, `통과`, `실패`, `차단`, `재검증 필요` 중 하나로 관리한다. 현재 문서는 시험 계획이며 제품 증거 `EVD`는 승인된 검증 절차에서 발행한다.
