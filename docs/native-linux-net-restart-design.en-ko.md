# Original virtio-net driver replacement / 원본 virtio-net 드라이버 프로세스 교체

**Proposed acceptance for [#5](https://github.com/Romanof123/JNOX/issues/5) and [#426](https://github.com/Romanof123/JNOX/issues/426).** In one AArch64 QEMU virt FIFO boot, let a driver exit while the device still owns RX buffers. Admit a distinct driver process only after verified reset, then deliver a fresh external challenge through the original RX path to the surviving consumer. This is a plan based on source inspection of the [published native poll implementation](https://github.com/Romanof123/JNOX/tree/e4027e6a57d91904306d6ba266047bab1090aa0d).

**목표.** 단일 QEMU 부팅에서 수신 버퍼가 장치에 게시된 채로 드라이버를 종료한다. 리셋을 확인한 뒤 별도 프로세스가 장치를 인수하고, 기존 소비자가 원본 RX 경로를 통해 새 외부 프레임을 받는지 검증한다. 아래 항목은 소스 검토를 바탕으로 한 구현·실측 계획이다.

## One recovery profile / 복구 프로필

1. **Package three processes.** Slot 0 is the primary, slot 1 the continuing consumer and slot 2 the dormant replacement. Load the original driver ELF into separate private instances for slots 0 and 2. Extend the packager and Rust selector together. Keep the two current 0↔1 pipe links. Add `2:3:1:5` for replacement data and `1:6:2:4` for its replies within the four-link limit. Bind each device call, posted EL0 span and notification to the authorized process and queue epoch. The survivor keeps its own journal across both sessions. [Package](../tools/build_native_el0.py) · [Kernel selectors](../kernel/build.rs) · [Pipe exit](../kernel/src/native_pipe_ipc.rs)

   슬롯 0은 주 드라이버, 1은 계속 실행할 소비자, 2는 별도 주소 공간의 예비 드라이버로 구성한다. 소비자의 fd 3/4는 기존 세션, fd 5/6은 새 세션에 연결한다. 커널은 장치 호출·버퍼·통지마다 소유 프로세스와 세대를 확인한다.

2. **Create observable outstanding work.** Exchange ordinary primary traffic first. With Status=15, stop slot 0 from polling or reaping and wait on its reply pipe. On the isolated QEMU link inject one unique old-epoch frame. Before allowing exit, freeze and join its ingress PCAP bytes to the device's new used ID, used length and the descriptor's EL1 bounce bytes. Verify the driver's consumed index and slot 1's journal still precede that frame. Also identify a different posted RX descriptor with WRITE, a live grant, and no used entry since posting. The two observations distinguish completed DMA awaiting delivery from buffers still offered to the device. Release the exit barrier and return 86 directly through SVC 1, bypassing voluntary SVC 156 release.

   기존 트래픽을 확인한 뒤 슬롯 0을 파이프에서 대기시키고 구세대 전용 프레임을 주입한다. 종료 직전 PCAP·used ID·길이·DMA 버퍼를 대조한다. 아직 소비자가 받지 않은 이 완료와 별도로, 사용 완료되지 않은 게시 디스크립터도 확인한다. 주 프로세스가 정리 호출 없이 종료 코드 86을 내도록 한다. 이는 드라이버 보고 실패이며, 동기 예외 격리는 별도 시험이다.

3. **Gate rebind on retirement.** Under the masked owner-exit transition clear owner eligibility and old-token access, stop further delivery and execute the bounded reset. Propagate its result. Capture QEMU MMIO write/read zero and RX/TX QueueReady readbacks, then inspect cleared grants/bounce bytes before new queue setup. Hash the private RX destination in slot 0 before exit and after slot 2 handles new traffic to detect a late copy. Admit slot 2 only on success and the chosen failure exit. Let it explicitly claim with SVC 156 and negotiate and set up fresh queues with SVC 161. For a future IRQ-driven profile, revoke the old interrupt recipient, mask the designated QEMU virt NIC line (INTID 79 in the design), acknowledge or drain pending notifications and synchronize the handler before re-enabling it for the successor. Acceptance of physical IRQ recovery needs GIC IAR/EOI, recipient epoch and callback-PC evidence. [Exit boundary](../kernel/src/native_el0.rs) · [Prior reset trace](../docs/evidence/native-net-dma/README.md)

   종료 시 이전 권한을 먼저 끊고 Status와 양쪽 QueueReady가 모두 0임을 관측한 뒤에만 버퍼를 회수하고 슬롯 2를 기동한다. 슬롯 0의 RX 목적지 해시를 교체 전후에 대조한다. 실제 NIC IRQ까지 인계하는 단계에서는 기존 인터럽트 수신자 해제·마스킹·대기 이벤트 처리와 새 수신자의 GIC/콜백 기록까지 요구한다.

4. **Prove the new instance and survivor.** Capture slot 2's first EL0 PC, TTBR0/ASID and initial driver state alongside slot 0's exit PC/root, distinct roots and the two ELF hashes. After a fresh queue token is issued, replay the old token from the authorized successor via SVC 162/171/172/173 and require `-116`. Slot 1 must receive `-13` even with the current token. Inject a different host nonce and run 80 RX frames through the original registered poll, GRO handoff and the survivor's second data pipe. Match each byte, nonce and sequence to ingress PCAP. Check that the unreaped old completion never appears as a new delivery. Correlate slot 1's unchanged root and increasing timer/sequence journal before exit, during retirement-to-claim, and after replacement. A survivor-controlled barrier before claim makes the middle interval observable. [Poll fixture](../examples/linux-source-net-rx/driver.c) · [Consumer](../examples/linux-source-net-rx/peer.c)

   종료한 슬롯 0과 처음 실행한 슬롯 2의 PC·TTBR0·ASID를 구분한다. 슬롯 2에서 구세대 토큰은 `-116`, 슬롯 1에서 현세대 토큰은 `-13`이어야 한다. 새 nonce의 80프레임을 외부 PCAP부터 같은 소비자까지 바이트 단위로 대조한다. 인계 전·중·후에 슬롯 1의 주소 공간과 타이머 진행을 확인한다.

## Failure controls / 음성 대조

| Case / 사례 | Required observation / 합격 판정 |
|---|---|
| Normal primary exit or second driver failure / 정상 종료·두 번째 실패 | Normal exit dismisses the unused spare. A failed replacement retires its own device once and exhausts the handoff allowance. Slot 1 continues. / 정상 종료 시 예비 슬롯 미실행, 예비 드라이버 실패 시 재인계 금지, 소비자 진행. |
| Missing reset acknowledgement or either QueueReady stuck / 리셋 미응답·큐 정지 실패 | Run deterministic register-model controls for each failure. Preserve quarantined backing with the old token inaccessible. Verify that the scrub count, replacement grants and new postings stay at zero. Label model results separately from live QEMU MMIO. / 격리 풀 보존·구토큰 거부·재사용 금지를 확인하고 모형 결과와 게스트 실측을 구분한다. [Reset controls](../kernel/src/native_virtio_reset_test.rs) |
| False handoff or stale completion / 잘못된 인계·늦은 완료 | Offline replay must reject same-root reacquisition, an altered used ID/old payload, a missing queue readback, token reuse, or an old nonce accepted by the surviving consumer. Traffic buffered outside the guest during reset needs its own nonce/sequence check. / 동일 루트 재획득, used ID·데이터 변조, 큐 확인 누락, 토큰 재사용과 구세대 전달을 각각 검출한다. 가상 NIC 밖에 대기한 외부 트래픽은 프로토콜 nonce로 식별한다. |
